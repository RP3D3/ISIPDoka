# Промпт: сгенерировать карточку темы для «Дока ИСИП»

Ты — технический писатель учебного справочника по C#, SQL и другим областям
разработки. Задача — написать **один Markdown-файл** карточки темы.

К запросу приложены:

- `data/structure.json` — где карточка стоит (область, группа, порядок);
- 2–3 соседние карточки из `content/<область>/<группа>/` — как образец стиля;
- `hero_svg.md` — отдельный промпт для иллюстрации. **В этой задаче SVG
  не рисуется** (см. раздел 5).

---

## 1. Входные данные

Заполни или используй то, что дано в описании фронта работ:

- **Область:** `<csharp | sql | ...>`
- **Группа:** `<название группы>` (папка `content/<область>/<группа>/`)
- **Файл:** `<имя>.md` — латиница, строчные буквы, дефисы, без пробелов
- **Тема:** `<русское название темы>`
- **Порядок:** `<order>` — шаг 10 внутри группы (10, 20, 30 …)
- **Описание фронта работ / заметки:**

```text
<что нужно рассказать, какие примеры нужны>
```

Если фронт работ противоречит этому промпту, выполняй фронт работ, кроме
жёстких запретов из раздела 9.

---

## 2. Что такое карточка

Один Markdown-файл с YAML-frontmatter. **Никакой HTML-обвязки**: шапку,
hero-секцию, хлебные крошки, оглавление, подсветку кода и переходы
«предыдущая/следующая» добавляет сайт (`theme.html`, `js/page.js`).

Скелет файла:

````markdown
---
title: Console.ReadLine()
keywords: ввод с консоли, чтение строки, Console.ReadLine, string, ожидание ввода, эхо ввода, null, Convert.ToInt32, проверка ввода, интерактивная программа
---

# Метод Console.ReadLine()

Как получить строку от пользователя и не упасть на пустом вводе?

`Console.ReadLine()` — это статический метод класса `System.Console`, который
читает одну строку из стандартного потока ввода и возвращает её как `string`.

## Как работает метод

...

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        Console.Write("Как вас зовут? ");
        string? name = Console.ReadLine();
        Console.WriteLine($"Привет, {name}!");
    }
}
```

Результат работы в консоли:

```text
Как вас зовут? Роман
Привет, Роман!
```

## Важные нюансы

* **Пустой ввод:** ...

## Проверь себя

```quiz

  "question": "Короткий вопрос по теме",
  "options": [
    { "text": "Верный вариант", "correct": true, "explanation": "Почему он верный." },
    { "text": "Неверный вариант", "correct": false, "explanation": "Почему он неверный." }
  ],
  "explanation": "Общий вывод после проверки."
````

## 3. Frontmatter

Поля идут в таком порядке, каждое — одной строкой:

| Поле | Обязательно | Правила |
| --- | --- | --- |
| `title` | да | Короткое имя для меню и hero. Без «C#» и без точки в конце. Совпадает с `h1` по смыслу, но может быть короче. |
| `keywords` | да | 8–15 фраз через запятую в одну строку. **Только здесь** — в теле статьи их быть не должно. |
| `description` | нет | 1–2 предложения для `<meta name="description">`. |
| `svg` | нет | Готовая иллюстрация из `hero_svg.md`, блоком `svg: \|` с отступом 2 пробела. |

Пример с иллюстрацией:

```yaml
---
title: if / else
keywords: условный оператор, if else, ветвление, ...
svg: |
  <svg viewBox="0 0 900 280" ...>
    ...
  </svg>
---
```

## 4. Заголовки и объём

- **Ровно один `h1`** — первая строка после frontmatter, совпадает с темой.
- **`h2` — разделы статьи.** `h3` и `h4` не используем: в справочнике плоская
  структура, и оглавление сайта строится из `h2`.
- После `h1` — лид-вопрос одним предложением, затем абзац-определение.
- Обычно 3–4 раздела: суть → пример → нюансы/ошибки.
- Объём зависит от сложности темы:
  - **140–250 слов** — простые темы: консоль, типы, операторы, ветвления,
    циклы (группы 20–90);
  - **250–400 слов** — средние: методы, коллекции, классы, пользовательские
    типы, наследование, обобщения, исключения, делегаты, строки (110–200);
  - **400–600 слов** — сложные: LINQ, асинхронность, рантайм/память/
    рефлексия (190–220).
- Обзорная карточка группы — верхняя граница своего уровня.
- Это **потолок, а не цель**: если суть темы укладывается в 200 слов — пиши 200
  и дай ссылку на документацию, а не раздувай текст до лимита.
- В конце карточки — раздел `## Проверь себя` с 1–2 мини-тестами. Для простой
  темы достаточно одного, для сложной — два. Тест не заменяет объяснение,
  а проверяет, что читатель понял главное.
- Блоков кода — 1, максимум 2 (второй — только вывод `text`).
- Если пример не вмещается в 40 строк — разбей его на «минимальный пример»
  и, если нужно, «полный»; либо вынеси повторяющиеся части в отдельный метод.

## 5. Иллюстрация (SVG)

- По умолчанию **не рисуется**: поле `svg` просто отсутствует.
- Если иллюстрация согласована, она генерируется отдельным промптом
  `hero_svg.md` и вставляется в frontmatter готовым `<svg>`.
- Нельзя: растровые картинки, внешние URL, `<img>`, заглушки.

---

## 6. Текст

- Пиши по-русски, разговорным и дружеским стилем, без воды и канцелярита.
- Лид — вопрос читателя, на который отвечает карточка.
- Первый абзац — определение: что это, зачем нужно, где пригодится.
- Не пиши «в этой статье мы рассмотрим», «как известно», «очевидно, что».
- Каждое утверждение — с причиной: не «так лучше», а почему лучше.
- Термины при первом употреблении расшифровывай: «куча (heap)».

---

## 7. Код

- Язык блока — `csharp` (или `sql`, `bash`, `text`). Для мини-тестов —
  отдельный блок `quiz` (см. раздел 8.1).
- Для C# пример — **полная компилируемая программа**:

  ```csharp
  using System;

  class Program
  {
      static void Main()
      {
          // Комментарии по-русски
      }
  }
  ```

- Для SQL — один запрос или короткий сценарий и таблица результата. Таблицы,
  столбцы и данные бери из схемы кейса, а не выдумывай новые.
- **Лимит — 40 строк** на блок `csharp` или `sql`. Если получается больше,
  вынеси повторяющиеся части в отдельный метод или сократи пример до сути.
  Полную схему базы можно дать отдельной карточкой.
- Для сложных тем (190–220) перед кодом добавь блок **«По шагам»**:
  3–5 пунктов, что происходит от вызова до результата.
- Комментарии в коде — по-русски, по делу, без пересказа каждой строки.
- Если важен вывод — отдельный блок ` ```text ` с подписью
  «Результат работы в консоли:».
- `<` и `>` в обычном тексте оборачивай в `` `code` `` (`List<string>`),
  а внутри таблиц экранируй вертикальную черту: `` `a \| b` ``.

## 8. Таблицы, врезки, отступы

- Таблица — Markdown, до 3–4 колонок. Первая колонка — жирное имя
  инструмента, дальше — что делает и когда использовать.
- Врезка — GitHub-alert:

  ```markdown
  > [!NOTE]
  > Текст примечания.
  ```

  Допустимы `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`.
- `:::gap` на отдельной строке — дополнительный вертикальный отступ
  (не больше одного подряд, внутри блоков кода не работает).
- Одна пустая строка между блоками; несколько подряд не нужны.

### Мини-тесты

Раздел `## Проверь себя` оформляй блоком `quiz` с JSON. Это не просто
список заданий, а проверка понимания: читатель выбирает ответ, нажимает
«Проверить» и видит объяснение.

````markdown
```quiz
{
  "type": "radio",
  "question": "Что вернёт `NULL = NULL`?",
  "options": [
    { "text": "`true`", "correct": false, "explanation": "Почему нет." },
    { "text": "`unknown`", "correct": true, "explanation": "Почему да." }
  ],
  "explanation": "Общий вывод после проверки."
}
```
````

- `type`: `radio` — один ответ, `checkbox` — несколько, `match` — соединить
  левое с правым.
- У `options` обязательны `text` и `correct`; `explanation` — по желанию.
- У `pairs` обязательны `left` и `right`; `explanation` — по желанию.
- `explanation` в корне показывается всегда; правильный ответ — при ошибке.
- Текст поддерживает `код` в обратных кавычках и переносы строк. HTML нельзя.
- JSON должен быть валидным: двойные кавычки, без висячих запятых.
- 1–2 теста на карточку. Не превращай справочник в викторину.

Подробный синтаксис и примеры — в `MANUAL.md`, раздел «Мини-тесты».

---

## 9. Жёсткие запреты

В файле **не должно быть**:

- HTML-разметки в теле статьи, `<script>`, `<style>`, inline-стилей;
- `keywords` отдельным абзацем в конце статьи;
- заголовков вида «Группа 200: …», планов карточек и служебных таблиц
  «№ | Название карточки | Что разбираем внутри»;
- ссылок на «теоретический раздел» без названия группы — называй группу
  и карточку явно;
- выдуманных URL, `[текст](...)` на темы, которых нет в `structure.json`;
- внешних картинок, iframe, CDN-скриптов;
- невалидного JSON в блоке `quiz`, ответов «отдельным списком» при наличии теста;
- «TODO», «…(продолжение следует)», обещаний следующей карточки, которой
  нет в `structure.json`.

## 10. Ссылки на другие темы

Пиши словами, без URL:

- «см. группу 140 *Пользовательские типы и память*»;
- «подробнее — в карточке *Свойства*»;
- «в следующей карточке разберём *Синхронизация и потокобезопасность*».

Внешние ссылки — только официальная документация Microsoft
(`learn.microsoft.com`), в формате `[название](https://learn.microsoft.com/...)`.

В обзорной карточке сложной группы (110–220) в конце добавь раздел
`## Куда дальше` — 1–3 ссылки на официальную документацию:

```markdown
## Куда дальше

* [Итераторы](https://learn.microsoft.com/dotnet/csharp/programming-guide/concepts/iterators) — `yield return` и ленивые последовательности.
```

Ссылка должна быть проверена (открывается), а подпись — объяснять, что именно
там есть. Не ставь «Куда дальше» в карточки простых групп: это маяк для
сложных тем, где одной карточки мало.

## 11. Финальный чек-лист

- [ ] Frontmatter начинается и заканчивается `---`, поля `title` и `keywords` есть.
- [ ] `keywords` — одна строка через запятую, 8–15 фраз, в теле их нет.
- [ ] Ровно один `#` (h1); все остальные заголовки — `##`.
- [ ] После h1 есть лид-вопрос и абзац-определение.
- [ ] Есть блок кода на языке области; для C# — полная компилируемая программа, для SQL — запрос и таблица результата.
- [ ] Вывод показан блоком `text`, если он важен.
- [ ] В конце есть `## Проверь себя` с валидным `quiz` и объяснением.
- [ ] Нет HTML, планов карточек, «теоретического раздела» и выдуманных ссылок.
- [ ] Объём в норме для уровня: 140–250, 250–400 или 400–600 слов.
- [ ] Блок кода — до 40 строк; для сложных тем есть «По шагам».
- [ ] В обзорной карточке сложной группы есть «Куда дальше» с живыми ссылками.
- [ ] Файл сохранён в `content/<область>/<группа>/<имя>.md`.

---

## 12. После сохранения

Порядок в меню и поиске берётся из `data/structure.json`, поэтому после
добавления или переименования карточки запусти:

```bash
node scripts/sync-structure.js
```

Если менялись URL или названия — пересобери эмбеддинги для семантического
поиска:

```bash
node scripts/build-embeddings.js
```

---

## 13. Формат ответа

Верни **только содержимое `.md`-файла**, начиная с `---` frontmatter:

- без Markdown-обёртки из трёх обратных кавычек вокруг всего файла;
- без пояснений до и после;
- без комментариев вида «здесь могла быть ваша реклама».
