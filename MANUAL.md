# Руководство по Markdown

Полная шпаргалка по маркерам, которые понимает Дока ИСИП. Нажмите
«Скопировать мануал», чтобы забрать её целиком, или копируйте нужные блоки.

## Заголовки

`#` — заголовок первого уровня (h1). Это название темы: оно попадает
в hero-блок и в `<title>` страницы. В одной теме должен быть один h1.

```markdown
# Переменные в C#
```

`##` — раздел (h2). Создаёт секцию и пункт в оглавлении.

```markdown
## Быстрый старт
```

`###` — подраздел (h3). Создаёт вложенный пункт оглавления.

```markdown
### 1. Объявление переменной
```

`####` — мелкий заголовок (h4). В оглавление не попадает.

```markdown
#### Примечание
```

## Абзацы

Абзацы разделяются пустой строкой. Одной пустой строки достаточно;
несколько подряд не добавляют отступ.

```markdown
Первый абзац.

Второй абзац.
```

## Явный отступ `:::gap`

Если нужен намеренный вертикальный отступ, поставьте на отдельной строке
маркер. Перед ним нужна пустая строка.

```markdown
:::gap
```

Одна единица ≈ `1.5em`. Количество можно указать числом:

```markdown
:::gap 2
:::gap:3
```

Внутри блоков кода маркер не срабатывает.

## Ссылки

Внешняя ссылка:

```markdown
[Документация .NET](https://learn.microsoft.com/dotnet/)
```

Внутренняя ссылка на тему — проще через кнопку «🔗 Ссылка на тему»
в редакторе. Вручную она выглядит так:

```markdown
[Привет, мир!](theme.html?path=content/csharp/osnovy/hello-world.md)
```

## Блоки кода

Три обратных кавычки и язык после них включают подсветку синтаксиса:

````markdown
```cs
int health = 100;
```
````

Поддерживаются языки `cs`, `sql`, `bash`, `html`, `js`, `json`, `css`
и другие из highlight.js.

## Frontmatter

В самом начале `.md` файла можно указать метаданные:

```yaml
---
title: Переменные в C#
description: Как объявлять и использовать переменные
keywords: переменные объявление инициализация C#
---
```

- `title` — название, если в тексте нет `#`.
- `description` — краткое описание для hero-блока.
- `keywords` — слова для поиска.
- `svg` — SVG-иллюстрация для hero-блока (многострочное значение).

## Ключевые слова

Поле `keywords` улучшает и обычный, и смысловой поиск.

- Минимум: 3–5 слов.
- Оптимально: 5–15 слов или коротких фраз.
- Максимум: около 20 слов. Дальше смысл размывается, а пользы почти нет.
- Пишите через пробел или запятую: `коллекция массивов List<T> перебор`.
- Фразу «коллекция массивов» можно писать слитно. Обычный поиск разобьёт
  её на слова, а смысловой слой учтёт контекст.
- Не дублируйте название темы и не добавляйте десятки синонимов.

## Локальная область «Админка»

Область **Админка** создаётся автоматически только на локальном dev-сервере.
Она создаётся пустой: группы и темы вы добавляете сами для служебных заметок
и черновиков.

- На GitHub Pages области нет: её файлы лежат в `content/admin/`, а структура —
  в `data/structure.local.json`. Они хранятся в репозитории, но не попадают
  в публичную `data/structure.json`, поэтому в интерфейсе и поиске их не видно.
- Удалить саму область нельзя. Группы и темы внутри удаляются как обычно.
- Всё остальное — Markdown, frontmatter, ключевые слова — работает так же,
  как в публичных областях.
