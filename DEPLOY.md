# Запуск и хостинг Дока ИСИП

## Локальный запуск (разработка)

Проект — статический сайт. Для работы поиска (загрузка `data/structure.json`,
`data/embeddings.json`, модели через `fetch`) нужен HTTP-сервер. Открытие файлов
по протоколу `file://` не сработает.

### Запуск dev-сервера

```powershell
npm run dev
```

или напрямую:

```powershell
node scripts/dev-server.js
```

Удобнее запускать через `doka.bat` — интерактивную консоль со статусом
последней синхронизации/векторизации и пунктами «запустить как есть»,
«запустить с обновлением структуры», «запустить с обновлением и
векторизацией».

Сайт будет доступен по адресу: `http://127.0.0.1:5173`

Сервер отдаёт правильные MIME-типы для `.wasm`, `.onnx`, `.json` — важно для
работы `transformers.js` и поиска. `scripts/dev-server.js` не нужен на хостинге
и исключён через `.gitignore`.

### Доступ из локальной сети

Чтобы другие компьютеры в сети могли открыть сайт, сервер должен слушать все
интерфейсы (`0.0.0.0`), а не только `localhost`.

1. В `scripts/dev-server.js` найдите строку запуска сервера и смените хост:

   ```javascript
   server.listen(5173, '0.0.0.0', () => { ... })
   ```

2. Перезапустите сервер.
3. Сайт станет доступен по вашему локальному IP, например:
   `http://192.168.1.42:5173`

**Важно:** на компьютере с сервером в брандмауэре Windows нужно разрешить
входящие подключения на порт 5173 (Панель управления → Брандмауэр →
Дополнительные параметры → Правила входящих подключений).

## Контент и структура

Весь контент лежит в `content/`:

```
content/
  <domain>/
    meta.json
    <group>/
      meta.json
      <topic>.html
```

- Области: `content/csharp/`, `content/sql/`.
- Названия областей и групп — в `meta.json`.
- Название темы — только в `<title>` HTML-страницы.
- Шаблон новой страницы — `content/_template.html`.
- Файлы и папки, начинающиеся с `_`, синхронизация игнорирует.

`data/structure.json` генерируется скриптом `scripts/sync-structure.js`.
Не редактируйте его вручную: это единственный источник порядка, URL и ключевых
слов для поиска.

### Обновление после добавления/изменения страниц

```powershell
npm run sync
```

Скрипт:

1. сканирует `content/`;
2. читает `<title>`, ключевые слова и seed-порядок;
3. сохраняет уже существующие `order` из `structure.json`;
4. добавляет новые области, группы и темы;
5. записывает `data/structure.json`;
6. удаляет использованные seed-теги `<meta name="order">` из HTML/meta.json.

Если добавляли или удаляли темы, меняли URL или текст статей — пересоберите
векторы:

```powershell
npm run sync:embeddings
```

Отдельная команда:

```powershell
npm run build:embeddings
```

`scripts/build-embeddings.js` использует только локальную модель
`models/rubert-tiny2/` (сеть не требуется). Скрипт читает полный текст статьи
из HTML, поэтому новые страницы автоматически попадают в семантический поиск.

## Готовый к хостингу сайт (GitHub Pages)

Сайт полностью статический — бэкенд не требуется. Можно развернуть на GitHub
Pages бесплатно.

### Шаги

1. Закоммитьте весь проект в репозиторий (кроме игнорируемых файлов — см.
   `.gitignore`).
2. В настройках репозитория GitHub → Pages → Build and deployment → Source
   выберите ветку (`main` или `gh-pages`) и папку (`/`).
3. Сайт будет доступен по адресу:
   `https://<ваш-логин>.github.io/<имя-репозитория>/`

### Что нужно обязательно включить в репозиторий

| Папка / файл | Назначение |
|---|---|
| `content/` | HTML-страницы тем, `meta.json` областей и групп, шаблон |
| `data/structure.json` | Структура сайта: области, группы, темы, порядок, ключевые слова |
| `data/embeddings.json` | Готовые векторы для семантического поиска |
| `js/libs/` | MiniSearch, Transformers.js, ORT-WASM (локальные, без CDN) |
| `models/rubert-tiny2/` | Модель `rubert-tiny2` (fp32, двумя частями `model.onnx.part_aa` + `model.onnx.part_ab`, ~111 МБ) |
| `css/style.css` | Стили сайта (включая `@font-face`) |
| `fonts/` | Локальные шрифты `Golos Text` и `JetBrains Mono` (woff2) |
| `js/search.js` | Гибридный поиск (MiniSearch + векторный слой) |
| `js/page.js` | Сборка страницы темы: шапка, крошки, оглавление, поиск |
| `index.html`, `domain.html` | Главная и страница области |

### Что можно исключить (уже в `.gitignore`)

- `node_modules/` — устанавливается через `npm install`
- `.cache/` — кэш transformers.js
- `scripts/transit/` — временные транспортные артефакты
- `scripts/dev-server.js` — только для локальной разработки, не нужен на хостинге

## Эмбеддинги (векторы для семантического поиска)

Векторы для всех тем лежат в `data/embeddings.json`. Пересобирайте их после
добавления/удаления тем или изменения URL:

```powershell
npm run build:embeddings
```

Готовый файл `data/embeddings.json` — это то, что браузер загружает при
семантическом поиске. Без него поиск будет работать только в лексическом режиме
(MiniSearch).

## Модель

Используется `Xenova/rubert-tiny2` (fp32, `quantized: false`). В браузере
векторизуется только поисковый запрос; векторы тем заранее подготовлены в
`data/embeddings.json`.

GitHub не принимает файлы больше 100 МБ, поэтому веса лежат в репозитории двумя
частями:

- `models/rubert-tiny2/onnx/model.onnx.part_aa` (~60 МБ);
- `models/rubert-tiny2/onnx/model.onnx.part_ab` (~51 МБ).

При первом открытии поиска `js/search.js` скачивает обе части, склеивает их в
единый `model.onnx` и сохраняет результат в Cache Storage браузера
(`rubert-local-cache-v1`). Повторные визиты берут готовую модель из кэша и не
скачивают части заново. В консоли браузера видны все этапы установки
(`[model] ...`).

### Сброс кэша модели (для проверки первой установки)

Обычное обновление страницы (`Ctrl+F5`) не удаляет Cache Storage. Чтобы
перепроверить скачивание и склейку, откройте консоль браузера (`F12` → Console)
и выполните:

```js
// посмотреть, какие кэши есть
await caches.keys()

// удалить кэш модели
await caches.delete('rubert-local-cache-v1')

// на всякий случай старый кэш transformers.js (от прошлых тестов)
await caches.delete('transformers-cache')

// проверить, что пусто
await caches.keys()
```

Затем обновите страницу и откройте поиск — модель снова скачается частями и
склеится. Альтернатива: `F12` → **Application** → **Storage** →
**Cache Storage** → удалить `rubert-local-cache-v1` (или **Clear site data**).

Опционально: можно положить `model_quantized.onnx` в
`models/rubert-tiny2/onnx/` и переключить `quantized: true` в `js/search.js` и
`scripts/build-embeddings.js` — размер модели сократится с ~111 МБ до ~2 МБ.

## Акценты и цвета

Цвета областей задаются в `meta.json` области (`accent`) и попадают в
`data/structure.json`. Они автоматически применяются к:

- шапке сайта и hero (`--domain-accent`);
- подчёркиванию результатов поиска (`--csharp-accent`, `--sql-accent` и т.д.);
- фону выбранного результата при навигации стрелками.

Менять цвета нужно в `content/<domain>/meta.json`, затем запустить
`npm run sync`.

## Поиск

- Горячая клавиша `/` (английская раскладка) или `.` (русская раскладка)
  открывает поиск.
- `↑`/`↓` — навигация по результатам, `Enter` — переход, `Escape` — закрыть.
- Клик по затемнению модального окна также закрывает поиск.
- Семантический слой инициализируется лениво при первом открытии окна поиска
  (индикатор «Инициализация ИИ-поиска…» внизу модалки).
- Порог косинусной близости для семантических совпадений: `0.45`
  (`AI_SEMANTIC_THRESHOLD` в `js/search.js`).
- Ссылки в результатах строятся от корня сайта, поэтому работают с любой
  глубины страницы.
