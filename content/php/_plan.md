# PHP: план области

Область учит PHP как бэкенд: основы языка, HTTP, работа с базами данных
через PDO, API для фронтенда и затем Ларавел.

## Группы

### 10. Основы PHP

Зачем нужен PHP, первый скрипт, переменные и типы, операторы и ветвления,
циклы и массивы, формы и суперглобалы, ошибки и отладка.

Итог: практика — первый скрипт.

### 20. Функции, массивы и ООП

Массивы и их функции, строки и mbstring, функции и замыкания, классы и
объекты, интерфейсы и трейты, namespaces и Composer.

Итог: практика — ООП.

### 30. HTTP, формы и сессии

HTTP-запрос и ответ, GET/POST и валидация, cookies и сессии, файлы и
загрузка, headers и редиректы, CSRF и XSS в формах.

Итог: практика — обработка формы.

### 40. Базы данных и PDO

SQL для PHP, подключение PDO, подготовленные запросы, CRUD на PDO,
транзакции, joins и выборки, пагинация и фильтры.

Итог: практика — CRUD на PDO.

### 50. API и фронтенд

JSON и формат ответа, REST и статус-коды, routing и контроллеры,
валидация и ошибки, CORS и cookies, auth-сессии и JWT.

Итог: практика — API для фронтенда.

### 60. Безопасность, тесты и деплой

SQL-инъекции и XSS, CSRF и сессии, пароли и хеширование, секреты и
конфигурация, PHPUnit и тестирование, Docker и деплой.

Итог: практика — безопасный бэкенд.

### 70. Ларавел: основы

Зачем Ларавел, установка и структура, routes и контроллеры, Blade и
views, Eloquent и модели, миграции и seeders, валидация и middleware,
API Resources.

Итог: практика — API на Ларавел.

### 80. Практика: PHP-бэкенд

План и требования, реализация API и базы данных, связка с фронтендом,
итог области и практика по задаче.

## Правила

- 2 квиза на тему: radio (3 варианта, 1 правильный) и checkbox
  (4 варианта, 2–3 правильных).
- В каждой теме есть раздел «Частые ошибки».
- Итог группы называется так же, как группа.
- Практика начинается со слова «Практика».
- Картинки — авторские SVG-схемы, без внешних хотлинков.
- Ссылки только на существующие темы области.
- Примеры кода — короткие и проверяемые.
- PDO и чистый PHP идут раньше Ларавел.
- Безопасность рассматривается как часть обычной работы, а не как
  отдельный «продвинутый» уровень.

## Главный принцип

**Запрос → валидация → база данных → ответ → проверка на фронтенде.**
