# GROUP BY по нескольким столбцам и ROLLUP

Как посчитать итоги не только по категориям, но и внутри каждой категории по активности напитка, а потом добавить общий итог?

`GROUP BY` умеет группировать по нескольким столбцам сразу. Тогда группа — это уникальная комбинация значений: например, «кофе + активен» и «кофе + снят с продажи» — разные группы. `ROLLUP` добавляет к этому промежуточные итоги и общую сумму, чтобы отчёт не приходилось склеивать вручную.

## Как это работает

Представь таблицу с двумя разрезами: категория и активность. Сначала ты раскладываешь напитки по ячейкам «категория × активность». Потом хочешь ещё строку «итого по категории» и совсем общую «итого по всем». `ROLLUP (category, is_active)` делает именно это: сначала детальные группы, потом итоги по категории, потом общий итог.

## Синтаксис

```sql
SELECT столбец1, столбец2, агрегат(столбец)
FROM таблица
GROUP BY столбец1, столбец2
ORDER BY столбец1, столбец2;
```

С `ROLLUP`:

```sql
SELECT столбец1, столбец2, агрегат(столбец)
FROM таблица
GROUP BY ROLLUP (столбец1, столбец2)
ORDER BY столбец1 NULLS LAST, столбец2 NULLS LAST;
```

`ROLLUP (a, b)` создаёт группы: `(a, b)`, `(a)` и `()`. Строки с `NULL` в столбце означают «итог по этому разрезу», а не отсутствие значения.

## Пример

Активность и цена по категориям:

```sql
SELECT
    category,
    is_active,
    COUNT(*) AS drinks_count,
    ROUND(AVG(price), 2) AS avg_price
FROM drinks
GROUP BY category, is_active
ORDER BY category, is_active;
```

| category | is_active | drinks_count | avg_price |
| --- | --- | --- | --- |
| кофе | false | 1 | 180.00 |
| кофе | true | 3 | 270.00 |
| напиток | true | 2 | 250.00 |
| чай | true | 2 | 255.00 |

Теперь тот же разрез с подытогами:

```sql
SELECT
    category,
    is_active,
    COUNT(*) AS drinks_count
FROM drinks
GROUP BY ROLLUP (category, is_active)
ORDER BY category NULLS LAST, is_active NULLS LAST;
```

| category | is_active | drinks_count |
| --- | --- | --- |
| кофе | false | 1 |
| кофе | true | 3 |
| кофе | NULL | 4 |
| напиток | true | 2 |
| напиток | NULL | 2 |
| чай | true | 2 |
| чай | NULL | 2 |
| NULL | NULL | 8 |

Строка `кофе | NULL | 4` — итог по всем кофе, а `NULL | NULL | 8` — итог по всей таблице.

## GROUPING

Чтобы отличить настоящий `NULL` в данных от строки итога, в PostgreSQL есть `GROUPING(столбец)`:

```sql
SELECT
    category,
    GROUPING(category) AS is_total,
    COUNT(*)
FROM drinks
GROUP BY ROLLUP (category)
ORDER BY category NULLS LAST;
```

`GROUPING` возвращает `1` для строки итога и `0` для обычной группы. В отчётах это помогает подписать итог словами «Всего».

## Грабли

* **Порядок столбцов в `ROLLUP` важен.** `ROLLUP (category, is_active)` даёт итоги по категориям и общий, а `ROLLUP (is_active, category)` — итоги по активности и общий. Это разные отчёты.
* **`NULL` в результате не всегда данные.** После `ROLLUP` пустой столбец может означать итог. Для честного отчёта используй `GROUPING`.
* **`ORDER BY` с `NULL`.** Без `NULLS LAST` строки итогов могут оказаться в начале таблицы и запутать.
* **`ROLLUP` — не то же самое, что `CUBE`.** `CUBE` даёт все комбинации разрезов, `ROLLUP` — только иерархию слева направо.
* **Лишние строки в отчёте.** Если приложение не умеет отличать итоги от данных, лучше собрать их отдельным запросом или через `GROUPING SETS`.
