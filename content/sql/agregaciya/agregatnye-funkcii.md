# Агрегаты: COUNT, SUM, AVG, MIN, MAX

Как одним запросом узнать, сколько было заказов, сколько денег принесли и какой чек был самым большим?

Агрегатная функция берёт много строк и возвращает одно значение. `COUNT` считает, `SUM` суммирует, `AVG` усредняет, `MIN` и `MAX` находят границы. Вместо ручной выгрузки в Excel ты пишешь один запрос, и база сама проходит по строкам.

## Как это работает

Представь кассира в конце смены. Он не переписывает каждый чек в блокнот, а складывает суммы, считает количество и запоминает самый крупный заказ. Агрегаты делают то же самое, только быстрее и без ошибок.

Важно: агрегат превращает **все** строки в одну. Если в `SELECT` есть обычный столбец и агрегат, база не поймёт, какое значение столбца показать. Поэтому либо все столбцы в `GROUP BY`, либо в `SELECT` только агрегаты.

## Синтаксис

```sql
SELECT
    COUNT(*) AS rows_count,
    COUNT(столбец) AS non_null_count,
    SUM(столбец) AS total,
    AVG(столбец) AS average,
    MIN(столбец) AS minimum,
    MAX(столбец) AS maximum
FROM таблица
WHERE условие;
```

| Функция | Что делает | `NULL` |
| --- | --- | --- |
| `COUNT(*)` | считает строки | считает все |
| `COUNT(столбец)` | считает непустые значения | пропускает |
| `SUM(столбец)` | сумма | пропускает |
| `AVG(столбец)` | среднее | пропускает |
| `MIN` / `MAX` | минимум и максимум | пропускают |

## Пример

Сводка по оплаченным и завершённым заказам:

```sql
SELECT
    COUNT(*) AS orders_count,
    SUM(total) AS revenue,
    ROUND(AVG(total), 2) AS avg_check,
    MIN(total) AS min_check,
    MAX(total) AS max_check,
    COUNT(DISTINCT customer_id) AS customers
FROM orders
WHERE status IN ('paid', 'done');
```

| orders_count | revenue | avg_check | min_check | max_check | customers |
| --- | --- | --- | --- | --- | --- |
| 7 | 3040.00 | 434.29 | 190.00 | 760.00 | 4 |

`COUNT(DISTINCT customer_id)` считает уникальных клиентов, а не заказы: Анна сделала три заказа, но в счёте она одна.

## Агрегаты с условием

Иногда нужны две суммы: общая и только по оплаченным. В PostgreSQL удобно использовать `FILTER`:

```sql
SELECT
    COUNT(*) AS all_orders,
    COUNT(*) FILTER (WHERE status = 'paid') AS paid_orders,
    SUM(total) FILTER (WHERE status = 'paid') AS paid_revenue
FROM orders;
```

В других СУБД тот же результат собирают через `SUM(CASE WHEN ... THEN ... ELSE 0 END)`.

## Грабли

* **`COUNT(*)` и `COUNT(столбец)` — разные вещи.** Первый считает строки, второй — только непустые значения. Если в столбце есть `NULL`, числа разойдутся.
* **`AVG` не учитывает `NULL`.** Среднее считается по непустым значениям, а не по всем строкам. Иногда это именно то, что нужно, но проверяй.
* **`SUM` по пустому набору возвращает `NULL`, а не `0`.** Для отчёта оборачивай в `COALESCE(SUM(...), 0)`.
* **Агрегат и обычный столбец без `GROUP BY`.** Запрос `SELECT name, COUNT(*) FROM drinks` не выполнится: непонятно, какое имя показать.
* **`AVG` по целым числам.** В некоторых СУБД среднее целых может округлиться. В PostgreSQL `AVG(integer)` возвращает `numeric`, но лучше приводить явно.
