# Деньги и NUMERIC

Почему цена в `FLOAT` через месяц превращается в 279.999999, а `10 / 3` в SQL равно трём?

Деньги нельзя хранить в типах с плавающей точкой. `FLOAT` и `REAL` представляют дроби в двоичной системе и не могут точно сохранить `0.10`. Для цен, налогов и средних чеков в PostgreSQL есть `NUMERIC` — десятичное число с фиксированной точностью. Он медленнее, но не теряет копейки.

## Как это работает

Представь, что ты делишь 10 рублей на троих. В обычном калькуляторе получится `3.333...`. В SQL с целыми числами `10 / 3` вернёт `3`: дробная часть отбрасывается. Если хотя бы один операнд — `NUMERIC`, результат будет точным десятичным числом, а округление ты задаёшь сам через `ROUND`.

## Синтаксис

```sql
NUMERIC(10, 2)
```

Первое число — общая точность (сколько всего цифр), второе — сколько из них после запятой. `NUMERIC(10, 2)` хранит до 8 цифр до запятой и 2 после: хватит на цены до 99 999 999.99.

| Операция | Пример | Результат |
| --- | --- | --- |
| Сложение | `280.00 + 190.00` | `470.00` |
| Умножение | `280.00 * 2` | `560.00` |
| Деление | `10::numeric / 3` | `3.3333333333333333` |
| Округление | `ROUND(10::numeric / 3, 2)` | `3.33` |
| Формат | `to_char(3600, 'FM999999990.00')` | `'3600.00'` |

## Пример

Выручка и средняя цена позиции:

```sql
SELECT
    SUM(quantity * unit_price) AS items_total,
    ROUND(AVG(unit_price), 2) AS avg_item_price
FROM order_items;
```

| items_total | avg_item_price |
| --- | --- |
| 3600.00 | 245.38 |

`quantity * unit_price` — это сумма по каждой позиции, `SUM` складывает их в общую сумму. `AVG` считает среднюю цену одной позиции, а `ROUND` оставляет две цифры после запятой.

## Округление и формат

`ROUND` меняет само число. `to_char` — только его представление:

```sql
SELECT
    ROUND(1234.567, 2) AS rounded,
    to_char(1234.567, 'FM999999990.00') AS formatted;
```

| rounded | formatted |
| --- | --- |
| 1234.57 | 1234.57 |

Для денег в интерфейсе чаще нужен `to_char`: он добавляет разделители и фиксирует две цифры. Для дальнейших расчётов — `ROUND` или `NUMERIC` без округления.

## Грабли

* **`FLOAT` для денег.** `0.1 + 0.2` может дать `0.30000000000000004`. В отчёте это выглядит как ошибка, хотя база считала «правильно» для двоичной дроби.
* **Целочисленное деление.** `10 / 3` вернёт `3`. Приводи хотя бы один операнд: `10::numeric / 3`.
* **Округление слишком рано.** Если округлить каждую позицию, а потом сложить, итог может отличаться от округления суммы. Для денег обычно округляют только финальный результат.
* **`NUMERIC` без точности.** `NUMERIC` без параметров хранит очень много цифр и может быть медленнее. Для цен задавай `NUMERIC(10, 2)`.
* **Валюта в одном столбце.** Если в базе несколько валют, одной колонки `price` мало: нужен код валюты или отдельные столбцы.
