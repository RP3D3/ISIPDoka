# NULL в агрегатах

Почему `COUNT(*)` и `COUNT(email)` дают разные числа, а `SUM` по пустому столбцу возвращает `NULL`, а не ноль?

Агрегаты по-разному обращаются с `NULL`. `COUNT(*)` считает строки, а `COUNT(столбец)` — только непустые значения. `SUM`, `AVG`, `MIN` и `MAX` пропускают `NULL`, но если непустых значений нет вообще, результат будет `NULL`. Это не баг, а следствие трёхзначной логики.

## Как это работает

Представь опрос: «Сколько у нас клиентов с email?» Ты считаешь не строки, а конверты с адресом. Клиент без email — это строка, которая существует, но в счётчик адресов не попадает. `COUNT(*)` отвечает на вопрос «сколько всего клиентов», `COUNT(email)` — «сколько из них оставили почту».

## Синтаксис

```sql
SELECT
    COUNT(*) AS all_rows,
    COUNT(столбец) AS non_null,
    COALESCE(SUM(столбец), 0) AS safe_sum
FROM таблица;
```

`COALESCE` подменяет `NULL` на ноль, когда пустой результат нужно показать как `0`.

## Пример

Клиенты кофейни:

```sql
SELECT
    COUNT(*) AS all_customers,
    COUNT(email) AS with_email,
    COUNT(phone) AS with_phone
FROM customers;
```

| all_customers | with_email | with_phone |
| --- | --- | --- |
| 5 | 4 | 3 |

Пять клиентов, у четырёх есть email, у трёх — телефон. Разница не ошибка: у Игоря и Павла нет телефона, у Марии нет email.

Отзывы:

```sql
SELECT
    COUNT(*) AS all_reviews,
    COUNT(comment) AS with_comment,
    ROUND(AVG(rating), 2) AS avg_rating
FROM reviews;
```

| all_reviews | with_comment | avg_rating |
| --- | --- | --- |
| 6 | 5 | 3.83 |

Один отзыв без комментария, но с оценкой. `AVG(rating)` считает по всем шести оценкам: `NULL` в комментариях на среднее не влияет.

## Где `NULL` ломает отчёт

- **`COUNT(столбец)` вместо `COUNT(*)`.** Если нужно «сколько всего строк», а не «сколько заполнено», разница будет заметна.
- **`AVG` по столбцу с пропусками.** Среднее считается по непустым значениям. Если `NULL` означает «ноль», результат завышен.
- **`SUM` по пустому набору.** Возвращает `NULL`. В отчёте это выглядит как пустая ячейка, а не `0`.
- **`COUNT(DISTINCT столбец)`.** Тоже пропускает `NULL`: уникальные пустые значения не считаются.

## Грабли

* **Думать, что `NULL` — это ноль.** В агрегатах он либо пропускается, либо делает результат неопределённым.
* **Сравнивать результат с `NULL` через `=`.** Для проверки нужен `IS NULL`.
* **Забыть про `COALESCE`.** Для сумм и счётчиков в отчётах почти всегда нужен запасной ноль.
* **Считать среднее по `NULL` как по нулю.** Если бизнес-смысл «нет оценки = 0», это нужно явно преобразовать через `COALESCE(rating, 0)`.
