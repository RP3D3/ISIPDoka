# Коррелированные подзапросы и LATERAL

Как для каждого клиента найти его последний заказ, не повторяя один и тот же запрос вручную?

Коррелированный подзапрос ссылается на строку внешнего запроса. Он выполняется как бы для каждой строки и может вернуть значение, зависящее от неё. `LATERAL` — более мощный инструмент: он позволяет подзапросу в `FROM` ссылаться на таблицы, стоящие перед ним, и возвращать не одно значение, а целый набор строк.

## Коррелированный подзапрос

```sql
SELECT
    c.name,
    (SELECT COUNT(*)
     FROM orders AS o
     WHERE o.customer_id = c.id) AS orders_count
FROM customers AS c
ORDER BY orders_count DESC, c.name;
```

| name | orders_count |
| --- | --- |
| Анна | 3 |
| Игорь | 2 |
| Мария | 2 |
| Ольга | 1 |
| Павел | 1 |

Подзапрос внутри `SELECT` ссылается на `c.id`. Для каждой строки клиента он считает свои заказы.

## LATERAL

Нужен последний заказ каждого клиента. `LATERAL` позволяет подзапросу видеть `c.id` и вернуть одну строку:

```sql
SELECT c.name, o.id AS last_order, o.total
FROM customers AS c
LEFT JOIN LATERAL (
    SELECT id, total
    FROM orders AS o
    WHERE o.customer_id = c.id
    ORDER BY created_at DESC
    LIMIT 1
) AS o ON true
ORDER BY c.name;
```

| name | last_order | total |
| --- | --- | --- |
| Анна | 128 | 640.00 |
| Игорь | 127 | 280.00 |
| Мария | 125 | 320.00 |
| Ольга | 123 | 190.00 |
| Павел | 124 | 500.00 |

`LEFT JOIN LATERAL ... ON true` сохраняет клиентов даже без заказов. `CROSS JOIN LATERAL` оставил бы только тех, у кого заказ есть.

## Когда что использовать

- **Одно значение на строку** — коррелированный скалярный подзапрос.
- **Набор строк на строку** — `LATERAL`.
- **Проверка существования** — `EXISTS`.
- **Сложная логика с `LIMIT`** — `LATERAL` читается лучше, чем вложенные оконные функции.

## Грабли

* **Коррелированный подзапрос выполняется для каждой строки.** Без индекса по `customer_id` это может быть очень медленно.
* **`LATERAL` без `LIMIT`.** Вернёт все заказы клиента и размножит строки. Это не ошибка, но проверяй смысл.
* **`LEFT JOIN LATERAL` без `ON true`.** PostgreSQL потребует условие; `ON true` — обычный способ сказать «соединяй с тем, что вернул подзапрос».
* **`LATERAL` не заменяет `JOIN` по ключу.** Если нужна простая связь, обычный `JOIN` проще и быстрее.
* **Порядок в `FROM`.** `LATERAL` видит только таблицы слева от себя.
