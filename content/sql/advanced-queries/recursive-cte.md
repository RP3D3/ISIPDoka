# Рекурсивный CTE

Как получить все дни месяца, включая те, в которые не было ни одного заказа?

Рекурсивный `CTE` — это запрос, который ссылается сам на себя. Сначала выполняется **якорь** — стартовая строка. Потом **рекурсивная часть** добавляет новые строки, пока условие не остановит процесс. Так генерируют последовательности, календари, обходят иерархии и деревья.

## Синтаксис

```sql
WITH RECURSIVE имя(столбцы) AS (
    SELECT ...              -- якорь
    UNION ALL
    SELECT ...              -- рекурсивная часть
    FROM имя
    WHERE условие_остановки
)
SELECT * FROM имя;
```

`RECURSIVE` обязателен, даже если рекурсия очевидна. Без него PostgreSQL не разрешит ссылку на сам `CTE`.

## Пример: числа от 1 до 5

```sql
WITH RECURSIVE nums(n) AS (
    SELECT 1
    UNION ALL
    SELECT n + 1
    FROM nums
    WHERE n < 5
)
SELECT n FROM nums;
```

| n |
| --- |
| 1 |
| 2 |
| 3 |
| 4 |
| 5 |

Якорь даёт `1`, рекурсивная часть добавляет `2`, `3`, `4`, `5`, пока условие `n < 5` не станет ложным.

## Пример: календарь продаж

```sql
WITH RECURSIVE days(day) AS (
    SELECT DATE '2026-05-10'
    UNION ALL
    SELECT day + 1
    FROM days
    WHERE day < DATE '2026-05-15'
)
SELECT
    d.day,
    COALESCE(SUM(o.total), 0) AS revenue
FROM days AS d
LEFT JOIN orders AS o
    ON o.created_at::date = d.day
   AND o.status IN ('paid', 'done')
GROUP BY d.day
ORDER BY d.day;
```

| day | revenue |
| --- | --- |
| 2026-05-10 | 260.00 |
| 2026-05-11 | 760.00 |
| 2026-05-12 | 690.00 |
| 2026-05-13 | 410.00 |
| 2026-05-14 | 920.00 |
| 2026-05-15 | 0.00 |

`LEFT JOIN` сохраняет дни без заказов, а `COALESCE` превращает `NULL` в `0`. Без рекурсивного календаря пришлось бы заранее создать таблицу дат.

## Где ещё нужна рекурсия

- **Иерархии.** Сотрудники и руководители, категории и подкатегории.
- **Деревья.** Комментарии с ответами, структура папок.
- **Графы.** Маршруты и связи, если нет циклов.
- **Последовательности.** Даты, числа, интервалы.

## Грабли

* **Нет условия остановки.** Запрос будет выполняться, пока не упрётся в лимит памяти или `max_recursion_depth`.
* **`UNION` вместо `UNION ALL`.** `UNION` удаляет дубли и может замедлить рекурсию. `UNION ALL` обычно быстрее, но требует контроля циклов.
* **Циклы в графе.** Рекурсия может ходить по кругу. В PostgreSQL есть `CYCLE`, но часто проще хранить путь и проверять его.
* **Неправильный якорь.** Если стартовая строка не та, результат будет бессмысленным.
* **Большой результат.** Рекурсивный `CTE` может вернуть миллионы строк. Ограничивай условием и проверяй план.
