# Подзапрос в FROM

Как отфильтровать результат агрегации, если `WHERE` не видит `AVG`, а `HAVING` не хватает?

Подзапрос в `FROM` создаёт временную таблицу внутри запроса. Сначала выполняется внутренний `SELECT`, затем внешний запрос работает с его результатом как с обычной таблицей. Это позволяет фильтровать по вычисленным столбцам, соединять агрегаты с деталями и разбивать сложный запрос на шаги.

## Синтаксис

```sql
SELECT столбцы
FROM (
    SELECT ...
    FROM ...
    GROUP BY ...
) AS псевдоним
WHERE условие;
```

Псевдоним обязателен: PostgreSQL должен как-то назвать производную таблицу.

## Пример

Категории, где средняя цена активных напитков выше 250:

```sql
SELECT category, avg_price
FROM (
    SELECT
        category,
        ROUND(AVG(price), 2) AS avg_price
    FROM drinks
    WHERE is_active
    GROUP BY category
) AS stats
WHERE avg_price > 250
ORDER BY avg_price DESC;
```

| category | avg_price |
| --- | --- |
| кофе | 270.00 |
| чай | 255.00 |

Внутренний запрос считает средние, внешний фильтрует по `avg_price`. В одном `WHERE` это было бы невозможно: агрегат ещё не посчитан.

## Соединение с деталями

```sql
SELECT d.name, d.price, s.avg_price
FROM drinks AS d
JOIN (
    SELECT category, AVG(price) AS avg_price
    FROM drinks
    WHERE is_active
    GROUP BY category
) AS s ON s.category = d.category
WHERE d.is_active
ORDER BY d.category, d.price;
```

Так каждая строка напитка получает среднюю цену своей категории.

## Подзапрос или CTE

Оба варианта работают. `CTE` читается сверху вниз и удобен, когда промежуточных шагов несколько. Подзапрос в `FROM` короче для одного шага. Выбирай по читаемости, а не по религии.

## Грабли

* **Забыть псевдоним.** `FROM (SELECT ...)` без `AS t` вызовет ошибку.
* **Слишком глубокая вложенность.** Три-четыре уровня подзапросов читать тяжело. Разбей на `CTE`.
* **Дубли столбцов.** Если внутренний и внешний запрос используют одинаковые имена, обращайся через псевдоним.
* **Материализация.** Некоторые подзапросы база может материализовать, что влияет на план. Смотри `EXPLAIN`, если важна скорость.
* **Фильтр не туда.** Условие по агрегату — во внешний запрос или `HAVING`; условие по строкам — во внутренний `WHERE`.
