# 1НФ

Почему хранить список напитков в одном столбце — плохая идея, даже если это удобно на демо?

Первая нормальная форма требует, чтобы каждое значение в ячейке было атомарным, а повторяющиеся группы выносились в отдельные строки или таблицы. «Атомарное» значит неделимое для задач базы: не список, не строка через запятую, не JSON-массив, если по элементам нужно искать и связывать.

## Плохая схема

```sql
CREATE TABLE orders_bad (
    id BIGINT PRIMARY KEY,
    customer_name TEXT,
    drinks TEXT,          -- 'Латте, Капучино, Какао'
    quantities TEXT       -- '2, 1, 1'
);
```

| id | customer_name | drinks | quantities |
| --- | --- | --- | --- |
| 1 | Анна | Латте, Капучино | 2, 1 |
| 2 | Игорь | Какао | 1 |

Проблемы:

- нельзя просто найти все заказы с «Латте»;
- нельзя посчитать сумму по напиткам;
- нельзя сослаться на `drinks.id`;
- количество и напиток связаны позицией в строке, но база об этом не знает.

## Хорошая схема

```sql
CREATE TABLE orders (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id BIGINT NOT NULL REFERENCES customers(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE order_items (
    order_id BIGINT REFERENCES orders(id) ON DELETE CASCADE,
    drink_id BIGINT REFERENCES drinks(id),
    quantity INT NOT NULL CHECK (quantity > 0),
    PRIMARY KEY (order_id, drink_id)
);
```

| order_id | drink_id | quantity |
| --- | --- | --- |
| 1 | 2 | 2 |
| 1 | 6 | 1 |
| 2 | 7 | 1 |

Теперь каждая позиция — отдельная строка. По ней можно фильтровать, соединять и агрегировать.

## Когда JSON допустим

`JSONB` тоже может нарушать 1НФ, если внутри лежит список сущностей. Но он уместен для неоднородных атрибутов, которые не участвуют в связях:

```sql
attributes JSONB  -- {"size": "L", "milk": "oat"}
```

Если по элементам нужно искать, связывать или считать — это уже не «атрибут», а сущность.

## Грабли

* **Строка через запятую.** `'Латте, Капучино'` — не атомарное значение.
* **Массив в столбце.** `drink_ids INT[]` усложняет внешние ключи и соединения.
* **Повторяющиеся столбцы.** `drink1`, `drink2`, `drink3` — та же проблема в другой форме.
* **JSON вместо связи.** Список позиций в JSON не даст целостности.
* **«Пока работает».** На демо список удобен, на отчётах — боль.
* **Потеря порядка.** Если порядок важен, храни его отдельным столбцом, а не позицией в строке.
