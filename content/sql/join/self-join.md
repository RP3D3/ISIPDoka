# SELF JOIN

Как найти пары напитков одной категории, где один дороже другого, если оба лежат в одной таблице?

`SELF JOIN` — это соединение таблицы с самой собой. Отдельного синтаксиса нет: ты дважды указываешь одну и ту же таблицу и даёшь ей разные псевдонимы. База воспринимает их как две разные таблицы и сопоставляет строки по условию.

## Как это работает

Представь, что ты разложил копии меню на два стола. На одном — «левая» версия, на другом — «правая». Ты сравниваешь напиток с левого стола с напитком с правого: та же категория, но цена ниже. Это и есть self join: одна таблица, два взгляда на неё.

## Синтаксис

```sql
SELECT ...
FROM таблица AS a
JOIN таблица AS b ON b.общий_признак = a.общий_признак
WHERE a.id <> b.id;
```

Псевдонимы обязательны: без них база не поймёт, к какой копии относится столбец. Условие `a.id <> b.id` часто нужно, чтобы строка не соединилась сама с собой.

## Пример

Пары активных напитков одной категории, где первый дешевле второго:

```sql
SELECT
    a.category,
    a.name AS cheaper,
    b.name AS pricier,
    b.price - a.price AS diff
FROM drinks AS a
JOIN drinks AS b
  ON a.category = b.category
 AND a.price < b.price
WHERE a.is_active AND b.is_active
ORDER BY a.category, diff;
```

| category | cheaper | pricier | diff |
| --- | --- | --- | --- |
| кофе | Капучино | Латте | 30.00 |
| кофе | Американо | Капучино | 60.00 |
| кофе | Американо | Латте | 90.00 |
| напиток | Лимонад | Какао | 20.00 |
| чай | Чай с бергамотом | Матча-латте | 130.00 |

Условие `a.price < b.price` одновременно задаёт пару и убирает самосравнение: напиток не может быть дороже самого себя.

## Где ещё нужен self join

- **Иерархия.** Сотрудники и их руководители в одной таблице `employees`: `JOIN employees AS boss ON boss.id = e.manager_id`.
- **Пары и сравнения.** Найти клиентов с одинаковым телефоном или заказы одного клиента в один день.
- **Поиск дублей.** Сравнить строки между собой по набору полей.
- **Последовательности.** Связать строку с предыдущей или следующей по времени, если оконные функции ещё не изучены.

## Грабли

* **Забыть псевдонимы.** `SELECT name FROM drinks JOIN drinks ...` вызовет ошибку неоднозначности.
* **Соединить строку с самой собой.** Без `a.id <> b.id` или неравенства по цене в результат попадут пары «напиток с самим собой».
* **Симметричные пары.** Условие `a.price < b.price` даёт пару один раз, а `a.price <> b.price` — дважды: (A, B) и (B, A). Выбирай осознанно.
* **Взрыв строк.** Self join большой таблицы без индексов может быть очень дорогим.
* **Путать с подзапросом.** Для «сравнить строку со средним по группе» чаще нужен подзапрос или оконная функция, а не self join.
