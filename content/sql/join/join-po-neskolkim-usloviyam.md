# JOIN по нескольким условиям

Как соединить таблицы не только по одному ключу, но и с дополнительным условием: «только отзывы этого клиента на этот напиток»?

Условие в `ON` не обязано быть одним равенством. Можно добавить фильтр по категории, количеству или второму ключу. Для составных ключей пишут два равенства через `AND`. Это позволяет точнее сопоставить строки и не тащить в результат лишние пары.

## Как это работает

Представь, что ты ищешь отзыв не просто «Анны», а «Анны на какао». Одного `customer_id` мало: у Анны есть отзыв и на капучино. Нужны два условия: совпал клиент **и** совпал напиток. `JOIN ... ON a.customer_id = b.customer_id AND a.drink_id = b.drink_id` делает именно это.

## Синтаксис

```sql
SELECT ...
FROM таблица_1 AS a
JOIN таблица_2 AS b
  ON b.ключ_1 = a.ключ_1
 AND b.ключ_2 = a.ключ_2;
```

Дополнительное условие может быть и неравенством, и проверкой на `NULL`, и фильтром по константе:

```sql
JOIN order_items AS oi
  ON oi.order_id = o.id
 AND oi.quantity >= 2
```

## Пример

Позиции, где купили две и более чашки:

```sql
SELECT o.id AS order_id, oi.drink_id, oi.quantity
FROM orders AS o
JOIN order_items AS oi
  ON oi.order_id = o.id
 AND oi.quantity >= 2
ORDER BY o.id DESC;
```

| order_id | drink_id | quantity |
| --- | --- | --- |
| 128 | 4 | 2 |
| 122 | 1 | 2 |

Условие `quantity >= 2` стоит в `ON`, а не в `WHERE`, чтобы было видно: это часть сопоставления, а не фильтр результата. Для `INNER JOIN` разницы нет, но для `LEFT JOIN` она принципиальна.

Соединение по двум ключам — отзывы клиента на конкретный напиток из его заказа:

```sql
SELECT
    o.id AS order_id,
    d.name AS drink,
    r.rating
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.id
JOIN drinks AS d ON d.id = oi.drink_id
JOIN reviews AS r
  ON r.customer_id = o.customer_id
 AND r.drink_id = oi.drink_id
ORDER BY o.id DESC;
```

| order_id | drink | rating |
| --- | --- | --- |
| 128 | Какао | 4 |
| 125 | Матча-латте | 3 |
| 124 | Чай с бергамотом | 5 |
| 122 | Американо | 4 |
| 121 | Какао | 4 |

Здесь `reviews` соединяется с заказом по двум полям: кто оставил отзыв и о каком напитке. Одного `customer_id` было бы мало — у Анны несколько отзывов.

## ON или WHERE

| Ситуация | Куда ставить условие |
| --- | --- |
| `INNER JOIN` | без разницы, результат тот же |
| `LEFT JOIN`, фильтр по правой таблице | в `ON`, чтобы сохранить левые строки |
| Фильтр по левой таблице | в `WHERE` |
| Условие сопоставления (ключи) | всегда в `ON` |

## Грабли

* **Составной ключ из одного поля.** Если у связи два ключа, а в `ON` только один, появятся ложные пары.
* **Фильтр правой таблицы в `WHERE` после `LEFT JOIN`.** Он превращает соединение во внутреннее и выбрасывает строки без пары.
* **Слишком широкое условие.** `ON r.customer_id = o.customer_id` без `drink_id` даст отзывы на другие напитки.
* **Условие в `ON` не заменяет `WHERE` для агрегатов.** Если нужно отфильтровать уже собранные группы, это `HAVING`.
* **Дубли из-за нескольких совпадений.** Два ключа снижают вероятность, но не гарантируют уникальность, если в таблице есть повторы.
