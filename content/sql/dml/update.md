# UPDATE

Как изменить цену у одной категории напитков и не затронуть всё остальное?

`UPDATE` меняет значения в существующих строках. Ты указываешь таблицу, столбцы и условие. Без `WHERE` команда затронет **все** строки — это самая частая и самая дорогая авария в SQL.

## Синтаксис

```sql
UPDATE таблица
SET столбец = значение,
    другой_столбец = выражение
WHERE условие;
```

Можно использовать текущие значения:

```sql
UPDATE drinks
SET price = ROUND(price * 1.1, 2)
WHERE category = 'кофе';
```

## Пример

Поднимем цены на кофе на 10%:

```sql
UPDATE drinks
SET price = ROUND(price * 1.1, 2)
WHERE category = 'кофе'
RETURNING name, price;
```

| name | price |
| --- | --- |
| Американо | 242.00 |
| Капучино | 308.00 |
| Латте | 341.00 |

## UPDATE ... FROM

Иногда новое значение лежит в другой таблице:

```sql
UPDATE order_items AS oi
SET unit_price = d.price
FROM drinks AS d
WHERE d.id = oi.drink_id
  AND oi.order_id = 128;
```

`FROM` в PostgreSQL позволяет присоединить другую таблицу к обновлению.

## Грабли

* **`UPDATE` без `WHERE`.** Обновит все строки. Сначала проверь `SELECT` с тем же условием.
* **`NULL` в арифметике.** `price + 10` вернёт `NULL`, если цена пустая. Используй `COALESCE`.
* **Потерянные изменения.** Два пользователя одновременно читают и записывают одну строку; последний побеждает. Для критичных данных нужны транзакции и блокировки.
* **Обновление первичного ключа.** Может сломать внешние ключи и приложение.
* **Триггеры.** `UPDATE` может запустить триггеры, которые меняют другие таблицы.
* **`UPDATE ... FROM` без условия связи.** Получится декартово произведение и хаос.
