# DROP и TRUNCATE

Чем `DELETE` отличается от `TRUNCATE`, а `TRUNCATE` — от `DROP`, и почему одну из этих команд нельзя откатить в MySQL?

Три команды удаляют данные, но на разных уровнях. `DELETE` убирает строки и может работать с `WHERE`. `TRUNCATE` быстро очищает всю таблицу. `DROP` удаляет саму таблицу вместе со структурой. Перепутать их — значит либо оставить лишние строки, либо потерять данные, которые не собирался трогать.

## Сравнение

| Команда | Что удаляет | `WHERE` | Скорость | Структура |
| --- | --- | --- | --- | --- |
| `DELETE` | строки | да | медленнее | остаётся |
| `TRUNCATE` | все строки | нет | быстро | остаётся |
| `DROP` | таблицу целиком | нет | быстро | исчезает |

## Синтаксис

```sql
DELETE FROM reviews WHERE rating < 3;

TRUNCATE TABLE order_items RESTART IDENTITY;

DROP TABLE IF EXISTS order_items;

DROP SCHEMA IF EXISTS shop CASCADE;

DROP DATABASE IF EXISTS coffee;
```

`RESTART IDENTITY` сбрасывает счётчик автонумерации. `CASCADE` у `DROP SCHEMA` удаляет все объекты внутри схемы, а у `TRUNCATE` — очищает и таблицы, которые ссылаются на неё.

## Пример

Очистим позиции заказов перед тестовым прогоном:

```sql
TRUNCATE TABLE order_items RESTART IDENTITY;
```

Таблица осталась, структура и ограничения на месте, но строки исчезли, а `order_id` и `drink_id` начинают нумерацию заново. В PostgreSQL `TRUNCATE` можно откатить внутри транзакции:

```sql
BEGIN;
TRUNCATE TABLE order_items;
ROLLBACK;
```

В MySQL `TRUNCATE` неявно коммитит транзакцию, поэтому откат не сработает.

## Когда что использовать

- **`DELETE`** — когда нужно удалить часть строк по условию.
- **`TRUNCATE`** — когда нужно быстро очистить всю таблицу, например перед загрузкой тестовых данных.
- **`DROP`** — когда таблица больше не нужна или её структура полностью меняется.

## Грабли

* **`DELETE` без `WHERE` удаляет всё.** Это не ошибка базы, но частая катастрофа. Сначала выполни `SELECT` с тем же условием.
* **`TRUNCATE` не умеет `WHERE`.** Для частичной очистки — только `DELETE`.
* **`TRUNCATE ... CASCADE` затрагивает связанные таблицы.** Проверь, какие внешние ключи указывают на таблицу.
* **`DROP TABLE` необратим.** Данные и структура исчезают. Резервная копия — обязательна.
* **`DROP DATABASE` нельзя выполнить, пока к базе подключены другие сессии.** И команда не работает внутри транзакции.
* **Права.** Для `TRUNCATE` и `DROP` нужны отдельные привилегии; не выдавай их приложению без необходимости.
