# SQL-инъекции

Как одна кавычка в поле поиска может превратиться в `DROP TABLE`, и почему параметры надёжнее склейки строк?

SQL-инъекция — это когда пользовательский ввод попадает в текст запроса и меняет его смысл. Классический пример: приложение склеивает строку `WHERE name = '` + ввод + `'`. Если ввести `' OR '1'='1`, условие станет всегда истинным. Если ввести `'; DROP TABLE ...; --`, последствия ещё хуже.

## Уязвимый код

Псевдокод:

```text
query = "SELECT * FROM drinks WHERE name = '" + userInput + "'"
```

При вводе `Латте' OR '1'='1` получается:

```sql
SELECT * FROM drinks WHERE name = 'Латте' OR '1'='1';
```

Вернутся все напитки.

## Безопасный подход

Параметризованный запрос передаёт значение отдельно от SQL:

```sql
SELECT * FROM drinks WHERE name = $1;
```

Приложение подставляет параметр через драйвер:

```text
cursor.execute("SELECT * FROM drinks WHERE name = %s", (user_input,))
```

В PostgreSQL параметры обозначаются `$1`, `$2`, а драйвер сам экранирует значения. SQL-текст остаётся неизменным.

## В функциях

Если внутри функции нужен динамический SQL, используй `quote_ident` и `quote_literal`, а лучше — `format` с правильными спецификаторами:

```sql
EXECUTE format('SELECT * FROM %I WHERE name = %L', p_table, p_name);
```

- `%I` — идентификатор (имя таблицы, столбца).
- `%L` — литерал (значение).

Никогда не подставляй пользовательский ввод в `EXECUTE` простой конкатенацией.

## Дополнительно

- **Ограничения прав.** Даже при инъекции приложение не должно иметь `DROP` и `TRUNCATE`.
- **Валидация.** Проверяй типы и допустимые значения на входе.
- **ORM.** Не гарантирует безопасность, если использовать «сырой» SQL со склейкой.
- **Логи.** Не пиши в логи пароли и токены.
- **Ошибки.** Не показывай пользователю полный текст ошибки базы.

## Грабли

* **Экранирование вручную.** Легко пропустить случай; параметры надёжнее.
* **«Только числа».** Числовой ввод тоже может быть вектором, если склеивается в строку.
* **Имена таблиц из ввода.** Параметры не работают для идентификаторов; нужен белый список.
* **`LIKE` с `%`.** Пользовательский `%` меняет смысл поиска; экранируй при необходимости.
* **Динамический SQL в `SECURITY DEFINER`.** Особенно опасен: код выполняется с правами владельца.
* **Надежда на WAF.** Он помогает, но не заменяет параметризацию.
