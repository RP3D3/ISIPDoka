# BETWEEN, IN, LIKE

Как одним условием поймать диапазон цен, список категорий или название, в котором есть «латте»?

Три оператора решают три частые задачи: `BETWEEN` проверяет попадание в диапазон, `IN` — совпадение с одним из списка, `LIKE` — совпадение с шаблоном. Они не заменяют `WHERE`, а делают его короче и понятнее, чем цепочка из `OR`.

## BETWEEN: диапазон

`BETWEEN a AND b` — это сокращение для `>= a AND <= b`. Границы **включаются**. Если нужен диапазон без одной из границ, пиши сравнения явно.

```sql
SELECT name, price
FROM drinks
WHERE price BETWEEN 200 AND 320
ORDER BY price;
```

| name | price |
| --- | --- |
| Американо | 220.00 |
| Лимонад | 240.00 |
| Какао | 260.00 |
| Капучино | 280.00 |
| Латте | 310.00 |
| Матча-латте | 320.00 |

`NOT BETWEEN` — наоборот, всё, что вне диапазона.

## IN: список

`IN (значение1, значение2, ...)` проверяет, совпадает ли значение хотя бы с одним из списка. Это короче и читаемее, чем `OR`:

```sql
SELECT name, category
FROM drinks
WHERE category IN ('кофе', 'чай')
  AND is_active
ORDER BY category, name;
```

| name | category |
| --- | --- |
| Американо | кофе |
| Капучино | кофе |
| Латте | кофе |
| Матча-латте | чай |
| Чай с бергамотом | чай |

В `IN` можно передать не только литералы, но и результат подзапроса — об этом будет отдельная карточка.

## LIKE: шаблон

`LIKE` сравнивает текст с шаблоном. Два спецсимвола:

| Символ | Что означает |
| --- | --- |
| `%` | любая последовательность символов, включая пустую |
| `_` | ровно один любой символ |

```sql
SELECT name
FROM drinks
WHERE name ILIKE '%латте%';
```

| name |
| --- |
| Латте |
| Матча-латте |

`ILIKE` — регистронезависимый вариант для PostgreSQL. В MySQL `LIKE` обычно и так не различает регистр, в SQL Server зависит от настроек сортировки.

Если в тексте встречается сам `%` или `_`, их экранируют через `ESCAPE`:

```sql
WHERE name LIKE '100\% скидка' ESCAPE '\'
```

## Грабли

* **`BETWEEN` включает границы.** `BETWEEN 200 AND 320` вернёт и 200, и 320. Для дат это особенно опасно: `BETWEEN '2026-05-01' AND '2026-05-31'` не включает заказы 31 мая после полуночи.
* **`NOT IN` и `NULL`.** Если в списке или подзапросе есть `NULL`, `NOT IN` может не вернуть ничего. Для подзапросов надёжнее `NOT EXISTS`.
* **`LIKE` чувствителен к регистру.** В PostgreSQL `'Латте' LIKE 'латте'` — ложь. Нужен `ILIKE` или `lower(name) LIKE ...`.
* **Ведущий `%` мешает индексу.** Поиск `'%латте%'` не может быстро отсечь строки по обычному индексу. Для больших текстов есть полнотекстовый поиск.
* **`IN` — не магия.** Список из тысячи значений превращается в громоздкий запрос. Для больших наборов используют `JOIN` или `= ANY(массив)`.
