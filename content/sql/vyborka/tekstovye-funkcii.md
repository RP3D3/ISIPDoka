# Текстовые функции

Как найти клиента по части имени, привести телефон к одному виду и собрать из полей аккуратную подпись для чека?

Текст в базе — не только для хранения. Его можно чистить, резать, склеивать и сравнивать без учёта регистра. Текстовые функции пригодятся в поиске, отчётах и при подготовке данных к выгрузке. Главное — помнить, что функция в условии может помешать индексу.

## Основные функции

| Функция | Что делает | Пример |
| --- | --- | --- |
| `lower(s)` / `upper(s)` | меняет регистр | `lower('Латте')` → `'латте'` |
| `length(s)` | число символов | `length('Латте')` → `5` |
| `trim(s)` | убирает пробелы по краям | `trim('  чай ')` → `'чай'` |
| `substring(s FROM 2 FOR 3)` | вырезает часть | `substring('Латте' FROM 2 FOR 3)` → `'атт'` |
| `replace(s, 'что', 'на что')` | заменяет все вхождения | `replace('Матча-латте', '-', ' ')` → `'Матча латте'` |
| `position('т' IN s)` | позиция подстроки | `position('т' IN 'Латте')` → `3` |
| `concat(a, b)` | склеивает, пропуская `NULL` | `concat('Латте', ' ', 310)` |
| `concat_ws(' ', a, b)` | склеивает с разделителем | `concat_ws(' ', 'Анна', 'Москва')` |
| `split_part(s, '@', 2)` | часть строки по разделителю | `'anna@zerno.ru'` → `'zerno.ru'` |
| `left(s, 1)` / `right(s, 1)` | первые/последние символы | `left('Анна', 1)` → `'А'` |

В PostgreSQL `length` считает символы, а не байты. Для кириллицы это важно: `length('Анна')` вернёт `4`, а `octet_length('Анна')` — `8`.

## Пример

Соберём подпись клиента и домен почты:

```sql
SELECT
    upper(left(name, 1)) || lower(substring(name FROM 2)) AS pretty_name,
    length(name) AS letters,
    split_part(email, '@', 2) AS domain
FROM customers
WHERE email IS NOT NULL
ORDER BY name;
```

| pretty_name | letters | domain |
| --- | --- | --- |
| Анна | 4 | zerno.ru |
| Игорь | 5 | mail.ru |
| Ольга | 5 | inbox.ru |
| Павел | 5 | zerno.ru |

`upper(left(name, 1))` делает первую букву заглавной, `lower(substring(name FROM 2))` опускает остальные. Получается аккуратный вид, даже если в базе имя записано как `АННА` или `анна`.

## Поиск без учёта регистра

```sql
SELECT name
FROM drinks
WHERE lower(name) LIKE '%латте%';
```

Это эквивалент `ILIKE '%латте%'`, но `lower()` полезен, когда нужно сравнивать с заранее приведённой строкой или строить выражение сложнее, чем шаблон.

## Чистка данных

```sql
SELECT
    trim(phone) AS phone,
    replace(trim(phone), '-', '') AS digits_only
FROM customers
WHERE phone IS NOT NULL;
```

Так убирают пробелы по краям и дефисы внутри. Для полноценной нормализации телефона этого мало, но для отчёта хватает.

## Грабли

* **`||` и `NULL`.** `name || ' — ' || phone` вернёт `NULL`, если телефон пуст. `concat()` пропускает `NULL`, `concat_ws()` — тоже, но ещё и ставит разделитель только между непустыми.
* **Функция в `WHERE` мешает индексу.** `WHERE lower(name) = 'латте'` не использует обычный индекс по `name`. Нужен expression-индекс или `ILIKE` с подходящим индексом.
* **`length` и пробелы.** `length(' ')` вернёт `1`. Если нужна «видимая» длина, сначала `trim`.
* **`substring` без длины.** `substring(s FROM 3)` вернёт всё до конца строки. Это не ошибка, но легко забыть.
* **Регистр в разных языках.** `lower('ЁЖ')` в PostgreSQL зависит от локали. Для сложных случаев проверяй `collation`.
* **Текст — не число.** `'10' + 5` не сработает без приведения. Для чисел используй `CAST`, для форматирования — `to_char`.
