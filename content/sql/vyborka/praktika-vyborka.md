# Практика: 10 запросов к кофейне

Как собрать вместе `WHERE`, `ORDER BY`, `LIMIT`, `CASE` и функции, чтобы ответить на реальные вопросы владельца кофейни?

Ниже — десять задач по схеме «Зерно». Сначала попробуй написать запрос сам, потом сверься с решением. В решениях важна не только правильность, но и порядок мыслей: что фильтруем, что вычисляем, как сортируем.

## Задачи

1. Показать все активные напитки дешевле 300 рублей по возрастанию цены.
2. Найти напитки категорий «кофе» или «чай» с ценой от 250 до 320 включительно.
3. Вывести клиентов, у которых не указан email.
4. Найти заказы за 13 мая 2026 года.
5. Показать три самых дорогих активных напитка.
6. Вывести уникальные категории напитков.
7. Найти напитки, в названии которых есть «латте», без учёта регистра.
8. Посчитать цену каждого активного напитка со скидкой 10% и округлить до копеек.
9. Разметить заказы: до 300 — «маленький», от 300 до 600 — «средний», больше 600 — «крупный».
10. Показать вторую страницу заказов по три штуки, от новых к старым.

## Решения

### 1. Активные напитки дешевле 300

```sql
SELECT name, price
FROM drinks
WHERE is_active AND price < 300
ORDER BY price;
```

`is_active` — уже булево выражение, сравнивать с `true` необязательно. Сортировка по цене ставит дешёвые вперёд.

### 2. Кофе или чай от 250 до 320

```sql
SELECT name, category, price
FROM drinks
WHERE category IN ('кофе', 'чай')
  AND price BETWEEN 250 AND 320
ORDER BY price;
```

`BETWEEN` включает обе границы, поэтому 320 попадёт в результат. Скобки не нужны: `AND` связывает два независимых условия.

### 3. Клиенты без email

```sql
SELECT id, name
FROM customers
WHERE email IS NULL;
```

`email = NULL` не сработал бы: сравнение с `NULL` даёт `unknown`.

### 4. Заказы за 13 мая 2026

```sql
SELECT id, created_at, total
FROM orders
WHERE created_at >= '2026-05-13'
  AND created_at <  '2026-05-14'
ORDER BY created_at;
```

Полуоткрытый интервал захватывает весь день, включая 23:59:59, и не зависит от того, есть ли в столбце время.

### 5. Три самых дорогих активных напитка

```sql
SELECT name, price
FROM drinks
WHERE is_active
ORDER BY price DESC
LIMIT 3;
```

`LIMIT` без `ORDER BY` вернул бы любые три строки, а не самые дорогие.

### 6. Уникальные категории

```sql
SELECT DISTINCT category
FROM drinks
ORDER BY category;
```

`DISTINCT` убирает повторы, `ORDER BY` делает список предсказуемым.

### 7. Напитки со словом «латте»

```sql
SELECT name
FROM drinks
WHERE name ILIKE '%латте%'
ORDER BY name;
```

`ILIKE` не различает регистр. `%` разрешает любые символы до и после слова.

### 8. Цена со скидкой 10%

```sql
SELECT
    name,
    price,
    ROUND(price * 0.9, 2) AS price_discount
FROM drinks
WHERE is_active
ORDER BY price_discount;
```

`ROUND(..., 2)` оставляет две цифры после запятой. `price * 0.9` не меняет исходную таблицу.

### 9. Разметка заказов по сумме

```sql
SELECT
    id,
    total,
    CASE
        WHEN total < 300 THEN 'маленький'
        WHEN total <= 600 THEN 'средний'
        ELSE 'крупный'
    END AS order_size
FROM orders
ORDER BY total;
```

Границы выбраны так, чтобы 300 попал в «средний», а 600 — тоже в «средний». Если бизнес-правило другое, меняй `WHEN`.

### 10. Вторая страница заказов

```sql
SELECT id, created_at, total
FROM orders
ORDER BY created_at DESC, id DESC
LIMIT 3 OFFSET 3;
```

`id` вторым ключом делает порядок однозначным, если у двух заказов совпало время. Без него страницы могут дублироваться.

## Что заметить

* Фильтр `WHERE` всегда стоит до сортировки и ограничения: сначала отбираем, потом упорядочиваем, потом обрезаем.
* `ORDER BY` и `LIMIT` работают в паре. Один `LIMIT` не гарантирует «самые» строки.
* `CASE` и функции в `SELECT` не меняют таблицу, а только результат запроса.
* Для дат надёжнее полуоткрытый интервал, чем `BETWEEN`.
