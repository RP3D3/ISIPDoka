# CASE

Как в одном запросе разделить напитки на дешёвые, средние и дорогие, не делая три отдельных запроса?

`CASE` — это `if/else` внутри SQL. Он проверяет условия по очереди и возвращает значение первого подходящего. `CASE` можно использовать в `SELECT`, `WHERE`, `ORDER BY` и даже внутри агрегатов: например, посчитать только оплаченные заказы.

## Как это работает

Представь сортировщика с тремя корзинами. Он смотрит на цену: если меньше 220 — в «дешёвые», иначе если меньше 300 — в «средние», иначе — в «дорогие». Проверка идёт сверху вниз, и срабатывает только первая подходящая ветка. Если ни одна не подошла, возвращается `ELSE`; если `ELSE` нет — `NULL`.

## Синтаксис

Поисковый `CASE` проверяет произвольные условия:

```sql
CASE
    WHEN условие1 THEN значение1
    WHEN условие2 THEN значение2
    ELSE значение_по_умолчанию
END
```

Простой `CASE` сравнивает одно выражение с набором значений:

```sql
CASE category
    WHEN 'кофе' THEN 'горячий'
    WHEN 'чай' THEN 'горячий'
    ELSE 'холодный'
END
```

Простой вариант короче, но умеет только сравнение на равенство. Для диапазонов и `IS NULL` нужен поисковый.

## Пример

```sql
SELECT
    name,
    price,
    CASE
        WHEN price < 220 THEN 'дешёвый'
        WHEN price < 300 THEN 'средний'
        ELSE 'дорогой'
    END AS price_band
FROM drinks
WHERE is_active
ORDER BY price;
```

| name | price | price_band |
| --- | --- | --- |
| Чай с бергамотом | 190.00 | дешёвый |
| Американо | 220.00 | средний |
| Лимонад | 240.00 | средний |
| Какао | 260.00 | средний |
| Капучино | 280.00 | средний |
| Латте | 310.00 | дорогой |
| Матча-латте | 320.00 | дорогой |

`Американо` за 220 попал в «средние», потому что условие `< 220` строгое. Если нужно включить 220 в «дешёвые», пиши `<= 220`.

## Сортировка по своим правилам

`CASE` умеет задавать не алфавитный порядок:

```sql
SELECT name, category
FROM drinks
ORDER BY CASE category
    WHEN 'кофе' THEN 1
    WHEN 'чай' THEN 2
    ELSE 3
END, name;
```

Сначала пойдут кофе, потом чай, потом остальное. Это удобно, когда бизнес-порядок важнее алфавита.

## CASE и агрегаты

Внутри `SUM` или `COUNT` `CASE` позволяет считать по условию:

```sql
SELECT
    COUNT(*) AS all_orders,
    COUNT(*) FILTER (WHERE status = 'paid') AS paid_orders
FROM orders;
```

`FILTER` — более читаемый аналог `CASE` для агрегатов в PostgreSQL. В других диалектах чаще пишут `SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END)`.

## Грабли

* **Срабатывает первая ветка.** Если первое условие слишком широкое, остальные не выполнятся. Порядок `WHEN` — часть логики.
* **Нет `ELSE` — будет `NULL`.** Если категория не подошла ни под одно условие, результат пустой. Для отчётов лучше задать `ELSE`.
* **Типы веток должны совпадать.** Нельзя в одной ветке вернуть число, в другой — текст без приведения.
* **`CASE` — не `COALESCE`.** `COALESCE` возвращает первый непустой аргумент, `CASE` выбирает по условию. Для замены `NULL` короче `COALESCE`.
* **`CASE` в `WHERE` может убить индекс.** Условие становится выражением, и обычный индекс по столбцу может не пригодиться.
