# Как база ищет строки

Почему для одной строки база читает всю таблицу, а для другой сразу открывает нужную страницу?

У базы есть несколько стратегий доступа к данным. `Seq Scan` читает таблицу целиком, `Index Scan` идёт по индексу к нужным строкам, `Bitmap Scan` сначала собирает ссылки, потом читает страницы. Планировщик выбирает стратегию по стоимости, а не по «красоте» запроса.

## Основные способы

| Способ | Как работает | Когда выбирают |
| --- | --- | --- |
| `Seq Scan` | читает все страницы таблицы | маленькая таблица или нужна большая доля строк |
| `Index Scan` | идёт по дереву индекса к строкам | мало строк, точное условие |
| `Bitmap Index Scan` | собирает битмап ссылок, потом читает страницы | средняя доля строк |
| `Index Only Scan` | отвечает из индекса без чтения таблицы | все нужные столбцы есть в индексе |

## Пример

```sql
EXPLAIN SELECT * FROM orders WHERE id = 129;
```

```text
Index Scan using orders_pkey on orders  (cost=0.29..8.30 rows=1 width=48)
  Index Cond: (id = 129)
```

База знает, что `id` уникален, и идёт прямо к строке.

```sql
EXPLAIN SELECT * FROM orders WHERE status = 'new';
```

```text
Seq Scan on orders  (cost=0.00..2240.00 rows=1200 width=48)
  Filter: (status = 'new'::text)
```

Если `status` не индексирован или подходит слишком много строк, дешевле прочитать всё.

## Стоимость

`cost=0.00..2240.00` — не миллисекунды, а условные единицы. Первое число — стоимость до первой строки, второе — до последней. Планировщик сравнивает варианты и выбирает самый дешёвый по своей модели.

Модель учитывает:

- количество страниц таблицы и индекса;
- селективность условия (сколько строк подходит);
- статистику из `ANALYZE`;
- настройки вроде `random_page_cost`.

## Почему это важно

Если ты добавил индекс, а база его не использует, дело не в «упрямстве»: по её оценке чтение через индекс дороже. Причины бывают разные — устаревшая статистика, функция в условии, слишком широкая выборка.

## Грабли

* **Смотреть только на `cost`.** Оценка приблизительна; для реального времени нужен `EXPLAIN ANALYZE`.
* **Ожидать `Index Scan` всегда.** Для большой доли строк `Seq Scan` честно быстрее.
* **Устаревшая статистика.** После массовой загрузки запусти `ANALYZE`.
* **`SELECT *`.** Тянет лишние столбцы и мешает `Index Only Scan`.
* **Функция в `WHERE`.** `WHERE lower(name) = ...` не использует индекс по `name`.
* **Маленькая таблица.** Индекс может быть не нужен вовсе: чтение целиком дешевле.
