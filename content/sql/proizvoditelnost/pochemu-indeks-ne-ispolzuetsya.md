# Почему индекс не используется

Ты создал индекс, а план всё равно показывает `Seq Scan`. Почему база его игнорирует и что с этим делать?

Индекс — не приказ, а один из вариантов доступа. Планировщик сравнивает стоимость и может выбрать чтение всей таблицы. Причины бывают технические (функция, тип, статистика) и смысловые (условие выбирает слишком много строк). Прежде чем «чинить» индекс, посмотри план.

## Частые причины

| Причина | Пример | Что делать |
| --- | --- | --- |
| функция от столбца | `WHERE lower(name) = 'латте'` | индекс по `lower(name)` |
| неявное приведение | `WHERE phone = 123` при `phone TEXT` | сравнивать с текстом |
| ведущий `%` | `LIKE '%латте%'` | полнотекстовый или trigram-индекс |
| широкая выборка | `WHERE status = 'new'` на 80% строк | индекс не нужен |
| устаревшая статистика | после массовой загрузки | `ANALYZE` |
| маленькая таблица | 100 строк | оставить `Seq Scan` |
| `OR` по разным столбцам | `WHERE a = 1 OR b = 2` | два индекса или переписать |

## Пример: функция

```sql
CREATE INDEX idx_drinks_name ON drinks (name);

EXPLAIN SELECT * FROM drinks WHERE lower(name) = 'латте';
```

План, скорее всего, покажет `Seq Scan`: индекс построен по `name`, а условие — по `lower(name)`.

Решение:

```sql
CREATE INDEX idx_drinks_lower_name ON drinks (lower(name));
```

## Пример: тип

```sql
EXPLAIN SELECT * FROM customers WHERE phone = 89991234567;
```

Если `phone` — `TEXT`, PostgreSQL приводит столбец или значение, и индекс может не примениться. Сравнивай с текстом:

```sql
SELECT * FROM customers WHERE phone = '89991234567';
```

## Статистика

```sql
ANALYZE drinks;
```

После массовой вставки или удаления статистика устаревает, и планировщик ошибается в оценке строк. `ANALYZE` обновляет её.

## Когда `Seq Scan` — это нормально

- Таблица маленькая.
- Условие выбирает большую долю строк.
- Нужны все столбцы, а индекс не покрывающий.
- Стоимость случайного чтения высока, а строк много.

## Грабли

* **«Индекс есть — значит должен использоваться».** Нет, планировщик решает по стоимости.
* **`SELECT *`.** Мешает покрывающему индексу и тянет лишние данные.
* **Функция в условии.** Самая частая причина.
* **Неявное приведение.** `WHERE id = '5'` может работать, но тип лучше соблюдать.
* **`OR`.** Иногда лучше `UNION` двух индексных запросов.
* **Тест на маленькой таблице.** На сотне строк `Seq Scan` почти всегда дешевле.
