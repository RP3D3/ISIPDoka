# Частичные, уникальные, expression-индексы

Как запретить два активных заказа на один столик, но разрешить много отменённых, и как искать по `lower(email)` без полного сканирования?

Обычный индекс строится по всем строкам и по значению столбца. Но иногда нужен индекс только для части строк, только для уникальности или по выражению. PostgreSQL поддерживает все три варианта, и они часто решают задачи, которые иначе требуют триггеров или лишних столбцов.

## Частичный индекс

```sql
CREATE INDEX idx_active_drinks_price
ON drinks (price)
WHERE is_active;
```

Индекс содержит только активные напитки. Он меньше, быстрее обновляется и помогает запросам с тем же условием:

```sql
SELECT name, price
FROM drinks
WHERE is_active AND price < 300;
```

## Уникальный индекс

```sql
CREATE UNIQUE INDEX idx_customers_email
ON customers (lower(email))
WHERE email IS NOT NULL;
```

Здесь два приёма сразу: уникальность по `lower(email)` и частичность, чтобы несколько `NULL` не мешали.

Уникальность только для активных строк:

```sql
CREATE UNIQUE INDEX idx_one_active_order_per_table
ON orders (table_id)
WHERE status IN ('new', 'paid');
```

Отменённые заказы не участвуют, поэтому на стол можно создать новый заказ.

## Expression-индекс

```sql
CREATE INDEX idx_drinks_lower_name
ON drinks (lower(name));
```

Запрос должен использовать то же выражение:

```sql
SELECT * FROM drinks WHERE lower(name) = 'латте';
```

Индекс по `name` здесь не поможет: база ищет по результату функции.

## Когда что использовать

| Задача | Индекс |
| --- | --- |
| искать только активные строки | частичный |
| запретить дубли с учётом регистра | уникальный expression |
| ускорить `lower(name)` | expression |
| один активный заказ на стол | частичный уникальный |

## Грабли

* **Условие индекса должно совпадать с запросом.** Частичный индекс по `WHERE is_active` не поможет запросу без этого условия.
* **Функция должна совпадать.** `lower(name)` в индексе и `LOWER(name)` в запросе — одно и то же, а `name` без функции — уже другое.
* **`UNIQUE` и `NULL`.** В PostgreSQL несколько `NULL` допустимы; частичный `WHERE email IS NOT NULL` делает правило явным.
* **Expression-индекс и типы.** `lower(name)` возвращает `text`; приведение к другому типу может помешать.
* **Слишком экзотическое выражение.** Индекс нужно поддерживать при каждой записи; сложная функция замедлит вставки.
* **Частичный индекс не универсален.** Он оптимизирован под конкретный сценарий, а не под все запросы.
