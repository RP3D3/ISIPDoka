# N+1 запросов

Почему страница с двадцатью заказами делает двадцать один запрос к базе и как это исправить одним соединением?

`N+1` — классическая проблема приложений с ORM. Сначала выполняется один запрос за списком сущностей, потом для каждой сущности — отдельный запрос за связанными данными. На маленьких данных это незаметно, на сотне строк превращается в сотню round-trip к базе.

## Как это выглядит

```text
1. SELECT * FROM orders LIMIT 20;
2. SELECT * FROM customers WHERE id = 1;
3. SELECT * FROM customers WHERE id = 2;
...
21. SELECT * FROM customers WHERE id = 20;
```

Итого 21 запрос вместо одного или двух.

## Решение: JOIN

```sql
SELECT
    o.id AS order_id,
    o.total,
    c.name AS customer
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
ORDER BY o.created_at DESC
LIMIT 20;
```

Один запрос — все нужные данные.

## Решение: два запроса

Если `JOIN` размножает строки из-за нескольких связей, иногда лучше два запроса:

```sql
-- 1. заказы
SELECT id, customer_id, total
FROM orders
ORDER BY created_at DESC
LIMIT 20;

-- 2. клиенты по списку id
SELECT id, name
FROM customers
WHERE id IN (1, 2, 3, ...);
```

Приложение собирает результат в памяти. Это лучше, чем 20 отдельных запросов, и не размножает строки.

## В ORM

- **Ленивая загрузка** (`lazy`) — частая причина `N+1`.
- **Жадная загрузка** (`eager`, `JOIN FETCH`, `include`) — загружает связи заранее.
- **Пакетная загрузка** (`batch`, `preload`) — собирает id и делает один запрос.

Названия зависят от ORM, смысл один: не ходи в базу за каждой строкой.

## Как заметить

- Логи запросов: много однотипных `SELECT ... WHERE id = ?`.
- Счётчик запросов в тестах или APM.
- Время страницы растёт линейно с числом элементов.
- `EXPLAIN` показывает `Nested Loop` с большим `loops`.

## Грабли

* **`N+1` не виден на трёх тестовых строках.** Проверяй на сотнях.
* **Жадная загрузка всего.** Можно получить огромный `JOIN` и дубли. Загружай только нужное.
* **`IN` с тысячами id.** Огромный список тоже плох; разбивай на пачки.
* **Скрытые запросы в шаблонах.** ORM может лениво подгружать связь при обращении в представлении.
* **Кэш.** Он маскирует проблему, но не решает её.
* **Преждевременная оптимизация.** Сначала измерь, потом меняй загрузку.
