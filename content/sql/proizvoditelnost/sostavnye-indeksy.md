# Составные индексы

Почему индекс по `(category, price)` помогает запросу с категорией и ценой, но почти бесполезен для поиска только по цене?

Составной индекс строится по нескольким столбцам в заданном порядке. Он работает как телефонный справочник: сначала сортировка по фамилии, внутри — по имени. Найти по фамилии можно, найти только по имени — нет. Поэтому порядок столбцов в индексе важнее, чем их количество.

## Синтаксис

```sql
CREATE INDEX idx_drinks_category_price
ON drinks (category, price);
```

## Какие запросы он ускорит

```sql
-- да: используется первый столбец
SELECT * FROM drinks WHERE category = 'кофе';

-- да: оба столбца
SELECT * FROM drinks
WHERE category = 'кофе' AND price < 300;

-- да: диапазон по второму столбцу после равенства по первому
SELECT * FROM drinks
WHERE category = 'кофе' AND price BETWEEN 200 AND 300;
```

## Какие не ускорит

```sql
-- нет: первый столбец не участвует
SELECT * FROM drinks WHERE price < 300;
```

Для такого запроса нужен отдельный индекс по `price`.

## Правило порядка

Сначала ставят столбец, по которому чаще всего ищут равенство, потом — по которому идёт диапазон или сортировка:

```sql
CREATE INDEX idx_orders_customer_created
ON orders (customer_id, created_at DESC);
```

Этот индекс поможет:

```sql
SELECT *
FROM orders
WHERE customer_id = 3
ORDER BY created_at DESC
LIMIT 5;
```

## Покрывающий индекс

Если индекс содержит все нужные запросы столбцы, база может ответить без чтения таблицы:

```sql
CREATE INDEX idx_drinks_category_price_name
ON drinks (category, price) INCLUDE (name);

SELECT name, price
FROM drinks
WHERE category = 'кофе'
ORDER BY price;
```

`INCLUDE` добавляет столбцы в листья индекса, не участвуя в сортировке. Это включает `Index Only Scan`.

## Грабли

* **Порядок столбцов.** `(price, category)` и `(category, price)` — разные индексы с разными возможностями.
* **Пропуск первого столбца.** Индекс по `(a, b)` не поможет условию только по `b`.
* **Слишком много столбцов.** Индекс растёт, вставки замедляются, а выигрыш не всегда есть.
* **Дубли.** Индекс по `(a)` и по `(a, b)` могут пересекаться; проверь, не лишний ли первый.
* **`INCLUDE` не для фильтра.** Столбцы в `INCLUDE` не помогают условиям `WHERE`, только покрывают `SELECT`.
* **Статистика.** После массовых изменений обнови `ANALYZE`, иначе планировщик может недооценить индекс.
