# Типы данных

Почему цену нельзя хранить в `FLOAT`, а дату — в обычном `TIMESTAMP`, если в кофейне несколько городов?

Тип данных — это правило, что именно можно положить в столбец и какие операции с ним допустимы. Он экономит место, ускоряет запросы и ловит ошибки на входе: строка «двадцать» не попадёт в числовой столбец, а дата не превратится в текст.

## Основные типы PostgreSQL

| Тип | Для чего | Пример |
| --- | --- | --- |
| `INTEGER` / `BIGINT` | Целые числа, идентификаторы | `42`, `1000000` |
| `NUMERIC(10, 2)` | Деньги и точные дроби | `280.50` |
| `TEXT` | Строки любой длины | `'Капучино'` |
| `BOOLEAN` | Да / нет | `true`, `false` |
| `DATE` | Дата без времени | `2026-05-14` |
| `TIMESTAMPTZ` | Момент времени с часовым поясом | `2026-05-14 10:30+03` |
| `UUID` | Глобально уникальный идентификатор | `gen_random_uuid()` |
| `JSONB` | Гибкий JSON-документ | `'{"milk": "oat"}'` |

## Пример

```sql
CREATE TABLE drinks (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    category TEXT NOT NULL,
    price NUMERIC(10, 2) NOT NULL CHECK (price >= 0),
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

| Столбец | Почему такой тип |
| --- | --- |
| `id` | `BIGINT` переживёт миллиарды заказов |
| `price` | `NUMERIC` не теряет копейки, в отличие от `FLOAT` |
| `is_active` | Булево значение вместо строк `'да'` / `'нет'` |
| `created_at` | `TIMESTAMPTZ` хранит момент, а не «локальные часы» |

## Грабли

* **`FLOAT` для денег.** Двоичная дробь не представляет `0.10` точно; суммы начнут расходиться на копейки. Для денег — `NUMERIC`.
* **`TIMESTAMP` без пояса.** Если сервер и клиент в разных городах, «10:30» превратится в разные моменты. Для событий — `TIMESTAMPTZ`.
* **`VARCHAR(255)` по привычке.** В PostgreSQL `TEXT` ничем не хуже и не медленнее; ограничение длины ставь только если оно бизнес-правило.
* **`JSONB` вместо таблиц.** JSON удобен для необязательных атрибутов, но связи, ключи и агрегаты лучше держать в обычных столбцах.
