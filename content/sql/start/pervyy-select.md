# Первый SELECT и стиль SQL

Как достать из таблицы нужные столбцы и не превратить запрос в нечитаемую строку?

`SELECT` — главная команда чтения. Ты перечисляешь столбцы, указываешь таблицу, а база возвращает строки. Даже самый сложный отчёт начинается с этой конструкции: `SELECT` → `FROM` → остальные уточнения.

## Синтаксис

```sql
SELECT столбец1, столбец2
FROM таблица
LIMIT количество;
```

`LIMIT` ограничивает число строк. На этапе знакомства он полезен: не нужно смотреть на тысячи записей, чтобы понять структуру.

## Пример

```sql
SELECT name, category, price
FROM drinks
LIMIT 5;
```

| name | category | price |
| --- | --- | --- |
| Американо | кофе | 220.00 |
| Капучино | кофе | 280.00 |
| Чай с бергамотом | чай | 190.00 |
| Матча-латте | чай | 320.00 |
| Какао | напиток | 260.00 |

Столбцы можно переименовать через `AS`. Это не меняет таблицу, только заголовок результата:

```sql
SELECT name AS drink, price AS rub
FROM drinks
LIMIT 3;
```

## Как писать, чтобы читать

- Ключевые слова (`SELECT`, `FROM`, `LIMIT`) — заглавными, имена — как в схеме.
- Каждый смысловой блок — с новой строки. Запрос из пяти условий в одну строку невозможно отлаживать.
- В конце — точка с запятой. В `psql` без неё запрос просто не выполнится.
- Комментарии — `-- до конца строки` или `/* блок */`.
- `SELECT *` оставь для знакомства со схемой. В приложении перечисляй столбцы явно: так запрос не сломается от нового столбца и не потянет лишние данные.

## Грабли

* **Регистр ключевых слов не важен.** `select` и `SELECT` работают одинаково, но заглавные легче читать.
* **Имена без кавычек PostgreSQL приводит к нижнему регистру.** `Drinks` станет `drinks`. Кавычки нужны только для имён с пробелами или заглавными, и тогда регистр придётся соблюдать всегда.
* **`LIMIT` без `ORDER BY` — лотерея.** Какие именно пять строк вернутся, база не обещает.
