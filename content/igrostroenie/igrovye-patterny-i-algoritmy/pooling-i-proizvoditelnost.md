# Пул объектов и производительность

Создание и удаление объектов — дорогая операция. Если делать это каждый кадр,
игра начинает тормозить. Пул объектов переиспользует уже созданные экземпляры.

## Проблема

```text
on_shoot():
    bullet = instantiate(bulletPrefab)
    destroy(bullet, 2.0)
```

При сотнях пуль:

- растёт нагрузка на память;
- сборщик мусора делает паузы;
- кадры становятся неровными.

## Решение

Пул заранее создаёт объекты и хранит их в неактивном состоянии.

```text
pool = []

get():
    if pool has inactive:
        obj = pool.pop()
        obj.setActive(true)
        return obj
    else:
        return instantiate(prefab)

release(obj):
    obj.setActive(false)
    pool.push(obj)
```

## Сброс состояния

При выдаче объекта из пула нужно сбросить:

- позицию;
- скорость;
- таймеры;
- здоровье;
- анимацию;
- ссылки на цель.

Иначе пуля «вспомнит» прошлую жизнь.

## Что пулить

- пули;
- частицы;
- всплывающий урон;
- врагов;
- звуковые источники;
- UI-элементы.

Не всё нужно пулить. Если объект создаётся редко, пул может усложнить код без
пользы.

## Профилирование

Сначала измерьте, потом оптимизируйте:

- профайлер;
- количество аллокаций;
- пики GC;
- время кадра;
- количество активных объектов.

Оптимизация без измерений часто делает код хуже.

## Ошибки

- **Забыли сбросить состояние.**
- **Пул растёт бесконечно.**
- **Объект возвращают дважды.**
- **Пулят всё подряд.**
- **Не проверяют, активен ли объект.**
