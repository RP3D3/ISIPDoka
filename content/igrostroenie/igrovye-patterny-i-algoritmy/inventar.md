# Инвентарь

Инвентарь кажется простой таблицей «предмет → количество», но именно на нём
ломаются сохранения, торговля и квесты. Предмет можно добавить дважды, стопка
переполняется, вес уходит в минус, а UI показывает не то, что лежит в модели.
Надёжный инвентарь начинается с разделения данных и представления и с честных
правил добавления.

## Модель и представление

**Модель** отвечает на вопросы «что лежит», «сколько» и «помещается ли».
**Представление** рисует слоты, иконки, подсказки и реакции на клики. Модель не
должна знать про кнопки и координаты, а UI — менять массив слотов напрямую.

Минимальный набор данных:

```csharp
public sealed class ItemStack
{
    public string DefinitionId; // какой это предмет
    public int Count;           // сколько в стопке
    public int MaxStack;        // лимит одной стопки
}
```

Модель инвентаря хранит слоты и общий вес. UI получает событие «инвентарь
изменился» и перерисовывается. Такой контракт позволяет тестировать логику без
движка и переиспользовать её для сундука, магазина и крафта.

## Слоты и стопки

Слот — ячейка фиксированного размера. Стопка — несколько одинаковых предметов
в одном слоте. Правила стопок:

- у каждого типа предмета свой `MaxStack`;
- расходники обычно складываются, экипировка — нет;
- при добавлении сначала заполняются неполные стопки, потом пустые слоты;
- остаток, который не поместился, возвращается вызывающему коду.

Если просто увеличивать `Count` без проверки `MaxStack`, в одном слоте
окажется 999 зелий, а UI нарисует «×999» поверх иконки. Формально данные
целы, но баланс и торговля уже сломаны.

## Вес и ограничения

Ограничение может быть по слотам, по весу или по тому и другому. Вес считается
по определению предмета, а не по экземпляру:

```text
вес инвентаря = Σ (вес предмета × количество)
```

Проверять лимит нужно **до** изменения слотов. Иначе придётся откатывать уже
применённые операции. Хороший контракт добавления:

```csharp
public bool TryAdd(string id, int count, int maxStack, float unitWeight)
{
    float addWeight = unitWeight * count;
    if (Weight + addWeight > MaxWeight)
    {
        return false; // не помещается целиком
    }

    // 1. Добить существующие стопки.
    // 2. Занять пустые слоты.
    // 3. Если остаток > 0 — вернуть false и откатить.
    return true;
}
```

Альтернатива — разрешать частичное добавление и возвращать остаток числом.
Главное, чтобы правило было одним и тем же во всех местах: при подборе лута,
покупке и награде за квест.

## Сетка или список

| Вариант | Плюсы | Минусы |
|---|---|---|
| Сетка | Наглядно, удобно для геймпада, место ощущается | Сложнее сортировка и адаптивность |
| Список | Компактно, легко фильтровать, хорошо для больших сумок | Меньше «физического» ощущения |
| Гибрид | Категории и вкладки, сетка внутри | Больше кода UI |

Сетка хорошо работает в играх, где важно пространство: выживание, крафт,
тактика. Список удобнее для RPG с сотнями предметов и поиском. В любом случае
модель может оставаться одной и той же — меняется только представление.

## Добавление и удаление

Добавление — это транзакция: либо предмет помещается целиком, либо состояние
не меняется. Удаление симметрично: сначала проверяем, что нужное количество
есть, потом списываем.

```csharp
public bool TryRemove(string id, int count)
{
    int available = 0;
    foreach (ItemStack stack in _slots)
    {
        if (stack != null && stack.DefinitionId == id)
        {
            available += stack.Count;
        }
    }

    if (available < count)
    {
        return false;
    }

    foreach (ItemStack stack in _slots)
    {
        if (stack == null || stack.DefinitionId != id)
        {
            continue;
        }

        int take = Math.Min(stack.Count, count);
        stack.Count -= take;
        count -= take;

        if (stack.Count == 0)
        {
            ClearSlot(stack);
        }

        if (count == 0)
        {
            break;
        }
    }

    RecalculateWeight();
    return true;
}
```

Типичные операции, которые стоит покрыть тестами:

- добавить предмет в пустой инвентарь;
- добавить больше, чем влезает в одну стопку;
- добавить при полном весе;
- удалить больше, чем есть;
- удалить последний предмет и очистить слот;
- обменять местами два слота.

## UI инвентаря

UI — это проекция модели, а не второй источник правды. Разумный цикл:

1. игрок нажимает «взять»;
2. модель пытается добавить предмет;
3. модель публикует событие изменения;
4. UI перерисовывает затронутые слоты;
5. если добавление не удалось, показывается причина: «нет места» или «слишком тяжело».

Полезные детали: подсветка неполных стопок, отдельные иконки для экипировки,
подтверждение при выбросе, навигация геймпадом, масштабирование шрифта. Не
стоит пересчитывать весь инвентарь каждый кадр — только по событию.

## Частые ошибки

- **UI хранит своё состояние.** После загрузки сохранения картинка и данные
  расходятся.
- **Нет проверки `MaxStack`.** Стопка растёт бесконечно.
- **Вес считается после добавления.** Инвентарь уходит в перегруз, и откат
  становится сложным.
- **Удаление по индексу слота.** Индексы меняются после сортировки; надёжнее
  искать по идентификатору.
- **Забыли очистить пустой слот.** В массиве остаётся объект с `Count = 0`.
- **Слишком умный UI.** Логика «куда положить предмет» продублирована в
  нескольких экранах и работает по-разному.
