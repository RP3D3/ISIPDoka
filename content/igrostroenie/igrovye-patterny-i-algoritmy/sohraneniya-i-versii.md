# Сохранения и миграции

Сохранение — это контракт между версиями игры. Если формат меняется, старые
сохранения не должны превращаться в мусор.

## Что хранить

- версию формата;
- прогресс;
- настройки;
- seed мира;
- позицию игрока;
- инвентарь;
- состояние квестов.

Не храните всё подряд: сохраняйте **состояние**, а не внутренние объекты движка.

## Версия формата

```json
{
  "version": 3,
  "player": { "hp": 80, "level": 5 },
  "inventory": ["sword", "potion"]
}
```

Версия позволяет понять, как читать данные.

## Миграции

Миграция — функция, которая превращает старый формат в новый:

```text
migrate_1_to_2(save)
migrate_2_to_3(save)
```

Загружайте последовательно, пока не дойдёте до текущей версии. Не пытайтесь
поддержать все версии одним огромным `if`.

## Атомарная запись

Запись должна быть безопасной:

1. записать во временный файл;
2. проверить;
3. заменить основной файл.

Если игра выключится в середине записи, основное сохранение останется целым.

## Валидация

После загрузки проверьте:

- обязательные поля;
- допустимые значения;
- ссылки на предметы;
- версию;
- целостность.

Если данных нет — используйте значения по умолчанию или предложите новую игру.

## Слоты и резервные копии

- несколько слотов;
- автосохранение;
- резервная копия перед миграцией;
- понятное сообщение об ошибке.

## Частые ошибки

- **Нет версии.** Непонятно, как читать файл.
- **Прямая запись поверх.** Риск повреждения.
- **Миграция без тестов.** Старые сохранения ломаются.
- **Хранение ссылок на объекты.** После загрузки они невалидны.
- **Нет резервной копии.** Одна ошибка — и прогресс потерян.
