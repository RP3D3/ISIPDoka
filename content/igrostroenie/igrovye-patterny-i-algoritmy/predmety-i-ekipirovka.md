# Предметы и экипировка

«Меч» в игре — это не один объект, а два разных понятия. Есть **описание**
типа: название, иконка, базовый урон, допустимые слоты. И есть **экземпляр**:
конкретный меч с прочностью 37, случайным бонусом и владельцем. Смешение этих
сущностей приводит к тому, что игрок улучшает один меч, а меняется урон у всех
мечей в мире.

## Definition и instance

| | Definition | Instance |
|---|---|---|
| Что описывает | Тип предмета | Конкретную вещь |
| Сколько живёт | Один на всю игру | Столько, сколько существует предмет |
| Что хранит | Название, иконку, базовые статы | Прочность, заряд, модификаторы, количество |
| Где лежит | В каталоге контента | В инвентаре, сундуке, сохранении |
| Меняется ли | Нет во время игры | Да, постоянно |

В коде это обычно два класса. Экземпляр хранит **ссылку по идентификатору** на
описание, а не копию всех полей:

```csharp
public sealed class ItemDefinition
{
    public string Id;
    public string DisplayName;
    public ItemSlot Slot;        // Weapon, Armor, Ring...
    public int BaseDamage;
    public int BaseArmor;
    public int MaxStack;
    public Rarity Rarity;
}

public sealed class ItemInstance
{
    public string DefinitionId;
    public int Durability;
    public int Level;
    public List<StatModifier> Modifiers = new();
}
```

Идентификатор должен быть стабильным. Если переименовать `id` при рефакторинге,
старые сохранения потеряют предметы.

## Статы и модификаторы

Статы удобно делить на **базовые** и **производные**. Базовые приходят от
персонажа и предметов, производные считаются формулой: например, урон зависит
от силы и оружия, а скорость атаки — от ловкости и веса.

Модификаторы бывают трёх видов:

- **flat** — прибавить число (`+5 к броне`);
- **percent** — прибавить процент от базы (`+20% к урону`);
- **multiplicative** — умножить итог (`×1.5`).

Порядок применения важно зафиксировать:

```text
итог = (база + flat) × (1 + сумма percent) × произведение множителей
```

Если порядок меняется от предмета к предмету, баланс становится
непредсказуемым. Одинаковые модификаторы лучше складывать, а не применять
цепочкой «процент от процента».

```csharp
public sealed class StatBlock
{
    public float Base;
    private readonly List<StatModifier> _mods = new();

    public float Value
    {
        get
        {
            float flat = 0f;
            float percent = 0f;
            float mult = 1f;

            foreach (StatModifier mod in _mods)
            {
                if (mod.Kind == ModKind.Flat) flat += mod.Value;
                else if (mod.Kind == ModKind.Percent) percent += mod.Value;
                else mult *= mod.Value;
            }

            return (Base + flat) * (1f + percent) * mult;
        }
    }
}
```

## Редкость

Редкость — это не только цвет рамки. Она задаёт ожидания игрока и обычно
влияет на число модификаторов, диапазон статов и цену.

| Редкость | Обычно | Риск |
|---|---|---|
| Common | 0 модификаторов | Мусор в инвентаре |
| Uncommon | 1 модификатор | Почти незаметна |
| Rare | 2 модификатора | Быстро обесценивает обычные вещи |
| Epic | 3 модификатора, уникальный эффект | Сложно балансировать |
| Legendary | Уникальная механика | Ломает экономику |

Цвета должны дублироваться формой или подписью: только цвет плохо читается
людьми с нарушениями цветовосприятия.

## Экипировка и слоты

У экипировки есть допустимые слоты. Проверка должна быть явной:

```csharp
public bool CanEquip(ItemDefinition item, ItemSlot slot)
{
    return item.Slot == slot && item.Level <= OwnerLevel;
}
```

При надевании предмета нужно:

1. проверить слот и требования;
2. снять текущий предмет;
3. надеть новый;
4. пересчитать производные статы;
5. опубликовать событие для UI.

Если пересчитывать статы «когда-нибудь потом», интерфейс покажет старые числа,
а урон посчитается по новым. Пересчёт должен быть синхронным с изменением
экипировки.

## Сериализация

Сохранять нужно **экземпляр**, а не определение целиком. Достаточно:

```json
{
  "definitionId": "sword_iron",
  "durability": 37,
  "level": 3,
  "modifiers": [
    { "stat": "damage", "kind": "flat", "value": 4 }
  ]
}
```

Что не стоит сохранять:

- ссылки на объекты сцены и материалы;
- вычисленные производные статы;
- локализованные названия;
- временные идентификаторы UI.

При загрузке определение находится по `definitionId`. Если его нет — предмет
пропал из контента. Нужна политика: заменить на «сломанный предмет», выдать
компенсацию или удалить с записью в лог. Молчаливое падение — худший вариант.

## Частые ошибки

- **Один объект на все мечи.** Изменение прочности affects весь тип.
- **Дублирование статов в определении и экземпляре.** Непонятно, какое
  значение главное.
- **Проценты применяются в разном порядке.** Баланс «плывёт» от порядка слотов.
- **Нет проверки слота.** Кольцо надевается в шлем.
- **Сохранение ссылается на ассет.** После переименования предмет исчезает.
- **Редкость влияет только на цвет.** Игрок быстро понимает, что разницы нет.
