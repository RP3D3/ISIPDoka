# HTTP, сети и REST API: план области

Область учит понимать путь запроса, проектировать REST API и проверять его
от браузера до сервера.

## Группы

### 10. Основы сетей

Клиент и сервер, IP и порты, DNS, TCP и UDP, прокси и NAT, localhost,
диагностика сети.

Итог: практика — проследить путь запроса.

### 20. HTTP: запрос и ответ

Структура запроса, методы, статус-коды, заголовки, URL и параметры,
Content-Type, кэширование, HTTP/2, HTTP/3, WebSocket и SSE.

Итог: практика — разобрать запрос.

### 30. HTTPS и TLS

Зачем HTTPS, TLS и сертификаты, handshake, HSTS, secure cookies, mixed
content, ошибки TLS.

Итог: практика — проверить HTTPS.

### 40. REST и контракт API

Ресурсы и URL, методы и идемпотентность, статус-коды API, формат ошибок,
пагинация, версионирование, OpenAPI.

Итог: практика — спроектировать API.

### 50. Auth, CORS и лимиты

Сессии и cookies, API keys, JWT, OAuth2 и OIDC, scopes и роли, CORS,
rate limiting.

Итог: практика — защитить API.

### 60. Клиент API и фронтенд

fetch и axios, обработка ошибок, таймауты и retry, отмена запросов,
cookies и credentials, загрузка файлов.

Итог: практика — подключить фронтенд к API.

### 70. Тестирование и отладка API

curl, Postman и Insomnia, DevTools Network, контрактные тесты, моки,
граничные случаи.

Итог: практика — протестировать API.

### 80. Практика: API и сеть

Требования и сценарии, контракт и эндпоинты, реализация и проверка,
итог области и практика по задаче.

## Правила

- 2 квиза на тему: radio (3 варианта, 1 правильный) и checkbox
  (4 варианта, 2–3 правильных).
- В каждой теме есть раздел «Частые ошибки».
- Итог группы называется так же, как группа.
- Практика начинается со слова «Практика».
- Картинки — авторские SVG-схемы, без внешних хотлинков.
- Ссылки только на существующие темы области.
- Примеры запросов — короткие и проверяемые.
- Сеть объясняется через путь реального запроса.
- REST — через контракт, а не через модные слова.
- Безопасность рассматривается как часть обычной работы.

## Главный принцип

**Клиент → DNS → TCP/TLS → HTTP → API → база → ответ → проверка.**
