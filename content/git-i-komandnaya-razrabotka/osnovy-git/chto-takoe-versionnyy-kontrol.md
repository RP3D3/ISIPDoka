# Что такое версионный контроль

Версионный контроль — это способ хранить историю изменений проекта и
возвращаться к любому сохранённому состоянию. Без него команда рискует
потерять работу, затереть чужие правки и тратить часы на выяснение
«кто и что сломал».

## Зачем это нужно

- видеть, кто и когда изменил файл;
- сравнивать версии;
- откатывать ошибки;
- работать над одной задачей паралельно;
- собирать релизы из проверенных изменений.

## Типы систем

- **Локальная** — история хранится только на одном компьютере.
- **Централизованная** — есть один сервер, без которого нельзя работать.
- **Распределённая** — у каждого участника есть полная копия истории.

Git — распределённая система. Локально можно делать коммиты, смотреть
историю и создавать ветки без интернета. Сервер нужен для обмена
изменениями, а не для каждого действия.

## Git не равен «сохранению»

Коммит — это снимок выбранных изменений с автором, датой и сообщением.
Он не делает резервную копию всех файлов на диске и не заменяет бэкап.
Если файл не добавлен в индекс, он не попадёт в коммит.

## Что даёт история

История полезна не только для отката. По ней можно понять:

- почему появилось решение;
- какая задача была в работе;
- где сломалось поведение;
- какие изменения связаны между собой.

Поэтому сообщение коммита — часть документации, а не формальность.

## Частые ошибки

- **«Git — это бэкап».** Бэкап хранит копии, Git — историю изменений.
- **«Можно коммитить всё подряд».** В коммит попадают лишние файлы,
  ключи и мусор.
- **«История не нужна, главное — код».** Без истории сложно понять причину
  ошибки и безопасно откатить изменение.
- **«Git нужен только в команде».** Даже в одиночку он помогает вести
  проект и эксперименты.
