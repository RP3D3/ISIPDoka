# Git и командная разработка: план области

Область учит не набору команд, а полному циклу работы с версиями в команде:
от первого репозитория до code review, релизов, CI/CD и разбора инцидентов.

## Группы

### 10. Основы Git

Зачем нужен версионный контроль, чем Git отличается от GitHub и GitLab,
установка и настройка, рабочая копия, индекс, первый коммит, состояния файлов,
`.gitignore`.

Итог: практика — первый репозиторий.

### 20. Ежедневная работа

`status`, `diff`, `log`, `add`, `commit`, `amend`, `restore`, `reset`, `revert`,
`clean`, `stash`. Главная идея: отменять изменения безопасно и понимать, что
именно отменяется.

Итог: практика — отмена изменений.

### 30. Ветки и слияния

Ветка как указатель, `branch` и `switch`, fast-forward, three-way merge,
конфликты, rebase vs merge, интерактивный rebase, cherry-pick.

Итог: практика — ветки и конфликт.

### 40. Удалённая работа и code review

`remote`, `clone`, `fetch`, `pull`, `push`, tracking branches, fork и upstream,
синхронизация форка, pull request, code review, защита веток.

Итог: практика — PR в команде.

### 50. Командные процессы

GitHub Flow, trunk-based development, Git Flow, feature branches, commit
messages, issues и задачи, Definition of Done, этикет code review.

Итог: практика — командный спринт.

### 60. Качество и безопасность репозитория

README, CONTRIBUTING, LICENSE, шаблоны issue и PR, секреты и `.env`, права
доступа, подписанные коммиты, обновление зависимостей.

Итог: практика — аудит репозитория.

### 70. Релизы и CI/CD

Теги, SemVer, changelog, hotfix, rollback, CI/CD, GitHub Actions, pipeline
lint/test/build, secrets в CI.

Итог: практика — CI и релиз.

### 80. Расследование и восстановление

`reflog`, `bisect`, `worktree`, hooks, submodules, Git LFS.

Итог: практика — найти баг через bisect.

### 85. Частые ошибки и их решения

Коммит не в ту ветку, потерянные коммиты, конфликты, `push rejected`,
detached HEAD, секреты в истории, ошибки rebase, потерянные изменения,
командные ошибки.

Итог: практика — разбор инцидентов.

### 90. Итог: командная разработка

Сводка по всей области и практика: командный проект с нуля.

## Правила

- 2 квиза на тему: radio (3 варианта, 1 правильный) и checkbox (4 варианта,
  2–3 правильных).
- В каждой теме есть раздел «Частые ошибки»: что случилось, почему и как
  исправить.
- Итог группы называется так же, как группа.
- Практика начинается со слова «Практика».
- Картинки — авторские SVG-схемы, без внешних хотлинков.
- Ссылки только на существующие темы области.
- Команды Git даются в Unix-подобном виде; для Windows отдельно отмечаем
  особенности, если они важны.
- GitHub Actions используется как основной пример CI, но concepts переносимы
  на GitLab CI и другие системы.
