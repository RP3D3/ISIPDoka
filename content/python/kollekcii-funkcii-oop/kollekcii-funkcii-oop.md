# Коллекции, функции и ООП

Главная идея группы: данные и поведение можно организовать так, чтобы код
был понятным и заменяемым.

## Что запомнить

- компрехеншены хороши для простых преобразований;
- генераторы экономят память;
- функции можно передавать как значения;
- класс объединяет данные и поведение;
- наследование — не всегда лучший выбор;
- dataclass уменьшает шаблонный код;
- Protocol задаёт контракт без наследования.

## Чек-лист

- [ ] Я не пишу слишком сложные компрехеншены.
- [ ] Я понимаю, когда генератор истощается.
- [ ] Я использую `sorted(key=...)`.
- [ ] Я не делаю глубокую иерархию классов.
- [ ] Я знаю, зачем нужен dataclass.

## Частые ошибки

- **Наследовать ради переиспользования.**
- **Использовать изменяемые значения по умолчанию.**
- **Писать сложные lambda.**
- **Путать dataclass и ORM.**
