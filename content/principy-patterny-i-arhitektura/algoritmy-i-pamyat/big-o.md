# Сложность алгоритмов: нотация Big O

Почему программа, которая мгновенно работает на десяти записях, зависает на миллионе и как заранее оценить рост времени выполнения кода?

**Big O** («О-большое») — это способ оценить, как быстро растёт время работы алгоритма или расход памяти при увеличении объёма входных данных (`n`). Скорость кода нельзя измерять в секундах, потому что на мощном компьютере программа выполнится быстрее, чем на слабом. Нотация Big O считает не секунды, а количество элементарных операций в **худшем случае**, позволяя объективно сравнить эффективность разных алгоритмов.

### Сравнение популярных оценок сложности

| Обозначение | Название | Как меняется скорость при росте данных | Пример из кода |
| --- | --- | --- | --- |
| `O(1)` | Константная | Время не зависит от количества элементов — всегда один шаг | Обращение к элементу массива по индексу (`arr[5]`) |
| `O(log n)` | Логарифмическая | При удвоении объёма данных добавляется всего один лишний шаг | Бинарный поиск в заранее отсортированном списке |
| `O(n)` | Линейная | Во сколько раз больше данных, во столько раз дольше работа | Обычный перебор списка в одном цикле `for` или `foreach` |
| `O(n^2)` | Квадратичная | При увеличении данных в 10 раз время вырастает в 100 раз | Вложенные циклы (например, поиск дубликатов полным перебором) |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        int[] numbers = { 12, 45, 7, 23, 45, 89 };

        // 1. O(1) — константная сложность: мгновенный доступ независимо от длины массива
        int first = numbers[0];
        Console.WriteLine($"Первый элемент (O(1)): {first}");

        // 2. O(n) — линейная сложность: один проход по массиву (до n шагов)
        Console.WriteLine($"Число 23 найдено (O(n)): {ContainsValue(numbers, 23)}");

        // 3. O(n^2) — квадратичная сложность: вложенный цикл (n * n шагов — медленно на больших данных)
        Console.WriteLine($"Есть дубликаты (O(n^2)): {HasDuplicatesSlow(numbers)}");
    }

    static bool ContainsValue(int[] array, int target)
    {
        for (int i = 0; i < array.Length; i++)
        {
            if (array[i] == target) return true;
        }
        return false;
    }

    static bool HasDuplicatesSlow(int[] array)
    {
        for (int i = 0; i < array.Length; i++)
        {
            for (int j = i + 1; j < array.Length; j++)
            {
                if (array[i] == array[j]) return true;
            }
        }
        return false;
    }
}

```

### Важные нюансы

* **Отбрасывание констант и младших членов:** в Big O не пишут `O(2n + 5)` — все постоянные множители и мелкие слагаемые отбрасывают, оставляя только самый быстрорастущий элемент (`O(n)`). Два последовательных цикла по `n` элементов всё равно дают `O(n)`, а вот цикл внутри цикла даёт `O(n^2)`.
* **Ориентация на худший случай:** даже если нужный элемент при линейном поиске может оказаться самым первым за один шаг, сложность алгоритма всё равно записывают как `O(n)` — по самому неблагоприятному сценарию, когда элемент стоит в самом конце или вообще отсутствует.
* **Сложность по памяти (*Space Complexity*):** нотация Big O оценивает не только время работы, но и объём дополнительной оперативной памяти. Часто программу можно ускорить с `O(n^2)` до `O(n)`, если потратить `O(n)` памяти на вспомогательную коллекцию (например, словарь или множество).
* **Практическая реализация:** правильный выбор встроенной коллекции напрямую определяет скорость поиска и вставки элементов в программе (см. раздел языка: *Массивы и списки* и *Словари и множества*).
