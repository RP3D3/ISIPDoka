# Память программы: стек и куча

Как программа распределяет данные между быстрым стеком и вместительной кучей, почему копирование объектов работает по-разному и как сборщик мусора очищает память?

Во время работы программа использует две основные области оперативной памяти: **стек** (*Stack*) и **кучу** (*Heap*). **Стек** работает по принципу стопки тарелок («последним пришёл — первым ушёл»): он мгновенно выделяет и очищает память для вызовов методов и простых типов значений. **Куча** — это общее пространство для сложных объектов и массивов, где данные живут до тех пор, пока на них есть ссылки, а за их уборку отвечает специальный механизм — **сборщик мусора** (*Garbage Collector*).

### Сравнение стека и кучи

| Критерий | Стек (*Stack*) | Куча (*Heap*) |
| --- | --- | --- |
| **Что хранится** | Локальные переменные простых типов (`int`, `double`, `bool`), структуры и ссылки на объекты | Сами экземпляры классов, строки, массивы и коллекции |
| **Скорость работы** | Очень высокая: память выделяется и освобождается простым сдвигом указателя | Ниже, чем у стека: требуется поиск свободного места и отслеживание ссылок |
| **Очистка памяти** | Автоматически и мгновенно при выходе из метода или блока кода | Периодически выполняется сборщиком мусора (*Garbage Collector*) |
| **Размер и ограничения** | Небольшой фиксированный объём (обычно 1–4 МБ на поток) | Ограничен только объёмом свободной оперативной памяти компьютера |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. СТЕК (типы значений): переменная хранит само число прямо в стеке
        int a = 10;
        int b = a; // Копируется само значение (создаётся независимая копия)
        b = 99;
        Console.WriteLine($"Стек: a = {a}, b = {b}"); // a осталось 10

        // 2. КУЧА (ссылочные типы): объект создаётся в куче, а в стеке лежит только адрес (ссылка)
        Box firstBox = new Box { Weight = 5 };
        Box secondBox = firstBox; // Копируется только ссылка — обе переменные смотрят на один объект
        secondBox.Weight = 20;
        Console.WriteLine($"Куча: вес через firstBox = {firstBox.Weight} кг"); // Выведет 20 кг

        // 3. СБОРКА МУСОРА: если обнулить все ссылки, объект в куче станет недоступным
        // и сборщик мусора (Garbage Collector) позже освободит занятую им память
        firstBox = null;
        secondBox = null;
    }
}

class Box
{
    public int Weight;
}

```

### Важные нюансы

* **Как работает сборщик мусора (*Garbage Collector*):** он периодически проверяет объекты в куче, начиная с «корней» (активных переменных в стеке и статических полей). Все объекты, до которых нельзя добраться ни по одной цепочке ссылок, считаются мусором и удаляются, а оставшиеся уплотняются в памяти.
* **Переполнение стека (*StackOverflowException*):** так как размер стека строго ограничен, бесконечная рекурсия (когда метод вызывает сам себя без условия выхода) или создание огромных структур быстро забивает весь стек и аварийно завершает программу.
* **Утечки памяти возможны даже со сборщиком мусора:** если программа продолжает хранить ссылку на ненужный объект в глобальном списке или забыла отписаться от события, сборщик мусора считает объект «живым» и никогда его не удалит.
* **Практическая реализация:** разделение данных на хранимые по значению и по ссылке напрямую определяет поведение переменных при передаче в методы (см. раздел языка: *Типы значений и ссылочные типы* и *Передача параметров по значению и по ссылке*).
