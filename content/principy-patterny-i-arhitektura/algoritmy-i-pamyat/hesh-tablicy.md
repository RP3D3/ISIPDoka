# Хеш-таблицы: как работает мгновенный поиск

Как программа находит нужную запись среди миллионов элементов за один шаг без перебора и почему изменение ключа после добавления ломает поиск?

**Хеш-таблица** (*Hash Table*) — это структура данных, которая лежит в основе словарей (*Dictionary*) и множеств (*HashSet*) и обеспечивает поиск, добавление и удаление элементов в среднем за `O(1)`. Вместо последовательного просмотра всех записей хеш-таблица пропускает ключ через специальную **хеш-функцию**, превращает его в число (хеш-код) и сразу вычисляет номер ячейки (корзины) в памяти, где лежат нужные данные.

### Сравнение поиска перебором и хеш-таблицы

| Критерий | Линейный поиск (массив или список) | Хеш-таблица (словарь или множество) |
| --- | --- | --- |
| **Скорость поиска** | `O(n)` — чем больше записей, тем дольше перебор с начала | `O(1)` — мгновенный переход в нужную ячейку по вычисленному адресу |
| **Требования к ключу** | Ключи могут быть любыми и меняться в любой момент | Ключ должен быть неизменяемым и уметь выдавать стабильный хеш-код |
| **Расход памяти** | Минимальный — элементы лежат вплотную друг к другу | Повышенный — требуется запас пустых ячеек для снижения числа совпадений |
| **Порядок элементов** | Строго сохраняется порядок добавления и доступ по индексу | Элементы распределяются по ячейкам в зависимости от хеша, а не по порядку |

### Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // 1. Как работает хеш-функция: любая строка превращается в числовой код
        string key = "Admin";
        Console.WriteLine($"Хеш-код строки \"{key}\": {key.GetHashCode()}");

        // 2. HashSet (множество) использует хеш-таблицу для мгновенной проверки уникальности за O(1)
        HashSet<string> bannedUsers = new HashSet<string> { "Bot_01", "Spammer99", "Hacker" };
        Console.WriteLine($"Заблокирован ли Spammer99: {bannedUsers.Contains("Spammer99")}");

        // 3. ОПАСНОСТЬ ИЗМЕНЯЕМЫХ КЛЮЧЕЙ: если поменять поле ключа после добавления,
        // таблица будет искать его по новому хешу в другой корзине и не найдёт
        UserKey user = new UserKey { Id = 101 };
        Dictionary<UserKey, string> roles = new Dictionary<UserKey, string>();
        roles[user] = "Модератор";

        user.Id = 999; // Изменили поле, от которого зависит GetHashCode()!
        Console.WriteLine($"Найден ли пользователь после смены Id: {roles.ContainsKey(user)}"); // False!
    }
}

class UserKey
{
    public int Id;
    public override int GetHashCode() => Id.GetHashCode();
    public override bool Equals(object obj) => obj is UserKey other && Id == other.Id;
}

```

### Важные нюансы

* **Что такое коллизия и как она решается:** разные ключи иногда дают одинаковый хеш-код и попадают в одну и ту же корзину (ячейку) — такая ситуация называется **коллизией**. Чтобы данные не перезаписали друг друга, внутри одной корзины элементы связываются в короткую цепочку и при поиске дополнительно сравниваются через метод `Equals`.
* **Правило согласованности `GetHashCode` и `Equals`:** если два объекта считаются равными через `Equals`, их хеш-коды обязаны совпадать. Обратное необязательно: у разных объектов могут случайно совпасть хеш-коды из-за коллизии.
* **Не используйте изменяемые объекты как ключи:** ключами в словаре и элементами множества должны быть неизменяемые типы (`string`, `int`, `Guid` или классы с полями `readonly`). Если изменить состояние ключа после добавления, его новый хеш укажет на пустую ячейку и объект «потеряется» в памяти.
* **Практическая реализация:** встроенные коллекции на базе хеш-таблиц применяются для быстрого поиска по ключу, подсчёта дубликатов и проверки уникальности (см. раздел языка: *Словари и множества*).
