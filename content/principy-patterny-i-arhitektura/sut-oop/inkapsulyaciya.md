# Инкапсуляция: защита внутреннего состояния

Как запретить внешнему коду ломать внутренние данные объекта и разрешить менять их только по безопасным правилам?

**Инкапсуляция** — это принцип проектирования, который объединяет данные и методы работы с ними внутри одного объекта, скрывая внутреннее устройство от прямого вмешательства извне. Внешний код не может напрямую перезаписать критически важные поля (например, сделать баланс счёта отрицательным), а взаимодействует с объектом только через строго контролируемые действия.

### Сравнение подходов

| Критерий | Открытые данные (без инкапсуляции) | Защищённое состояние (инкапсуляция) |
| --- | --- | --- |
| **Изменение данных** | Любой участок кода может записать некорректное значение напрямую | Данные меняются только через методы и свойства с проверкой правил |
| **Целостность объекта** | Легко нарушить логику (отрицательный остаток, некорректная дата) | Объект сам гарантирует корректность своего состояния в любой момент |
| **Зависимость от деталей** | Внешний код завязан на внутренние поля — их нельзя безопасно менять | Внутреннее устройство можно переписать без поломки остальной программы |
| **Поиск ошибок** | Приходится искать по всему проекту, кто именно испортил значение | Вся проверка сосредоточена в одном месте — внутри самого объекта |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // ❌ ПЛОХО: поле открыто напрямую — можно записать бессмысленный отрицательный баланс
        OpenAccount brokenAccount = new OpenAccount();
        brokenAccount.Balance = -5000;
        Console.WriteLine($"Открытый счёт (ошибка логики): {brokenAccount.Balance} руб.");

        // ✅ ХОРОШО: состояние скрыто, изменение возможно только через проверенные операции
        SafeAccount safeAccount = new SafeAccount(1000);
        safeAccount.Withdraw(5000); // Попытка снять больше остатка будет заблокирована
        safeAccount.Deposit(500);
        Console.WriteLine($"Защищённый счёт: {safeAccount.Balance} руб.");
    }
}

class OpenAccount
{
    public decimal Balance; // Любой код может записать сюда любое число
}

class SafeAccount
{
    private decimal _balance; // Скрытое внутреннее состояние

    // Чтение разрешено всем, но изменить поле напрямую извне нельзя
    public decimal Balance => _balance;

    public SafeAccount(decimal initialBalance)
    {
        if (initialBalance >= 0) _balance = initialBalance;
    }

    public void Deposit(decimal amount)
    {
        if (amount > 0) _balance += amount;
    }

    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance)
        {
            Console.WriteLine("Операция отклонена: недостаточно средств или неверная сумма.");
            return false;
        }

        _balance -= amount;
        return true;
    }
}

```

### Важные нюансы

* **Инкапсуляция — это защита правил, а не просто «скрыть поля»:** если сделать поле закрытым, но открыть к нему доступ на запись без всяких проверок, защита остаётся формальной — в объект по-прежнему можно записать некорректные данные.
* **Соблюдение инвариантов:** инвариант — это условие, которое всегда должно оставаться истинным для объекта (например, «заряд батареи от 0 до 100%» или «баланс не меньше нуля»). Инкапсуляция не даёт нарушить эти границы.
* **Упрощение работы с объектом:** внешнему коду не нужно помнить, какие три внутренних поля обновить при покупке товара — достаточно вызвать одно действие (например, `Buy()`), которое согласованно изменит состояние само.
* **Практическая реализация:** в коде инкапсуляция реализуется с помощью модификаторов доступа (`private`, `public`) и свойств (см. раздел языка: *Модификаторы доступа и свойства*).
