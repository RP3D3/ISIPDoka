# Паттерны проектирования: готовые архитектурные решения

Как не изобретать велосипед при решении типовых задач архитектуры и общаться с другими разработчиками на одном понятном языке?

**Паттерн проектирования** (шаблон проектирования) — это проверенная временем типовая схема организации кода для решения часто встречающейся архитектурной задачи. Паттерн — не готовая библиотека и не кусок кода для копирования, а общий чертёж, который показывает, как распределить роли между классами и связать их так, чтобы система оставалась гибкой и понятной.

### Три категории паттернов проектирования

| Категория | Главная задача | Популярные примеры |
| --- | --- | --- |
| **Порождающие** (Creational) | Управляют гибким созданием объектов, скрывая сложную логику их сборки | Одиночка (Singleton), Фабрика (Factory), Строитель (Builder) |
| **Структурные** (Structural) | Помогают удобно объединять классы и объекты в более крупные структуры | Адаптер (Adapter), Фасад (Facade), Декоратор (Decorator) |
| **Поведенческие** (Behavioral) | Определяют правила взаимодействия и распределения обязанностей между объектами | Стратегия (Strategy), Наблюдатель (Observer), Команда (Command) |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // ❌ ПЛОХО: вызывающий код вынужден сам управлять всеми внутренними шагами системы
        StockService stock = new StockService();
        PaymentService payment = new PaymentService();
        DeliveryService delivery = new DeliveryService();

        stock.Reserve("Книга");
        payment.Pay(1200);
        delivery.Ship("Книга");

        // ✅ ХОРОШО: применён структурный паттерн (Фасад) — сложная работа спрятана за одним простым действием
        OrderFacade orderShop = new OrderFacade();
        orderShop.BuyProduct("Книга", 1200);
    }
}

class StockService
{
    public void Reserve(string item) => Console.WriteLine($"Товар «{item}» зарезервирован на складе.");
}

class PaymentService
{
    public void Pay(decimal amount) => Console.WriteLine($"Оплата {amount} руб. проведена.");
}

class DeliveryService
{
    public void Ship(string item) => Console.WriteLine($"Товар «{item}» передан в доставку.");
}

// Типовой шаблон организации взаимодействия: объединяет сложные шаги в единую точку входа
class OrderFacade
{
    private readonly StockService _stock = new StockService();
    private readonly PaymentService _payment = new PaymentService();
    private readonly DeliveryService _delivery = new DeliveryService();

    public void BuyProduct(string item, decimal price)
    {
        _stock.Reserve(item);
        _payment.Pay(price);
        _delivery.Ship(item);
    }
}

```

### Важные нюансы

* **Паттерн — это идея, а не код для копипасты:** один и тот же шаблон выглядит по-разному в зависимости от задачи и языка программирования. Важно понимать суть связей между объектами, а не заучивать названия классов наизусть.
* **Защита от «болезни паттернов»:** попытка втиснуть сложные шаблоны в простую программу ради самой архитектуры нарушает принципы *KISS* и *YAGNI*. Паттерн применяют только тогда, когда в коде реально появилась проблема гибкости или запутанности.
* **Единый словарь команды:** главное преимущество паттернов — скорость общения. Фраза «давай здесь сделаем Наблюдатель» заменяет долгие объяснения о том, как организовать подписку на события.
* **Практическая связь:** большинство паттернов проектирования являются практическим воплощением принципов *SOLID*, *композиции* и *слабой связанности* (см. раздел принципов: *Принцип открытости и закрытости* и *Наследование против композиции*).
