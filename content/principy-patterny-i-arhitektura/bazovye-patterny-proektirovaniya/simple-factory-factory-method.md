# Паттерн Фабрика: вынос создания объектов

Как убрать громоздкие проверки выбора и создания объектов через `new` из основного кода и легко добавлять новые типы продуктов?

**Фабрика** (*Factory*) — это порождающий паттерн проектирования, который выносит логику выбора и создания объектов из основного кода в отдельное место. Вместо того чтобы разбрасывать оператор `new` и цепочки `if-else` по всей программе, основной код просто запрашивает готовый объект через общий интерфейс, не зная, какой именно класс был создан под капотом. На практике чаще всего используют два варианта: **Простую фабрику** (*Simple Factory*) и **Фабричный метод** (*Factory Method*).

### Сравнение вариантов Фабрики

| Критерий | Простая фабрика (*Simple Factory*) | Фабричный метод (*Factory Method*) |
| --- | --- | --- |
| **Как устроена** | Отдельный класс с одним методом, который по параметру решает, какой объект создать | Базовый класс задаёт метод создания, а дочерние классы сами решают, какой объект вернуть |
| **Добавление нового типа** | Приходится дописывать новую ветку в метод самой фабрики | Создаётся новый класс-наследник фабрики без правки старого кода (соблюдается OCP) |
| **Сложность кода** | Максимально простая и компактная, подходит для небольшого числа вариантов | Требует больше классов и интерфейсов, но даёт полную гибкость при росте системы |
| **Когда выбирать** | Когда типов объектов немного и логика их создания редко меняется | Когда заранее неизвестно, какие именно типы объектов появятся в будущем |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. Простая фабрика: выбор нужного класса спрятан в одном месте
        ITransport truck = SimpleTransportFactory.Create("truck");
        truck.Deliver();

        // 2. Фабричный метод: каждая фабрика сама знает, какой объект создать, без if-else
        Logistics seaLogistics = new SeaLogistics();
        seaLogistics.PlanDelivery();
    }
}

// Общий контракт для всех создаваемых объектов
interface ITransport
{
    void Deliver();
}

class Truck : ITransport
{
    public void Deliver() => Console.WriteLine("Доставка груза по дороге на грузовике.");
}

class Ship : ITransport
{
    public void Deliver() => Console.WriteLine("Доставка груза по морю на корабле.");
}

// Вариант 1: Простая фабрика (Simple Factory) — выносит switch/if из основного кода
class SimpleTransportFactory
{
    public static ITransport Create(string type)
    {
        if (type == "truck") return new Truck();
        if (type == "ship") return new Ship();
        throw new ArgumentException("Неизвестный тип транспорта");
    }
}

// Вариант 2: Фабричный метод (Factory Method) — делегирует создание наследникам
abstract class Logistics
{
    // Фабричный метод, который переопределяют конкретные фабрики
    public abstract ITransport CreateTransport();

    // Основная логика работает с общим интерфейсом и не зависит от конкретного класса
    public void PlanDelivery()
    {
        ITransport transport = CreateTransport();
        transport.Deliver();
    }
}

class SeaLogistics : Logistics
{
    public override ITransport CreateTransport() => new Ship();
}

```

### Важные нюансы

* **Связь с принципами SOLID:** фабрика напрямую поддерживает *принцип единственной ответственности (SRP)*, отделяя сборку объектов от их использования, и *принцип открытости и закрытости (OCP)* — особенно в варианте Фабричного метода, где новые типы добавляются без правки старого кода.
* **Работа через общий интерфейс:** чтобы фабрика приносила пользу, все создаваемые ею классы должны возвращаться под единым интерфейсом или базовым классом — иначе вызывающему коду всё равно придётся проверять конкретный тип объекта.
* **Не усложняйте раньше времени:** если в программе объект создаётся в одном месте и у него нет нескольких взаимозаменяемых вариантов, обычный вызов `new` проще и чище любой фабрики (помните о *KISS* и *YAGNI*).
* **Практическая реализация:** для построения фабрик используются интерфейсы, абстрактные классы и переопределение методов (см. раздел языка: *Интерфейсы* и *Абстрактные классы*).
