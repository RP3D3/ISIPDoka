# Паттерн Наблюдатель: подписка на события

Как автоматически оповещать десятки разных модулей об изменении состояния объекта, не связывая их жёстко друг с другом и не заставляя постоянно проверять обновления в цикле?

**Наблюдатель** (*Observer*) — это поведенческий паттерн проектирования, который создаёт механизм подписки: один объект (**издатель** или субъект) хранит список заинтересованных объектов (**подписчиков**) и автоматически рассылает им уведомления при любом важном изменении своего состояния. Издатель ничего не знает о внутреннем устройстве подписчиков и общается с ними через единый интерфейс.

### Сравнение подходов

| Критерий | Жёсткая привязка или постоянный опрос | Паттерн Наблюдатель (*Observer*) |
| --- | --- | --- |
| **Связь между объектами** | Издатель напрямую хранит ссылки на конкретные классы получателей | Издатель работает только со списком абстрактных подписчиков |
| **Добавление реакции** | Приходится лезть в код издателя и дописывать вызов нового модуля (нарушение OCP) | Новый класс просто подписывается на события без правки кода издателя |
| **Актуальность данных** | Подписчикам приходится в цикле постоянно спрашивать «не изменилось ли чего?» | Реакция происходит мгновенно в момент наступления события |
| **Гибкость в работе** | Набор получателей жёстко зашит на этапе написания кода | Объекты могут свободно подписываться и отписываться прямо во время работы программы |

### Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // ❌ ПЛОХО: магазин жёстко привязан к конкретным получателям уведомлений.
        // Чтобы добавить оповещение в мессенджер, придётся менять код самого магазина.
        StoreBad badStore = new StoreBad(new EmailClient(), new WarehouseLog());
        badStore.Restock("Видеокарта");

        // ✅ ХОРОШО (Observer): магазин работает со списком абстрактных подписчиков
        Store store = new Store();
        EmailClient emailClient = new EmailClient();
        WarehouseLog log = new WarehouseLog();

        store.Subscribe(emailClient);
        store.Subscribe(log);
        store.Restock("Видеокарта");

        // Любой модуль можно легко отписать во время работы программы
        store.Unsubscribe(emailClient);
        store.Restock("Процессор");
    }
}

// Нарушение: издатель знает обо всех конкретных получателях и вызывает их вручную
class StoreBad
{
    private readonly EmailClient _email;
    private readonly WarehouseLog _log;

    public StoreBad(EmailClient email, WarehouseLog log)
    {
        _email = email;
        _log = log;
    }

    public void Restock(string product)
    {
        Console.WriteLine($"[Магазин] Поступил товар: {product}");
        _email.Update(product);
        _log.Update(product);
    }
}

// Общий контракт для всех подписчиков (наблюдателей)
interface ISubscriber
{
    void Update(string product);
}

class EmailClient : ISubscriber
{
    public void Update(string product) =>
        Console.WriteLine($"[Email] Письмо клиенту: товар «{product}» снова в наличии!");
}

class WarehouseLog : ISubscriber
{
    public void Update(string product) =>
        Console.WriteLine($"[Журнал склада] Зафиксировано поступление: {product}");
}

// Издатель: хранит только список подписчиков и оповещает их при наступлении события
class Store
{
    private readonly List<ISubscriber> _subscribers = new List<ISubscriber>();

    public void Subscribe(ISubscriber subscriber) => _subscribers.Add(subscriber);
    public void Unsubscribe(ISubscriber subscriber) => _subscribers.Remove(subscriber);

    public void Restock(string product)
    {
        Console.WriteLine($"[Магазин] Поступил товар: {product}");
        foreach (ISubscriber subscriber in _subscribers)
        {
            subscriber.Update(product);
        }
    }
}

```

### Важные нюансы

* **Риск утечки памяти:** пока подписчик находится в списке издателя, издатель удерживает на него ссылку в памяти. Если объект-подписчик больше не нужен, но забыл вызвать `Unsubscribe`, сборщик мусора не сможет удалить его из памяти.
* **Независимость порядка оповещения:** издатель обходит список подписчиков по очереди, но архитектура не должна зависеть от того, кто получит уведомление первым, а кто вторым.
* **Модель «проталкивания» и «вытягивания»:** в простом варианте издатель сам передаёт нужные данные в аргументах метода `Update` (*Push*-модель), но в сложных системах подписчик может получать ссылку на самого издателя и забирать только нужные ему поля (*Pull*-модель).
* **Практическая реализация:** помимо ручного списка подписчиков и интерфейсов, во многих языках этот паттерн встроен в сам синтаксис через делегаты и события (см. раздел языка: *Интерфейсы* и *Делегаты и события*).
