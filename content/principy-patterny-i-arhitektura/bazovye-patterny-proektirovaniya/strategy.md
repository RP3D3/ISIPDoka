# Паттерн Стратегия: подмена алгоритма поведения

Как научить объект менять способ выполнения задачи прямо во время работы программы и избавиться от громоздких цепочек `if-else` при выборе алгоритма?

**Стратегия** (*Strategy*) — это поведенческий паттерн проектирования, который выносит набор похожих алгоритмов в отдельные взаимозаменяемые классы с общим интерфейсом. Основной класс (контекст) не реализует вычисления сам, а хранит ссылку на текущую стратегию и делегирует ей работу, позволяя легко переключать логику поведения «на лету».

### Сравнение подходов

| Критерий | Громоздкие условия (`if-else` / `switch`) | Паттерн Стратегия (*Strategy*) |
| --- | --- | --- |
| **Добавление алгоритма** | Приходится лезть в основной класс и дописывать новые ветки проверок | Создаётся новый класс-стратегия без изменения существующего кода (OCP) |
| **Смена поведения** | Жёстко зашита в логику метода через флаги и текстовые параметры | Алгоритм можно свободно подменить в любой момент через сеттер или метод |
| **Размер и читаемость** | Класс разрастается в огромный файл со смешанными формулами | Каждый алгоритм изолирован в компактном и понятном классе |
| **Повторное использование** | Логику расчёта трудно вытащить и применить в другом месте | Любую стратегию легко подключить к другим независимым объектам |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // ❌ ПЛОХО: все способы построения маршрута зашиты в один класс через if-else
        NavigatorBad oldNavigator = new NavigatorBad();
        oldNavigator.BuildRoute("Центр", "Вокзал", "Car");

        // ✅ ХОРОШО (Strategy): алгоритм передаётся извне и легко меняется прямо во время работы
        Navigator navigator = new Navigator(new CarRouteStrategy());
        navigator.BuildRoute("Центр", "Вокзал");

        // Подменяем стратегию поведения «на лету» без изменения класса Navigator
        navigator.SetStrategy(new WalkingRouteStrategy());
        navigator.BuildRoute("Центр", "Вокзал");
    }
}

// Нарушение: при добавлении маршрута на велосипеде придётся менять класс NavigatorBad
class NavigatorBad
{
    public void BuildRoute(string from, string to, string mode)
    {
        if (mode == "Car")
            Console.WriteLine($"[Авто] Маршрут по дорогам от «{from}» до «{to}» (15 мин).");
        else if (mode == "Walk")
            Console.WriteLine($"[Пешком] Маршрут по тротуарам от «{from}» до «{to}» (50 мин).");
    }
}

// Общий контракт для всех взаимозаменяемых алгоритмов
interface IRouteStrategy
{
    void Calculate(string from, string to);
}

class CarRouteStrategy : IRouteStrategy
{
    public void Calculate(string from, string to) =>
        Console.WriteLine($"[Авто] Маршрут по дорогам от «{from}» до «{to}» (15 мин).");
}

class WalkingRouteStrategy : IRouteStrategy
{
    public void Calculate(string from, string to) =>
        Console.WriteLine($"[Пешком] Маршрут по тротуарам от «{from}» до «{to}» (50 мин).");
}

// Контекст: хранит текущую стратегию и делегирует ей выполнение задачи
class Navigator
{
    private IRouteStrategy _strategy;

    public Navigator(IRouteStrategy strategy)
    {
        _strategy = strategy;
    }

    public void SetStrategy(IRouteStrategy strategy) => _strategy = strategy;

    public void BuildRoute(string from, string to) => _strategy.Calculate(from, to);
}

```

### Важные нюансы

* **Прямое воплощение композиции и OCP:** Стратегия заменяет наследование композицией — вместо создания подклассов `CarNavigator` и `WalkingNavigator` мы передаём нужный алгоритм внутрь одного навигатора, соблюдая *принцип открытости и закрытости (OCP)*.
* **Отличие от паттерна Состояние (State):** внешне оба паттерна похожи, но в *Стратегии* внешний код сам выбирает и подменяет нужный алгоритм (например, пользователь нажал кнопку «Пешком»), а в *Состоянии* объект меняет своё поведение автоматически при изменении внутренних условий.
* **Когда паттерн лишний:** если в задаче всего два простых варианта расчёта в пару строк, которые никогда не будут меняться и переключаться на лету, обычный `if-else` проще и понятнее (помните о *KISS* и *YAGNI*).
* **Практическая реализация:** для построения стратегий используются интерфейсы и передача объектов через конструктор или метод (см. раздел языка: *Интерфейсы* и раздел принципов: *Наследование против композиции*).
