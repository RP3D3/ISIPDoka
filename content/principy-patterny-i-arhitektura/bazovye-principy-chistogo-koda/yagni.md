# Принцип YAGNI: вам это не понадобится

Почему написание кода «на вырост» замедляет разработку и как перестать тратить время на функции, которые так и не пригодятся?

**YAGNI** (*You Aren't Gonna Need It* — «вам это не понадобится») — принцип разработки, который запрещает добавлять в программу функционал до тех пор, пока в нём не возникнет реальная, подтверждённая необходимость. Предсказать будущие требования почти невозможно: код, написанный «про запас», часто остаётся мёртвым грузом, но при этом усложняет проект и требует времени на тестирование и поддержку.

### Сравнение подходов

| Критерий | Разработка «на вырост» | Подход YAGNI |
| --- | --- | --- |
| **Объём работы** | Тратится время на гипотетические сценарии и запасные режимы | Реализуются только задачи, нужные прямо сейчас |
| **Сложность проекта** | Лишние параметры, проверки и ветвления засоряют код | Кодовая база остаётся компактной и прозрачной |
| **Цена будущих правок** | При изменении требований запасной код всё равно переписывают | Новые функции добавляются чисто, исходя из реальных фактов |
| **Скорость запуска** | Рабочий результат откладывается из-за «доделок на будущее» | Программа быстрее готова к проверке и использованию |

### Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Задача: просто вывести приветствие пользователя в консоль.

        // ❌ ПЛОХО: добавлены флаги, регистр и повторы «на вырост», хотя они нигде не нужны
        GreetUserOverengineered("Алексей", isUpperCase: false, repeatCount: 1, prefix: "");

        // ✅ ХОРОШО (YAGNI): метод решает ровно текущую задачу без лишних параметров
        GreetUser("Алексей");
    }

    // Лишние параметры усложняют вызов и требуют поддержки внутри метода
    static void GreetUserOverengineered(string name, bool isUpperCase, int repeatCount, string prefix)
    {
        string message = $"{prefix}Привет, {name}!";
        if (isUpperCase) message = message.ToUpper();

        for (int i = 0; i < repeatCount; i++)
        {
            Console.WriteLine(message);
        }
    }

    // Простая и достаточная реализация для сегодняшней задачи
    static void GreetUser(string name)
    {
        Console.WriteLine($"Привет, {name}!");
    }
}

```

### Важные нюансы

* **YAGNI — не оправдание для неряшливого кода:** отказ от лишних функций не означает, что нужно писать грязный код без разделения на методы и понятных имён. Код должен оставаться аккуратным, чтобы в будущем его было легко расширить.
* **Отличие от KISS и DRY:** DRY запрещает дублировать уже существующую логику, KISS требует делать текущее решение максимально простым, а YAGNI вообще не даёт писать то, что ещё не потребовалось.
* **Скрытая цена «бесплатного» кода:** любая лишняя строчка «на всякий случай» требует чтения, отладки и проверки при каждом обновлении программы, даже если её ни разу не вызвали.
* **Практическая реализация:** не добавляйте в методы лишние необязательные параметры, перегрузки и ветвления «про запас» (см. раздел языка: *Необязательные параметры и именованные аргументы*).
