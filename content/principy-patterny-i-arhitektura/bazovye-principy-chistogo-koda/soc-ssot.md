# Разделение ответственности и единый источник истины

Почему не стоит смешивать расчёты, хранение данных и вывод на экран в одном месте и как избежать противоречий в состоянии программы?

**SoC** (*Separation of Concerns* — разделение ответственности) — это принцип проектирования, который требует делить программу на независимые части, где каждая отвечает строго за свою задачу (например, отдельно — ввод данных, отдельно — вычисления, отдельно — вывод на экран). **SSOT** (*Single Source of Truth* — единый источник истины) дополняет его и требует, чтобы любая настройка, правило или факт хранились ровно в одном месте, откуда их берут все остальные модули.

### Сравнение принципов

| Принцип | Главная идея | Какую проблему решает | Как выглядит на практике |
| --- | --- | --- | --- |
| **SoC** (Разделение ответственности) | Разные по смыслу задачи выполняются в отдельных независимых блоках | «Каша» в коде, где нельзя изменить вывод на экран, не сломав формулу расчёта | Метод вычислений ничего не знает о консоли или окне и просто возвращает число |
| **SSOT** (Единый источник истины) | У каждого факта, правила или настройки есть только один главный владелец | Рассинхрон данных, когда в одном месте значение обновилось, а в копии осталось старым | Ставка налога задана одной константой, а итог вычисляется из исходных данных без дублей |

### Пример кода

```csharp
using System;

class Program
{
    // SSOT: единый источник для ставки налога во всей программе
    const double TaxRate = 0.20;

    static void Main()
    {
        double itemPrice = 1000;
        int quantity = 3;

        // ❌ ПЛОХО: расчёт и вывод смешаны (нарушение SoC), а итог записан в отдельную переменную,
        // которая легко устаревает при изменении исходных данных (нарушение SSOT)
        double totalCache = itemPrice * quantity * 1.20;
        quantity = 4; // Количество изменили, а totalCache остался старым!
        Console.WriteLine($"Старый итог с ошибкой: {totalCache}");

        // ✅ ХОРОШО: математика отделена от вывода (SoC), а итог считается из актуальных данных (SSOT)
        double actualTotal = CalculateTotal(itemPrice, quantity);
        PrintReceipt(itemPrice, quantity, actualTotal);
    }

    // Отвечает ТОЛЬКО за расчёт (не зависит от способа вывода результата)
    static double CalculateTotal(double price, int count)
    {
        double subtotal = price * count;
        return subtotal + (subtotal * TaxRate);
    }

    // Отвечает ТОЛЬКО за отображение информации пользователю
    static void PrintReceipt(double price, int count, double total)
    {
        Console.WriteLine($"Товар: {price} руб. x {count} шт. | Итого с налогом: {total} руб.");
    }
}

```

### Важные нюансы

* **Не храните вычисляемые значения как вторую «правду»:** если итоговую сумму можно в любой момент посчитать из цены и количества, не заводите для неё отдельную переменную-копию — при изменении исходных данных она неизбежно устареет.
* **Отделяйте логику от интерфейса:** методы расчётов должны принимать данные через параметры и возвращать ответ через `return`, а не вызывать `Console.ReadLine` или `Console.WriteLine` внутри себя — тогда ту же логику можно будет перенести из консоли на сайт или в приложение.
* **Связь с принципом DRY:** SSOT — это применение DRY к данным и настройкам: у каждой константы, формулы или состояния должен быть ровно один хозяин.
* **Практическая реализация:** распределяйте ввод, вычисления и вывод по разным подпрограммам и выносите общие правила в константы (см. раздел языка: *Возврат результата из метода* и *Область видимости переменных*).
