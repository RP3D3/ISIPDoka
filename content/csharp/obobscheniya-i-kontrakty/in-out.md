# Вариантность (in и out): совместимость обобщённых типов

Почему коллекцию наследников `IEnumerable<Dog>` можно передать туда, где ждут `IEnumerable<Animal>`, но со списком `List<Dog>` этот трюк запрещён компилятором?

Хотя класс `Dog` наследуется от `Animal`, по умолчанию обобщённые типы в C# **инвариантны**: это значит, что `List<Dog>` и `List<Animal>` для компилятора — два совершенно несовместимых типа. Сделано это для защиты памяти: если бы список собак можно было выдать за список животных, в него удалось бы добавить кошку. Чтобы безопасно разрешить преобразование обобщённых **интерфейсов и делегатов** в нужную сторону, используют модификаторы **ковариантности** (`out`) и **контравариантности** (`in`).

## Виды вариантности в C#

| Вид вариантности | Модификатор | Направление совместимости | Суть и условие работы |
| --- | --- | --- | --- |
| **Инвариантность** | *(отсутствует)* | Только точное совпадение (`List<Dog>`) | Тип `T` используется и на вход, и на выход (как в `List<T>`), поэтому подмена запрещена |
| **Ковариантность** | `out T` | От наследника к родителю<br>

<br>(`IEnumerable<Dog>` → `IEnumerable<Animal>`) | Интерфейс или делегат только **возвращает** `T` (поставщик данных), записывать в него нельзя |
| **Контравариантность** | `in T` | От родителя к наследнику<br>

<br>(`IProcessor<Animal>` → `IProcessor<Dog>`) | Интерфейс или делегат только **принимает** `T` (потребитель данных), ничего не возвращая |

## Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<Dog> dogs = new List<Dog> { new Dog("Рекс"), new Dog("Бим") };

        // 1. КОВАРИАНТНОСТЬ (out T): IEnumerable<out T> умеет только отдавать элементы
        // Безопасно передаём последовательность собак туда, где ожидаются любые животные
        IEnumerable<Animal> animals = dogs;
        PrintNames(animals);

        // 2. КОНТРАВАРИАНТНОСТЬ (in T): обработчик любого животного гарантированно справится с собакой
        IAnimalCare<Animal> generalVet = new GeneralVet();
        IAnimalCare<Dog> dogVet = generalVet;
        dogVet.Examine(dogs[0]);

        // ❌ Ошибка компиляции (CS0029): List<T> инвариантен — иначе в список собак можно было бы добавить кошку
        // List<Animal> brokenList = dogs;
    }

    static void PrintNames(IEnumerable<Animal> animals)
    {
        foreach (Animal animal in animals)
            Console.WriteLine($"Питомец: {animal.Name}");
    }
}

class Animal
{
    public string Name { get; }
    public Animal(string name) => Name = name;
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
}

// Контравариантный интерфейс: параметр T стоит только во входной позиции (in)
interface IAnimalCare<in T>
{
    void Examine(T patient);
}

class GeneralVet : IAnimalCare<Animal>
{
    public void Examine(Animal patient) =>
        Console.WriteLine($"Ветеринар осмотрел животное: {patient.Name}");
}

```

## Важные нюансы

* **Почему инвариантность спасает от поломки типов:** если бы компилятор разрешил присвоить `List<Animal> list = dogs;`, то следующая строка `list.Add(new Cat())` прошла бы проверку компилятора, но положила бы кошку в список собак. Модификатор `out` разрешается ставить только тогда, когда у интерфейса вообще нет методов, принимающих `T` на вход.
* **Работает только для интерфейсов, делегатов и ссылочных типов:** указывать `in` и `out` можно исключительно в объявлениях `interface` и `delegate` (для `class` и `struct` это запрещено). Кроме того, вариантность не работает с типами значений — например, `IEnumerable<int>` нельзя привести к `IEnumerable<object>`, так как для этого потребовалась бы упаковка (*boxing*) каждого элемента в куче.
* **Историческая ловушка обычных массивов:** в отличие от `List<T>`, встроенные массивы в C# сделаны ковариантными (`Animal[] arr = new Dog[2];`) для совместимости со старыми версиями языка. При попытке записать туда `arr[0] = new Cat()` компилятор промолчит, но программа аварийно упадёт во время выполнения с `ArrayTypeMismatchException`.
* **Связь с соседними темами:** вариантность напрямую развивает правила наследования и *принцип подстановки Лисков (LSP)*, а в следующей карточке подробно разберём устройство главного ковариантного интерфейса .NET — `IEnumerable<T>` и генератора последовательностей `yield return`.
