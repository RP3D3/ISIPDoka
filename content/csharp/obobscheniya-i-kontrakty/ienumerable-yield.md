# `IEnumerable<T>` и `yield`: итераторы и ленивые последовательности

Как цикл `foreach` перебирает любые коллекции под капотом и как генерировать элементы по одному по мере запроса, не загружая миллионы записей в оперативную память?

Интерфейс `IEnumerable<T>` — это главный контракт перечисления в .NET, который позволяет перебирать данные в цикле `foreach`. Он содержит всего один метод `GetEnumerator()`, возвращающий объект-курсор `IEnumerator<T>` с текущим элементом (`Current`) и методом шага вперёд (`MoveNext()`). Чтобы не писать сложные классы-курсоры вручную, в C# используют ключевое слово `yield return`: компилятор сам превращает такой метод в **конечный автомат** (*state machine*), который вычисляет и отдаёт значения **лениво** (*lazy evaluation*) — строго в тот момент, когда цикл запрашивает очередной элемент.

## Ключевые элементы механизма итерации

| Конструкция | Роль в переборе данных | Как работает |
| --- | --- | --- |
| `IEnumerable<T>` | Источник последовательности | Предоставляет метод `GetEnumerator()`, открывая доступ к циклу `foreach` и методам LINQ |
| `IEnumerator<T>` | Курсор (указатель на текущий элемент) | Хранит позицию, сдвигает её через `MoveNext()` и отдаёт значение через свойство `Current` |
| `yield return` | Ленивая выдача элемента | Возвращает очередное значение и ставит метод на паузу до следующего шага цикла |
| `yield break` | Досрочное завершение генерации | Останавливает выдачу элементов и завершает цикл `foreach` (аналог `break` для итератора) |

## Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // 1. Вызов метода с yield return НЕ запускает цикл внутри него — создаётся лишь генератор
        IEnumerable<string> stream = GenerateSensorData(1_000_000);
        Console.WriteLine("Генератор создан, но ни одно измерение ещё не вычислено.\n");

        // 2. Элементы вычисляются по одному (лениво) по мере запроса циклом foreach
        foreach (string record in stream)
        {
            Console.WriteLine($"Получено: {record}");

            // Прерываем цикл на 3-м элементе — остальные 999 997 значений даже не будут созданы
            if (record.Contains("#3"))
                break;
        }

        Console.WriteLine("\nКак foreach работает под капотом:");
        // 3. Любой цикл foreach компилятор разворачивает в работу с IEnumerator<T>
        using IEnumerator<string> enumerator = GenerateSensorData(2).GetEnumerator();
        while (enumerator.MoveNext())
        {
            Console.WriteLine($"Шаг курсора: {enumerator.Current}");
        }
    }

    // Метод-итератор: компилятор превратит его в конечный автомат (state machine)
    static IEnumerable<string> GenerateSensorData(int totalCount)
    {
        for (int i = 1; i <= totalCount; i++)
        {
            if (i > 5)
                yield break; // Досрочно завершаем последовательность

            Console.WriteLine($"  [Генератор вычисляет запись #{i}...]");
            yield return $"Датчик А — пакет #{i}";
        }
    }
}

```

## Важные нюансы

* **Отложенное выполнение и повторный перебор:** код внутри метода с `yield return` не выполняется в момент его вызова — запуск происходит только при начале цикла `foreach`. Если пройтись по такой последовательности `IEnumerable<T>` дважды, генератор выполнит все вычисления с нуля второй раз; чтобы сохранить результат в памяти, используйте `.ToList()` или `.ToArray()`.
* **Ловушка проверки аргументов (`ArgumentNullException`):** из-за отложенного запуска любая проверка входных параметров в начале метода с `yield return` сработает не сразу при вызове, а лишь когда дойдёт очередь до `foreach`. На практике проверку аргументов выносят в обычный метод-обёртку, а саму генерацию через `yield` прячут в локальную функцию.
* **Утиная типизация цикла `foreach`:** компилятор разрешает использовать в `foreach` даже собственный тип без реализации `IEnumerable<T>`, если у него просто есть публичный метод `GetEnumerator()`, возвращающий объект с `MoveNext()` и `Current` (именно так работают быстрые перечислители структур в стандартных коллекциях без упаковки).
* **Связь с соседними темами:** интерфейс `IEnumerator<T>` наследует контракт `IDisposable` для автоматического освобождения ресурсов в конце цикла `foreach` (см. карточку *IDisposable и using*), а ленивые последовательности `IEnumerable<T>` являются главным фундаментом для всей библиотеки запросов *LINQ*.
