# Обобщения (Generics): универсальные типы

Как написать один класс или метод для работы с любыми типами данных, не дублируя код и не теряя проверку типов при компиляции?

**Обобщения** (*Generics*) позволяют создавать классы, структуры, интерфейсы и методы с **параметром типа** в угловых скобках — например, `OperationResult<T>` или `Swap<T>()`. Вместо того чтобы писать отдельные версии одного и того же контейнера для `int`, `string` и `User` или прятать всё в универсальный тип `object`, программист оставляет «заполнитель» `T`, а конкретный тип подставляется в момент использования. Компилятор строго проверяет совместимость типов ещё до запуска программы и избавляет от лишнего приведения и упаковки (*boxing*) значимых типов в куче.

## Сравнение подходов к универсальному коду

| Критерий | Дублирование под каждый тип | Через базовый тип `object` | Обобщения (`<T>`) |
| --- | --- | --- | --- |
| **Объём кода** | Приходится копировать класс под каждый тип (`IntBox`, `StringBox`) | Один общий класс, но много ручных проверок | Один компактный шаблон под все типы сразу |
| **Безопасность типов** | Высокая, проверяется на этапе компиляции | Низкая — неверный тип уронит программу (`InvalidCastException`) | Высокая — компилятор сразу запретит подставить чужой тип |
| **Производительность** | Максимальная, без лишних накладных расходов | Низкая для `int` и `struct` из-за упаковки (*boxing*) в куче | Максимальная — среда выполнения работает без упаковки |
| **Удобство использования** | Без лишних преобразований | Приходится постоянно делать явный каст `(int)box.Data` | Сразу возвращает готовый тип `T` и подсказки в редакторе |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. Один обобщённый класс обслуживает разные типы без приведения (cast)
        OperationResult<int> ageResult = OperationResult<int>.Success(25);
        OperationResult<string> loginResult = OperationResult<string>.Success("roman_dev");

        // Компилятор точно знает тип Data: для ageResult это int, для loginResult — string
        int nextYearAge = ageResult.Data + 1;
        Console.WriteLine($"Возраст через год: {nextYearAge}, логин: {loginResult.Data.ToUpper()}");

        // 2. Обобщённый метод: компилятор сам выводит тип <string> из переданных аргументов
        string first = "Первый", second = "Второй";
        Swap(ref first, ref second);
        Console.WriteLine($"После обмена: {first}, {second}");

        // ❌ Ошибка компиляции (CS0029): нельзя передать string туда, где ожидается int
        // OperationResult<int> broken = OperationResult<int>.Success("ошибка");
    }

    // Обобщённый метод: меняет местами две переменные любого одинакового типа T
    static void Swap<T>(ref T left, ref T right)
    {
        T temp = left;
        left = right;
        right = temp;
    }
}

// Обобщённый класс с параметром типа <T>
class OperationResult<T>
{
    public bool IsOk { get; }
    public T Data { get; }

    private OperationResult(bool isOk, T data)
    {
        IsOk = isOk;
        Data = data;
    }

    public static OperationResult<T> Success(T data) => new OperationResult<T>(true, data);
}

```

## Важные нюансы

* **Соглашение об именовании параметров типа:** если параметр один, его принято называть одной заглавной буквой `T` (*Type*); если параметров несколько, им дают осмысленные имена с префиксом `T` — например, `Dictionary<TKey, TValue>` или `Converter<TInput, TOutput>`.
* **Как JIT-компилятор экономит память и время:** для каждого значимого типа (`OperationResult<int>`, `OperationResult<double>`) среда выполнения генерирует отдельный нативный код, поэтому числа и структуры хранятся напрямую без упаковки (*boxing*) в куче. Для всех ссылочных типов (`OperationResult<string>`, `OperationResult<User>`) создаётся единый машинный код, так как все ссылки в памяти имеют одинаковый размер.
* **Автоматический вывод типов (*Type Inference*):** при вызове обобщённого метода вроде `Swap(ref first, ref second)` писать `<string>` вручную не требуется — компилятор сам определяет `T` по типам аргументов. Явно указывать `<T>` нужно только тогда, когда тип нельзя вывести из входных параметров (например, `JsonSerializer.Deserialize<User>(json)`).
* **Связь с теорией и соседними темами:** обобщения напрямую воплощают принцип *DRY* (не повторяйся), лежат в основе знакомых контейнеров `List<T>` и `Dictionary<TKey, TValue>` и избавляют от ловушек упаковки из карточек *class против struct* и *Базовый класс object*. В следующей карточке разберём, как задать требования к типу `T` через ограничения `where`.
