# Ограничения where: контроль над параметром T

Как разрешить обобщённому классу или методу вызывать свойства и конструкторы параметра `T`, запретив подставлять неподходящие типы?

По умолчанию компилятор ничего не знает о том, какой именно тип подставят вместо параметра `T`, поэтому внутри обобщённого кода у переменной `T` доступны только базовые методы класса `object` (`ToString()`, `Equals()`, `GetHashCode()`). Чтобы получить доступ к конкретным свойствам, методам или конструктору типа `T`, на него накладывают **ограничения** с помощью ключевого слова `where`. Они работают как фильтр на этапе компиляции: пропускают только подходящие типы и сразу открывают их возможности внутри шаблона.

## Основные виды ограничений в C#

| Ограничение | Синтаксис | Что гарантирует и разрешает внутри кода |
| --- | --- | --- |
| **Ссылочный тип** | `where T : class` | Разрешает только классы, интерфейсы и делегаты; позволяет присваивать `null` |
| **Тип значений** | `where T : struct` | Разрешает только не-Nullable структуры и `enum`; гарантирует отсутствие `null` |
| **Конструктор без параметров** | `where T : new()` | Позволяет создавать новые экземпляры прямо внутри кода через `new T()` |
| **Базовый класс или интерфейс** | `where T : IEntity` | Гарантирует реализацию контракта и открывает доступ ко всем его методам и свойствам |
| **Запрет на `null`** | `where T : notnull` | Запрещает передавать Nullable-типы (`string?`, `int?`); часто нужно для ключей словарей |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // User подходит под все ограничения: это class, реализует IEntity и имеет пустой конструктор
        Repository<User> userRepo = new Repository<User>();
        User created = userRepo.CreateWithId(101);
        created.Name = "Роман";

        User[] users = { created };
        User? found = userRepo.FindById(users, 101);
        Console.WriteLine($"Найден пользователь: {found?.Name} (ID: {found?.Id})");

        // ❌ Ошибка компиляции (CS0311): класс Guest не реализует интерфейс IEntity
        // Repository<Guest> guestRepo = new Repository<Guest>();
    }
}

interface IEntity
{
    int Id { get; set; }
}

class User : IEntity
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
}

class Guest
{
    public string Nickname { get; set; } = string.Empty;
}

// Комбинируем три ограничения: T обязан быть ссылочным типом, реализовывать IEntity и иметь new()
class Repository<T> where T : class, IEntity, new()
{
    public T CreateWithId(int id)
    {
        // Благодаря ограничению new() мы можем создать объект неизвестного заранее типа T
        T entity = new T();
        // Благодаря ограничению IEntity компилятор разрешает обратиться к свойству Id
        entity.Id = id;
        return entity;
    }

    public T? FindById(T[] items, int id)
    {
        foreach (T item in items)
        {
            if (item.Id == id)
                return item;
        }
        // default вернёт null, так как T ограничен как ссылочный тип (class)
        return default;
    }
}

```

## Важные нюансы

* **Строгий порядок при комбинировании ограничений:** если на один параметр `T` накладывается несколько правил через запятую, первым всегда идёт основное ограничение (`class`, `struct` или базовый класс), затем перечисляются интерфейсы, а ограничение `new()` обязано стоять **строго последним**. Если параметров типа несколько, для каждого пишут свой блок `where` подряд (`where TKey : notnull where TValue : class`).
* **Значение по умолчанию `default`:** когда нужно вернуть «пустой» результат для неизвестного типа `T` без жёсткой привязки к `class` или `struct`, используют выражение `default(T)` (или просто `default`). Для ссылочных типов оно автоматически превратится в `null`, а для числовых и структур — в ноль и пустые поля.
* **Почему нельзя написать `a + b` для обычного `T`:** базовые ограничения `class` или `struct` не сообщают компилятору, поддерживает ли тип арифметические операции. Для универсальной математики в современном .NET используют ограничение числовыми интерфейсами из пространства `System.Numerics` (например, `where T : INumber<T>`).
* **Связь с теорией и соседними темами:** ограничения через интерфейсы напрямую развивают идею контрактов из карточки *Интерфейсы (interface)*, а в следующей карточке разберём, как модификаторы `in` и `out` управляют совместимостью обобщённых интерфейсов при наследовании (*Вариантность: `in` и `out*`).
