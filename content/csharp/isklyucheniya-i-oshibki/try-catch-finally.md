# `try / catch / finally`: обработка исключений

Как перехватить ошибку во время работы программы, не дать приложению аварийно закрыться и гарантированно выполнить завершающие действия?

Даже идеально скомпилированная программа может столкнуться с проблемами во время выполнения: пользователь ввёл буквы вместо числа, файл оказался удалён или пропала сеть. В таких ситуациях среда выполнения .NET создаёт объект **исключения** (*exception*) и начинает аварийно сворачивать цепочку вызовов методов (*stack unwinding*), пока не найдёт обработчик или не завершит программу. Конструкция `try / catch / finally` позволяет взять этот процесс под контроль: опасный код помещают в блок `try`, реакцию на конкретные сбои описывают в `catch`, а обязательную очистку выносят в `finally`.

## Роль каждого блока в конструкции

| Блок | Обязательность | Назначение и поведение |
| --- | --- | --- |
| `try` | Обязательный (строго 1) | Оборачивает участок кода, в котором потенциально может произойти исключение |
| `catch (SpecificException ex)` | Необязательный (0 или несколько) | Перехватывает конкретный тип ошибки и открывает доступ к её описанию через `ex` |
| `catch` *(без параметров)* | Необязательный (в конце) | Перехватывает любое исключение, когда сам объект ошибки не нужен |
| `finally` | Необязательный (0 или 1) | Выполняется **всегда** после `try` и `catch` — независимо от наличия ошибки или `return` |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        Console.Write("Введите количество участников: ");
        string? input = Console.ReadLine();

        try
        {
            // Опасные операции: преобразование строки и деление
            int count = int.Parse(input ?? string.Empty);
            int share = 1000 / count;

            Console.WriteLine($"Каждому достанется по {share} бонусов.");
        }
        catch (FormatException)
        {
            // Сработает, если пользователь ввёл текст вместо цифр
            Console.WriteLine("Ошибка ввода: нужно ввести целое число.");
        }
        catch (DivideByZeroException)
        {
            // Сработает, если пользователь ввёл 0
            Console.WriteLine("Ошибка расчёта: количество участников не может быть нулём.");
        }
        catch (Exception ex)
        {
            // Общий перехватчик для любых других непредвиденных исключений (например, OverflowException)
            Console.WriteLine($"Непредвиденный сбой ({ex.GetType().Name}): {ex.Message}");
        }
        finally
        {
            // Выполнится в любом случае — и при успехе, и после любого блока catch
            Console.WriteLine("Операция расчёта завершена.");
        }

        // ❌ Ошибка компиляции (CS0160): общий catch (Exception) нельзя ставить выше частных
        // try { } catch (Exception) { } catch (FormatException) { }
    }
}

```

## Важные нюансы

* **Строгий порядок блоков `catch` от частного к общему:** при возникновении ошибки среда выполнения проверяет блоки `catch` сверху вниз и заходит в первый подходящий по типу. Поэтому узкие исключения (`FormatException`, `DivideByZeroException`) всегда ставят первыми, а базовый `Exception` — строго последним, иначе компилятор выдаст ошибку `CS0160`.
* **Никогда не «проглатывайте» ошибки пустым `catch { }`:** пустой блок перехвата скрывает проблему, оставляя программу работать с некорректными данными. Если ошибка ожидаема при пользовательском вводе, лучше заранее проверять данные через `int.TryParse` без выброса исключений, а в `catch` хотя бы записывать сообщение в лог.
* **Блок `finally` срабатывает даже при наличии `return`:** если внутри `try` или `catch` встретился оператор `return`, среда выполнения сначала выполнит код в `finally` и только потом выйдет из метода (писать сам `return` внутри `finally` компилятор запрещает — ошибка `CS0157`).
* **Связь с теорией и соседними темами:** для гарантированного закрытия файлов и соединений вместо ручного блока `finally` применяют синтаксис `using` (см. карточку *IDisposable и using*), а в следующей карточке разберём, как самостоятельно генерировать исключения и правильно пробрасывать их выше через `throw` (*Оператор throw и проброс ошибок*).
