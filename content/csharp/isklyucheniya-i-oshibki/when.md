# Фильтры when: условный перехват исключений

Как перехватить ошибку только при выполнении конкретного условия — например, по коду ответа сервера — или записать её в лог, вообще не прерывая раскрутку стека?

К любому блоку `catch` можно добавить **фильтр исключений** с помощью ключевого слова `when (условие)`. Если выброшенная ошибка совпала по типу, среда выполнения сначала проверяет выражение в `when`: блок `catch` сработает только тогда, когда условие вернёт `true`. Если же условие вернёт `false`, поиск подходящего обработчика продолжится дальше, а состояние стека вызовов останется нетронутым — как будто этого блока `catch` вообще не существовало.

## Сценарии использования фильтров `when`

| Сценарий | Синтаксис | Как работает |
| --- | --- | --- |
| **Фильтрация по свойствам ошибки** | `catch (ApiException ex) when (ex.StatusCode == 429)` | Перехватывает только ошибку с кодом `429`, пропуская все остальные коды дальше |
| **Несколько веток для одного типа** | Несколько `catch (ApiException ex) when (...)` подряд | Позволяет разделить обработку одного и того же класса исключения по разным условиям |
| **Логирование без перехвата** | `catch (Exception ex) when (LogError(ex))` | Метод `LogError` записывает сбой и возвращает `false` — ошибка летит дальше без раскрутки стека |
| **Учёт внешнего контекста** | `catch (IOException) when (retryCount < 3)` | Разрешает перехватить сбой и повторить попытку только пока не исчерпан лимит |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Пример 1: перехват разных кодов одного и того же исключения ApiException
        for (int code = 429; code <= 430; code++)
        {
            try
            {
                SendRequest(code);
            }
            catch (ApiException ex) when (ex.StatusCode == 429)
            {
                Console.WriteLine($"[Повтор]: сервер перегружен (код {ex.StatusCode}), ждём 1 сек.");
            }
            catch (ApiException ex) when (ex.StatusCode >= 400 && ex.StatusCode < 500)
            {
                Console.WriteLine($"[Клиентская ошибка {ex.StatusCode}]: {ex.Message}");
            }
        }

        Console.WriteLine();

        // Пример 2: сквозное логирование без перехвата (фильтр возвращает false)
        try
        {
            try
            {
                SendRequest(503);
            }
            catch (Exception ex) when (LogWithoutCatching(ex))
            {
                // Сюда управление никогда не попадёт, так как LogWithoutCatching возвращает false
            }
        }
        catch (ApiException ex)
        {
            Console.WriteLine($"[Внешний обработчик]: поймана ошибка {ex.StatusCode} — {ex.Message}");
        }

        // ❌ Ошибка компиляции (CS0160): общий catch нельзя ставить перед таким же catch с фильтром when
        // try { } catch (ApiException) { } catch (ApiException ex) when (ex.StatusCode == 429) { }
    }

    static void SendRequest(int simulatedStatusCode)
    {
        throw new ApiException(simulatedStatusCode, "Сервер отклонил запрос");
    }

    // Метод-шпион: фиксирует сбой в логе, но возвращает false, чтобы не прерывать полёт ошибки
    static bool LogWithoutCatching(Exception ex)
    {
        Console.WriteLine($"[Аудит-лог без раскрутки стека]: {ex.GetType().Name} -> {ex.Message}");
        return false;
    }
}

class ApiException : Exception
{
    public int StatusCode { get; }

    public ApiException(int statusCode, string message) : base(message)
    {
        StatusCode = statusCode;
    }
}

```

## Важные нюансы

* **Главное отличие от `if (...) throw;` внутри `catch`:** если поймать исключение обычным `catch` и внутри через `if` сделать `throw;`, среда выполнения всё равно сначала раскрутит стек до этого блока (выполнив все промежуточные блоки `finally`). Фильтр `when` вычисляется *до* раскрутки стека: если он вернёт `false`, все локальные переменные в точке падения останутся нетронутыми для отладчика и аварийных дампов памяти.
* **Несколько обработчиков для одного класса исключений:** без `when` компилятор запрещает писать два блока `catch (IOException)` подряд. С фильтрами `when` можно сколько угодно раз перехватывать один и тот же тип исключения с разными условиями, завершая цепочку общим `catch (IOException)` для всех остальных случаев.
* **Порядок блоков и ошибка `CS0160`:** блок `catch` с фильтром `when` считается более узким, чем такой же `catch` без фильтра. Если поставить обычный `catch (ApiException)` выше `catch (ApiException ex) when (...)`, компилятор выдаст ошибку `CS0160`, так как до условного блока управление никогда не дойдёт.
* **Связь с теорией и следующей темой:** приём с `when (Log(ex))` дополняет правила сохранения `StackTrace` из карточки *Оператор throw*, а в следующей карточке разберём встроенную иерархию исключений .NET и научимся выбирать правильный тип под каждую ситуацию (*Стандартные исключения .NET*).
