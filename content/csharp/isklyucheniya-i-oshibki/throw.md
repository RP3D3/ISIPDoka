# Оператор throw: генерация и проброс ошибок

Как самостоятельно прервать выполнение метода при некорректных данных и правильно передать перехваченную ошибку выше по стеку, не потеряв место её возникновения?

Оператор `throw` позволяет вручную сгенерировать объект исключения, если метод получил недопустимые аргументы или оказался в нерабочем состоянии. Кроме создания новых ошибок (`throw new ...`), этот оператор используют внутри блока `catch`, чтобы выполнить промежуточные действия (например, записать сбой в лог) и передать исключение дальше вызывающему коду. При этом критически важно различать пустой `throw;` и `throw ex;`: первый сохраняет исходную историю вызовов (`StackTrace`), а второй затирает её, маскируя реальный источник сбоя.

## Способы использования оператора `throw`

| Конструкция | Назначение | Как влияет на трассировку стека (`StackTrace`) |
| --- | --- | --- |
| `throw new Exception(...)` | Выброс нового исключения | Записывает текущую строку как точку возникновения новой ошибки |
| `throw;` *(без аргументов)* | Повторный проброс (*rethrow*) внутри `catch` | **Сохраняет** оригинальный стек вызовов и точную строку реальной поломки |
| `throw ex;` *(антипаттерн)* | Проброс переменной исключения | **Затирает** исходный стек — отладчик покажет, что ошибка возникла в самом `catch` |
| `x ?? throw new ...` | `throw`-выражение *(C# 7+)* | Позволяет компактно выбрасывать ошибку прямо в выражениях `??`, `?:` и `=>` |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        try
        {
            PaymentService service = new PaymentService();
            service.ProcessOrder("ORD-404", -500m);
        }
        catch (Exception ex)
        {
            Console.WriteLine($"Верхний уровень поймал: {ex.GetType().Name} — {ex.Message}");
            if (ex.InnerException != null)
            {
                Console.WriteLine($"Первопричина (InnerException): {ex.InnerException.Message}");
            }
        }

        // ❌ Ошибка компиляции (CS0156): пустой оператор throw; разрешён только внутри блока catch
        // throw;
    }
}

class PaymentService
{
    public void ProcessOrder(string orderId, decimal amount)
    {
        // 1. throw-выражение (C# 7+): краткая проверка ссылки на null
        string validId = orderId ?? throw new ArgumentNullException(nameof(orderId));

        try
        {
            ChargeCard(validId, amount);
        }
        catch (ArgumentOutOfRangeException ex)
        {
            Console.WriteLine("[Лог сервиса]: зафиксирована попытка списания некорректной суммы.");

            // ✅ ПРАВИЛЬНО: пустой throw; отправляет ошибку выше, сохраняя реальную строку сбоя в ChargeCard
            // throw;

            // ❌ ПЛОХО: throw ex; перезаписал бы StackTrace, скрыв метод ChargeCard
            // throw ex;

            // 2. Оборачивание (Wrapping): заменяем техническую ошибку на бизнес-исключение,
            // но передаём исходный ex вторым аргументом, чтобы сохранить его в InnerException
            throw new InvalidOperationException($"Не удалось провести платёж по заказу {validId}.", ex);
        }
    }

    private void ChargeCard(string orderId, decimal amount)
    {
        if (amount <= 0)
        {
            // 3. Генерация нового исключения при нарушении бизнес-правила
            throw new ArgumentOutOfRangeException(nameof(amount), "Сумма списания должна быть больше нуля.");
        }
    }
}

```

## Важные нюансы

* **Почему `throw ex;` — опасный антипаттерн:** при выполнении `throw ex;` среда .NET заново формирует свойство `StackTrace` начиная с текущей строки. В результате при разборе логов вы увидите только блок `catch`, но никогда не узнаете, в каком вложенном методе и на какой строке реально произошёл сбой. Для повторного проброса используйте исключительно `throw;`.
* **Сохранение первопричины через `InnerException`:** если низкоуровневая ошибка (например, сбой парсинга или сети) заменяется на более понятное исключение верхнего уровня, всегда передавайте пойманный объект `ex` в конструктор нового исключения (`new InvalidOperationException("...", ex)`). Свойство `InnerException` сохранит полную цепочку сбоев от первопричины до внешнего обработчика.
* **Выражения `throw` (*Throw Expressions*):** начиная с C# 7, `throw` можно встраивать прямо в выражения инициализации и стрелочные методы — например, `Name = name ?? throw new ArgumentNullException(nameof(name));`. Это избавляет от громоздких конструкций `if (name == null)` в конструкторах и свойствах.
* **Связь с теорией и следующей темой:** подробнее о том, как читать цепочку вызовов при сбое, разберём в карточке *StackTrace и отладка*, а в следующей карточке изучим условный перехват ошибок без раскрутки стека — *Фильтры `when` в блоках catch*.
