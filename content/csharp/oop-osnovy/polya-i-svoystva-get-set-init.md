# Поля и свойства (get, set, init)

Как защитить здоровье персонажа от случайного ухода в минус или разрешить задать имя игрока только один раз при создании?

:::gap

## Кратко

Поля (*fields*) — это обычные переменные внутри класса, которые напрямую хранят его данные. Свойства (*properties*) — это умные обёртки над полями с блоками `get` (чтение) и `set` (запись), позволяющие проверять корректность данных при изменении, скрывать внутреннее устройство класса или запрещать перезапись. Модификатор `init` — особый вариант записи, который разрешает задать значение только в момент создания объекта (`new { ... }`), а затем навсегда закрывает его от правок.

:::gap

## Быстрый пример

Объявим в классе приватное поле, автосвойство, свойство с `init` и свойство с проверкой границ при записи:

```cs
Hero hero = new() { Name = "Кира", Level = 5 };
// hero.Name = "Алекс"; // Ошибка: init запрещает менять имя после создания

hero.Hp = 150; // Сработает проверка в set и обрежет значение до 100
Console.WriteLine($"{hero.Name} (ур. {hero.Level}): {hero.Hp} HP"); // Кира (ур. 5): 100 HP

class Hero
{
    private int _hp = 100; // Приватное поле для внутреннего хранения

    public string Name { get; init; } = "Безымянный"; // Задаётся только при создании
    public int Level { get; set; } = 1;                // Автосвойство (чтение и запись)

    // Полное свойство с валидацией при записи
    public int Hp
    {
        get => _hp;
        set => _hp = Math.Clamp(value, 0, 100);
    }
}

```

:::gap

## Как это работает

При выполнении кода среда .NET разделяет внутреннее хранилище данных и контролируемый доступ к ним:

1. **Приватное поле (`private int _hp`).** Поле хранит само число внутри объекта. По соглашению C# приватные поля называют с нижнего подчёркивания и маленькой буквы (`_camelCase`). Снаружи класса напрямую обратиться к `_hp` нельзя.
2. **Автосвойство (`public int Level { get; set; }`).** Когда дополнительная проверка не нужна, создавать поле вручную не обязательно — компилятор сгенерирует его сам за кулисами. Публичные свойства всегда именуют с заглавной буквы (`PascalCase`).
3. **Запись при инициализации (`{ get; init; }`).** Аксессор `init` разрешает записать имя `"Кира"` внутри фигурных скобок сразу после `new()`, но как только объект создан, свойство начинает работать в режиме «только для чтения».
4. **Проверка при записи (`set`) и слово `value`.** Когда снаружи выполняется присваивание `hero.Hp = 150`, запускается блок `set`. Внутри него неявный параметр `value` содержит переданное число (`150`). Метод `Math.Clamp` ограничивает его диапазоном от `0` до `100`, и в поле `_hp` попадает уже безопасное значение `100`.

> [!TIP]
> Никогда не делайте поля класса `public` (кроме констант `const`). Всегда открывайте данные наружу через автосвойства `{ get; set; }`: даже если сейчас проверка не нужна, вы сможете добавить её позже, не сломав остальной код проекта.

:::gap

## Грабли и частые ошибки

### 1. Бесконечная рекурсия при обращении к свойству внутри самого себя

* **Так упадёт:** написать внутри блока `set` обращение к самому свойству с заглавной буквы: `public int Hp { get => Hp; set => Hp = value; }`. При попытке прочитать или записать `Hp` свойство начнёт бесконечно вызывать само себя и уронит программу с `StackOverflowException`.
* **Так правильно:** внутри `get` и `set` всегда обращаться к приватному полю с нижним подчёркиванием (`_hp`).

### 2. Попытка изменить `init`-свойство после создания объекта

* **Так не скомпилируется:** объявить `public string Name { get; init; }` и позже написать `hero.Name = "Макс";` — компилятор остановит сборку с ошибкой `CS8852`.
* **Так правильно:** передавать значения `init`-свойств только в инициализаторе `new Hero { Name = "Макс" }` или в конструкторе, а для изменяемых данных использовать `set` или `private set`.

### 3. Передача свойства в метод по ссылке (`ref` или `out`)

* **Так не скомпилируется:** написать `Heal(ref hero.Hp, 20);` (ошибка `CS0206`). Свойство — это не ячейка памяти, а пара скрытых методов, поэтому взять на него прямой адрес нельзя.
* **Так правильно:** сохранить значение свойства во временную переменную, передать её по `ref` и записать результат обратно в свойство.

### 4. Открытые публичные поля вместо свойств (`public int Hp;`)

* **Так сработает неправильно:** объявить поле публичным — любой внешний код сможет записать туда `-9999`, а при замене поля на свойство в будущем придётся перекомпилировать все зависимые библиотеки и переписывать места с `ref`/`out`.
* **Так правильно:** использовать автосвойства `public int Hp { get; set; }` с самого начала разработки.

:::gap

## Под капотом и нюансы

### Во что компилируются свойства (IL-код)

На уровне промежуточного языка IL никаких свойств не существует — это синтаксический сахар компилятора C#. Каждое свойство разворачивается в пару обычных методов с префиксами `get_` и `set_` (например, `get_Hp()` и `set_Hp(int value)`). Для автосвойства `Level` компилятор также автоматически создаёт скрытое приватное поле `<Level>k__BackingField`. Именно поэтому свойство нельзя передать через `ref` — за ним стоит вызов метода, а не адрес переменной.

### Разный уровень доступа (`private set`) и вычисляемые свойства

У блоков `get` и `set` можно задавать разную видимость. Самый популярный приём инкапсуляции — `{ get; private set; }`: читать свойство могут все, а менять его — только методы внутри самого класса. Кроме того, свойства могут вообще не хранить данные, а вычислять результат на лету через стрелку `=>`:

```cs
class Player
{
    public int Score { get; private set; } // Читать можно всем, менять — только внутри Player
    public bool IsWinner => Score >= 1000; // Вычисляемое свойство только для чтения

    public void AddPoints(int points) => Score += points;
}

```

### Шпаргалка по вариантам объявления свойств

| Запись свойства | Где можно читать | Где можно менять | Типичный сценарий |
| --- | --- | --- | --- |
| `{ get; set; }` | Везде | Везде | Обычные изменяемые настройки и данные |
| `{ get; private set; }` | Везде | Только внутри своего класса | Состояние, которым управляет сам объект (`Score`, `Hp`) |
| `{ get; init; }` | Везде | Только при создании (`new { ... }`) | Неизменяемые после создания данные (`Id`, `Name`) |
| `{ get; }` | Везде | Только в конструкторе или при объявлении | Постоянные параметры экземпляра |
| `=> выражение;` | Везде | Нигде (вычисляется заново) | Производные флаги и расчёты (`IsAlive`, `FullName`) |

### Обязательные свойства (`required`)

В современном C# (начиная с C# 11) вместе с `{ get; init; }` часто ставят модификатор `required`: `public required string Name { get; init; }`. Он заставляет компилятор проверять, что при создании объекта через `new Hero { ... }` программист не забыл заполнить это свойство, избавляя от необходимости писать громоздкие конструкторы с десятком параметров.
