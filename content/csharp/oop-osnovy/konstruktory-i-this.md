# Конструкторы и this

Как гарантировать, что новый объект сразу получит обязательные параметры при создании, и как разрешить конфликт имён между параметрами и полями класса?

:::gap

## Кратко

Конструктор — это специальный метод класса, который автоматически запускается при создании объекта через `new` и отвечает за его начальную настройку. Он всегда носит то же имя, что и сам класс, и не имеет возвращаемого типа. Ключевое слово `this` внутри класса ссылается на **текущий экземпляр** объекта: оно помогает отличить поле класса от параметра с таким же именем и позволяет одному конструктору вызывать другой через `: this(...)`.

:::gap

## Быстрый пример

Создадим класс `Player` с двумя перегруженными конструкторами и использованием `this`:

```cs
Player newbie = new("Алекс");         // Вызовет 1-й конструктор (здоровье станет 100)
Player boss = new("Дракон", 500);     // Вызовет 2-й конструктор напрямую

newbie.PrintInfo(); // Алекс: 100 HP
boss.PrintInfo();   // Дракон: 500 HP

class Player
{
    private string name;
    private int hp;

    // 1-й конструктор: передаёт работу во 2-й через цепочку : this(...)
    public Player(string name) : this(name, 100)
    {
    }

    // 2-й конструктор: основной, заполняет поля объекта
    public Player(string name, int hp)
    {
        this.name = name; // this.name — поле класса, name — параметр конструктора
        this.hp = Math.Max(1, hp);
    }

    public void PrintInfo() => Console.WriteLine($"{this.name}: {this.hp} HP");
}

```

:::gap

## Как это работает

При выполнении кода среда .NET связывает выделение памяти под объект с запуском нужного конструктора:

1. **Автоматический запуск при `new`.** Когда выполняется `new("Алекс")`, среда выделяет память под новый объект и сразу ищет конструктор, принимающий одну строку.
2. **Делегирование через `: this(name, 100)`.** Вместо того чтобы дублировать код проверки здоровья, первый конструктор передаёт управление второму конструктору того же класса с помощью двоеточия и `: this(...)`. Сначала отработает тело второго конструктора, а затем (если бы оно было) тело первого.
3. **Разрешение конфликта имён (`this.name = name`).** Параметр конструктора `name` перекрывает одноимённое поле класса. Слово `this` явно указывает компилятору: «возьми поле `name` текущего создаваемого объекта и запиши в него значение из параметра `name`».
4. **Обращение к себе (`this.hp`).** Внутри обычных методов класса `this` всегда указывает на тот конкретный экземпляр, у которого вызвали метод (`newbie` или `boss`). Если конфликта имён нет, писать `this.` необязательно — компилятор подставит его сам.

> [!TIP]
> Чтобы не писать `this.name = name` вручную, соблюдайте соглашение об именовании: называйте приватные поля с нижнего подчёркивания (`_name`), а параметры — с обычной буквы (`name`). Тогда имена не совпадут, и `this` понадобится только для цепочек конструкторов.

:::gap

## Грабли и частые ошибки

### 1. Исчезновение пустого конструктора после добавления своего

* **Так не скомпилируется:** объявить `public Player(string name)` и затем попытаться создать объект без параметров: `Player p = new();`. Пока в классе нет ни одного конструктора, компилятор создаёт пустой `Player()` сам, но стоит вам написать хотя бы один свой конструктор — автоматический пустой исчезает (ошибка `CS7036`).
* **Так правильно:** если создание пустого объекта всё же нужно, явно дописать `public Player() : this("Гость", 100) { }`.

### 2. Указание типа возврата (`void`) перед именем конструктора

* **Так не скомпилируется:** написать `public void Player(string name) { ... }`. Из-за слова `void` компилятор перестаёт считать это конструктором и воспринимает как обычный метод, а имя метода не может совпадать с именем класса (ошибка `CS0542`).
* **Так правильно:** никогда не писать ни `void`, ни какой-либо другой тип возврата перед именем конструктора — только модификатор доступа и имя класса (`public Player(...)`).

### 3. Попытка использовать `this` внутри статического метода

* **Так не скомпилируется:** обратиться к `this.name` внутри метода с модификатором `static` (ошибка `CS0026`). Статический метод принадлежит всему классу целиком, а не конкретному объекту, поэтому «текущего экземпляра» у него просто нет.
* **Так правильно:** использовать `this` только в обычных (экземплярных) конструкторах, свойствах и методах.

### 4. Зацикливание цепочки конструкторов `: this(...)`

* **Так не скомпилируется:** заставить первый конструктор вызывать второй через `: this("A")`, а второй — снова первый через `: this()`. Компилятор отследит бесконечный круг ещё при сборке и остановит её с ошибкой `CS0516`.
* **Так правильно:** выстраивать цепочку строго в одном направлении — от простых конструкторов с меньшим числом параметров к одному главному конструктору с полным набором данных.

:::gap

## Под капотом и нюансы

### Что происходит в памяти при вызове `new` (метод `.ctor`)

На уровне промежуточного языка IL конструктор превращается в обычный экземплярный метод со специальным именем `.ctor` (*constructor*) и возвращаемым типом `void`. Когда процессор выполняет инструкцию `newobj`, происходит два шага:

1. Сначала в управляемой куче выделяется блок памяти, и все поля объекта **принудительно зануляются** (`0` для чисел, `false` для `bool`, `null` для ссылок).
2. Затем в этот метод `.ctor` скрытым нулевым аргументом передаётся ссылка на только что выделенный кусок памяти — это и есть знакомое нам слово `this`.

### Первичные конструкторы (Primary Constructors, C# 12+)

Если классу нужно просто принять несколько параметров при создании и использовать их внутри методов или свойств, в современном C# параметры можно написать прямо в заголовке класса без отдельного блока конструктора:

```cs
class Weapon(string title, int damage)
{
    public string Title { get; } = title;
    public void Strike() => Console.WriteLine($"Удар оружием {title} на {damage} урона!");
}

```

### Шпаргалка по видам конструкторов и `this`

| Конструкция | Синтаксис | Когда срабатывает и зачем нужна |
| --- | --- | --- |
| Конструктор по умолчанию | `public Hero() { }` | Создаётся компилятором автоматически, если других конструкторов нет |
| Параметризованный | `public Hero(string name)` | Задаёт обязательные начальные данные при вызове `new Hero("Аня")` |
| Цепочка конструкторов | `public Hero() : this("Аня")` | Позволяет одному конструктору вызвать другой без дублирования кода |
| Первичный конструктор | `class Hero(string name)` | Компактная запись параметров прямо в объявлении класса (C# 12+) |
| Статический конструктор | `static Hero() { }` | Запускается **один раз** перед самым первым обращением к классу (без параметров и без `this`) |

### Передача текущего объекта в другой метод

Помимо разрешения конфликтов имён, `this` часто используют как обычную переменную, чтобы передать сам текущий объект в сторонний сервис, менеджер событий или список: `GameWorld.RegisterPlayer(this);`.
