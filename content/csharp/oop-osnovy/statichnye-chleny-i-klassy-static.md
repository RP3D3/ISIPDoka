# Статичные члены и классы (static)

Как вести общий счётчик всех созданных врагов в игре или вызывать готовые формулы вроде `Math.Sqrt()` без создания лишнего объекта через `new`?

:::gap

## Кратко

Модификатор `static` привязывает поле, свойство или метод не к конкретному объекту, а ко **всему классу целиком**. К таким членам обращаются напрямую по имени класса (`Enemy.TotalCount`), а их данные существуют в единственном экземпляре на всю программу. Если сам класс объявлен как `static class`, создавать его экземпляры через `new` вообще запрещено — такой класс служит удобным контейнером для набора вспомогательных функций и констант, как встроенные `Console` или `Math`.

:::gap

## Быстрый пример

Создадим обычный класс `Enemy` с общим счётчиком созданных врагов и полностью статичный класс `DamageMath` для расчёта урона:

```cs
// Обращаемся к статичным членам напрямую через имя класса (без new)
Enemy goblin = new("Гоблин");
Enemy orc = new("Орк");

Console.WriteLine($"Создано врагов: {Enemy.TotalCount}");             // Создано врагов: 2
Console.WriteLine($"Урон с критом: {DamageMath.CalculateCrit(40)}"); // Урон с критом: 80

class Enemy
{
    // Статичное свойство: одно общее на весь класс Enemy
    public static int TotalCount { get; private set; }

    // Обычное свойство: у каждого врага своё имя
    public string Name { get; }

    public Enemy(string name)
    {
        Name = name;
        TotalCount++; // Увеличиваем общий счётчик при каждом создании объекта
    }
}

// Статичный класс: нельзя создать через new, внутри только static-члены
static class DamageMath
{
    public static int CritMultiplier = 2;

    public static int CalculateCrit(int baseDamage) => baseDamage * CritMultiplier;
}

```

:::gap

## Как это работает

При выполнении кода среда .NET разделяет общие данные типа и личные данные каждого экземпляра:

1. **Общая память для `TotalCount`.** Свойство `TotalCount` помечено словом `static`, поэтому оно создаётся в памяти ровно один раз. Когда мы создаём `goblin` и `orc`, конструктор каждого из них увеличивает одно и то же общее число с `0` до `1`, а затем до `2`.
2. **Вызов по имени класса (`Enemy.TotalCount`).** Чтобы узнать количество врагов, нам не нужен конкретный объект — мы пишем имя самого класса и ставим точку.
3. **Утилитарный класс (`static class DamageMath`).** Поскольку формула критического удара зависит только от переданного аргумента `baseDamage` и не хранит состояние конкретного персонажа, весь класс помечен как `static`. Это экономит память и сразу подсказывает другим разработчикам, что класс является набором утилит.

> [!TIP]
> Объявляйте метод статичным, если он не читает и не меняет обычные (экземплярные) поля класса. Это делает код предсказуемым и избавляет от лишних выделений памяти под объекты.

:::gap

## Грабли и частые ошибки

### 1. Попытка обратиться к статичному члену через объект

* **Так не скомпилируется:** написать `Enemy goblin = new("Гоблин"); Console.WriteLine(goblin.TotalCount);`. В C# запрещено вызывать статичные поля, свойства и методы через переменную экземпляра — компилятор выдаст ошибку `CS0176`.
* **Так правильно:** всегда обращаться через имя класса: `Enemy.TotalCount`.

### 2. Обращение к обычным полям или `this` внутри `static`-метода

* **Так не скомпилируется:** написать внутри статичного метода `Console.WriteLine(Name);` или использовать `this.Name` (ошибки `CS0120` и `CS0026`). Статичный метод запускается без объекта, поэтому он не знает, у какого именно из тысячи врагов нужно взять имя.
* **Так правильно:** передавать нужный объект в статичный метод как параметр (`void PrintName(Enemy enemy)`) или убрать модификатор `static` у самого метода.

### 3. Попытка создать экземпляр `static class` или унаследоваться от него

* **Так не скомпилируется:** написать `var math = new DamageMath();` или `class SuperMath : DamageMath`. Статичные классы неявно являются запечатанными (`sealed`) и абстрактными на уровне среды выполнения, поэтому их нельзя ни инстанцировать (`CS0712`), ни наследовать (`CS0713`).
* **Так правильно:** использовать статичные классы только для чистых функций и констант, а если нужно наследование — убрать `static` у класса.

### 4. Хранение изменяемых данных пользователя в `static`-полях

* **Так сработает неправильно:** сохранить в `static string CurrentUserName` имя вошедшего пользователя в веб-приложении или многопоточной программе. Статичное поле одно на весь запущенный процесс, поэтому следующий пользователь перезапишет имя предыдущего, и все увидят чужие данные.
* **Так правильно:** хранить в `static` только неизменяемые настройки, константы и потокобезопасные кэши, а данные конкретных пользователей держать в обычных экземплярах классов.

:::gap

## Под капотом и нюансы

### Где живут статичные данные в памяти

Обычные объекты размещаются в управляемой куче (*Managed Heap*) и удаляются сборщиком мусора (*Garbage Collector*), как только на них исчезают ссылки. Статичные поля устроены иначе: среда CLR размещает их в специальной области памяти (**High-Frequency Heap**), привязанной к таблице методов самого типа (`MethodTable`). Эти данные выделяются при первом обращении к классу и **живут до самого завершения работы приложения**, никогда не очищаясь сборщиком мусора.

### Статический конструктор (`static ClassName()`)

У любого класса (как обычного, так и статичного) может быть один **статический конструктор**. У него нет модификатора доступа (`public`/`private`) и параметров:

```cs
static class AppConfig
{
    public static string StartedAt { get; }

    static AppConfig()
    {
        StartedAt = DateTime.Now.ToString("HH:mm:ss");
    }
}

```

Среда .NET гарантированно вызовет его ровно **один раз** перед самым первым обращением к любому члену класса, причём сделает это потокобезопасно.

### Сравнение обычных и статичных членов

| Критерий | Обычный (экземплярный) член | Статичный член (`static`) |
| --- | --- | --- |
| Кому принадлежит | Конкретному объекту (`goblin`, `orc`) | Всему классу целиком (`Enemy`) |
| Как вызывается | Через переменную: `goblin.Name` | Через имя типа: `Enemy.TotalCount` |
| Сколько копий в памяти | Своя копия у каждого объекта | Ровно одна копия на всю программу |
| Доступ к `this` | Есть | Нет (`this` не существует) |
| Сборка мусором (GC) | Удаляется вместе с объектом | Живёт до закрытия программы |

### Константы и методы расширения

* **Константы (`const`).** Любое поле с модификатором `const` (например, `public const int MaxLevel = 100;`) в C# **неявно является статичным** — писать `static const` нельзя, компилятор сам привязывает константу к типу.
* **Методы расширения (*Extension Methods*).** Если вы хотите добавить свой метод к существующему классу (например, `string.WordCount()`), такой метод обязательно объявляется как `static` внутри верхнеуровневого `static class` с ключевым словом `this` перед первым параметром.
