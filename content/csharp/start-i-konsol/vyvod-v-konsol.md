# Вывод в консоль

Как заставить программу показать результат вычислений, статус загрузки или подсказку пользователю прямо в окне терминала?

:::gap

## Кратко

Методы `Console.WriteLine` и `Console.Write` отправляют текст, числа и значения переменных в стандартный поток вывода (окно консоли или терминала). Главная разница между ними простая: `WriteLine` после печати переводит курсор на новую строку, а `Write` оставляет его на той же. Это основной способ увидеть, что происходит внутри консольного приложения, и быстро отладить логику без графического интерфейса.

:::gap

## Быстрый пример

Сравним оба метода и популярные способы подстановки данных в строку:

```cs
string player = "Алекс";
int hp = 85;

// Write печатает в одну строку без переноса
Console.Write("Игрок: ");
Console.Write(player); // Игрок: Алекс

// WriteLine переносит курсор на следующую строку после вывода
Console.WriteLine($" | Здоровье: {hp}%"); // Игрок: Алекс | Здоровье: 85%
Console.WriteLine(); // Пустая строка

// Форматирование с плейсхолдерами и спецификаторами
double price = 149.5;
Console.WriteLine("Итого: {0:F2} руб.", price); // Итого: 149,50 руб.

```

:::gap

## Как это работает

При выполнении кода среда .NET последовательно отправляет переданные данные в буфер терминала:

1. **Вывод без переноса (`Console.Write`).** Первые два вызова печатают сначала `"Игрок: "`, а затем значение переменной `player`. Поскольку перенос строки не добавляется, слова склеиваются в одну строку.
2. **Интерполяция и перенос строки (`Console.WriteLine`).** Символ `$` перед кавычками позволяет встраивать переменные прямо внутрь фигурных скобок `{hp}`. Метод `WriteLine` дописывает текст в текущую строку и в конце добавляет символ новой строки (`\r\n` в Windows или `\n` в Linux/macOS), переводя курсор вниз.
3. **Пустая строка.** Вызов `Console.WriteLine()` без аргументов ничего не печатает, а просто отправляет символ переноса строки — удобно для визуального разделения блоков текста.
4. **Составное форматирование (`{0:F2}`).** Вместо знака `$` можно использовать нумерованные заглушки `{0}`, `{1}` и передавать значения после запятой. Модификатор `:F2` заставляет число `149.5` вывестись строго с двумя знаками после точки (`149,50` в русской локали).

> [!TIP]
> В современном C# для подстановки переменных в текст почти всегда используют интерполяцию `$"Текст {var}"` — она читается намного легче, чем склейка через `+` или нумерованные заглушки `{0}`.

:::gap

## Грабли и частые ошибки

### 1. Вызов `Console.Write()` без аргументов

* **Так не скомпилируется:** написать `Console.Write();` по аналогии с `Console.WriteLine();` для отступа. У `Write` нет перегрузки без параметров — компилятор выдаст ошибку `CS1501`.
* **Так правильно:** использовать `Console.WriteLine();` или явно передать символ переноса `Console.Write("\n");`.

### 2. Забытый знак `$` при интерполяции строк

* **Так сработает неправильно:** написать `Console.WriteLine("Счёт: {score}");`. Программа не упадёт, но вместо числа выведет в консоль буквально текст `Счёт: {score}`.
* **Так правильно:** поставить символ доллара перед открывающей кавычкой: `Console.WriteLine($"Счёт: {score}");`.

### 3. Путаница между сложением и склейкой строк

* **Так сработает неправильно:** написать `Console.WriteLine("Результат: " + 5 + 3);`. Выражение вычисляется слева направо: сначала `"Результат: "` склеивается с `5` в строку `"Результат: 5"`, а затем к ней приклеивается `3`. В итоге выведется `Результат: 53` вместо `8`.
* **Так правильно:** использовать интерполяцию `Console.WriteLine($"Результат: {5 + 3}");` или брать арифметику в скобки `("Результат: " + (5 + 3))`.

### 4. Знаки вопроса `?` вместо кириллицы или эмодзи

* **Так сработает неправильно:** вывести эмодзи или редкие символы Юникода в стандартной консоли Windows без настройки кодировки — вместо них появятся знаки вопроса `?`.
* **Так правильно:** в самом начале программы переключить кодировку вывода на UTF-8: `Console.OutputEncoding = System.Text.Encoding.UTF8;`.

> [!WARNING]
> Попытка вызвать `Console.WriteLine` или изменить свойства консоли (например, `Console.Title`) в приложении без консольного окна (Windows Forms, WPF, фоновая служба) может привести к потере вывода или исключению `IOException`.

:::gap

## Под капотом и нюансы

### Куда на самом деле уходит текст

Класс `Console` — это обёртка над тремя стандартными потоками операционной системы:

* `Console.Out` (`TextWriter`) — стандартный поток вывода (`stdout`), куда пишут `Write` и `WriteLine`.
* `Console.Error` (`TextWriter`) — поток ошибок (`stderr`), используемый для логов и диагностики, чтобы не смешивать их с полезными данными при перенаправлении вывода в файл (`app.exe > result.txt`).
* `Console.In` (`TextReader`) — стандартный поток ввода (`stdin`).

При первом обращении к `Console` среда выполнения лениво инициализирует потоковый буфер поверх системных дескрипторов ОС и оборачивает его в потокобезопасную обёртку (`SyncTextWriter`), поэтому вызовы `Console.WriteLine` из разных потоков не перемешивают символы внутри одной строки.

### Почему `Console.WriteLine` в цикле тормозит программу

Каждый вызов `Console.WriteLine` выполняет блокировку потока (`lock`) и обращается к системному API терминала для отрисовки текста. Если вызвать его 100 000 раз подряд внутри цикла, программа потратит в десятки раз больше времени на перерисовку окна, чем на сами вычисления.

| Подход | Скорость на 100 000 строк | Когда применять |
| --- | --- | --- |
| `Console.WriteLine` на каждой итерации | Медленно (сотни мс — секунды) | Редкие логи, интерактивный диалог, прогресс-бар |
| Накопление в `StringBuilder` + один `WriteLine` | Быстро (единицы миллисекунд) | Вывод больших таблиц, отчётов, массивов данных |

```cs
using System.Text;

var buffer = new StringBuilder();
for (int i = 0; i < 1000; i++)
{
    buffer.AppendLine($"Строка #{i}");
}
// Один системный вызов вместо тысячи
Console.Write(buffer.ToString());

```

### Что происходит при передаче объекта в `WriteLine`

У `Console.WriteLine` почти два десятка перегрузок для базовых типов (`int`, `double`, `bool`, `char[]`), чтобы избежать лишнего выделения памяти (упаковки — *boxing*). Если передать любой собственный класс или структуру, сработает перегрузка `WriteLine(object? value)`: она проверит объект на `null` (для `null` просто напечатает пустую строку) и вызовет у него виртуальный метод `.ToString()`.

### Оформление вывода: цвета и управляющие последовательности

Раскрасить текст в терминале можно двумя способами:

* **Через свойства класса:** `Console.ForegroundColor = ConsoleColor.Green;` (меняет цвет текста) и `Console.ResetColor();` (возвращает стандартную палитру).
* **Через ANSI escape-коды:** современные терминалы (Windows Terminal, Linux, macOS) понимают управляющие последовательности прямо внутри строки, например `"\x1b[32mУспешно\x1b[0m"` выведет зелёный текст без переключения глобального состояния консоли.

> [!NOTE]
> В C# 10+ интерполированные строки `$"..."` работают через специальную структуру `DefaultInterpolatedStringHandler`, которая формирует итоговую строку в арендованном буфере из `ArrayPool` и минимизирует нагрузку на сборщик мусора (GC).
