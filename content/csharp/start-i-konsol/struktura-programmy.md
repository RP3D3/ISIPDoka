# Структура программы (Main и инструкции верхнего уровня)

Откуда процессор узнаёт, с какой именно строчки кода начинать запуск вашей программы?

:::gap

## Кратко

Любой программе нужна стартовая дверь — конкретное место, с которого процессор начнёт выполнять команды сверху вниз. В современном C# для этого достаточно сразу писать код в файле `Program.cs` (инструкции верхнего уровня), а в более старых проектах или крупных системах точка входа оформляется явно через метод `Main`. Это избавляет от путаницы, с какого файла и строчки стартует приложение.

:::gap

## Быстрый пример

В современных версиях языка (начиная с C# 9) точка входа пишется без обёрток из классов и методов:

```cs
// Современный стиль — инструкции верхнего уровня (Program.cs)
var user = args.Length > 0 ? args[0] : "Гость";
Console.WriteLine($"Привет, {user}!"); // Привет, Гость!
return 0; // Код успешного завершения

```

В проектах до C# 9 или при явном стиле оформления тот же код оборачивается в класс и метод `Main`:

```cs
// Классический стиль — явный метод Main
namespace MyApp;

class Program
{
    static int Main(string[] args)
    {
        var user = args.Length > 0 ? args[0] : "Гость";
        Console.WriteLine($"Привет, {user}!"); // Привет, Гость!
        return 0;
    }
}

```

:::gap

## Как это работает

При запуске приложения среда выполнения .NET ищет единственную точку входа и выполняет инструкции строго сверху вниз:

1. **Чтение входных параметров (`args`).** В первой строке программа проверяет встроенный массив строк `args`. В него попадают аргументы, переданные при запуске из терминала (например, при команде `dotnet run Анна` в `args[0]` окажется `"Анна"`). Если ничего не передали, берётся значение по умолчанию `"Гость"`.
2. **Выполнение основной логики.** Во второй строке `Console.WriteLine` выводит сформированное приветствие в консоль.
3. **Завершение и код возврата (`return 0`).** Последняя строка завершает программу и возвращает операционной системе число `0` — общепринятый сигнал, что всё прошло без ошибок.

> [!TIP]
> Если в простом скрипте или консольной утилите код возврата не важен, `return 0;` можно вообще не писать — компилятор подставит его сам.

В классическом варианте логика абсолютно та же, но разработчику приходилось вручную описывать каркас: пространство имён (`namespace`), класс (`Program`) и специальный статический метод `Main`, который среда .NET распознаёт как стартовый.

:::gap

## Грабли и частые ошибки

### 1. Инструкции верхнего уровня в нескольких файлах

* **Так не скомпилируется:** написать код без классов сразу в двух файлах (`Program.cs` и `Utils.cs`). Компилятор остановит сборку с ошибкой `CS8802` — стартовая дверь у программы может быть только одна.
* **Так правильно:** держать инструкции верхнего уровня только в одном файле (`Program.cs`), а в остальные файлы выносить классы, структуры и методы.

### 2. Объявление классов выше исполняемого кода

* **Так не скомпилируется:** объявить `class User { }` в начале `Program.cs`, а ниже написать `Console.WriteLine("Старт");` (ошибка `CS8803`).
* **Так правильно:** в файле с инструкциями верхнего уровня сначала идёт весь исполняемый код, а объявления собственных типов (`class`, `record`, `struct`, `enum`) размещаются строго в самом низу файла.

### 3. Обращение к `args[0]` без проверки

* **Так упадёт:** написать `Console.WriteLine(args[0]);` и запустить программу без параметров — приложение аварийно закроется с ошибкой `IndexOutOfRangeException`.
* **Так правильно:** всегда проверять длину массива (`args.Length > 0`) перед обращением по индексу.

### 4. Смешивание `Main` и кода верхнего уровня

* **Так сработает неправильно:** оставить в проекте инструкции верхнего уровня и параллельно объявить свой `static void Main()`. Компилятор выдаст предупреждение `CS7022` и полностью проигнорирует ваш `Main`.
* **Так правильно:** использовать в одном проекте только один подход.

> [!WARNING]
> Код верхнего уровня доступен только в проектах типа **Консольное приложение** или **Веб-приложение** (`OutputType = Exe`). В библиотеках классов (`Class Library`) точка входа не нужна и не компилируется.

:::gap

## Под капотом и нюансы

Инструкции верхнего уровня — это не магия, а **синтаксический сахар**. На этапе компиляции Roslyn автоматически заворачивает ваш код из `Program.cs` в скрытый класс `Program` (в глобальном пространстве имён) и генерирует точку входа с именем `<Main>$`.

### Допустимые сигнатуры `Main`

Если вы используете классический стиль или читаете чужой код, точка входа может выглядеть по-разному в зависимости от того, нужны ли аргументы запуска, код возврата или асинхронность:

| Сигнатура метода | Аргументы CLI | Код возврата | Поддержка `await` |
| --- | --- | --- | --- |
| `static void Main()` | Нет | Всегда `0` | Нет |
| `static void Main(string[] args)` | Да | Всегда `0` | Нет |
| `static int Main()` | Нет | Да (`int`) | Нет |
| `static int Main(string[] args)` | Да | Да (`int`) | Нет |
| `static async Task Main(string[] args)` | Да | Всегда `0` | Да |
| `static async Task<int> Main(string[] args)` | Да | Да (`int`) | Да |

В инструкциях верхнего уровня компилятор выбирает нужную сигнатуру автоматически:

* переменная `args` существует в области видимости всегда;
* если в коде встретится оператор `await`, сгенерированный `<Main>$` автоматически станет асинхронным (`Task` или `Task<int>`).

### Локальные функции вместо методов класса

Любые методы, которые вы объявите в `Program.cs` рядом с инструкциями верхнего уровня, компилятор превратит в **локальные функции** внутри метода `<Main>$`. Из-за этого к ним нельзя применять модификаторы доступа (`public`, `private`, `internal`), но можно добавить `static`, чтобы запретить случайный захват переменных из основного потока выполнения.

### Доступ к `Program` из тестов

Поскольку сгенерированный класс `Program` по умолчанию получает модификатор `internal`, проекты с интеграционными тестами (например, при использовании `WebApplicationFactory<Program>` в ASP.NET Core) его не увидят. Чтобы открыть класс для тестов, в самый низ `Program.cs` добавляют одну строку:

```cs
// Делает неявный класс Program публичным для тестовых сборок
public partial class Program { }

```

> [!NOTE]
> Начиная с .NET 10 (C# 14), запускать одиночные `.cs`-файлы с инструкциями верхнего уровня можно напрямую без создания `.csproj`-файла командой `dotnet run app.cs` — это удобно для быстрых скриптов и автоматизации.
