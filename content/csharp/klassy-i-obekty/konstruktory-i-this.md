# Конструкторы и this: начальная сборка объекта

Как гарантировать, что объект создаётся сразу с корректными обязательными данными, и как избежать дублирования кода при нескольких способах его создания?

**Конструктор** (*constructor*) — это специальный метод класса, который автоматически вызывается в момент создания объекта через оператор `new` и отвечает за начальную настройку его полей. Имя конструктора всегда точно совпадает с именем класса, а возвращаемый тип у него отсутствует. Внутри класса часто используют ключевое слово `this` — ссылку на текущий экземпляр объекта, которая помогает отличать поля класса от параметров с такими же именами и перенаправлять вызов из одного конструктора в другой.

## Виды и особенности конструкторов

| Вариант | Как объявляется | Когда применяется |
| --- | --- | --- |
| **Конструктор по умолчанию** | `public ClassName() { }` (или создаётся компилятором скрыто) | Когда объект можно создать без передачи начальных данных |
| **Параметризованный конструктор** | `public ClassName(string name, int age)` | Когда объекту для корректной работы сразу нужны обязательные значения |
| **Цепочка конструкторов (`: this`)** | `public ClassName(string name) : this(name, 18)` | Когда в классе несколько перегруженных конструкторов и нужно избежать повтора кода |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Вызов основного конструктора с двумя параметрами
        GameCharacter warrior = new GameCharacter("Артур", 150);
        warrior.PrintInfo();

        // Вызов перегруженного конструктора с одним параметром (здоровье подставится само)
        GameCharacter novice = new GameCharacter("Лука");
        novice.PrintInfo();
    }
}

class GameCharacter
{
    public string Name;
    public int Health;

    // Основной конструктор: принимает все данные и проверяет их корректность
    public GameCharacter(string name, int health)
    {
        // this.Name — поле текущего объекта, name — параметр конструктора
        this.Name = name;
        this.Health = health > 0 ? health : 100;
    }

    // Перегруженный конструктор: передаёт работу основному через : this(...) (принцип DRY)
    public GameCharacter(string name) : this(name, 100)
    {
    }

    public void PrintInfo()
    {
        Console.WriteLine($"Персонаж: {Name}, здоровье: {Health} HP");
    }
}

```

## Важные нюансы

* **Исчезновение пустого конструктора:** если в классе не написано ни одного конструктора, компилятор C# автоматически создаёт скрытый пустой конструктор без параметров. Но как только вы объявите хотя бы один свой конструктор с параметрами, автоматический пустой конструктор исчезнет — при необходимости его придётся дописать вручную.
* **Две главные роли `this`:** во-первых, `this.Field` снимает конфликт имён, когда параметр конструктора или метода назван так же, как поле класса; во-вторых, конструкция `: this(...)` позволяет перегруженным конструкторам переиспользовать общий код инициализации без дублирования.
* **Конструктор — не обычный метод:** его нельзя вызвать повторно у уже существующего объекта (`warrior.GameCharacter(...)` вызовет ошибку компиляции) — он срабатывает строго один раз при создании объекта через `new`.
* **Связь с соседними темами:** передача обязательных параметров в конструктор защищает объект от создания в «полупустом» состоянии (*инкапсуляция*), а цепочки `: this(...)` убирают повтор логики (*DRY*). Также только внутри конструктора разрешено задавать значения полям `readonly` (см. предыдущую карточку: *Поля и константы*).
