# Переменные

Куда девать очки опыта, никнейм игрока или таймер до взрыва, пока программа работает? 

## Быстрый старт

Быстро вспоминаем синтаксис:

```cs
int playerHealth = 100;
string playerName = "Alex";

Console.WriteLine(playerName);
Console.WriteLine(playerHealth);

```

Базовый шаблон всегда один и тот же:
`ТипДанных имяПеременной = значение;`

## Что это такое 

Представь пустой склад или кухню с одинаковыми пластиковыми банками. Переменная — это как раз такая банка, на которую ты наклеил скотч с надписью и положил внутрь конкретную вещь.

Работа с переменной делится на два отдельных действия:

1. **Объявление (взяли банку и подписали):**
```cs
int coins;

```


Ты сказал компилятору: *«Забей мне место под целое число и отзывайся на имя `coins`»*. Место зарезервировано, но внутри пока ничего нет.
2. **Инициализация (первый раз что-то туда положили):**
```cs
coins = 50;

```


Теперь банка заполнена. Знак `=` здесь — это не знак равенства из математики, это **оператор присваивания** (стрелка справа налево: возьми значение справа и запихни в банку слева).

Дальше по ходу программы старое значение можно затирать новым сколько угодно:

```cs
coins = 80; // Старые 50 стёрлись, теперь там 80

```

>[!IMPORTANT] **Главный закон C#:** компилятор категорически запрещает доставать >что-то из пустой банки. Если написать `int damage; Console.WriteLine(damage);`, среда >подчеркнёт всё красным и выдаст ошибку `CS0165 (Use of unassigned local variable)`. >Сначала положи — потом пользуйся.

## Стены и комнаты: область видимости

Переменная живёт ровно внутри тех фигурных скобок `{ }`, где была создана. Фигурные скобки — это стены комнаты. Из комнаты видно то, что лежит снаружи в коридоре, но из коридора заглянуть в комнату нельзя.

```cs
int totalScore = 500;

if (totalScore > 100)
{
    // Внутри скобок видно и то, что снаружи, и то, что создано здесь
    int bonus = 50;
    Console.WriteLine(totalScore + bonus);
}

// За пределами скобок переменная bonus бесследно уничтожена:
// Console.WriteLine(bonus); // Ошибка CS0103: имя bonus здесь не существует!

```

Как только программа доходит до закрывающей скобки `}`, компилятор безжалостно выбрасывает из памяти всё, что было объявлено внутри этого блока.

## Как называть переменные по-человечески

C# очень щепетилен к регистру: `speed`, `Speed` и `SPEED` — это три абсолютно разные переменные. Чтобы в твоём коде не путались ни ты сам через неделю, ни преподаватель:

* **Стиль `camelCase`:** имена обычных переменных начинаются с маленькой буквы. Если слов несколько — склеиваем их, а каждое новое пишем с большой (`playerSpeed`, `enemiesLeft`, `isGameOver`).
* **Понятный смысл:** переменная должна отвечать на вопрос «что внутри», а не быть загадкой Жака Фреско.
* ❌ Плохо: `int a;`, `string s1;`, `int kolvo;`, `int nabor_chisel;`
* ✔️ Хорошо: `int attemptsCount;`, `string userEmail;`, `int maxScore;`


* **Правила языка:** можно использовать буквы латиницы, цифры и знак подчёркивания `_`. Начинать имя с цифры нельзя (`int 1level;` не скомпилируется).

## Классические грабли

### 1. Попытка наклеить одну бирку дважды

В пределах одного блока нельзя объявить две переменные с одинаковым именем:

```cs
int mana = 100;
int mana = 50; // Ошибка CS0128: переменная mana уже объявлена в этой области

```

Чтобы просто поменять значение, тип повторно писать не нужно:

```cs
int mana = 100;
mana = 50; // Всё в порядке

```

### 2. Запихнуть невпихуемое

C# — строго типизированный язык. Если ячейка создана под целое число (`int`), положить туда текст нельзя, даже если это цифра в кавычках:

```cs
int age = "19"; // Ошибка CS0029: Нельзя неявно преобразовать string в int

```

Чтобы достать число из текста, его придётся явно распарсить (об этом в статье про `int`).

## Под капотом

Для процессора и скомпилированного байт-кода (IL) никаких красивых имён вроде `playerHealth` не существует. Имена придуманы для людей. При компиляции C# превращает каждую локальную переменную в номер ячейки на стеке (`V_0`, `V_1` и т.д.).

Если объявить переменную, положить в неё значение, но ни разу не прочитать в коде — умный компилятор при сборке в Release-режиме может просто выкинуть её, чтобы не тратить память и такты процессора впустую.
