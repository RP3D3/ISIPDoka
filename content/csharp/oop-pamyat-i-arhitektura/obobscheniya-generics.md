# Обобщения (Generics) в C#

Как написать один универсальный класс `Box<T>` или метод `Swap<T>`, который одинаково безопасно работает и с числами, и со строками, и с объектами игроков, не дублируя код и не теряя скорость на приведении типов?

:::gap

## Кратко

Обобщения (*Generics*) позволяют создавать классы, структуры, интерфейсы и методы с параметром типа в угловых скобках `<T>`. Вместо того чтобы писать отдельные копии одного и того же хранилища для `int`, `string` и `Hero` или использовать небезопасный тип `object`, вы описываете логику один раз, а конкретный тип подставляете при использовании. Компилятор строго проверяет типы ещё на этапе сборки, защищая от ошибок приведения, а среда .NET избавляет программу от лишних выделений памяти.

:::gap

## Быстрый пример

Создадим универсальный контейнер `Box<T>` и обобщённый метод обмена значений `Swap<T>`:

```cs
// Обобщённый класс: T превращается в конкретный тип при создании
Box<int> scoreBox = new(150);
Box<string> nameBox = new("Артур");

Console.WriteLine($"Очки: {scoreBox.Value}, Имя: {nameBox.Value}"); // Очки: 150, Имя: Артур

// Обобщённый метод: компилятор сам выводит тип <string> из аргументов
string first = "Меч", second = "Щит";
Swap(ref first, ref second);
Console.WriteLine($"{first} и {second}"); // Щит и Меч

class Box<T>(T value)
{
    public T Value { get; set; } = value;
}

void Swap<T>(ref T a, ref T b)
{
    (a, b) = (b, a);
}

```

:::gap

## Как это работает

При компиляции и выполнении кода среда .NET заменяет абстрактный параметр типа на реальный тип данных:

1. **Параметр типа (`<T>`).** Буква `T` (*Type*) в угловых скобках работает как заполнитель для будущего типа данных. Внутри класса `Box<T>` мы пишем `T` везде, где обычно стоял бы конкретный тип (`int` или `string`).
2. **Закрытие типа при создании (`Box<int>`).** Когда вы объявляете `Box<int>`, компилятор подставляет `int` вместо `T`. Свойство `Value` становится строго целочисленным, и случайно записать туда строку уже не получится.
3. **Автоматический вывод типов (`Swap(ref first, ref second)`).** При вызове обобщённого метода угловые скобки `Swap<string>(...)` можно не указывать — компилятор сам понимает, что раз переданы две строки, значит `T` равно `string`.
4. **Ограничения типов (`where`).** По умолчанию компилятор считает, что на место `T` могут подставить любой тип в мире, поэтому разрешает вызывать у него только базовые методы `object`. Чтобы сравнивать элементы или создавать их через `new T()`, на `T` накладывают ограничения с помощью ключевого слова `where`.

> [!TIP]
> Если у класса или метода несколько параметров типа (как в `Dictionary<TKey, TValue>`), давайте им осмысленные имена с префиксом `T` (`TKey`, `TValue`, `TResult`) вместо обезличенных `T1` и `T2`.

:::gap

## Грабли и частые ошибки

### 1. Попытка сравнивать значения типа `T` через `==` или `!=` (`CS0019`)

* **Так не скомпилируется:** написать внутри обобщённого метода `if (a == b)` без ограничений. Не для всех типов в C# определён оператор `==` (например, для обычных структур), поэтому компилятор выдаст ошибку `CS0019`.
* **Так правильно:** использовать `EqualityComparer<T>.Default.Equals(a, b)` или добавить ограничение `where T : IEquatable<T>`.

### 2. Попытка присвоить переменной типа `T` значение `null` (`CS0403`)

* **Так не скомпилируется:** написать `T item = null;` в методе без ограничений. Если на место `T` подставят значимый тип `int`, он не сможет принять `null` (ошибка `CS0403`).
* **Так правильно:** использовать выражение `T? item = default;` — оно подставит `null` для ссылочных типов и нулевое значение (`0`, `false`) для значимых.

### 3. Использование `object` вместо обобщений (упаковка и сбои приведения)

* **Так сработает неправильно:** делать универсальный список на базе `List<object>` и при чтении вручную приводить `(int)list[0]`. Это вызывает лишнюю упаковку (*boxing*) чисел в куче и грозит падением `InvalidCastException` во время работы программы.
* **Так правильно:** всегда использовать обобщённые типы (`List<T>`, `Dictionary<TKey, TValue>`), чтобы ошибки несовпадения типов ловились ещё при компиляции.

### 4. Попытка создать `new T()` без ограничения `new()` (`CS0304`)

* **Так не скомпилируется:** написать `T instance = new T();` внутри обобщённого класса, не предупредив компилятор. У переданного типа может не оказаться публичного конструктора без параметров (ошибка `CS0304`).
* **Так правильно:** добавить в заголовок класса или метода ограничение `where T : new()`.

:::gap

## Под капотом и нюансы

### Специализация в JIT-компиляторе и нулевая упаковка

В отличие от Java, где обобщения стираются до `Object` при компиляции, среда выполнения .NET CLR сохраняет информацию о параметрах типа прямо в метаданных. Во время запуска JIT-компилятор работает по умной схеме:

* **Для каждого значимого типа** (`List<int>`, `List<double>`, `List<Point>`) JIT генерирует отдельный машинный код с точным размером полей в памяти — никакой упаковки (*boxing*) не происходит.
* **Для всех ссылочных типов** (`List<string>`, `List<Hero>`, `List<Order>`) JIT генерирует **одну общую** версию машинного кода, поскольку любая ссылка в памяти имеет одинаковый размер (8 байт на 64-битной системе).

### Ограничения типов (`where`) на практике

Если методу нужно найти больший из двух элементов, мы можем потребовать, чтобы тип `T` реализовывал стандартный интерфейс сравнения `IComparable<T>`:

```cs
T GetMax<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) >= 0 ? a : b;
}

```

### Шпаргалка по популярным ограничениям `where`

| Ограничение | Что разрешает и требует от типа `T` |
| --- | --- |
| `where T : class` | `T` должен быть ссылочным типом (классом, интерфейсом, строкой) |
| `where T : struct` | `T` должен быть значимым типом (структурой или перечислением) |
| `where T : new()` | У `T` обязан быть публичный конструктор без параметров (пишется всегда последним) |
| `where T : BaseClass` | `T` должен быть самим `BaseClass` или его наследником |
| `where T : IComparable<T>` | `T` обязан реализовывать указанный интерфейс |
| `where T : notnull` | Запрещает передавать Nullable-типы вроде `int?` или `string?` |
