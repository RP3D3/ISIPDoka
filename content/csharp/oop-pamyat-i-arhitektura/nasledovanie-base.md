# Наследование :, base

Как не переписывать заново имя, здоровье и логику получения урона для каждого нового типа персонажа — воина, мага и лучника?

:::gap

## Кратко

Наследование позволяет создать новый класс на основе уже существующего, автоматически передав ему все открытые и защищённые поля, свойства и методы родителя. В C# связь между дочерним и базовым классом задаётся через двоеточие (`class Warrior : Character`), а ключевое слово `base` даёт наследнику прямой доступ к конструкторам и методам родительского класса. Это избавляет от дублирования кода и помогает выстраивать понятную иерархию сущностей от общего к частному.

:::gap

## Быстрый пример

Создадим общий базовый класс `Character` и унаследуем от него класс `Warrior`, дополнив его бронёй:

```cs
Warrior warrior = new("Артур", armor: 15);
warrior.TakeDamage(40); // Броня поглощает 15 ед. -> Артур получил 25 урона. HP: 75

// Базовый (родительский) класс
class Character
{
    public string Name { get; }
    public int Hp { get; protected set; } = 100;

    public Character(string name)
    {
        Name = name;
    }

    public virtual void TakeDamage(int damage)
    {
        Hp = Math.Max(0, Hp - damage);
        Console.WriteLine($"{Name} получил {damage} урона. HP: {Hp}");
    }
}

// Дочерний класс-наследник
class Warrior : Character
{
    public int Armor { get; }

    // Передаём имя в конструктор родителя через : base(name)
    public Warrior(string name, int armor) : base(name)
    {
        Armor = armor;
    }

    public override void TakeDamage(int damage)
    {
        int reduced = Math.Max(0, damage - Armor);
        base.TakeDamage(reduced); // Вызываем родительскую логику расчёта HP
    }
}

```

:::gap

## Как это работает

При компиляции и выполнении кода среда .NET объединяет члены родительского и дочернего классов в единую структуру объекта:

1. **Связь через двоеточие (`class Warrior : Character`).** Символ `:` указывает, что `Warrior` наследуется от `Character`. Воин автоматически получает свойства `Name` и `Hp`, а также метод `TakeDamage`, хотя внутри самого `Warrior` они заново не объявлены.
2. **Вызов родительского конструктора (`: base(name)`).** Прежде чем настроить самого воина, нужно инициализировать его базовую часть (`Character`). Запись `: base(name)` передаёт имя в конструктор родителя, и только после его завершения выполняется тело конструктора `Warrior`.
3. **Доступ к методу родителя (`base.TakeDamage(reduced)`).** Внутри переопределённого метода слово `base` позволяет обратиться к исходной версии метода в базовом классе, чтобы не дублировать вычитание здоровья и вывод текста в консоль.
4. **Защищённый доступ (`protected set`).** Свойство `Hp` в родителе помечено как `protected set`, поэтому наследник `Warrior` имеет право изменять здоровье, а внешний код в `Program.cs` может его только читать.

> [!TIP]
> Используйте наследование только тогда, когда между классами выполняется правило «**является**» (*is-a*): воин *является* персонажем (`Warrior : Character`). Если объект лишь *содержит* другой объект (например, у машины *есть* двигатель), используйте композицию (свойство `Engine` внутри `Car`), а не наследование.

:::gap

## Грабли и частые ошибки

### 1. Попытка унаследоваться сразу от двух классов

* **Так не скомпилируется:** написать `class Paladin : Warrior, Priest`. В C# запрещено множественное наследование классов — у любого класса может быть строго один прямой родитель (ошибка `CS1721`).
* **Так правильно:** выбирать один основной базовый класс, а дополнительные способности подключать через интерфейсы (`class Paladin : Warrior, IHealer`).

### 2. Забытый вызов `: base(...)`, когда у родителя нет пустого конструктора

* **Так не скомпилируется:** объявить в `Character` только `public Character(string name)` и написать в наследнике `public Warrior(int armor) { Armor = armor; }`. Компилятор неявно пытается вызвать пустой `base()`, которого нет, и останавливает сборку с ошибкой `CS7036`.
* **Так правильно:** явно передавать нужные аргументы в конструктор родителя через `: base(name)`.

### 3. Рекурсивный вызов самого себя вместо `base.Method()`

* **Так упадёт:** написать внутри `override void TakeDamage(int damage)` строку `TakeDamage(reduced);` без префикса `base.`. Метод начнёт бесконечно вызывать сам себя и аварийно завершит программу с `StackOverflowException`.
* **Так правильно:** всегда указывать `base.TakeDamage(reduced);`, когда нужно запустить родительскую реализацию метода.

### 4. Попытка унаследоваться от `sealed`-класса или структуры

* **Так не скомпилируется:** попытаться унаследовать класс от `string` или от своего класса с модификатором `sealed` (ошибка `CS0509`), а также унаследовать одну структуру `struct` от другой.
* **Так правильно:** помнить, что структуры вообще не поддерживают наследование классов, а модификатор `sealed` специально закрывает класс от создания наследников.

:::gap

## Под капотом и нюансы

### Единый предок `System.Object` и порядок вызова конструкторов

Даже если вы объявили класс без двоеточия (`class Item`), компилятор неявно наследует его от корневого типа `System.Object` (псевдоним `object`). Именно от него каждый объект в C# получает базовые методы `ToString()`, `Equals()` и `GetHashCode()`.

При создании экземпляра наследника конструкторы всегда запускаются **сверху вниз** по цепочке предков (`Object` > `Character` > `Warrior`), чтобы к моменту выполнения кода в дочернем классе вся родительская основа уже была полностью инициализирована.

### Запрет наследования с помощью `sealed`

Если вы хотите запретить создание наследников от конкретного класса (например, для защиты логики или чтобы помочь JIT-компилятору ускорить вызов методов), добавьте перед `class` модификатор `sealed` («запечатанный»):

```cs
sealed class FinalBoss : Character
{
    public FinalBoss(string name) : base(name) { }
}

```

### Сравнение ключевых слов `this` и `base`

| Критерий | `this` | `base` |
| --- | --- | --- |
| На что ссылается | На текущий экземпляр своего класса | На родительскую часть текущего экземпляра |
| Вызов конструктора | `: this(...)` — вызывает другой конструктор **этого же** класса | `: base(...)` — вызывает конструктор **базового** класса |
| Вызов метода | Запускает версию метода текущего класса (с учётом `override`) | Запускает исходную реализацию из родительского класса |
| Использование в `static` | Запрещено | Запрещено |
