# null и Nullable-типы ?, ??, ?.

Как безопасно достать название гильдии у игрока, которого может не существовать, и не уронить программу знаменитой ошибкой `NullReferenceException`?

:::gap

## Кратко

Значение `null` означает отсутствие объекта или пустую ссылку «в никуда». Чтобы программа не падала при попытке обратиться к пустоте, в C# есть семейство специальных инструментов: суффикс `?` явно разрешает переменной принимать `null`, условный оператор `?.` аккуратно прерывает цепочку вызовов, если встретил `null`, а операторы `??` и `??=` подставляют запасное значение по умолчанию. Это главный щит от самых частых сбоев во время выполнения программы.

:::gap

## Быстрый пример

Проверим работу Nullable-типов и защитных операторов при получении данных игрока:

```cs
Player? player = FindPlayer("Алекс");

// ?. (null-условный оператор): вернёт null вместо падения, если player или Guild равны null
string? guildTitle = player?.Guild?.Title;

// ?? (оператор объединения с null): подставит запасное значение, если слева оказался null
string displayGuild = guildTitle ?? "Без гильдии";
Console.WriteLine($"Гильдия: {displayGuild}"); // Гильдия: Без гильдии

// Nullable значимый тип (int?) и ленивое присваивание ??=
int? bonusScore = null;
bonusScore ??= 50; // Запишет 50, только если переменная была равна null
bonusScore ??= 99; // Не сработает, так как значение уже есть (50)
Console.WriteLine($"Бонус: {bonusScore}");     // Бонус: 50

Player? FindPlayer(string name) => null;

class Guild { public string Title { get; set; } = "Орден Света"; }
class Player { public Guild? Guild { get; set; } }

```

:::gap

## Как это работает

При выполнении кода компилятор и среда .NET отслеживают пустые ссылки и защищают цепочки обращений:

1. **Явное разрешение пустоты (`Player?`, `int?`).** В современном C# обычные ссылочные переменные (например, `string` или `Player`) считаются не допускающими `null` — компилятор выдаст предупреждение, если попытаться записать туда пустоту. Знак `?` после типа явно сообщает: «здесь законно может быть `null`, будь осторожен».
2. **Безопасная навигация (`player?.Guild?.Title`).** Оператор `?.` проверяет значение слева от точки. Если `player` равен `null`, выражение мгновенно останавливается и возвращает `null`, даже не пытаясь зайти в `Guild` или `Title`.
3. **Запасное значение (`??`).** Оператор `??` проверяет выражение слева: если там не `null`, возвращает его как есть, а если `null` — возвращает резервный вариант справа (`"Без гильдии"`).
4. **Присваивание при пустоте (`??=`).** Оператор `??=` работает как короткая запись для `if (bonusScore is null) bonusScore = 50;`. Он вычисляет и записывает правую часть только в том случае, если переменная слева ещё пуста.

> [!TIP]
> Объединяйте `?.` и `??` в одну лаконичную связку: `int level = player?.Level ?? 1;`. Такая строка заменяет сразу пять строчек проверок `if / else` и гарантированно возвращает корректное число.

:::gap

## Грабли и частые ошибки

### 1. Обращение к `.Value` у `Nullable<T>` без проверки (`InvalidOperationException`)

* **Так упадёт:** написать `int? count = null; int x = count.Value;`. Если внутри значимого Nullable-типа лежит `null`, прямое чтение свойства `.Value` немедленно выбросит исключение `InvalidOperationException`.
* **Так правильно:** извлекать значение безопасно через `count ?? 0`, метод `count.GetValueOrDefault()` или проверку шаблоном `if (count is int val)`.

### 2. Попытка записать результат `?.` в обычный значимый тип

* **Так не скомпилируется:** написать `string? text = null; int len = text?.Length;`. Поскольку цепочка `?.` может вернуть `null`, тип всего выражения автоматически становится `int?`, а его нельзя напрямую положить в обычный `int` (ошибка `CS0266`).
* **Так правильно:** дополнить выражение оператором `??`: `int len = text?.Length ?? 0;`.

### 3. Злоупотребление оператором подавления `!` (*null-forgiving*)

* **Так упадёт:** написать `Player? p = null; Console.WriteLine(p!.Name);`. Восклицательный знак `!` после переменной **не защищает код** при запуске — он лишь приказывает компилятору замолчать и скрыть жёлтое предупреждение, из-за чего программа всё равно рухнет с `NullReferenceException`.
* **Так правильно:** ставить `!` только в редких случаях, когда вы на 100% уверены, что переменная уже инициализирована, а во всех остальных ситуациях проверять `if (p is not null)`.

### 4. Проверка на `null` через `==` в классах с перегруженным равенством

* **Так сработает неправильно:** проверять `if (obj == null)` для объектов из движков или библиотек (например, `UnityEngine.Object`), где оператор `==` перегружен и может вести себя нестандартно или тратить лишнее время.
* **Так правильно:** использовать сопоставление с образцом `if (obj is null)` и `if (obj is not null)` — эти конструкции всегда проверяют реальную ссылку на уровне среды CLR.

:::gap

## Под капотом и нюансы

### Два разных механизма под одним знаком `?`

Хотя синтаксис `int?` и `string?` выглядит одинаково, на уровне среды выполнения .NET они устроены совершенно по-разному:

* **Значимые Nullable-типы (`int?`, `bool?`, `DateTime?`).** Компилятор разворачивает `int?` в реальную структуру `System.Nullable<int>`, внутри которой лежат два поля: `bool hasValue` (флаг наличия данных) и `int value` (само число). Поэтому `int?` занимает в памяти больше места, чем обычный `int` (8 байт вместо 4 из-за выравнивания).
* **Ссылочные Nullable-типы (`string?`, `Player?`).** Появились в C# 8 исключительно как **статический анализ на этапе компиляции**. В скомпилированном IL-коде `string` и `string?` — это абсолютно один и тот же класс `System.String` с нулевыми накладными расходами памяти.

### Шпаргалка по операторам для работы с `null`

| Оператор | Название | Что делает | Пример |
| --- | --- | --- | --- |
| `T?` | Nullable-тип | Разрешает переменной хранить значение `null` | `int? age = null;` |
| `?.` и `?[]` | Null-условный доступ | Обращается к члену или индексу, только если объект не `null` | `user?.Name`, `arr?[0]` |
| `??` | Объединение с `null` | Возвращает левый операнд, если он не `null`, иначе — правый | `name ?? "Гость"` |
| `??=` | Присваивание с `null` | Присваивает значение справа, только если слева `null` | `list ??= [];` |
| `!` | Подавление предупреждений | Отключает предупреждение компилятора о возможном `null` | `text!.Length` |

### Безопасный вызов делегатов и индексаторов (`?[]` и `?.Invoke()`)

Оператор `?.` работает не только для свойств и методов, но и для безопасного обращения к элементам массива или списка (`items?[0]`), а также для потокобезопасного вызова событий и делегатов:

```cs
Action<string>? onNotify = null;
onNotify?.Invoke("Сообщение"); // Ничего не произойдёт, ошибки не будет

```

> [!NOTE]
> В современных проектах .NET в файле `.csproj` по умолчанию включена настройка `<Nullable>enable</Nullable>`. Благодаря ей компилятор анализирует поток выполнения кода: если вы проверили `if (player is not null)`, внутри этого блока компилятор сам снимет предупреждения и позволит обращаться к `player.Name` без знака `?`.
