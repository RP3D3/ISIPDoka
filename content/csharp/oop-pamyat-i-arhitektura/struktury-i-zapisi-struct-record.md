# Структуры и записи (struct, record)

Как хранить лёгкие координаты точки без нагрузки на сборщик мусора или сравнивать два заказа по их содержимому, а не по адресу в памяти?

:::gap

## Кратко

Структура (`struct`) — это лёгкий значимый тип данных, который копируется целиком при присваивании и не нагружает сборщик мусора, поэтому идеально подходит для небольших наборов значений вроде координат или цвета. Запись (`record`) — это специальный тип для моделей данных, в котором компилятор автоматически реализует сравнение по значениям всех полей, красивый вывод в строку и удобное копирование с изменениями через оператор `with`. В современном C# записи бывают как ссылочными (`record` или `record class`), так и значимыми (`record struct`).

:::gap

## Быстрый пример

Сравним неизменяемую структуру для координат и позиционную запись для модели пользователя:

```cs
// 1. Структура (struct) — значимый тип, копируется целиком
Point p1 = new(10, 20);
Point p2 = p1; // Полная независимая копия

// 2. Запись (record) — сравнение по значениям и копирование через with
UserDto u1 = new("Алекс", 20);
UserDto u2 = new("Алекс", 20);
UserDto u3 = u1 with { Age = 21 }; // Создаёт копию u1 с новым возрастом

Console.WriteLine(u1 == u2); // True (сравниваются значения полей, а не ссылки!)
Console.WriteLine(u3);       // UserDto { Name = Алекс, Age = 21 }

// Неизменяемая структура для координат
readonly struct Point(double x, double y)
{
    public double X { get; } = x;
    public double Y { get; } = y;
}

// Позиционная запись (по умолчанию — ссылочный тип record class)
record UserDto(string Name, int Age);

```

:::gap

## Как это работает

При компиляции и выполнении кода среда .NET по-разному организует хранение в памяти и работу со сравнением:

1. **Лёгкая структура (`readonly struct Point`).** Ключевое слово `struct` создаёт значимый тип (*value type*), который размещается прямо в стеке и при присваивании `p2 = p1` копируется по значению. Модификатор `readonly` запрещает менять свойства после создания, защищая от скрытых ошибок при передаче структуры в методы.
2. **Компактная запись (`record UserDto(string Name, int Age)`).** Одна строчка заменяет громоздкий класс: компилятор сам создаёт публичные свойства `{ get; init; }`, конструктор, деконструктор и всю логику сравнения.
3. **Сравнение по содержимому (`u1 == u2`).** В отличие от обычных классов, где `==` сравнивает адреса объектов в куче, у `record` оператор `==` проверяет равенство всех свойств (`"Алекс" == "Алекс"` и `20 == 20`), поэтому возвращает `true`.
4. **Неразрушающее копирование (`u1 with { Age = 21 }`).** Выражение `with` создаёт новый экземпляр записи, копируя все свойства из `u1` и подменяя только указанные поля — исходный объект `u1` остаётся нетронутым.
5. **Читаемый вывод (`Console.WriteLine(u3)`).** Компилятор автоматически генерирует метод `ToString()`, который печатает имя типа и все его свойства с текущими значениями вместо названия пространства имён.

> [!TIP]
> Используйте `readonly struct` для маленьких наборов чисел размером до 16–24 байт (координаты, векторы, цвета), а `record` — для моделей данных, настроек и ответов от сервера (DTO), которые удобно сравнивать и передавать без случайных изменений.

:::gap

## Грабли и частые ошибки

### 1. Попытка унаследовать структуру от другой структуры или класса (`CS0527`)

* **Так не скомпилируется:** написать `struct Point3D : Point` или унаследовать структуру от обычного класса. Значимые типы в C# не поддерживают наследование типов (они неявно запечатаны `sealed`).
* **Так правильно:** реализовывать в структурах интерфейсы (`struct Point : IEquatable<Point>`) или использовать композицию (хранить `Point` внутри `Point3D`).

### 2. Попытка изменить свойства позиционного `record` напрямую (`CS8852`)

* **Так не скомпилируется:** объявить `record UserDto(string Name, int Age);` и затем написать `u1.Age = 25;`. Позиционные параметры в `record class` получают аксессор `init`, поэтому после создания они доступны строго только для чтения.
* **Так правильно:** создавать обновлённую копию через выражение `u1 = u1 with { Age = 25 };` (или, если изменяемость действительно нужна, объявить свойства в теле записи вручную с `{ get; set; }`).

### 3. Ожидание, что `record struct` по умолчанию неизменяем

* **Так сработает неправильно:** написать `record struct Cell(int X, int Y)` и считать, что его поля защищены от перезаписи, как у обычного `record`. По историческим причинам у `record struct` сгенерированные свойства по умолчанию имеют `{ get; set; }` и свободно меняются.
* **Так правильно:** всегда добавлять слово `readonly` для неизменяемых значимых записей: `readonly record struct Cell(int X, int Y);`.

### 4. Использование крупных структур (`struct`) при частой передаче в методы

* **Так сработает неправильно:** сложить в `struct` десяток полей и передавать её в методы по значению в цикле. При каждом вызове процессор будет заново копировать все байты структуры, что окажется медленнее передачи 8-байтной ссылки класса.
* **Так правильно:** держать `struct` компактными (до 16–24 байт) или передавать крупные структуры по защищённой ссылке с модификатором `in`.

:::gap

## Под капотом и нюансы

### Что компилятор генерирует для `record`

На уровне скомпилированного IL-кода `record` — это не отдельный вид типа в среде CLR, а обычный `class` (или `struct` для `record struct`), в который компилятор Roslyn автоматически дописывает шаблонный код:

* Свойства только для инициализации (`{ get; init; }`) для каждого позиционного параметра.
* Метод деконструкции `Deconstruct(out string Name, out int Age)`, благодаря которому запись можно сразу разложить на переменные: `var (name, age) = u1;`.
* Структурное равенство: реализацию интерфейса `IEquatable<T>`, переопределённые `Equals()`, `GetHashCode()`, а также операторы `==` и `!=`.
* Защищённый конструктор копирования и служебный метод `<Clone>$()`, на которых работает оператор `with`.

### Сводная таблица: `class`, `struct`, `record class` и `record struct`

| Критерий | `class` | `struct` | `record` (`record class`) | `record struct` |
| --- | --- | --- | --- | --- |
| Категория типа | Ссылочный (*Reference*) | Значимый (*Value*) | Ссылочный (*Reference*) | Значимый (*Value*) |
| Где хранятся данные | В куче (*Heap*) | В стеке (или внутри объекта) | В куче (*Heap*) | В стеке (или внутри объекта) |
| Как работает `==` | Сравнение **ссылок** (адресов) | Не определён по умолчанию | Сравнение **значений** полей | Сравнение **значений** полей |
| Позиционные параметры | Изменяемы, если задать `set` | Изменяемы, если задать `set` | Неизменяемы (`init`) | **Изменяемы** (`set`), нужен `readonly` |
| Поддержка выражения `with` | Нет | Да (начиная с C# 10) | Да (из коробки) | Да (из коробки) |
| Наследование | Поддерживает | Запрещено (только интерфейсы) | Поддерживает (только от других `record`) | Запрещено (только интерфейсы) |

### Оператор `with` для обычных структур

Начиная с C# 10 выражение `with` работает не только для записей `record`, но и для любых обычных структур (`struct`) и анонимных типов:

```cs
var rawPoint = new RawPoint { X = 5, Y = 10 };
var moved = rawPoint with { X = 15 }; // Скопирует структуру и заменит X на 15

struct RawPoint { public int X; public int Y; }

```
