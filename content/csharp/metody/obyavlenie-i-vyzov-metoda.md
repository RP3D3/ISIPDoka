# Объявление и вызов метода

Как не копировать один и тот же код расчёта урона или проверки пароля в десяти местах программы, а упаковать его в одну удобную команду?

:::gap

## Кратко

Метод — это именованный блок кода, который решает одну конкретную задачу и может вызываться из разных мест программы сколько угодно раз. Он помогает избавиться от дублирования (принцип DRY — *Don't Repeat Yourself*), разбить сложную логику на понятные кирпичики и скрыть детали вычислений за простым именем. В C# методы могут как просто выполнять действия без ответа (`void`), так и вычислять и возвращать готовый результат.

:::gap

## Быстрый пример

Объявим два метода — один для вывода приветствия, другой для расчёта урона — и вызовем их в основном коде:

```cs
// Вызов методов
PrintBanner("Игрок 1");
int finalDamage = CalculateDamage(25, 2);
Console.WriteLine($"Итоговый урон: {finalDamage}"); // Итоговый урон: 50

// Метод, который только выполняет действие и ничего не возвращает (void)
void PrintBanner(string playerName)
{
    Console.WriteLine($"=== Добро пожаловать, {playerName}! ===");
}

// Метод, который вычисляет и возвращает результат типа int
int CalculateDamage(int baseDamage, int multiplier)
{
    return baseDamage * multiplier;
}

```

:::gap

## Как это работает

При выполнении кода среда .NET связывает вызов по имени с нужным блоком инструкций и передаёт туда данные:

1. **Заголовок метода (`int CalculateDamage(int baseDamage, int multiplier)`).** В самом начале указывается тип результата (`int` — метод обязан вернуть целое число), затем имя в стиле `PascalCase` (каждое слово с заглавной буквы), а в круглых скобках — входные параметры с их типами.
2. **Метод без возврата (`void`).** Если методу нужно просто совершить действие (напечатать текст, сохранить файл) и нечего отдавать обратно, вместо типа результата пишется ключевое слово `void` («пустота»).
3. **Возврат результата (`return`).** Оператор `return` мгновенно завершает работу метода и отправляет вычисленное значение (`50`) обратно в ту строку, откуда метод вызвали.
4. **Вызов метода (`CalculateDamage(25, 2)`).** Чтобы запустить код внутри метода, мы пишем его имя и передаём в круглых скобках конкретные значения (аргументы) в том же порядке, в каком объявлены параметры.

> [!TIP]
> Называйте методы с глагола, описывающего действие (`CalculateTotal`, `SendEmail`, `CheckPassword`), и старайтесь, чтобы один метод решал ровно одну понятную задачу и помещался на один экран.

:::gap

## Грабли и частые ошибки

### 1. Забытый `return` на одной из веток внутри метода

* **Так не скомпилируется:** написать метод `string GetRank(int score)` с проверкой `if (score >= 100) return "Профи";` и не указать, что вернуть, если очков меньше ста. Компилятор требует возврат значения при любом сценарии (ошибка `CS0161`).
* **Так правильно:** убедиться, что все ветки исполнения заканчиваются оператором `return` (например, добавить `return "Новичок";` в конце метода).

### 2. Попытка вернуть значение из `void`-метода или записать его в переменную

* **Так не скомпилируется:** написать `var text = PrintBanner("Аня");` или добавить `return 10;` внутри метода с типом `void`. Пустоту нельзя присвоить переменной (ошибка `CS0815` или `CS0127`).
* **Так правильно:** вызывать `void`-методы отдельной строкой без знака `=`, а если результат всё же нужен — заменить `void` на нужный тип (`string`, `int`, `bool`).

### 3. Несовпадение количества или типов аргументов при вызове

* **Так не скомпилируется:** вызвать `CalculateDamage("25", 2)` (передать строку вместо числа) или забыть второй аргумент `CalculateDamage(25)` — компилятор выдаст ошибку `CS1503` или `CS1501`.
* **Так правильно:** сверяться с подсказкой редактора и передавать аргументы строго в нужном количестве и с совместимыми типами.

### 4. Объявление методов выше инструкций верхнего уровня

* **Так не скомпилируется:** написать объявление `void PrintBanner(...)` в первой строчке `Program.cs`, а основной код ниже — компилятор остановит сборку с ошибкой `CS8803`.
* **Так правильно:** в файле с инструкциями верхнего уровня размещать все методы строго внизу после основного кода (или выносить в отдельные классы).

:::gap

## Под капотом и нюансы

### Стек вызовов (Call Stack) и стековые фреймы

Когда программа встречает вызов метода, среда .NET запоминает текущую строчку кода (адрес возврата), ставит её на паузу и выделяет в памяти потока новый блок — **стековый фрейм** (*Stack Frame*). Внутри этого фрейма живут все параметры и локальные переменные вызванного метода. Как только срабатывает `return` или закрывающая скобка `}`, фрейм мгновенно очищается, а выполнение продолжается с сохранённого адреса.

Если метод вызывает сам себя (рекурсия) без условия остановки, стековые фреймы наслаиваются друг на друга, пока не закончится выделенная под стек память (обычно 1 МБ в Windows), что приводит к фатальному падению `StackOverflowException`.

### Короткие методы с выражением (`=>`)

Если тело метода состоит из одной-единственной инструкции или возврата формулы, фигурные скобки и слово `return` можно заменить на компактную стрелку `=>` (*expression-bodied member*):

```cs
int Square(int x) => x * x;
void SayHi(string name) => Console.WriteLine($"Привет, {name}!");

```

### Локальные функции и модификатор `static`

В современном C# функции, объявленные внизу `Program.cs` с инструкциями верхнего уровня, технически являются **локальными функциями** внутри неявного метода `Main`. По умолчанию они могут случайно прочитать или изменить переменные из основного кода выше. Если добавить перед типом возврата слово `static` (`static int CalculateDamage(...)`), компилятор запретит доступ к внешним переменным — это защитит от случайных побочных эффектов и уберёт лишние выделения памяти под замыкания.

### Основные термины

| Термин | Что означает | Пример |
| --- | --- | --- |
| Сигнатура метода | Имя метода + типы и порядок его параметров (без типа возврата) | `CalculateDamage(int, int)` |
| Параметр | Переменная в скобках при **объявлении** метода | `int baseDamage` |
| Аргумент | Конкретное значение, передаваемое при **вызове** метода | `25` |
| Возвращаемый тип | Тип результата перед именем метода (или `void`, если результата нет) | `int`, `string`, `void` |
