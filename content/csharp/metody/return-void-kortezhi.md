# Возврат значений (return, void, кортежи)

Как вернуть из метода сразу два результата — например, статус операции вместе с текстом ошибки или координаты игрока — не создавая ради этого целый класс?

:::gap

## Кратко

Методы в C# либо просто выполняют работу без ответа (`void`), либо вычисляют результат и отправляют его обратно в место вызова с помощью оператора `return`. Когда одного возвращаемого значения мало, на помощь приходят кортежи (*tuples*) — лёгкий способ упаковать сразу несколько значений разных типов в круглые скобки `(bool, string)` и тут же распаковать их в отдельные переменные при вызове метода.

:::gap

## Быстрый пример

Посмотрим на три сценария: метод `void` с досрочным выходом, обычный возврат числа и возврат кортежа из двух значений:

```cs
// 1. Метод void с досрочным выходом
PrintReward(-10); // Ничего не выведет

// 2. Обычный возврат одного значения
int total = AddBonus(100, 25);
Console.WriteLine($"Итого: {total}"); // Итого: 125

// 3. Возврат кортежа и его распаковка (деконструкция)
var (isSuccess, message) = TryBuyItem(gold: 50, price: 80);
Console.WriteLine($"{isSuccess}: {message}"); // False: Недостаточно золота

void PrintReward(int coins)
{
    if (coins <= 0) return; // Досрочный выход из void-метода
    Console.WriteLine($"Награда: {coins} монет");
}

int AddBonus(int score, int bonus) => score + bonus;

(bool Ok, string Info) TryBuyItem(int gold, int price)
{
    if (gold < price)
    {
        return (false, "Недостаточно золота");
    }
    return (true, "Покупка совершена");
}

```

:::gap

## Как это работает

При выполнении кода среда .NET управляет завершением метода и передачей данных обратно по следующим правилам:

1. **Пустой возврат (`void`) и досрочный `return;`.** Метод `PrintReward` ничего не отдаёт наружу, поэтому его тип указан как `void`. Оператор `return;` без значения внутри такого метода работает как стоп-кран: если монет ноль или меньше, метод мгновенно прерывается и не печатает сообщение.
2. **Возврат одного значения (`int AddBonus`).** Ключевое слово `return` (или короткая стрелка `=>`) вычисляет сумму `125`, завершает работу метода и подставляет это число на место вызова `AddBonus(100, 25)`.
3. **Упаковка нескольких значений в кортеж (`(bool Ok, string Info)`).** В заголовке метода `TryBuyItem` мы перечисляем типы и понятные имена полей в круглых скобках. Внутри метода достаточно вернуть пару значений в таких же скобках: `(false, "Недостаточно золота")`.
4. **Распаковка при вызове (`var (isSuccess, message)`).** При получении кортежа мы можем сразу разложить его на две обычные локальные переменные с помощью деконструкции и работать с каждой по отдельности.

> [!TIP]
> Всегда давайте полям кортежа понятные имена в сигнатуре метода — `(int X, int Y)` вместо обезличенного `(int, int)`. Тогда при вызове подсказки редактора покажут `pos.X` и `pos.Y` вместо безликих `Item1` и `Item2`.

:::gap

## Грабли и частые ошибки

### 1. Недостижимый код после оператора `return`

* **Так сработает неправильно:** написать команды ниже `return` в том же блоке кода (например, `return true; Console.WriteLine("Готово");`). Оператор `return` мгновенно выходит из метода, поэтому строка ниже не выполнится никогда, а компилятор выдаст предупреждение `CS0162` (обнаружен недостижимый код).
* **Так правильно:** выполнять все нужные действия (логирование, очистку) строго до инструкции `return`.

### 2. Возврат значения из `void` или пропущенный `return` в ветке

* **Так не скомпилируется:** написать `return 0;` внутри `void`-метода (ошибка `CS0127`) или забыть `return` в одной из веток `if / else` у метода, который обязан вернуть результат (ошибка `CS0161`).
* **Так правильно:** в `void`-методах использовать только пустой `return;`, а в методах с типом результата гарантировать возврат значения при любом сценарии.

### 3. Обезличенные кортежи с обращением через `Item1`, `Item2`

* **Так сработает неправильно:** объявить `(string, int, bool) GetUser()` без имён полей и писать в коде `if (user.Item3) Console.WriteLine(user.Item1);`. Через неделю вы сами забудете, что именно хранится в `Item3`.
* **Так правильно:** задавать полям имена `(string Name, int Age, bool IsAdmin)` или сразу распаковывать кортеж через деконструкцию `var (name, _, isAdmin) = GetUser();`.

### 4. Слишком громоздкие кортежи на 4–5 и более элементов

* **Так сработает неправильно:** возвращать кортеж вида `(int, string, string, double, bool, DateTime)` — сигнатура метода становится нечитаемой, а порядок элементов легко перепутать при распаковке.
* **Так правильно:** использовать кортежи для 2–3 тесно связанных значений, а для более крупных наборов данных объявлять компактный `record` или `struct`.

:::gap

## Под капотом и нюансы

### `ValueTuple` против устаревшего `Tuple`

В современном C# синтаксис `(int, string)` под капотом разворачивается в структуру `System.ValueTuple<T1, T2>`. В отличие от старого класса `System.Tuple` из ранних версий .NET, современный `ValueTuple` является **значимым типом** (*value type*):

* Он размещается прямо в стеке (или внутри регистров процессора) и **не выделяет память в управляемой куче**, не нагружая сборщик мусора.
* Его поля можно изменять после создания (`var pair = (A: 1, B: 2); pair.A = 10;`).

### Стирание имён полей при компиляции

Имена элементов кортежа (`Ok`, `Info`) существуют только на этапе компиляции в виде специального атрибута `[TupleElementNames]` для подсказок в IDE. В скомпилированном IL-коде поля по-прежнему называются `Item1` и `Item2`. Благодаря этому два кортежа с одинаковыми типами, но разными именами полей полностью совместимы друг с другом:

```cs
(int Width, int Height) size = (1920, 1080);
(int X, int Y) point = size; // Работает без ошибок приведения типов

```

### Отбрасывание ненужных элементов (`_`)

Если метод возвращает кортеж из трёх значений, а вам нужно только одно, лишние позиции при распаковке можно проигнорировать с помощью символа отбрасывания `_` (*discard*), не создавая ненужных переменных:

```cs
(string Name, int Hp, int Mana) GetHero() => ("Кира", 100, 50);

var (heroName, _, currentMana) = GetHero(); // Hp проигнорировано

```

### Выбор способа возврата данных из метода

| Способ | Когда лучше использовать | Затраты памяти |
| --- | --- | --- |
| `void` | Метод только выполняет действие (печать, запись в файл) | Нулевые |
| Один тип (`int`, `string`) | Метод вычисляет ровно одно конкретное значение | Зависит от типа |
| Кортеж `(T1, T2)` | Нужно быстро вернуть 2–3 значения без создания нового типа | Нулевые (стек, `ValueTuple`) |
| Параметр `out` | Паттерн `Try...` (`bool TryParse(..., out int result)`) | Нулевые |
| `record` / `struct` | Возвращается сложная сущность с 4 и более полями и логикой | Стек (`record struct`) или куча (`record`) |
