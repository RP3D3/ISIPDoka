# Модификаторы параметров (ref, out, in)

Как изменить исходную переменную внутри метода, вернуть сразу два результата без кортежа или передать тяжёлую структуру без лишнего копирования?

:::gap

## Кратко

По умолчанию C# передаёт числа и структуры в метод **по значению** — то есть создаёт их копию, поэтому любые изменения внутри метода теряются после его завершения. Модификаторы `ref`, `out` и `in` передают переменную **по ссылке**, открывая методу прямой доступ к той же ячейке памяти. Модификатор `ref` разрешает и читать, и менять переменную; `out` обязывает метод записать в неё новый результат; а `in` защищает данные от записи, позволяя быстро передавать крупные структуры без копирования.

:::gap

## Быстрый пример

Посмотрим на работу всех трёх модификаторов на примере лечения персонажа, безопасного деления и чтения 3D-координат:

```cs
int hp = 80;
Heal(ref hp, 30);
Console.WriteLine($"Здоровье: {hp}"); // Здоровье: 100

if (TryDivide(17, 5, out int result))
{
    Console.WriteLine($"Результат: {result}"); // Результат: 3
}

Point3D pos = new(10.5, 20.0, -4.2);
PrintPoint(in pos); // Передаётся по ссылке без копирования

void Heal(ref int health, int amount)
{
    health = Math.Min(100, health + amount); // Меняет исходную переменную hp
}

bool TryDivide(int a, int b, out int quotient)
{
    if (b == 0)
    {
        quotient = 0; // Метод обязан записать значение перед выходом
        return false;
    }
    quotient = a / b;
    return true;
}

void PrintPoint(in Point3D p)
{
    // p.X = 0; // Ошибка компиляции: параметр 'in' доступен только для чтения
    Console.WriteLine($"X: {p.X}, Y: {p.Y}, Z: {p.Z}");
}

readonly struct Point3D(double x, double y, double z)
{
    public double X { get; } = x;
    public double Y { get; } = y;
    public double Z { get; } = z;
}

```

:::gap

## Как это работает

При выполнении кода среда .NET вместо копирования данных передаёт в метод адрес исходной переменной в памяти:

1. **Двусторонний обмен (`ref`).** Переменная `hp` заранее получает значение `80`. При вызове `Heal(ref hp, 30)` параметр `health` становится псевдонимом для `hp`: метод читает текущее здоровье, прибавляет лечение, ограничивает максимумом и записывает `100` прямо в исходную переменную.
2. **Выходной результат (`out`).** В вызове `TryDivide(17, 5, out int result)` переменную `result` не нужно создавать заранее — её можно объявить прямо внутри круглых скобок. Метод `TryDivide` возвращает `bool` как статус успеха, а само частное (`3`) кладёт в `quotient`.
3. **Защищённая ссылка (`in`).** Модификатор `in` передаёт структуру `Point3D` по ссылке, экономя время на копировании её полей, но компилятор строго следит, чтобы внутри `PrintPoint` никто не изменил её свойства.

> [!TIP]
> Объявляйте `out`-переменную прямо в скобках вызова (`if (int.TryParse(input, out int number))`) вместо создания пустой переменной строкой выше — так её область видимости сразу ограничивается нужным блоком кода.

:::gap

## Грабли и частые ошибки

### 1. Забытое слово `ref` или `out` в месте вызова метода

* **Так не скомпилируется:** объявить `void Heal(ref int hp)` и вызвать его как `Heal(hp);`. Для `ref` и `out` компилятор требует дублировать модификатор при вызове, чтобы вы случайно не позволили методу изменить вашу переменную (ошибка `CS1620`).
* **Так правильно:** явно писать `Heal(ref hp);` (только для `in` слово при вызове разрешено опускать).

### 2. Передача неинициализированной переменной в `ref`

* **Так не скомпилируется:** написать `int score; AddBonus(ref score);`. Поскольку метод с `ref` имеет право сразу прочитать значение переменной, она обязана быть заполнена до вызова (ошибка `CS0165`).
* **Так правильно:** присвоить начальное значение `int score = 0;` до вызова `ref`-метода или заменить модификатор на `out`.

### 3. Забытое присваивание `out`-параметру перед выходом из метода

* **Так не скомпилируется:** написать `return false;` внутри `TryDivide`, не присвоив перед этим `quotient = 0;`. Компилятор гарантирует вызывающему коду, что после метода `out`-переменная точно будет заполнена (ошибка `CS0177`).
* **Так правильно:** присваивать значение всем `out`-параметрам на каждой ветке `return`.

### 4. Попытка передать в `ref` или `out` число-литерал или свойство класса

* **Так не скомпилируется:** написать `Heal(ref 50, 10);` или `Heal(ref player.Hp, 10);`, если `Hp` — это свойство. Свойство под капотом является парой методов `get` и `set`, а не прямой ячейкой памяти (ошибка `CS1510` или `CS0206`).
* **Так правильно:** передавать в `ref` и `out` только обычные переменные, поля или элементы массива (`scores[0]`).

:::gap

## Под капотом и нюансы

### Управляемые указатели (Managed Pointers)

На уровне промежуточного языка IL модификаторы `ref`, `out` и `in` устроены абсолютно одинаково — все три компилируются в **управляемый указатель** (`int32&` или `Point3D&`). Это специальный адрес в памяти (размером 8 байт на 64-битной системе), который может указывать как на переменную в стеке, так и на поле объекта в управляемой куче, причём сборщик мусора (GC) умеет корректно обновлять этот адрес при перемещении объектов. Разница между `ref`, `out` и `in` существует исключительно на этапе компиляции C# в виде правил безопасности.

### Сравнительная таблица

| Критерий | `ref` | `out` | `in` |
| --- | --- | --- | --- |
| Инициализация до вызова | **Обязательна** | Не требуется | **Обязательна** |
| Запись внутри метода | Необязательна | **Обязательна** | **Запрещена** (только чтение) |
| Слово при вызове метода | Обязательно (`ref x`) | Обязательно (`out x`) | Необязательно (`in x` или просто `x`) |
| Главный сценарий | Изменение готовой переменной на месте | Возврат нескольких значений (`Try...`) | Быстрая передача крупных `readonly struct` |

### Скрытое копирование (`defensive copy`) и когда нужен `in`

Передавать через `in` обычные маленькие типы вроде `int` (4 байта) или `double` (8 байт) бессмысленно — сам адрес ссылки на 64-битном процессоре занимает те же 8 байт, а лишнее разыменование указателя только замедлит код. Модификатор `in` имеет смысл только для крупных структур размером от 16–24 байт и выше (например, матриц или векторов).

При этом важно объявлять такие структуры как `readonly struct`. Если передать через `in` обычную изменяемую структуру и вызвать у неё любой метод или свойство, компилятор под капотом создаст **защитную копию** (*defensive copy*) всей структуры в стеке, чтобы метод случайно не изменил её поля — и вся экономия памяти пропадёт.

> [!NOTE]
> Начиная с C# 12 появился модификатор `ref readonly`. Он работает так же, как `in` (защищает данные от записи), но разрешает писать `ref` при вызове (`PrintPoint(ref pos)`), наглядно показывая программисту, что переменная передаётся по ссылке, а не копируется.
