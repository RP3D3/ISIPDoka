# Сортировка и выборка (OrderBy, Select)

Как выстроить таблицу лидеров по убыванию очков, а при их равенстве — по алфавиту, и превратить громоздкие объекты игроков в аккуратный список строк для вывода на экран?

:::gap

## Кратко

Методы расширения `OrderBy` и `Select` из пространства имён `System.Linq` отвечают за упорядочивание коллекций и их преобразование в новую форму (*проекцию*). Метод `OrderBy` (и его пара `OrderByDescending`) сортирует элементы по выбранному ключу без изменения исходного списка, позволяя задать дополнительные критерии через `ThenBy`. Метод `Select` пропускает каждый элемент через функцию-преобразователь, превращая объекты одного типа в другой — например, извлекает только имена из списка героев или собирает готовые строки для интерфейса.

:::gap

## Быстрый пример

Отсортируем таблицу игроков сначала по очкам по убыванию, затем по имени по алфавиту, и сформируем список имён и итоговых строк:

```cs
List<Player> players =
[
    new("Кира", Score: 1200, Level: 8),
    new("Артур", Score: 1500, Level: 10),
    new("Борис", Score: 1200, Level: 7)
];

// 1. Сортировка по убыванию очков, а при равенстве — по имени (A -> Я)
List<Player> leaderboard = players
    .OrderByDescending(p => p.Score)
    .ThenBy(p => p.Name)
    .ToList();

// 2. Выборка (проекция): превращаем List<Player> в List<string> с одними именами
List<string> namesOnly = leaderboard
    .Select(p => p.Name)
    .ToList();

Console.WriteLine(string.Join(", ", namesOnly)); // Артур, Борис, Кира

// 3. Комбинация фильтрации, сортировки и форматирования в одну цепочку
var topSummary = players
    .Where(p => p.Score >= 1200)
    .OrderByDescending(p => p.Score)
    .ThenBy(p => p.Name)
    .Select((p, index) => $"#{index + 1} {p.Name}: {p.Score} очков");

foreach (string line in topSummary)
{
    Console.WriteLine(line);
}

record Player(string Name, int Score, int Level);

```

:::gap

## Как это работает

При выполнении кода среда .NET строит конвейер обработки данных, не затрагивая исходную коллекцию `players`:

1. **Ключ сортировки (`OrderByDescending(p => p.Score)`).** Лямбда-выражение `p => p.Score` указывает, по какому именно полю сравнивать объекты. Среда упорядочивает игроков от большего счёта к меньшему (`Артур` с 1500 очками встаёт первым).
2. **Вторичная сортировка (`ThenBy(p => p.Name)`).** У `Киры` и `Бориса` по 1200 очков. Метод `ThenBy` подключается только к отсортированной последовательности и разрешает ничью по второму признаку — по алфавиту, ставя `Бориса` выше `Киры`.
3. **Проекция в другой тип (`Select(p => p.Name)`).** Метод `Select` работает как конвейерная лента: на вход заходит объект `Player`, а на выход выходит строка `string` с его именем. Тип последовательности меняется с `IEnumerable<Player>` на `IEnumerable<string>`.
4. **Перегрузка `Select` с индексом (`(p, index) => ...`).** Если передать в `Select` лямбду с двумя параметрами, вторым аргументом среда автоматически подставит порядковый номер элемента начиная с `0`, что удобно для нумерации мест в рейтинге.

> [!TIP]
> Всегда ставьте фильтрацию `Where(...)` **до** сортировки `OrderBy(...)`. Тогда программе придётся сортировать только уже отфильтрованные элементы, а не всю исходную коллекцию целиком.

:::gap

## Грабли и частые ошибки

### 1. Повторный вызов `OrderBy` вместо `ThenBy`

* **Так сработает неправильно:** написать `.OrderByDescending(p => p.Score).OrderBy(p => p.Name)`. Второй вызов `OrderBy` полностью **перезапишет** первую сортировку и перемешает игроков с разным количеством очков, оставив порядок только по алфавиту.
* **Так правильно:** для всех дополнительных уровней сортировки после первого всегда использовать `.ThenBy(...)` или `.ThenByDescending(...)`.

### 2. Ожидание, что `OrderBy` отсортирует сам исходный список

* **Так сработает неправильно:** написать отдельной строкой `players.OrderBy(p => p.Score);` и думать, что элементы внутри `players` поменялись местами. В отличие от метода `players.Sort()`, LINQ-метод `OrderBy` не меняет исходный список, а возвращает новую отсортированную последовательность.
* **Так правильно:** сохранять результат в новую переменную с вызовом `.ToList()` или использовать изменяющий метод `players.Sort((a, b) => b.Score.CompareTo(a.Score))`, если нужно перестроить список на месте.

### 3. Побочные эффекты и изменение объектов внутри `Select`

* **Так сработает неправильно:** писать внутри `Select` изменение полей объекта (`players.Select(p => { p.Score += 10; return p; })`). Из-за отложенного выполнения LINQ очки будут начисляться заново при каждом проходе цикла `foreach` по этой переменной.
* **Так правильно:** использовать `Select` только для создания новых значений, строк или записей (`p => p with { Score = p.Score + 10 }`), а для изменения объектов на месте применять обычный цикл `foreach`.

### 4. Сортировка строк без учёта регистра или культуры

* **Так сработает неправильно:** сортировать имена `.OrderBy(p => p.Name)`, когда часть имён написана со строчной буквы (`"артур"` окажется после `"Яков"` при посимвольном сравнении).
* **Так правильно:** передавать вторым аргументом правило сравнения строк: `.OrderBy(p => p.Name, StringComparer.OrdinalIgnoreCase)` или `StringComparer.CurrentCultureIgnoreCase`.

:::gap

## Под капотом и нюансы

### Устойчивая сортировка (*Stable Sort*) и интерфейс `IOrderedEnumerable<T>`

Методы `OrderBy` и `OrderByDescending` возвращают не обычный `IEnumerable<T>`, а специальный наследный интерфейс `IOrderedEnumerable<T>`. Именно поэтому методы `ThenBy` и `ThenByDescending` появляются в подсказках редактора только сразу после `OrderBy` — им нужен доступ к накопленному списку ключей сравнения.

Кроме того, сортировка в LINQ гарантированно является **устойчивой** (*stable*): если у двух элементов ключи сортировки полностью совпадают (и `ThenBy` не задан), они гарантированно сохранят свой исходный взаимный порядок из коллекции, в отличие от нестабильного `List<T>.Sort()`.

### Разворачивание вложенных списков через `SelectMany`

Если у каждого игрока есть свой список предметов (`List<string> Inventory`), обычный `players.Select(p => p.Inventory)` вернёт «список списков» (`IEnumerable<List<string>>`). Чтобы склеить все инвентари в единый плоский список всех предметов отряда, используют метод `SelectMany`:

```cs
// Превращает коллекцию коллекций в единый плоский список
List<string> allItems = players.SelectMany(p => p.Inventory).ToList();

```

### Шпаргалка по методам сортировки и проекции

| Метод | Назначение | Что возвращает | Меняет исходный список? |
| --- | --- | --- | --- |
| `OrderBy(key)` | Сортировка по возрастанию (`0 -> 9`, `А -> Я`) | `IOrderedEnumerable<T>` | Нет |
| `OrderByDescending(key)` | Сортировка по убыванию (`9 -> 0`, `Я -> А`) | `IOrderedEnumerable<T>` | Нет |
| `ThenBy(key)` / `ThenByDescending(key)` | Вторичная сортировка при совпадении первого ключа | `IOrderedEnumerable<T>` | Нет |
| `List<T>.Sort(...)` | Сортировка списка непосредственно на месте | `void` | **Да** |
| `Select(selector)` | Преобразование каждого элемента в новый вид или тип | `IEnumerable<TResult>` | Нет |
| `SelectMany(selector)` | Извлечение и склейка вложенных коллекций в один поток | `IEnumerable<TResult>` | Нет |
