# Агрегация (Count, Sum, Min, Max)

Как в одну строчку посчитать общий вес добычи в рюкзаке, найти самый дорогой предмет или узнать, сколько редких артефактов собрал игрок, не заводя десяток циклов `foreach` и промежуточных переменных?

:::gap

## Кратко

Методы агрегации из пространства имён `System.Linq` сводят целую коллекцию элементов к одному итоговому значению — числу или конкретному объекту. Метод `Count` подсчитывает количество элементов (всех или подходящих под условие), `Sum` складывает числовые значения, а `Min` и `Max` находят наименьший и наибольший показатель. Все эти методы выполняются немедленно в момент вызова, превращая громоздкие циклы подсчёта в читаемые однострочные выражения.

:::gap

## Быстрый пример

Посчитаем статистику по инвентарю игрока с помощью четырёх главных методов агрегации:

```cs
List<LootItem> loot =
[
    new("Зелье здоровья", Price: 50, Weight: 1, IsRare: false),
    new("Клинок Тени", Price: 1200, Weight: 4, IsRare: true),
    new("Кольцо Маны", Price: 650, Weight: 1, IsRare: true),
    new("Железный щит", Price: 300, Weight: 6, IsRare: false)
];

// 1. Count: общее количество и количество по условию
int totalCount = loot.Count();
int rareCount = loot.Count(item => item.IsRare);

// 2. Sum: общая стоимость всех предметов
int totalGold = loot.Sum(item => item.Price);

// 3. Min и Max: самый лёгкий вес и самая высокая цена
int minWeight = loot.Min(item => item.Weight);
int maxPrice = loot.Max(item => item.Price);

Console.WriteLine($"Всего вещей: {totalCount} (редких: {rareCount})"); // Всего вещей: 4 (редких: 2)
Console.WriteLine($"Общая ценность: {totalGold} золота");             // Общая ценность: 2200 золота
Console.WriteLine($"Мин. вес: {minWeight}, Макс. цена: {maxPrice}");  // Мин. вес: 1, Макс. цена: 1200

record LootItem(string Name, int Price, int Weight, bool IsRare);

```

:::gap

## Как это работает

При выполнении кода среда .NET проходит по коллекции и сворачивает элементы в единый результат:

1. **Подсчёт элементов (`Count()` и `Count(predicate)`).** Вызов без аргументов возвращает общее число элементов (`4`), а вызов с лямбда-условием `item => item.IsRare` проверяет каждый объект и считает только те, для которых условие вернуло `true` (`2`).
2. **Суммирование по полю (`Sum(item => item.Price)`).** Метод по очереди извлекает числовое свойство `Price` из каждого предмета и накапливает общую сумму (`50 + 1200 + 650 + 300 = 2200`).
3. **Поиск крайних значений (`Min` и `Max`).** Методы запоминают первое встреченное значение, сравнивают с ним все последующие и возвращают наименьшее (`1`) или наибольшее (`1200`) число.
4. **Немедленное выполнение (*Immediate Execution*).** В отличие от ленивых `Where` и `Select`, методы агрегации не откладывают работу на потом — они запускают перебор сразу в момент вызова и возвращают готовое число.

> [!TIP]
> Не пишите длинную цепочку `loot.Where(x => x.IsRare).Count()` — передавайте условие сразу внутрь `loot.Count(x => x.IsRare)`. Так код короче, а среде не приходится создавать промежуточный объект-итератор.

:::gap

## Грабли и частые ошибки

### 1. Падение `Min()` и `Max()` на пустой коллекции (`InvalidOperationException`)

* **Так упадёт:** вызвать `emptyList.Min()` или `emptyList.Max(x => x.Price)` на пустом списке (или после фильтра `Where`, который не нашёл ни одного элемента). Среда выбросит исключение `InvalidOperationException` («Последовательность не содержит элементов»).
* **Так правильно:** проверять коллекцию через `if (loot.Any())`, подставлять запасное значение через `loot.Select(x => x.Price).DefaultIfEmpty(0).Max()` или приводить число к Nullable-типу: `loot.Max(x => (int?)x.Price) ?? 0`.

### 2. Вызов `Sum()`, `Min()` или `Max()` на объектах без выбора поля

* **Так не скомпилируется или упадёт:** написать `loot.Sum()` для списка объектов `LootItem` (ошибка компиляции `CS1929`, так как непонятно, что именно складывать) или вызвать `loot.Max()` у класса, не реализующего интерфейс `IComparable<T>` (выбросит `ArgumentException` при запуске).
* **Так правильно:** всегда указывать конкретное числовое свойство в лямбде (`loot.Sum(x => x.Price)`) или использовать метод `MaxBy` для получения самого объекта.

### 3. Переполнение `int` при суммировании больших чисел (`OverflowException`)

* **Так упадёт:** вызвать `bigScores.Sum()` для массива целых чисел типа `int`, сумма которых превышает `2_147_483_647`. Внутри `Sum()` используется проверяемая арифметика (`checked`), поэтому при выходе за границу `int` программа аварийно завершится с `OverflowException`.
* **Так правильно:** явно расширить тип селектора до `long` или `decimal`: `bigScores.Sum(x => (long)x)`.

### 4. Проверка наличия элементов через `.Count() > 0` вместо `.Any()`

* **Так сработает неправильно:** писать `if (items.Where(...).Count() > 0)`. Для ленивой последовательности `Count()` честно переберёт все элементы до самого конца, даже если вам нужно было лишь узнать, пуста она или нет.
* **Так правильно:** всегда проверять непустоту через `if (items.Any(...))` — этот метод остановится на первом же найденном элементе.

:::gap

## Под капотом и нюансы

### Быстрый путь за `O(1)` внутри `Count()`

Когда вы вызываете `Count()` без условия на обычном списке `List<T>`, массиве `T[]` или словаре `Dictionary<TKey, TValue>`, LINQ не запускает медленный перебор в цикле. Под капотом вызывается оптимизация `Enumerable.TryGetNonEnumeratedCount()`, которая проверяет, реализует ли коллекция интерфейс `ICollection<T>` или `IReadOnlyCollection<T>`, и мгновенно возвращает готовое свойство `.Count` за `O(1)`. Однако при передаче условия `Count(x => ...)` полный проход по коллекции всё равно обязателен.

### Как получить сам объект с максимумом, а не число (`MaxBy` и `MinBy`)

Обычный `loot.Max(x => x.Price)` возвращает только число `1200`, но не сам предмет. Начиная с .NET 6 в LINQ появились методы `MaxBy` и `MinBy`, которые возвращают **сам объект целиком** (причём на пустой коллекции они не падают, а безопасно возвращают `null`):

```cs
LootItem? mostExpensive = loot.MaxBy(item => item.Price);
Console.WriteLine(mostExpensive?.Name); // Клинок Тени

```

### Шпаргалка по методам агрегации LINQ

| Метод | Что возвращает | Поведение на пустой коллекции | Примечание |
| --- | --- | --- | --- |
| `Count()` / `Count(pred)` | `int` (`long` для `LongCount`) | Возвращает `0` | Без условия работает за `O(1)` для списков и массивов |
| `Sum(selector)` | `int`, `long`, `double`, `decimal` | Возвращает `0` | Выбрасывает `OverflowException` при переполнении |
| `Min(selector)` / `Max(selector)` | Числовое или сравнимое значение | **Падает** (`InvalidOperationException`) | С Nullable-типом (`(int?)x.Price`) возвращает `null` |
| `MinBy(selector)` / `MaxBy(selector)` | Исходный объект `T?` | Возвращает `null` (для классов) | Возвращает первый объект с крайним значением ключа |
| `Average(selector)` | `double` (или `decimal` / `float`) | **Падает** (`InvalidOperationException`) | Даже для `int` результат имеет тип `double` |
| `Aggregate(func)` | Пользовательский итог | **Падает** без начального значения | Позволяет написать свою формулу свёртки (например, произведение) |
