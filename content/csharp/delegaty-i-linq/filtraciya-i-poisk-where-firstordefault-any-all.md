# Фильтрация и поиск (Where, FirstOrDefault, Any, All)

Как отобрать всех живых врагов в радиусе атаки, найти конкретного раненого союзника по условию или в одну строчку проверить, готов ли весь отряд к бою, не плодя десятки циклов `foreach` и временных списков?

:::gap

## Кратко

Методы расширения из пространства имён `System.Linq` позволяют фильтровать коллекции и искать в них элементы с помощью компактных лямбда-условий (*предикатов*). Метод `Where` отбирает все подходящие элементы в новую последовательность, `FirstOrDefault` находит первый совпавший объект (или безопасно возвращает `null`, если ничего не найдено), `Any` проверяет, подходит ли под условие **хотя бы один** элемент, а `All` убеждается, что условию соответствуют **абсолютно все** элементы коллекции.

:::gap

## Быстрый пример

Отфильтруем отряд героев, найдём первого раненого бойца и проверим общее состояние команды:

```cs
List<Unit> squad =
[
    new("Артур", Hp: 100, IsAlive: true),
    new("Лира", Hp: 35, IsAlive: true),
    new("Борис", Hp: 0, IsAlive: false)
];

// 1. Where: отбираем всех живых бойцов
var aliveUnits = squad.Where(u => u.IsAlive).ToList();
Console.WriteLine($"В строю: {aliveUnits.Count}"); // В строю: 2

// 2. FirstOrDefault: ищем первого раненого бойца (или null, если таких нет)
Unit? wounded = squad.FirstOrDefault(u => u.IsAlive && u.Hp < 50);
Console.WriteLine($"Нуждается в лечении: {wounded?.Name ?? "никто"}"); // Нуждается в лечении: Лира

// 3. Any: проверяем, есть ли в отряде хоть один павший боец
bool hasFallen = squad.Any(u => !u.IsAlive);
Console.WriteLine($"Есть павшие: {hasFallen}"); // Есть павшие: True

// 4. All: проверяем, все ли бойцы имеют полный запас здоровья
bool allFullHp = squad.All(u => u.Hp == 100);
Console.WriteLine($"Все здоровы на 100%: {allFullHp}"); // Все здоровы на 100%: False

record Unit(string Name, int Hp, bool IsAlive);

```

:::gap

## Как это работает

При выполнении кода среда .NET пропускает элементы коллекции через переданную лямбда-функцию и управляет перебором по следующим правилам:

1. **Предикат как условие отбора (`u => u.IsAlive`).** Все четыре метода принимают делегат `Func<T, bool>` — мини-функцию, которая получает очередной элемент `u` и возвращает `true` (подходит) или `false` (пропускаем).
2. **Неразрушающая фильтрация (`Where`).** Метод `Where` не удаляет элементы из исходного списка `squad`, а возвращает ленивую последовательность `IEnumerable<Unit>`, содержащую только живых героев. Вызов `.ToList()` сохраняет результат в новый готовый список.
3. **Безопасный поиск первого совпадения (`FirstOrDefault`).** Просматривает элементы по порядку сверху вниз и возвращает самый первый объект, для которого условие вернуло `true` (`Лира`). Если ни один элемент не подошёл, метод не роняет программу, а возвращает значение по умолчанию (`null` для классов).
4. **Мгновенные логические проверки (`Any` и `All`).** Метод `Any` возвращает `true` сразу на первом же совпадении (`Борис`), а `All` возвращает `false` на первом же несовпадении (`Лира` с 35 HP), не тратя время на просмотр оставшейся части списка.

> [!TIP]
> Чтобы просто проверить, есть ли в коллекции хоть какие-то элементы, используйте `squad.Any()` без аргументов вместо `squad.Count() > 0` — `Any()` заглянет только в самый первый элемент и сразу остановится, не пересчитывая всю последовательность.

:::gap

## Грабли и частые ошибки

### 1. Использование `First()` вместо `FirstOrDefault()` при поиске несуществующего элемента

* **Так упадёт:** написать `squad.First(u => u.Name == "Дракон")`, когда такого персонажа в списке нет. Метод `First()` требует минимум одно совпадение и при его отсутствии выбрасывает исключение `InvalidOperationException` («Последовательность не содержит элементов»).
* **Так правильно:** использовать `FirstOrDefault(...)` и безопасно обрабатывать возможный `null` с помощью операторов `?.` и `??` или проверки `if (unit is not null)`.

### 2. Ожидание, что `Where()` изменит исходный список на месте

* **Так сработает неправильно:** написать отдельной строкой `squad.Where(u => u.IsAlive);` и думать, что из `squad` удалились павшие бойцы. Методы LINQ никогда не модифицируют исходную коллекцию — без присваивания результата эта строчка просто ничего не сделает.
* **Так правильно:** записывать результат в новую переменную (`var alive = squad.Where(u => u.IsAlive).ToList();`) или использовать изменяющий метод самого списка `squad.RemoveAll(u => !u.IsAlive);`.

### 3. Многократный перебор одного и того же `Where` без `.ToList()`

* **Так сработает неправильно:** сохранить запрос `var filtered = bigList.Where(x => HeavyCheck(x));` и трижды пройтись по `filtered` в циклах или проверках `filtered.Count()`. Из-за отложенного выполнения тяжёлая проверка `HeavyCheck` будет запускаться заново при каждом обращении.
* **Так правильно:** если результат фильтрации нужен больше одного раза, сразу зафиксировать его в памяти вызовом `.ToList()` или `.ToArray()`.

### 4. Путаница с `FirstOrDefault` для значимых типов (`int`, `struct`)

* **Так сработает неправильно:** искать число в `List<int> numbers = [10, 20];` через `int found = numbers.FirstOrDefault(n => n > 50);` и считать, что в списке нашёлся ноль. Для `int` значением по умолчанию является `0`, поэтому отличить отсутствие элемента от реального нуля не получится.
* **Так правильно:** передавать собственное запасное значение вторым аргументом `numbers.FirstOrDefault(n => n > 50, -1)` (доступно начиная с .NET 6).

:::gap

## Под капотом и нюансы

### Отложенное (*Deferred*) и немедленное (*Immediate*) выполнение

В LINQ методы делятся на два лагеря по моменту запуска вычислений:

* **Отложенное выполнение (`Where`).** Сам вызов `squad.Where(...)` почти не тратит процессорного времени и не создаёт новый массив в памяти. Он возвращает специальный объект-итератор (`WhereListIterator`), который запоминает ссылку на список и условие. Реальная фильтрация начинается только тогда, когда вы запускаете `foreach` или вызываете `.ToList()`.
* **Немедленное выполнение (`FirstOrDefault`, `Any`, `All`).** Эти методы запускают цикл перебора сразу в момент вызова и используют **короткое замыкание** (*short-circuiting*): как только ответ становится очевидным, цикл прерывается через `break`, не просматривая остаток коллекции.

### `FirstOrDefault` против `SingleOrDefault`

Если вам нужно найти элемент по уникальному идентификатору (например, `Id == 42`) и вы хотите гарантировать, что дубликатов в базе нет, используйте `SingleOrDefault(x => x.Id == 42)`:

* `FirstOrDefault` вернёт первый найденный элемент, даже если в списке их десять штук.
* `SingleOrDefault` проверит всю коллекцию до конца и **выбросит исключение** `InvalidOperationException`, если подходящих элементов окажется больше одного.

### Шпаргалка по методам фильтрации и поиска LINQ

| Метод | Что возвращает | Когда останавливает перебор | Поведение, если ничего не найдено |
| --- | --- | --- | --- |
| `Where(pred)` | `IEnumerable<T>` (все совпадения) | Проходит всю коллекцию при переборе | Возвращает пустую последовательность |
| `FirstOrDefault(pred)` | `T?` (первый подходящий элемент) | На **первом** совпадении | Возвращает `null` (или `default` / запасное значение) |
| `First(pred)` | `T` (первый подходящий элемент) | На **первом** совпадении | Выбрасывает `InvalidOperationException` |
| `SingleOrDefault(pred)` | `T?` (единственный элемент) | Проходит до конца (ищет дубликаты) | Возвращает `null` (падает, если совпадений 2 и больше) |
| `Any(pred)` | `bool` | На **первом** совпадении (`true`) | Возвращает `false` |
| `All(pred)` | `bool` | На **первом** несовпадении (`false`) | Возвращает `true` (даже для пустой коллекции!) |
