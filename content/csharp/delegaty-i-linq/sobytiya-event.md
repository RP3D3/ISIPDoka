# События (event) в C#

Как оповестить интерфейс, систему достижений и звуковой движок о том, что герой получил урон, не связывая класс персонажа напрямую со всеми остальными системами игры?

:::gap

## Кратко

Событие (`event`) — это защищённая обёртка над делегатом, которая реализует паттерн «Издатель — Подписчик» (*Publisher — Subscriber*). Класс-издатель объявляет событие, а внешние классы-подписчики присоединяют к нему свои обработчики с помощью оператора `+=` и отключают их через `-=`. В отличие от обычного публичного поля-делегата, событие запрещает внешнему коду вызвать его напрямую или затереть чужие подписки присваиванием `=`. Это позволяет строить слабосвязанную архитектуру, где компоненты реагируют на изменения, ничего не зная друг о друге.

:::gap

## Быстрый пример

Создадим класс персонажа `Hero` с событием получения урона и подпишем на него обновление интерфейса и проверку достижения:

```cs
Hero hero = new("Артур", 100);

// Подписчик 1: интерфейс (именованный метод, чтобы потом можно было отписаться)
hero.OnDamaged += UpdateHealthBar;

// Подписчик 2: система достижений (лямбда-выражение)
hero.OnDamaged += hp =>
{
    if (hp <= 20) Console.WriteLine("[ДОСТИЖЕНИЕ] На волосок от смерти!");
};

hero.TakeDamage(30); // [UI] Здоровье обновлено: 70
hero.TakeDamage(55); // [UI] Здоровье обновлено: 15 -> [ДОСТИЖЕНИЕ] На волосок от смерти!

// Отписываем интерфейс от уведомлений
hero.OnDamaged -= UpdateHealthBar;
hero.TakeDamage(5);  // Сработает только проверка достижения

void UpdateHealthBar(int currentHp) => Console.WriteLine($"[UI] Здоровье обновлено: {currentHp}");

class Hero(string name, int hp)
{
    public string Name { get; } = name;
    public int Hp { get; private set; } = hp;

    // Событие: снаружи доступны только += и -=
    public event Action<int>? OnDamaged;

    public void TakeDamage(int amount)
    {
        Hp = Math.Max(0, Hp - amount);
        OnDamaged?.Invoke(Hp); // Вызвать событие может только сам класс Hero
    }
}

```

:::gap

## Как это работает

При выполнении кода среда .NET разделяет права на управление подписками и запуск уведомлений:

1. **Объявление события (`public event Action<int>? OnDamaged`).** Ключевое слово `event` ставится перед типом делегата (`Action<int>`). Знак `?` указывает, что пока на событие никто не подписался, оно равно `null`.
2. **Подписка на уведомления (`+=`).** Внешний код добавляет свои обработчики в список получателей. При каждом `+=` формируется цепочка вызовов, и все подписанные методы будут запущены по очереди в порядке подписки.
3. **Запуск внутри издателя (`OnDamaged?.Invoke(Hp)`).** Когда здоровье уменьшается, метод `TakeDamage` проверяет, есть ли хоть один подписчик (`?.`), и оповещает всех сразу, передавая актуальное значение `Hp`.
4. **Отписка (`-=`).** Оператор `-=` находит указанный метод в цепочке подписчиков и удаляет его, поэтому при следующем ударе `UpdateHealthBar` уже не вызовется.

> [!TIP]
> Для внутренней логики игр и приложений удобнее всего объявлять события на базе стандартных `Action` и `Action<T>`. Классический шаблон `EventHandler<TEventArgs>` используйте при создании публичных библиотек или элементов пользовательского интерфейса.

:::gap

## Грабли и частые ошибки

### 1. Попытка вызвать событие или перезаписать его через `=` снаружи (`CS0070`)

* **Так не скомпилируется:** написать в `Program.cs` строку `hero.OnDamaged(50);` или `hero.OnDamaged = UpdateHealthBar;`. Компилятор запрещает внешнему коду запускать чужое событие или стирать список подписчиков через `=` (ошибка `CS0070`).
* **Так правильно:** снаружи использовать только `+=` и `-=`, а вызов `OnDamaged?.Invoke(...)` оставлять строго внутри самого класса `Hero`.

### 2. Утечка памяти из-за забытой отписки (`-=`)

* **Так сработает неправильно:** подписать временное окно интерфейса или врага на событие глобального менеджера игры (`GameManager.OnTick += enemy.Update`) и уничтожить объект врага, забыв отписаться. Пока жив глобальный `GameManager`, он хранит ссылку на метод врага внутри события и не даёт сборщику мусора удалить объект из памяти.
* **Так правильно:** всегда отписываться (`-=`) от событий долгоживущих объектов при уничтожении подписчика (например, в методе `Dispose()`).

### 3. Попытка отписаться от анонимной лямбды

* **Так сработает неправильно:** написать `hero.OnDamaged += hp => Console.WriteLine(hp);`, а ниже попытаться отписаться такой же строкой `hero.OnDamaged -= hp => Console.WriteLine(hp);`. Каждое лямбда-выражение компилируется в отдельный скрытый метод, поэтому `-=` не найдёт совпадения и ничего не удалит.
* **Так правильно:** если от события потребуется отписываться, оформлять обработчик как обычный метод или сохранять лямбду в переменную `Action<int> handler = ...` и передавать её в `+=` и `-=`.

### 4. Падение одного подписчика обрывает оповещение остальных

* **Так упадёт:** если первый из трёх подписчиков выбросит неперехваченное исключение, выполнение `OnDamaged?.Invoke(Hp)` немедленно прервётся, и второй с третьим подписчиком вообще не узнают о событии.
* **Так правильно:** в критически важных системах перебирать подписчиков вручную через `OnDamaged?.GetInvocationList()` и оборачивать каждый вызов в свой блок `try / catch`.

:::gap

## Под капотом и нюансы

### Во что компилируется `event` (IL-код)

На уровне промежуточного языка IL событие устроено почти так же, как свойство над полем. Когда вы пишете `public event Action<int>? OnDamaged;`, компилятор генерирует:

1. Приватное поле-делегат `private Action<int>? OnDamaged;`, доступное только внутри класса-издателя.
2. Два публичных метода: `add_OnDamaged(Action<int> value)` и `remove_OnDamaged(Action<int> value)`.

Внутри этих методов среда использует `Delegate.Combine` и `Delegate.Remove` в связке с атомарной операцией `Interlocked.CompareExchange`, благодаря чему подписка и отписка в C# по умолчанию являются **потокобезопасными**.

### Стандартный паттерн .NET: `EventHandler<TEventArgs>`

В стандартной библиотеке .NET (WinForms, WPF, ASP.NET) принят единый формат событий, где первым параметром передаётся сам отправитель (`object? sender`), а вторым — класс с данными о событии, унаследованный от `EventArgs`:

```cs
record DamageEventArgs(int Damage, int RemainingHp);

class Boss
{
    public event EventHandler<DamageEventArgs>? Damaged;

    public void Hit(int dmg) => Damaged?.Invoke(this, new DamageEventArgs(dmg, 450));
}

```

### Сравнение публичного делегата и события (`event`)

| Критерий | Публичный делегат (`public Action? OnHit;`) | Событие (`public event Action? OnHit;`) |
| --- | --- | --- |
| Подписка и отписка (`+=` / `-=`) | Разрешены везде | Разрешены везде |
| Перезапись через `=` снаружи | **Разрешена** (может стереть чужие подписки) | **Запрещена** компилятором (`CS0070`) |
| Вызов `.Invoke()` снаружи | **Разрешён** (кто угодно может подделать сигнал) | **Запрещён** компилятором (`CS0070`) |
| Использование в интерфейсах | Только как свойство `{ get; set; }` | Поддерживается напрямую (`event Action OnHit;`) |
| Главный сценарий | Передача колбэка в конкретный метод | Уведомление неограниченного числа подписчиков |
