# Базовый класс object: корень всех типов

Почему любой объект в C# умеет превращаться в строку, как научить обычные классы сравниваться по содержимому полей и зачем словарям правильный хеш-код?

В C# абсолютно каждый тип данных — будь то ваш собственный `class`, структура `struct`, перечисление `enum`, массив или даже число `int` — неявно наследуется от встроенного базового класса `System.Object` (псевдоним `object`). Благодаря этому любой объект в программе изначально обладает набором универсальных методов: `ToString()`, `Equals()` и `GetHashCode()`. Эти методы объявлены как `virtual`, поэтому их можно переопределить (`override`) в своём классе, чтобы задать понятный текстовый вывод и научить коллекции сравнивать объекты по их данным, а не по адресу в памяти.

## Главные методы класса `System.Object`

| Метод | Поведение по умолчанию (для `class`) | Зачем переопределяют через `override` |
| --- | --- | --- |
| `ToString()` | Возвращает полное имя типа (например, `MyApp.Product`) | Чтобы выводить читаемое описание объекта в консоль, логи и отладчик |
| `Equals(object? obj)` | Сравнивает ссылки (являются ли две переменные одним объектом в куче) | Чтобы считать разными экземплярами равными, если у них совпадают ключевые поля |
| `GetHashCode()` | Генерирует числовой код на основе внутренней идентичности ссылки | Чтобы корректно хранить и находить объекты в `Dictionary` и `HashSet` за `O(1)` |
| `GetType()` | *(Невиртуальный)* Возвращает метаданные реального типа объекта (`Type`) | Используется для точной проверки типа во время выполнения программы |

## Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // Создаём два разных объекта в куче с одинаковым артикулом (Isbn)
        Book first = new Book("978-5-4461", "CLR via C#");
        Book second = new Book("978-5-4461", "CLR via C# (переиздание)");

        // 1. Работает переопределённый ToString() (вызывается автоматически внутри Console.WriteLine)
        Console.WriteLine(first);

        // 2. Сравнение по значению через Equals() возвращает True, хотя ссылки в памяти разные
        Console.WriteLine($"Равны через Equals: {first.Equals(second)}");
        Console.WriteLine($"Один объект в памяти: {ReferenceEquals(first, second)}");

        // 3. Согласованные Equals и GetHashCode позволяют HashSet и Dictionary находить дубликаты
        HashSet<Book> library = new HashSet<Book> { first };
        Console.WriteLine($"Есть ли книга в каталоге: {library.Contains(second)}"); // True!
    }
}

class Book
{
    public string Isbn { get; }
    public string Title { get; }

    public Book(string isbn, string title)
    {
        Isbn = isbn;
        Title = title;
    }

    // Удобное строковое представление объекта
    public override string ToString() => $"[{Isbn}] «{Title}»";

    // Сравнение по уникальному идентификатору книги
    public override bool Equals(object? obj) =>
        obj is Book other && Isbn == other.Isbn;

    // Хеш-код вычисляется строго по тем же неизменяемым полям, что участвуют в Equals
    public override int GetHashCode() => HashCode.Combine(Isbn);
}

```

## Важные нюансы

* **Золотой контракт `Equals` и `GetHashCode`:** если два объекта считаются равными через `Equals()`, их хеш-коды обязаны совпадать. Если переопределить `Equals()`, но забыть про `GetHashCode()`, компилятор выдаст предупреждение `CS0659`, а `Dictionary` и `HashSet` перестанут находить существующие ключи, так как будут искать их в разных корзинах памяти.
* **Используйте в `GetHashCode()` только неизменяемые поля:** вычисляйте хеш через встроенный метод `HashCode.Combine(Field1, Field2)` строго по полям `readonly` или свойствам только для чтения. Если поле изменится после добавления объекта в словарь, хеш-код станет другим и объект «потеряется» внутри коллекции.
* **Разница между `Equals()`, `==` и `ReferenceEquals()`:** переопределение `Equals()` у обычного `class` не меняет поведение оператора `==` — по умолчанию `==` продолжает сравнивать адреса ссылок (в отличие от `record`, где компилятор сам генерирует и `Equals`, и перегрузку `==`). Чтобы принудительно проверить, указывают ли две переменные на один и тот же участок кучи, используйте статический метод `object.ReferenceEquals(a, b)`.
* **Связь с теорией и соседними темами:** устройство корзин и коллизий при работе `GetHashCode()` разобрано в теоретическом разделе (*Хеш-таблицы*), механизм переопределения — в карточке *virtual и override*, а автоматическая генерация всех трёх методов — в карточке *Записи (record)*.
