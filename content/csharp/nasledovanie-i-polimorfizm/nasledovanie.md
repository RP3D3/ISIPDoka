# Наследование: создание иерархии классов

Как не переписывать общие поля и методы в похожих классах заново, а вынести их в один родительский класс и расширить в наследниках?

**Наследование** (*inheritance*) — это механизм объектно-ориентированного программирования, позволяющий создать новый класс на основе уже существующего. Исходный класс называют **базовым** (родительским), а новый — **производным** (дочерним). Наследник автоматически получает все открытые (`public`) и защищённые (`protected`) поля, свойства и методы родителя, добавляя к ним свои уникальные характеристики и поведение.

## Ключевые инструменты наследования в C#

| Инструмент | Синтаксис | Назначение в иерархии |
| --- | --- | --- |
| `:` *(двоеточие)* | `class Developer : Employee` | Указывает, что класс `Developer` наследуется от базового класса `Employee` |
| `protected` | `protected decimal BaseSalary;` | Открывает доступ к члену внутри самого класса и всех его наследников, скрывая от внешнего кода |
| `base` | `: base(name)` / `base.Work()` | Обращается к конструктору или методу родительского класса изнутри наследника |
| `sealed` | `sealed class TeamLead : Developer` | Запечатывает класс — запрещает любым другим классам наследоваться от него дальше |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        Developer dev = new Developer("Алексей", 120000m, "C#");

        // Вызываем метод, унаследованный от базового класса Employee
        dev.PrintBadge();

        // Вызываем собственный метод класса Developer, использующий protected-поле родителя
        Console.WriteLine($"Итоговая выплата: {dev.CalculateSalary()} руб.");

        // ❌ Ошибка компиляции (CS0122): protected-поле недоступно из внешнего кода
        // Console.WriteLine(dev.BaseSalary);
    }
}

// Базовый (родительский) класс
class Employee
{
    public string Name { get; }

    // protected: доступно внутри Employee и во всех классах-наследниках
    protected decimal BaseSalary;

    public Employee(string name, decimal baseSalary)
    {
        Name = name;
        BaseSalary = baseSalary;
    }

    public void PrintBadge()
    {
        Console.WriteLine($"Сотрудник: {Name}");
    }
}

// Производный запечатанный класс: наследует Employee, но от самого Developer наследоваться уже нельзя
sealed class Developer : Employee
{
    public string MainLanguage { get; }

    // Передаём общие параметры в конструктор базового класса через : base(...)
    public Developer(string name, decimal baseSalary, string mainLanguage)
        : base(name, baseSalary)
    {
        MainLanguage = mainLanguage;
    }

    public decimal CalculateSalary()
    {
        // Напрямую используем унаследованное protected-поле BaseSalary
        return BaseSalary + 25000m;
    }
}

```

## Важные нюансы

* **Только одиночное наследование классов:** в C# класс может иметь строго одного прямого родителя (`class B : A`). Множественное наследование от нескольких классов сразу (`class C : A, B`) запрещено, чтобы избежать конфликтов одинаковых полей и методов (для объединения нескольких ролей используют интерфейсы).
* **Порядок выполнения конструкторов:** при создании дочернего объекта через `new` сначала всегда срабатывает конструктор базового класса, и только потом — конструктор наследника. Если у родителя нет пустого конструктора без параметров, наследник обязан явно вызвать подходящий родительский конструктор через `: base(...)`.
* **Приватные поля наследуются, но не видны:** `private`-поля родителя физически присутствуют в памяти внутри каждого дочернего объекта, однако напрямую обратиться к ним из наследника нельзя — для этого используют модификатор `protected` или открытые свойства базового класса.
* **Связь со следующими темами:** наследование избавляет от дублирования кода (*DRY*), но глубокие иерархии делают архитектуру жёсткой (*Наследование против Композиции* и *Принцип подстановки Лисков — LSP*). В следующей карточке разберём, как менять поведение унаследованных методов через `virtual` и `override`.
