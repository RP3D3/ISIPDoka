# Интерфейсы (interface): контракты поведения

Как заставить совершенно разные классы гарантированно поддерживать один и тот же набор действий и обойти запрет на множественное наследование в C#?

**Интерфейс** (`interface`) — это чистый контракт, который описывает, *что* объект умеет делать (набор методов, свойств или событий), но не диктует, *как* именно это устроено внутри. В отличие от наследования классов, где дочерний класс может иметь строго одного родителя, любой `class` или `struct` способен реализовать **сколько угодно интерфейсов одновременно** (например, быть одновременно `INotifiable`, `IExportable` и `IComparable`).

## Сравнение интерфейса и абстрактного класса

| Критерий | Интерфейс (`interface`) | Абстрактный класс (`abstract class`) |
| --- | --- | --- |
| **Назначение** | Описывает роль и возможности («умеет выгружаться», «можно сравнить») | Задаёт общую природу и родство («является платежом», «является сотрудником») |
| **Множественность** | Класс или структура могут реализовать **сколько угодно** интерфейсов сразу | Класс может унаследоваться **строго от одного** базового класса |
| **Поля и конструкторы** | Не может содержать обычных полей состояния и конструкторов | Может хранить любые поля (`private`, `protected`) и иметь конструкторы |
| **Модификаторы членов** | По умолчанию все члены публичные (`public`), слово `override` не пишется | Поддерживает `public`, `protected`, `internal`; требует ключевое слово `override` |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        InvoiceReport report = new InvoiceReport("Отчёт за квартал", 450000m);
        ServerAlert alert = new ServerAlert("Высокая нагрузка на CPU");

        // Полиморфизм через интерфейс: объединяем разнородные классы по общей способности
        INotifiable[] queue = { report, alert };
        foreach (INotifiable item in queue)
        {
            item.SendNotification("admin@company.ru");
        }

        // Этот же объект выступает и в роли другого интерфейса
        IExportable exportable = report;
        Console.WriteLine($"CSV-строка: {exportable.ExportToCsv()}");

        // ❌ Ошибка компиляции (CS0144): создать экземпляр интерфейса через new нельзя
        // INotifiable raw = new INotifiable();
    }
}

// Контракт 1: способность отправлять уведомления (имена принято начинать с заглавной I)
interface INotifiable
{
    void SendNotification(string recipient);
}

// Контракт 2: способность выгружаться в CSV
interface IExportable
{
    string ExportToCsv();
}

// Один класс может реализовать сразу несколько интерфейсов через запятую
class InvoiceReport : INotifiable, IExportable
{
    public string Title { get; }
    public decimal TotalAmount { get; }

    public InvoiceReport(string title, decimal totalAmount)
    {
        Title = title;
        TotalAmount = totalAmount;
    }

    // Реализация метода из INotifiable (модификатор public обязателен, override не нужен)
    public void SendNotification(string recipient)
    {
        Console.WriteLine($"[Отчёт «{Title}»] Отправлен на {recipient}");
    }

    // Реализация метода из IExportable
    public string ExportToCsv() => $"{Title};{TotalAmount}";
}

class ServerAlert : INotifiable
{
    public string Message { get; }
    public ServerAlert(string message) => Message = message;

    public void SendNotification(string recipient)
    {
        Console.WriteLine($"[Тревога для {recipient}]: {Message}");
    }
}

```

## Важные нюансы

* **Именование и ошибка неполного контракта (`CS0535`):** по соглашению C# имена всех интерфейсов начинаются с заглавной буквы `I` (`IDisposable`, `IEnumerable`, `IComparable`). Если класс подписался на интерфейс, но не реализовал хотя бы один его член с модификатором `public`, компилятор выдаст ошибку `CS0535`.
* **Поддержка структурами и цена упаковки:** в отличие от абстрактных классов, интерфейсы могут реализовывать даже структуры (`struct` и `record struct`). Однако при сохранении структуры в переменную интерфейсного типа происходит упаковка (*boxing*) в куче (*Heap*).
* **Явная реализация интерфейса (*Explicit Implementation*):** если класс реализует два интерфейса с одинаковыми именами методов (например, `IPrinter.Start()` и `IScanner.Start()`), конфликт разрешают через явное указание имени интерфейса без слова `public`: `void IPrinter.Start() { ... }`. Вызвать такой метод можно только после приведения объекта к нужному интерфейсу.
* **Связь со следующими темами:** интерфейсы лежат в основе *принципа разделения интерфейса (ISP)* и *инверсии зависимостей (DIP)*, позволяя легко подменять реальные модули заглушками при тестировании (см. раздел *Принципы, паттерны и архитектура* → *Принципы SOLID* и следующую карточку: *Приведение типов: is, as и сопоставление с образцом*).
