# Приведение типов: `is`, `as` и сопоставление с образцом

Как безопасно узнать реальный тип объекта, скрытого за базовым классом или интерфейсом, и получить доступ к его уникальным свойствам без риска уронить программу?

При работе через переменную базового класса или интерфейса компилятор видит только общие члены контракта, даже если в куче (*Heap*) лежит конкретный наследник со своими полями и методами. Преобразование от наследника к родителю (**восходящее приведение**, *upcasting*) выполняется неявно и всегда безопасно, но обратный переход (**нисходящее приведение**, *downcasting*) требует проверки реального типа объекта во время выполнения. Для этого в C# используют защищённые операторы `is`, `as` и механизм **сопоставления с образцом** (*pattern matching*), который позволяет проверять тип и сразу извлекать свойства объекта.

## Сравнение способов приведения типов

| Конструкция | Синтаксис | Поведение при несовпадении типа | Когда применять |
| --- | --- | --- | --- |
| **Явное приведение** | `(Circle)shape` | Выбрасывает исключение `InvalidCastException` | Только когда вы на 100% уверены в типе объекта (иначе программа упадёт) |
| **Оператор `as`** | `shape as Circle` | Возвращает `null` без исключения | Когда нужно получить ссылку или `null` для последующей работы через `?.` или `??` |
| **Оператор `is` с переменной** | `if (shape is Circle c)` | Возвращает `false`, ветка `if` не выполняется | Основной способ безопасной проверки типа с мгновенным созданием типизированной переменной |
| **Сопоставление в `switch`** | `shape switch { Circle c => ... }` | Переходит к следующей ветке или к образцу `_` | Когда нужно обработать сразу несколько разных наследников и проверить их свойства |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Восходящее приведение (upcasting): наследники неявно помещаются в массив базового типа
        Shape[] shapes =
        {
            new Circle(10),
            new Rectangle(4, 5),
            new Rectangle(7, 7)
        };

        foreach (Shape shape in shapes)
        {
            // 1. Оператор is: проверяем реальный тип и сразу записываем результат в переменную circle
            if (shape is Circle circle)
            {
                Console.WriteLine($"Круг с радиусом {circle.Radius}");
            }

            // 2. Сопоставление с образцом (pattern matching) с проверкой свойств объекта
            string description = shape switch
            {
                Circle { Radius: >= 10 } big => $"Крупный круг (R = {big.Radius})",
                Rectangle r when r.Width == r.Height => $"Квадрат со стороной {r.Width}",
                Rectangle r => $"Прямоугольник {r.Width}x{r.Height}",
                _ => "Неизвестная фигура"
            };
            Console.WriteLine($"Описание: {description}");
        }

        // 3. Оператор as: при несовпадении типа не бросает исключение, а возвращает null
        Rectangle? maybeRect = shapes[0] as Rectangle;
        Console.WriteLine($"Первая фигура — прямоугольник: {maybeRect != null}");

        // ❌ Ошибка во время выполнения (InvalidCastException): shapes[0] на самом деле Circle
        // Rectangle broken = (Rectangle)shapes[0];
    }
}

abstract class Shape { }

class Circle : Shape
{
    public double Radius { get; }
    public Circle(double radius) => Radius = radius;
}

class Rectangle : Shape
{
    public double Width { get; }
    public double Height { get; }
    public Rectangle(double width, double height) => (Width, Height) = (width, height);
}

```

## Важные нюансы

* **Почему `is Type variable` лучше связки `as` и `if (x != null)`:** современный оператор `is` объединяет проверку типа и создание типизированной переменной в одно действие. Это избавляет от лишней проверки на `null` и исключает риск случайно обратиться к неинициализированной ссылке.
* **Ограничение оператора `as` для типов значений:** конструкцию `obj as int` или `obj as Point` нельзя скомпилировать (ошибка `CS0077`), потому что при неудаче `as` обязан вернуть `null`, а обычные типы значений не поддерживают пустоту — для них используют `obj as int?` или `obj is int number`.
* **Образец свойств (*Property Pattern*) и защита от `null`:** запись `if (shape is Circle { Radius: 5 })` одновременно проверяет, что переменная `shape` не равна `null`, что её реальный тип — `Circle`, и что свойство `Radius` равно `5`.
* **Связь со следующей темой:** если в коде постоянно приходится проверять конкретные типы наследников через `is` и `switch`, подумайте, нельзя ли перенести эту логику в `virtual`-метод базового класса — это сделает архитектуру гибче (см. раздел *Принципы, паттерны и архитектура* → *Принципы SOLID (O — OCP)* и следующую обобщающую карточку группы: *Наследование и полиморфизм*).
