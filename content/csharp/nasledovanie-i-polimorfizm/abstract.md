# Абстрактные классы (abstract): каркас для наследников

Как запретить прямое создание базового класса-заготовки и заставить каждый дочерний класс обязательно реализовать недостающие методы по-своему?

**Абстрактный класс** (`abstract class`) — это незавершённый базовый класс, который служит общим фундаментом для наследников, но не позволяет создавать свои экземпляры напрямую через `new`. Внутри такого класса можно объединить обычные поля, конструкторы и готовую общую логику с **абстрактными методами и свойствами** (`abstract`), у которых нет тела — только сигнатура. Любой обычный класс-наследник обязан предоставить собственную реализацию (`override`) всех абстрактных членов родителя.

## Сравнение методов внутри абстрактного базового класса

| Вид члена класса | Реализация в родителе | Обязанность наследника | Когда применять |
| --- | --- | --- | --- |
| **Обычный метод** | Полностью написана | Использует как есть, менять нельзя | Когда алгоритм одинаков для всех наследников без исключений |
| **Виртуальный (`virtual`)** | Есть логика по умолчанию | Может переопределить (`override`), но не обязан | Когда базовое поведение подходит большинству, но некоторым нужно своё |
| **Абстрактный (`abstract`)** | Отсутствует (только заголовок и `;`) | **Обязан** реализовать через `override` | Когда у родителя нет универсальной логики и каждый наследник обязан задать свою |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // ❌ Ошибка компиляции (CS0144): нельзя создать экземпляр абстрактного класса напрямую
        // Payment raw = new Payment(1000m);

        // Переменную абстрактного типа можно использовать для полиморфного хранения наследников
        Payment[] payments =
        {
            new CardPayment(2500m, "4276 **** 9812"),
            new SbpPayment(1400m, "+7 (999) 123-45-67")
        };

        foreach (Payment payment in payments)
        {
            payment.Execute();
        }
    }
}

// Абстрактный класс: задаёт общие данные (Amount) и общий сценарий оплаты (Execute)
abstract class Payment
{
    public decimal Amount { get; }

    // Конструктор абстрактного класса обычно делают protected, так как вызвать его может только наследник
    protected Payment(decimal amount)
    {
        Amount = amount;
    }

    // Обычный метод: общая для всех наследников последовательность шагов
    public void Execute()
    {
        Console.WriteLine($"Инициализация платежа на сумму {Amount} руб...");
        ProcessTransaction();
        Console.WriteLine("Чек сформирован.\n");
    }

    // Абстрактный метод: тела нет, каждый способ оплаты обязан реализовать его сам
    protected abstract void ProcessTransaction();
}

class CardPayment : Payment
{
    public string MaskedCard { get; }

    public CardPayment(decimal amount, string maskedCard) : base(amount)
    {
        MaskedCard = maskedCard;
    }

    protected override void ProcessTransaction()
    {
        Console.WriteLine($"Списание с банковской карты {MaskedCard} через эквайринг.");
    }
}

class SbpPayment : Payment
{
    public string PhoneNumber { get; }

    public SbpPayment(decimal amount, string phoneNumber) : base(amount)
    {
        PhoneNumber = phoneNumber;
    }

    protected override void ProcessTransaction()
    {
        Console.WriteLine($"Перевод по СБП на номер {PhoneNumber} без комиссии.");
    }
}

```

## Важные нюансы

* **Неявная виртуальность абстрактных членов:** любой метод или свойство с модификатором `abstract` автоматически считается виртуальным, поэтому писать `abstract virtual` запрещено (ошибка компиляции), а в наследнике для реализации всегда используется слово `override`.
* **Наказание за неполную реализацию (`CS0534`):** если дочерний класс унаследовался от абстрактного родителя, но не переопределил хотя бы один его абстрактный метод, компилятор выдаст ошибку `CS0534` — либо допишите недостающий `override`, либо объявите сам дочерний класс тоже как `abstract`.
* **Состояние и конструкторы:** несмотря на невозможность вызвать `new Payment()`, абстрактный класс имеет полноценные поля, автосвойства и конструкторы, которые вызываются при создании наследника через `: base(...)`.
* **Связь со следующими темами:** абстрактный класс напрямую воплощает принцип *абстракции*, а если нужно описать только общий контракт действий без общих полей и конструкторов — используют интерфейсы (см. раздел *Принципы, паттерны и архитектура* → *Абстракция* и следующую карточку: *Интерфейсы*).
