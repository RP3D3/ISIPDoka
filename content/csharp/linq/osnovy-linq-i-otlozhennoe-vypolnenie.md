# Основы LINQ и отложенное выполнение

Как описывать сложную фильтрацию и преобразование коллекций в несколько читаемых строк без вложенных циклов `foreach` и почему запрос LINQ не выполняется в момент объявления?

**LINQ** (*Language Integrated Query* — интегрированный язык запросов) позволяет работать с массивами, списками и любыми последовательностями `IEnumerable<T>` в **декларативном стиле**: вы описываете *что* нужно получить, а не *как* крутить циклы и накапливать временные списки. Запросы можно записывать двумя равнозначными способами — через цепочку методов расширения (**синтаксис методов**, *Method Syntax*) или SQL-подобными выражениями (**синтаксис запросов**, *Query Syntax*). Главная особенность LINQ — **отложенное выполнение** (*deferred execution*): при вызове `Where` или `Select` программа только строит план запроса, а реальный перебор элементов запускается лишь при материализации результата (в цикле `foreach` или при вызове `ToList()`, `Count()`).

## Сравнение форм записи и режимов выполнения LINQ

| Понятие / форма | Синтаксис / пример | Как работает и когда применять |
| --- | --- | --- |
| **Синтаксис методов** *(Method Syntax)* | `items.Where(x => x > 0).Select(x => x * 2)` | Основной стандарт в C# — использует методы расширения `System.Linq` и лямбда-выражения |
| **Синтаксис запросов** *(Query Syntax)* | `from x in items where x > 0 select x * 2` | SQL-подобная запись; удобна при сложных вложенных циклах и соединениях (`join`) |
| **Отложенное выполнение** *(Deferred)* | `Where`, `Select`, `OrderBy`, `Skip`, `Take` | Не запускает перебор сразу; вычисляет элементы лениво при каждом обращении к запросу |
| **Немедленное выполнение** *(Immediate)* | `ToList()`, `ToArray()`, `Count()`, `First()` | Мгновенно запускает запрос, материализует данные в память и фиксирует результат |

## Пример кода

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        List<int> numbers = new List<int> { 5, 12, 8, 20, 3, 15 };

        // 1. Синтаксис методов (Method Syntax) — строит план запроса, но ещё НЕ фильтрует список
        IEnumerable<int> deferredQuery = numbers
            .Where(n => n > 10)
            .Select(n => n * 10);

        // 2. Синтаксис запросов (Query Syntax) — компилируется в те же вызовы Where и Select
        IEnumerable<int> querySyntax =
            from n in numbers
            where n > 10
            select n * 10;

        // 3. Немедленное выполнение (материализация): фиксируем текущий снимок в отдельный список
        List<int> snapshot = deferredQuery.ToList();

        // Добавляем элемент в исходный список ПОСЛЕ объявления запроса
        numbers.Add(30);

        Console.Write("Отложенный запрос (увидел 30): ");
        foreach (int item in deferredQuery)
            Console.Write($"{item} "); // 120 200 150 300

        Console.Write("\nСнимок ToList() (остался прежним): ");
        foreach (int item in snapshot)
            Console.Write($"{item} "); // 120 200 150
        Console.WriteLine();

        // ❌ Ловушка повторного перечисления (Multiple Enumeration):
        // Без ToList() цепочка Where/Select выполнится заново при каждом обращении к querySyntax
        // int count = querySyntax.Count();
        // int first = querySyntax.First();
    }
}

```

## Важные нюансы

* **Отложенное выполнение и актуальность данных:** запрос `IEnumerable<T>` хранит не готовые элементы, а сам рецепт их получения (цепочку итераторов на базе `yield`). Если добавить или изменить элемент в исходном `List<T>` *после* создания запроса, но *до* цикла `foreach`, изменения попадут в выборку. Чтобы зафиксировать снимок данных на текущий момент, вызывайте `.ToList()` или `.ToArray()`.
* **Риск повторного перечисления (*Multiple Enumeration*):** если пройтись по отложенному запросу `IEnumerable<T>` дважды (например, сначала проверить `query.Any()`, а затем обойти в `foreach`), вся цепочка фильтров и вычислений выполнится с нуля два раза. Когда результат нужен неоднократно, материализуйте его один раз в коллекцию через `ToList()`.
* **Синтаксис методов против синтаксиса запросов:** компилятор переводит любой *Query Syntax* (`from ... where ... select`) в обычные вызовы методов (`Where`, `Select`) ещё на этапе сборки — разницы в скорости нет. На практике стандартом является *Method Syntax*, так как многие операторы (`Take`, `Distinct`, `FirstOrDefault`, `Count`) вообще не имеют ключевых слов в синтаксисе запросов.
* **Связь с теорией и следующей темой:** ленивая природа LINQ работает прямо поверх контракта `IEnumerable<T>` и генераторов `yield` (см. группу 150 *Обобщения и контракты*), а в следующей карточке мы подробно разберём главные операторы отбора и преобразования данных (*Фильтрация и проекция: `Where` и `Select*`).
