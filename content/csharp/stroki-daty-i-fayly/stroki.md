# Строки в C#: неизменяемость, сравнение и форматирование

Почему любое изменение строки в C# создаёт новый объект в памяти, как сравнивать текст без багов региональных настроек и как записывать многострочные шаблоны без экранирования кавычек?

Тип `string` (псевдоним `System.String`) представляет собой **неизменяемую** (*immutable*) последовательность символов Unicode в кодировке UTF-16. После создания строку невозможно отредактировать на месте: любые методы вроде `Replace`, `Trim` или `ToUpper` всегда выделяют память в управляемой куче (*Heap*) под новый экземпляр. Для удобной сборки текста используют интерполяцию `$"..."` и необработанные строковые литералы (`"""..."""`, появившиеся в C# 11), а для надёжного сравнения — явное указание правил через `StringComparison`, исключающее ошибки из-за системной локали.

## Ключевые возможности и правила работы со строками

| Инструмент / операция | Синтаксис / пример | Назначение и особенности |
| --- | --- | --- |
| **Проверка на пустоту** | `string.IsNullOrWhiteSpace(input)` | Безопасно проверяет строку сразу на `null`, `""` и любые пробельные символы |
| **Интерполяция строк** | `$"Заказ #{id}: {price:F2} руб."` | Встраивает выражения и спецификаторы формата прямо в текст |
| **Необработанные литералы** *(C# 11+)* | `"""{"role": "admin"}"""` | Позволяют писать JSON, SQL и пути без экранирования `\"` и `\n`, автоматически убирая общий отступ |
| **Безопасное сравнение** | `a.Equals(b, StringComparison.OrdinalIgnoreCase)` | Сравнивает коды символов напрямую без учёта регистра и зависимости от языка ОС |
| **Поиск и разбиение** | `Trim()`, `StartsWith()`, `Contains()`, `Split()` | Возвращают *новую* строку или массив подстрок, оставляя исходную строку без изменений |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. Неизменяемость (Immutability): методы не меняют исходную строку, а возвращают новую
        string rawLogin = "  Admin_Roman  ";
        string cleanLogin = rawLogin.Trim();

        Console.WriteLine($"Исходная: '{rawLogin}' | Очищенная: '{cleanLogin}'");
        Console.WriteLine($"Это один и тот же объект в памяти: {ReferenceEquals(rawLogin, cleanLogin)}"); // False

        // 2. Проверка входных данных на null, пустоту и пробелы
        string? userInput = "   \t  ";
        if (string.IsNullOrWhiteSpace(userInput))
        {
            Console.WriteLine("Ввод пуст или состоит только из пробелов.");
        }

        // 3. Безопасное сравнение строк без лишних выделений памяти и влияния локали ОС
        string expectedRole = "ADMIN";
        string actualRole = "admin";
        bool isAdmin = string.Equals(expectedRole, actualRole, StringComparison.OrdinalIgnoreCase);
        Console.WriteLine($"Роли совпадают: {isAdmin}"); // True

        // 4. Необработанный строковый литерал с интерполяцией ($$"""...""" в C# 11+):
        // Двойной знак $$ позволяет использовать одиночные { } как обычный текст JSON, а {{ }} — для вставки переменных
        int userId = 42;
        string jsonPayload = $$"""
            {
              "id": {{userId}},
              "login": "{{cleanLogin}}",
              "path": "C:\Projects\App\config.json"
            }
            """;

        Console.WriteLine($"\nСформированный JSON:\n{jsonPayload}");

        // ❌ Ошибка новичка: вызов Trim() или Replace() без сохранения результата ничего не меняет
        // cleanLogin.Replace("Admin", "User");

        // ❌ Антипаттерн: ToLower() выделяет две новые строки в куче и зависит от региональных настроек ОС
        // bool badCompare = expectedRole.ToLower() == actualRole.ToLower();
    }
}

```

## Важные нюансы

* **Неизменяемость (*Immutability*) и потокобезопасность:** благодаря тому, что строку нельзя изменить после создания, её безопасно передавать между разными потоками без блокировок, а также использовать как ключ в `Dictionary<string, T>` (её хэш-код никогда не изменится). Но если вы забудете присвоить результат метода (`text.Trim();`), исходная переменная останется прежней.
* **Пул интернирования строк (*String Interning*):** среда .NET хранит внутреннюю таблицу уникальных строковых литералов, записанных прямо в коде. Если в разных местах программы встречается одинаковый литерал `"admin"`, обе переменные будут указывать на один и тот же объект в памяти. Строки, собранные динамически во время выполнения, по умолчанию не интернируются.
* **Никогда не сравнивайте строки через `.ToLower() == .ToLower()`:** такой способ создаёт две лишние временные строки в куче и зависит от региональных настроек системы (например, в турецкой локали заглавная `I` превращается в строчную `ı` без точки, ломая проверку технических ключей вроде `"FILE"`). Для технических идентификаторов, путей и команд всегда используйте `StringComparison.Ordinal` или `StringComparison.OrdinalIgnoreCase`, а `CurrentCulture` оставляйте только для сортировки текста, предназначенного для чтения человеком.
* **Связь с теорией и следующей темой:** неизменяемость строк избавляет от случайных побочных эффектов при передаче ссылок (см. группу 110 *Типы значений и ссылочные типы*), но превращается в узкое место при склейке сотен фрагментов в цикле — в следующей карточке разберём, как собирать и нарезать текст без лишней нагрузки на сборщик мусора (*`StringBuilder` и `Span<char>*`).
