# StringBuilder и ReadOnlySpan: текст без лишних аллокаций

Как склеивать тысячи фрагментов текста без нагрузки на сборщик мусора и нарезать подстроки, не копируя ни одного байта в управляемой куче?

Поскольку обычный `string` в C# неизменяем, конкатенация через `+=` в цикле на каждом шаге создаёт новую строку и заново копирует все предыдущие символы, превращая сборку текста в операцию сложности $O(N^2)$. Эту проблему решает класс `StringBuilder` из пространства имён `System.Text` — изменяемый буфер символов, который накапливает фрагменты и формирует итоговую строку только один раз при вызове `ToString()`. Для обратной задачи — быстрого чтения и разбора уже готовых строк — используют структуру `ReadOnlySpan<char>`, которая позволяет работать со срезами текста по ссылке без выделения памяти (*zero allocation*).

## Инструменты оптимизации работы со строками

| Инструмент / метод | Синтаксис / пример | Назначение и особенности |
| --- | --- | --- |
| **`StringBuilder`** | `var sb = new StringBuilder(256);` | Изменяемый буфер в куче; устраняет создание промежуточных строк при сборке текста в цикле |
| **`Append` / `AppendJoin`** | `sb.Append("ID: ").AppendJoin(", ", list);` | Добавляет значения разных типов и коллекции в буфер без лишних преобразований в `string` |
| **`AsSpan()` / `ReadOnlySpan<char>`** | `ReadOnlySpan<char> span = text.AsSpan();` | Создаёт лёгкое «окно» (указатель + длина) на существующую строку без копирования символов |
| **Срезы и парсинг `Span`** | `int.Parse(span[5..9]);` | Извлекает подстроку за $O(1)$ и парсит числа или даты напрямую из среза без `Substring()` |

## Пример кода

```csharp
using System;
using System.Text;

class Program
{
    static void Main()
    {
        // 1. StringBuilder: собираем большой отчёт в цикле без создания тысяч промежуточных строк
        // Задаём примерную начальную ёмкость (capacity), чтобы избежать лишних расширений внутреннего буфера
        StringBuilder report = new StringBuilder(capacity: 256);
        report.AppendLine("=== Отчёт по датчикам ===");

        for (int i = 1; i <= 3; i++)
        {
            report.Append("Датчик #").Append(i).Append(": ").Append(20 + i * 2).AppendLine(" °C");
        }

        // AppendJoin склеивает коллекцию через разделитель прямо внутри буфера
        string[] activeZones = { "Север", "Центр", "Юг" };
        report.Append("Активные зоны: ").AppendJoin(", ", activeZones);

        string finalReport = report.ToString();
        Console.WriteLine(finalReport);

        // 2. ReadOnlySpan<char>: разбираем строку лога без единого выделения памяти (Zero Allocation)
        string logEntry = "ORDER_ID:4815;TOTAL:12990";
        ReadOnlySpan<char> span = logEntry.AsSpan();

        int separatorIndex = span.IndexOf(';');
        ReadOnlySpan<char> idPart = span[..separatorIndex];          // "ORDER_ID:4815" (без копирования!)
        ReadOnlySpan<char> totalPart = span[(separatorIndex + 1)..]; // "TOTAL:12990"

        // Парсим числа напрямую из среза ReadOnlySpan<char>, не вызывая Substring()
        int orderId = int.Parse(idPart[(idPart.IndexOf(':') + 1)..]);
        decimal total = decimal.Parse(totalPart[(totalPart.IndexOf(':') + 1)..]);

        Console.WriteLine($"\nРазобрано из лога -> Заказ #{orderId}, сумма: {total} руб.");

        // ❌ Антипаттерн 1: склейка через += в цикле на каждой итерации копирует всю строку заново (O(N²))
        // string badLog = "";
        // for (int i = 0; i < 10_000; i++) badLog += i;

        // ❌ Антипаттерн 2: Substring() создаёт новый объект string в куче ради чтения пары цифр
        // int slowId = int.Parse(logEntry.Substring(9, 4));
    }
}

```

## Важные нюансы

* **Когда `StringBuilder` выигрывает, а когда проигрывает:** для 2–4 конкатенаций (`a + b + c` или интерполяции `$"..."`) компилятор сам объединяет все части в один оптимальный вызов `string.Concat` — `StringBuilder` здесь только создаст лишний объект. Используйте `StringBuilder`, когда количество склеек заранее неизвестно или происходит внутри цикла; при этом передача примерного размера буфера (`new StringBuilder(1024)`) избавит его от повторного выделения внутренних массивов.
* **Как `ReadOnlySpan<char>` экономит память:** обычный вызов `text.Substring(5, 10)` создаёт новый объект `string` в управляемой куче и копирует туда 10 символов. Срез `text.AsSpan(5, 10)` (или диапазоны `span[5..15]`) размещает на стеке крошечную структуру из двух полей — ссылки на начало фрагмента и его длины — вообще не создавая мусора для *Garbage Collector*.
* **Ограничения `ref struct` для `Span<T>` и `ReadOnlySpan<T>`:** ради безопасности работы с памятью `ReadOnlySpan<char>` может существовать *только* на стеке. Его нельзя сохранить в поле обычного класса, упаковать в `object`, захватить в замыкание лямбда-выражения или использовать в `async`-методе через границу `await` (для таких сценариев применяют `ReadOnlyMemory<char>`).
* **Связь со следующей темой:** размещение `ReadOnlySpan<char>` исключительно на стеке опирается на устройство памяти и типы `ref struct` из раздела *Принципы, паттерны и архитектура* (*Stack & Heap*), а в следующей карточке мы разберём поиск, валидацию и извлечение данных по сложным текстовым шаблонам (*Регулярные выражения `Regex` и парсинг*).
