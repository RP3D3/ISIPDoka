# Регулярные выражения (Regex) и парсинг текста

Как проверить формат входной строки, вытащить структурированные данные из неформатированного текста и защитить приложение от зависания на сложных шаблонах?

Класс `Regex` из пространства имён `System.Text.RegularExpressions` позволяет искать, проверять и заменять текст по формальным шаблонам (*регулярным выражениям*). В современном .NET стандартом стал атрибут `[GeneratedRegex]` (появившийся в .NET 7): он генерирует оптимизированный C#-код парсера прямо на этапе компиляции без задержек при запуске и лишних выделений памяти. Для извлечения конкретных фрагментов из текста используют именованные группы захвата `(?<name>...)`, а для защиты от катастрофического возврата (*ReDoS*) всегда ограничивают время поиска параметром `matchTimeout`.

## Основные инструменты и конструкции Regex

| Инструмент / метод | Синтаксис / пример | Назначение и особенности |
| --- | --- | --- |
| **`[GeneratedRegex(...)]`** | `private static partial Regex Pattern();` | Генерирует быстрый конечный автомат во время сборки (работает без рефлексии и поддерживает `Span`) |
| **`IsMatch(input)`** | `OrderPattern().IsMatch(text)` | Проверяет, соответствует ли строка шаблону (`true` / `false`), не создавая объектов совпадений |
| **`Match` / `Matches**` | `foreach (Match m in regex.Matches(text))` | Находит первое или все совпадения в тексте и открывает доступ к извлечённым группам `m.Groups` |
| **`Replace(input, ...)`** | `regex.Replace(text, "***")` | Заменяет найденные фрагменты (поддерживает подстановку групп `${name}` или лямбда-выражение) |
| **Таймаут и `NonBacktracking**` | `matchTimeoutMilliseconds: 200` | Прерывает поиск через `RegexMatchTimeoutException`, защищая поток от зависания на сложном вводе |

## Пример кода

```csharp
using System;
using System.Text.RegularExpressions;

partial class Program
{
    // 1. Генератор исходного кода (.NET 7+): шаблон компилируется в чистый C# на этапе сборки,
    // а таймаут 200 мс защищает приложение от зависания на вредоносных строках
    [GeneratedRegex("""Заказ #(?<id>\d+) на сумму (?<amount>\d+(?:\.\d{2})?) руб\.""",
        RegexOptions.IgnoreCase,
        matchTimeoutMilliseconds: 200)]
    private static partial Regex OrderRegex();

    [GeneratedRegex(@"\b(?<prefix>\d{4})\d{8}(?<suffix>\d{4})\b",
        RegexOptions.None,
        matchTimeoutMilliseconds: 200)]
    private static partial Regex CardMaskRegex();

    static void Main()
    {
        string messageLog = """
            [10:15] Клиент оформил Заказ #4082 на сумму 3490.50 руб. с доставкой.
            [10:42] Оплата подтверждена: Заказ #4083 на сумму 1200 руб. принят в работу.
            """;

        // 2. Быстрая проверка наличия совпадения без выделения памяти под объекты Match
        if (OrderRegex().IsMatch(messageLog))
        {
            Console.WriteLine("В логе найдены записи о заказах:");
        }

        // 3. Извлечение данных через именованные группы (?<id>...) и (?<amount>...)
        try
        {
            foreach (Match match in OrderRegex().Matches(messageLog))
            {
                string id = match.Groups["id"].Value;
                decimal amount = decimal.Parse(match.Groups["amount"].Value,
                    System.Globalization.CultureInfo.InvariantCulture);

                Console.WriteLine($"  -> Заказ №{id}: {amount} руб.");
            }
        }
        catch (RegexMatchTimeoutException)
        {
            Console.WriteLine("Превышено время разбора текста по регулярному выражению.");
        }

        // 4. Замена по шаблону с использованием именованных групп ${prefix} и ${suffix}
        string rawReceipt = "Оплата картой 4276123456789012 прошла успешно.";
        string safeReceipt = CardMaskRegex().Replace(rawReceipt, "${prefix}********${suffix}");
        Console.WriteLine($"\nМаскирование данных: {safeReceipt}");

        // ❌ Антипаттерн 1: создание new Regex(...) внутри цикла заново парсит шаблон на каждой итерации
        // foreach (string line in lines) { var r = new Regex(@"\d+"); ... }

        // ❌ Антипаттерн 2: не используйте Regex для разбора вложенных структур (HTML, XML, JSON)
        // Для них нужны специализированные парсеры (System.Text.Json, HtmlAgilityPack)
    }
}

```

## Важные нюансы

* **Три способа создания `Regex` и преимущество `[GeneratedRegex]`:** статические вызовы (`Regex.IsMatch(str, pattern)`) кэшируют до 15 последних шаблонов, `new Regex(pattern, RegexOptions.Compiled)` компилирует шаблон в IL-код при первом запуске (замедляя старт программы), а атрибут `[GeneratedRegex]` в `partial`-классе переносит генерацию кода на этап компиляции — он запускается мгновенно, поддерживает анализ `ReadOnlySpan<char>` без выделения строк и полностью совместим с Native AOT.
* **Защита от ReDoS (*Regular Expression Denial of Service*):** шаблоны с вложенными квантификаторами (вроде `(a+)+b`) на специально подобранной входной строке вызывают экспоненциальный перебор вариантов и способны намертво подвесить поток процессора. Всегда задавайте разумный таймаут (`matchTimeout`) или используйте флаг `RegexOptions.NonBacktracking` (.NET 7+), который гарантирует линейное время работы $O(N)$ без откатов.
* **Буквальные строки и именованные группы `(?<name>...)`:** в регулярных выражениях символ `\` используется постоянно (`\d`, `\s`, `\w`), поэтому шаблон всегда записывают через `@"..."` или необработанный литерал `"""..."""`, чтобы не дублировать слэши (`\\d`). Для извлечения значений предпочитайте именованные группы `(?<id>\d+)` вместо числовых индексов `Groups[1]` — такой код не сломается при добавлении новых скобок в шаблон.
* **Когда `Regex` не нужен (связь с предыдущей и следующей темами):** не используйте регулярные выражения для простых проверок вроде `StartsWith`, `Split` или нарезки строки фиксированного формата — срез `ReadOnlySpan<char>` (см. карточку *`StringBuilder` и `ReadOnlySpan*`) работает в десятки раз быстрее. В следующей карточке мы перейдём от текста к хронологии и разберём, как правильно хранить и вычислять время (*Дата и время: `DateTime`, `DateTimeOffset` и `DateOnly*`).
