# Целые числа (int, long, byte)

Как хранить количество жизней персонажа, баланс золота в игре или идентификатор пользователя в базе, не тратя лишнюю память?

:::gap

## Кратко

Целые числа нужны для всего, что считается поштучно без дробной части: счётчиков в циклах, возраста, очков опыта или ID записей. В C# для них есть несколько типов разного «размера» — от компактного `byte` до вместительного `long`, способного хранить квинтиллионы. Разделение по объёму памяти позволяет экономить ресурсы на больших массивах данных и защищаться от выхода за пределы допустимых значений.

:::gap

## Быстрый пример

Объявим переменные разных целочисленных типов и выполним базовые операции:

```cs
byte level = 80;                  // От 0 до 255 (1 байт)
int health = -50;                 // От -2 млрд до +2 млрд (4 байта)
long worldPopulation = 8_200_000_000L; // До 9 квинтиллионов (8 байт)

int a = 7;
int b = 2;
Console.WriteLine(a / b); // 3 (дробная часть просто отбрасывается)
Console.WriteLine(a % b); // 1 (остаток от деления)

```

:::gap

## Как это работает

При выполнении кода среда выполнения .NET выделяет в стеке ячейки строго фиксированного размера под каждую переменную:

1. **Компактное число (`byte`).** Для уровня персонажа `level` выделяется всего 1 байт (8 бит). В него помещаются только положительные числа от `0` до `255`.
2. **Стандартное целое (`int`).** Для `health` выделяется 4 байта (32 бита). Это базовый целочисленный тип в C#, поддерживающий как положительные, так и отрицательные значения примерно до 2,14 миллиарда в обе стороны.
3. **Большое целое (`long`).** Население Земли не помещается в `int`, поэтому используется 8-байтный `long`. Символ `_` внутри числа работает как визуальный разделитель разрядов для человека, а суффикс `L` в конце явно говорит компилятору, что литерал имеет тип `long`.
4. **Целочисленная арифметика (`/` и `%`).** Когда оба числа в выражении целые, оператор `/` выполняет деление нацело без округления — `7 / 2` даёт ровно `3`. Оператор `%` возвращает остаток от такого деления (`1`).

> [!TIP]
> Используйте `int` по умолчанию для большинства задач — современные процессоры оптимизированы именно под 32-битные и 64-битные операции. Переходите на `byte` или `short` только при работе с большими массивами данных (например, пикселями картинок или сетевыми пакетами).

:::gap

## Грабли и частые ошибки

### 1. Потеря дробной части при делении

* **Так сработает неправильно:** написать `double percent = 50 / 100 * 100;`. Выражение `50 / 100` вычисляется в целых числах, даёт `0`, и итоговый результат будет равен `0` вместо `50`.
* **Так правильно:** сделать хотя бы один из операндов дробным, добавив `.0` или суффикс: `double percent = 50.0 / 100 * 100;`.

### 2. Ошибка при сложении двух переменных типа `byte` или `short`

* **Так не скомпилируется:** написать `byte a = 10; byte b = 20; byte sum = a + b;`. При любой арифметике процессор автоматически расширяет `byte` и `short` до `int`, поэтому результат выражения `a + b` имеет тип `int`, и компилятор выдаст ошибку `CS0266`.
* **Так правильно:** явно привести результат обратно к нужному типу `byte sum = (byte)(a + b);` или сразу использовать `int`.

### 3. Тихое переполнение диапазона (Overflow)

* **Так сработает неправильно:** прибавить единицу к максимальному значению `int max = int.MaxValue; max += 1;`. Программа не выдаст ошибку, но число «прокрутится» по кругу и превратится в огромное отрицательное `-2147483648`.
* **Так правильно:** заранее выбирать тип с запасом (`long`) или оборачивать критичные вычисления в блок `checked`, который выбросит исключение при переполнении.

### 4. Забытый суффикс `L` у чисел больше 2 миллиардов

* **Так не скомпилируется:** объявить `long id = 3000000000;` в старых версиях языка или при передаче в перегруженные методы без явного типа — литерал без суффикса по умолчанию считается `int` и не влезает в диапазон.
* **Так правильно:** всегда дописывать заглавную `L` в конце крупных литералов: `long id = 3_000_000_000L;` (строчную `l` лучше не использовать, чтобы не путать с единицей `1`).

:::gap

## Под капотом и нюансы

### Таблица всех целочисленных типов C#

В C# есть знаковые типы (хранят и минус, и плюс) и беззнаковые (начинаются с `u` от *unsigned* — хранят только ноль и положительные числа, за счёт чего верхняя граница увеличивается вдвое):

| Тип C# | Тип .NET | Размер | Диапазон значений |
| --- | --- | --- | --- |
| `sbyte` | `System.SByte` | 1 байт | от `-128` до `127` |
| `byte` | `System.Byte` | 1 байт | от `0` до `255` |
| `short` | `System.Int16` | 2 байта | от `-32 768` до `32 767` |
| `ushort` | `System.UInt16` | 2 байта | от `0` до `65 535` |
| `int` | `System.Int32` | 4 байта | от `-2 147 483 648` до `2 147 483 647` |
| `uint` | `System.UInt32` | 4 байта | от `0` до `4 294 967 295` |
| `long` | `System.Int64` | 8 байт | от `-9.22 * 10^18` до `9.22 * 10^18` |
| `ulong` | `System.UInt64` | 8 байт | от `0` до `1.84 * 10^19` |
| `nint` / `nuint` | `System.IntPtr` | 4 или 8 байт | Зависит от разрядности ОС (32 или 64 бита) |

### Как хранятся отрицательные числа (дополнительный код)

В памяти компьютера нет знака «минус» — есть только биты `0` и `1`. Для знаковых типов самый левый (старший) бит отвечает за знак: `0` означает плюс, а `1` — минус. Отрицательные числа кодируются в **дополнительном коде** (*Two's Complement*): все биты положительного числа инвертируются, и к результату прибавляется `1`. Именно из-за такого представления прибавление `1` к максимальному положительному числу `0111...111` превращает его в `1000...000`, то есть в минимальное отрицательное число.

### Контроль переполнения: `checked` и `unchecked`

По умолчанию среда .NET работает в режиме `unchecked` ради максимальной скорости — процессор не тратит такты на проверку границ. Если вам важнее безопасность (например, в финансовых расчётах), используйте ключевое слово `checked`:

```cs
int balance = int.MaxValue;

checked
{
    // Выбросит System.OverflowException вместо перехода в минус
    balance += 1;
}

```

### Системы счисления в литералах

Целое число в коде можно записать не только в привычной десятичной системе, но и в шестнадцатеричной или двоичной:

```cs
int dec = 42;           // Десятичная
int hex = 0x2A;         // Шестнадцатеричная (префикс 0x)
int bin = 0b0010_1010;  // Двоичная (префикс 0b)

```

> [!NOTE]
> Если вам нужно работать с числами, которые больше даже `ulong` (например, в криптографии или при вычислении факториала сотни), подключите пространство имён `System.Numerics` и используйте структуру `BigInteger` — её размер ограничен только объёмом свободной оперативной памяти.
