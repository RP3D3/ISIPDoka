# Дробные числа (double, float, decimal)

Как рассчитать скидку в магазине, координаты персонажа в 3D-мире или процент загрузки файла, когда одних только целых чисел не хватает?

:::gap

## Кратко

Дробные числа нужны везде, где встречаются части целого: цены с копейками, физика движения, проценты или научные измерения. В C# для них есть три основных типа: быстрый `float` для графики и игр, универсальный `double` для большинства расчётов и сверхточный `decimal` для денег и бухгалтерии. Разделение позволяет выбирать между максимальной скоростью процессора и отсутствием ошибок округления.

:::gap

## Быстрый пример

Объявим переменные трёх дробных типов (обратите внимание на суффиксы) и сравним точность вычислений:

```cs
float speed = 5.75f;             // 4 байта, нужен суффикс f (графика, физика)
double distance = 142.8;         // 8 байт, тип по умолчанию (общие расчёты)
decimal price = 199.99m;         // 16 байт, нужен суффикс m (деньги, финансы)

// Классический подвох двоичных дробей vs decimal
Console.WriteLine(0.1 + 0.2);    // 0.30000000000000004 (double)
Console.WriteLine(0.1m + 0.2m);  // 0.3 (decimal)

```

:::gap

## Как это работает

При выполнении кода среда выполнения .NET выделяет в памяти ячейки разного размера и использует разные способы кодирования дроби:

1. **Облегчённая дробь (`float`).** Для скорости персонажа выделяется 4 байта памяти (32 бита). Поскольку любое число с точкой в C# по умолчанию считается `double`, в конце литерала обязательно ставят суффикс `f` (или `F`).
2. **Стандартная точность (`double`).** Для дистанции выделяется 8 байт (64 бита). Это базовый дробный тип в языке, поэтому суффиксы не требуются — компилятор сам распознаёт `142.8` как `double`.
3. **Финансовая точность (`decimal`).** Для цены товара выделяется целых 16 байт (128 бит), а в конце числа ставится суффикс `m` (от слова *money*).
4. **Разница в сложении (`0.1 + 0.2`).** Типы `float` и `double` хранят числа в двоичной системе, где дробь `0.1` превращается в бесконечную периодическую последовательность бит (как `1/3 = 0.333...` в десятичной). Из-за этого при сложении накапливается крошечный хвост `0.00000000000000004`. Тип `decimal` хранит цифры в десятичном виде, поэтому `0.1m + 0.2m` даёт чистые `0.3`.

> [!TIP]
> Используйте `double` по умолчанию для большинства задач, `float` — при работе с 3D-графикой и игровыми движками вроде Unity, а `decimal` — всегда, когда речь заходит о деньгах, налогах и чеках.

:::gap

## Грабли и частые ошибки

### 1. Забытый суффикс `f` или `m` при объявлении

* **Так не скомпилируется:** написать `float gravity = 9.8;` или `decimal tax = 0.2;`. Компилятор воспринимает любое число с точкой как `double` и запрещает неявно сужать его до `float` или `decimal` (ошибка `CS0664`).
* **Так правильно:** явно указывать суффикс типа: `float gravity = 9.8f;` и `decimal tax = 0.2m;`.

### 2. Прямое сравнение `double` и `float` через `==`

* **Так сработает неправильно:** написать `if (0.1 + 0.2 == 0.3)` — условие вернёт `false`, потому что слева получится `0.30000000000000004`.
* **Так правильно:** сравнивать числа с плавающей точкой через допустимую погрешность (*epsilon*): `if (Math.Abs((0.1 + 0.2) - 0.3) < 0.000001)`.

### 3. Расчёт денег через `double`

* **Так сработает неправильно:** копить сумму покупок или начислять проценты по вкладу в переменной `double` — на тысячах транзакций микроскопические погрешности сложатся в потерянные или лишние копейки.
* **Так правильно:** для любых финансовых расчётов использовать исключительно `decimal`.

### 4. Попытка смешать `double` и `decimal` в одном выражении

* **Так не скомпилируется:** написать `decimal total = price * 1.2;` (где `price` — это `decimal`, а `1.2` — `double`). Компилятор выдаст ошибку `CS0019`, так как неявного преобразования между ними нет.
* **Так правильно:** привести оба числа к одному типу: `decimal total = price * 1.2m;`.

:::gap

## Под капотом и нюансы

### Сводная таблица дробных типов

| Тип C# | Тип .NET | Размер | Точность (значащих цифр) | Диапазон значений | Суффикс |
| --- | --- | --- | --- | --- | --- |
| `float` | `System.Single` | 4 байта | 6–9 цифр | от `+-1.5 * 10^-45` до `+-3.4 * 10^38` | `f` / `F` |
| `double` | `System.Double` | 8 байт | 15–17 цифр | от `+-5.0 * 10^-324` до `+-1.7 * 10^308` | `d` / `D` (необязателен) |
| `decimal` | `System.Decimal` | 16 байт | 28–29 цифр | от `+-1.0 * 10^-28` до `+-7.9 * 10^28` | `m` / `M` |

### Почему точка «плавает» (стандарт IEEE 754)

Типы `float` и `double` устроены по стандарту **IEEE 754**: число разбивается на знак, мантиссу (значащие цифры) и экспоненту (степень двойки). Чем больше целая часть числа (например, расстояния в астрономии), тем меньше бит остаётся на дробную часть — десятичная точка буквально «плавает», жертвуя точностью ради огромного диапазона.

У `decimal` экспонента хранит степень **десятки**, поэтому любое конечное десятичное число вроде `0.1` или `19.99` представляется в памяти без потери точности.

### Деление на ноль, `Infinity` и `NaN`

В отличие от целых чисел, деление `double` или `float` на `0.0` не останавливает программу с исключением `DivideByZeroException`. Вместо этого стандартом IEEE 754 предусмотрены специальные значения:

```cs
double inf = 10.0 / 0.0;        // Infinity (положительная бесконечность)
double negInf = -10.0 / 0.0;    // -Infinity (отрицательная бесконечность)
double nan = 0.0 / 0.0;         // NaN (Not a Number — не число)

// Важно: NaN не равен даже самому себе!
Console.WriteLine(nan == double.NaN);    // False
Console.WriteLine(double.IsNaN(nan));    // True

```

> [!WARNING]
> У типа `decimal` нет значений `Infinity` и `NaN`. Попытка выполнить `1m / 0m` выбросит стандартное исключение `DivideByZeroException`.

### Производительность

Операции над `float` и `double` выполняются аппаратно прямо в блоке вычислений с плавающей точкой процессора (FPU/SIMD) за доли наносекунды. Тип `decimal` не поддерживается процессором напрямую и вычисляется программно силами среды .NET, поэтому работает примерно в 10–20 раз медленнее, чем `double`.
