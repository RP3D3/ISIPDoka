# Преобразование типов (Parse, TryParse, Convert, явное приведение)

Как превратить введённую с клавиатуры строку `"42"` в настоящее число для расчётов или отбросить дробную часть у цены товара?

:::gap

## Кратко

Преобразование типов позволяет переводить данные из одного формата в другой — например, превращать текст из консоли в число, а дробь — в целое значение. В C# строгая типизация, поэтому компилятор не даст случайно сложить строку `"10"` и число `5` без явного указания, как именно их соединить. Разные способы конвертации помогают выбирать между максимальной скоростью, безопасной проверкой пользовательского ввода и математическим округлением.

:::gap

## Быстрый пример

Рассмотрим четыре основных способа перевести данные из одного типа в другой:

```cs
// 1. Явное приведение (отбрасывает дробную часть)
double exactPrice = 99.95;
int wholeRubles = (int)exactPrice; // 99

// 2. Parse — жёсткий перевод строки в число
int count = int.Parse("15"); // 15

// 3. TryParse — безопасный перевод без падения программы
bool isOk = int.TryParse("abc", out int result); // isOk = false, result = 0

// 4. Convert — универсальный конвертер с округлением
int rounded = Convert.ToInt32(99.6); // 100

```

:::gap

## Как это работает

При выполнении кода среда .NET использует разные механизмы в зависимости от того, преобразуем ли мы числа между собой или разбираем текст:

1. **Явное приведение `(int)`.** Когда мы переводим более широкий тип (`double`) в более узкий (`int`), возможна потеря данных. Круглые скобки `(int)` перед переменной говорят компилятору: «я понимаю риск, просто отбрось всё после точки». В итоге `99.95` превращается в `99`.
2. **Прямой разбор (`int.Parse`).** Метод пробегает по символам строки `"15"` и собирает из них целое число. Он работает быстро, но требует, чтобы строка гарантированно содержала корректное число.
3. **Безопасная проверка (`int.TryParse`).** В отличие от `Parse`, этот метод не выбрасывает ошибку при встрече с мусором (`"abc"`). Он возвращает `false` как признак неудачи, а в выходную переменную `out int result` записывает значение по умолчанию (`0`).
4. **Универсальный класс `Convert`.** Метод `Convert.ToInt32()` умеет работать с разными типами (строками, `bool`, `double`). При переводе дробного числа в целое он не обрезает хвост, а выполняет математическое округление (`99.6` превращается в `100`).

> [!TIP]
> Для любых данных, которые вводит пользователь (из консоли, файла или формы), всегда используйте `TryParse`. Оставьте `Parse` только для ситуаций, когда формат строки заранее проверен.

:::gap

## Грабли и частые ошибки

### 1. Падение программы при вызове `Parse` на мусорных данных

* **Так упадёт:** написать `int age = int.Parse("20 лет");` или передать пустую строку `""` — программа аварийно завершится с исключением `FormatException`.
* **Так правильно:** использовать `if (int.TryParse(input, out int age))` и обрабатывать некорректный ввод без выброса исключений.

### 2. Неявная потеря точности при сужении типа

* **Так не скомпилируется:** написать `double d = 10.5; int i = d;`. Компилятор запрещает автоматически переводить большой или дробный тип в меньший, чтобы вы случайно не потеряли данные (ошибка `CS0266`).
* **Так правильно:** указать целевой тип явно в скобках `int i = (int)d;` или использовать `Convert.ToInt32(d)`.

### 3. Переполнение при явном приведении больших чисел

* **Так сработает неправильно:** привести `long big = 3_000_000_000L; int small = (int)big;`. По умолчанию явное приведение не проверяет границы диапазона — лишние старшие биты просто отрежутся, и получится отрицательное число `-1294967296`.
* **Так правильно:** использовать `Convert.ToInt32(big)` (он выбросит `OverflowException` при выходе за пределы `int`) или оборачивать приведение в блок `checked`.

### 4. Запятая вместо точки при парсинге дробных чисел

* **Так упадёт:** вызвать `double.Parse("3.14")` на компьютере с русской локалью Windows — система ждёт запятую `"3,14"` и выбросит `FormatException`.
* **Так правильно:** при чтении технических данных или конфигов передавать инвариантную культуру: `double.TryParse("3.14", CultureInfo.InvariantCulture, out double pi)`.

:::gap

## Под капотом и нюансы

### Неявное и явное приведение (Implicit vs Explicit)

Все преобразования между числовыми типами делятся на два лагеря:

* **Неявные (расширяющие)** происходят автоматически без потери информации, когда меньший тип помещается в больший: `byte > short > int > long > double`.
* **Явные (сужающие)** требуют скобок `(тип)`, потому что целевой тип меньше исходного или не умеет хранить дробную часть.

### Банковское округление в `Convert`

Многие ожидают, что `Convert.ToInt32(2.5)` вернёт `3`, но метод вернёт `2`, а для `3.5` вернёт `4`. В .NET по умолчанию используется **банковское округление** (*MidpointRounding.ToEven*) — половина округляется к ближайшему чётному числу, чтобы на больших объёмах статистики не накапливалось смещение вверх. Если нужно привычное школьное округление (`2.5 > 3`), используйте `Math.Round(2.5, MidpointRounding.AwayFromZero)`.

### Сравнение способов преобразования

| Способ | Поведение при неверной строке | Поведение при `null` | Округление дробей |
| --- | --- | --- | --- |
| `(int)x` | Не работает со строками | Не работает со строками | Отбрасывает дробную часть (`2.9 > 2`) |
| `int.Parse(s)` | Выбрасывает `FormatException` | Выбрасывает `ArgumentNullException` | Не работает с дробными строками (`"2.9"` упадёт) |
| `int.TryParse(s, out x)` | Возвращает `false` (`x = 0`) | Возвращает `false` (`x = 0`) | Не работает с дробными строками |
| `Convert.ToInt32(x)` | Выбрасывает `FormatException` | Возвращает `0` | Банковское округление (`2.5 > 2`, `3.5 > 4`) |

### Парсинг без выделения памяти через `Span`

Начиная с .NET 7, у всех базовых типов (`int`, `double`, `DateTime`, `Guid`) появился общий интерфейс `ISpanParsable<T>`. Он позволяет разбирать число прямо из среза строки (`ReadOnlySpan<char>`) без создания лишней копии текста в управляемой куче:

```cs
ReadOnlySpan<char> slice = "ID:777".AsSpan(3);
int id = int.Parse(slice); // 777 без аллокации новой строки

```
