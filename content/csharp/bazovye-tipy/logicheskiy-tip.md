# Логический тип (bool)

Как программе решить, открывать ли дверь игроку, пускать ли пользователя в аккаунт или завершать игровой цикл?

:::gap

## Кратко

Логический тип `bool` — это простейший переключатель в программе, который умеет хранить только одно из двух состояний: истину (`true`) или ложь (`false`). Он лежит в основе любого принятия решений: проверок пароля, условий в циклах и фильтрации данных. Без него код выполнялся бы строго по прямой без возможности реагировать на действия пользователя или события в игре.

:::gap

## Быстрый пример

Объявим логические флаги и объединим их с помощью операторов сравнения и логических связок:

```cs
bool hasKey = true;
int playerLevel = 12;

// Результат сравнения — всегда bool
bool isHighLevel = playerLevel >= 10; // true

// Логическое И (&&), ИЛИ (||) и НЕ (!)
bool canOpenChest = hasKey && isHighLevel; // true
bool isBlocked = !hasKey;                  // false

Console.WriteLine(canOpenChest); // True

```

:::gap

## Как это работает

При выполнении кода программа вычисляет истинность каждого выражения и сводит всё к одному из двух значений:

1. **Прямое присваивание (`true` / `false`).** Переменной `hasKey` мы напрямую задаём состояние `true` — ключ у игрока есть. В C# эти ключевые слова пишутся строго с маленькой буквы.
2. **Получение `bool` из сравнения (`>=`).** Выражение `playerLevel >= 10` проверяет, больше или равен уровень десяти. Поскольку `12 >= 10`, результатом сравнения становится `true`, которое записывается в переменную `isHighLevel`.
3. **Логические операторы (`&&`, `!`).** Оператор `&&` (логическое И) возвращает `true`, только если оба условия истинны одновременно. Восклицательный знак `!` (логическое НЕ) инвертирует значение наоборот: превращает `true` в `false`.
4. **Вывод в консоль.** Метод `Console.WriteLine` печатает значение логической переменной с заглавной буквы (`True` или `False`) — так устроено её стандартное строковое представление в .NET.

> [!TIP]
> Называйте логические переменные как вопрос, на который можно ответить «да» или «нет», начиная с префиксов `is`, `has`, `can` или `should`: `isAlive`, `hasAccess`, `canJump`. Код сразу станет читаться как обычный текст.

:::gap

## Грабли и частые ошибки

### 1. Попытка использовать `1` и `0` вместо `true` и `false`

* **Так не скомпилируется:** написать `bool isActive = 1;` или `if (1)` по привычке из C++ или Python. В C# строгая типизация: целые числа не приводятся к логическому типу неявно (ошибка `CS0029`).
* **Так правильно:** использовать исключительно литералы `true` и `false` или явное сравнение `count > 0`.

### 2. Одинарное `=` вместо двойного `==` внутри условия

* **Так сработает неправильно:** написать `if (isAdmin = true)` вместо `if (isAdmin == true)`. Одинарное равно — это присваивание: оно перезапишет переменную на `true` и всегда пропустит внутрь блока.
* **Так правильно:** для сравнения использовать `==`, а для `bool`-переменных вообще не писать сравнение с `true` — достаточно `if (isAdmin)`.

### 3. Путаница между `&&` и `&` (или `||` и `|`)

* **Так упадёт:** написать `if (user != null & user.IsActive)` с одинарным амперсандом. Оператор `&` вычисляет **оба** выражения всегда, поэтому при `user == null` программа попытается обратиться к `user.IsActive` и упадёт с `NullReferenceException`.
* **Так правильно:** использовать двойные операторы `&&` и `||` — они работают по ленивой схеме и остановятся сразу, как только станет понятен итоговый результат.

### 4. Лишнее нагромождение `if (...) return true; else return false;`

* **Так сработает неправильно:** писать громоздкую конструкцию из 6 строк там, где выражение само по себе уже возвращает `bool` — это усложняет чтение кода.
* **Так правильно:** возвращать результат сравнения напрямую: `return age >= 18;`.

:::gap

## Под капотом и нюансы

### Сколько памяти занимает `bool`

Логически для хранения `0` или `1` достаточно одного бита, но минимальная адресуемая ячейка оперативной памяти в современных процессорах — **1 байт (8 бит)**. Поэтому одна переменная типа `bool` (соответствует структуре `System.Boolean`) занимает в стеке ровно 1 байт: все нули (`00000000`) означают `false`, а любое ненулевое значение (обычно `00000001`) — `true`.

### Логические операторы и таблица истинности

| Оператор | Название | Когда возвращает `true` | Пример |
| --- | --- | --- | --- |
| `!a` | Логическое НЕ (инверсия) | Когда `a` равно `false` | `!false == true` |
| `a && b` | Условное И (AND) | Когда и `a`, и `b` равны `true` | `true && false == false` |
| `a |  | b` | Условное ИЛИ (OR) |
| `a ^ b` | Исключающее ИЛИ (XOR) | Когда `a` и `b` **разные** (одно `true`, другое `false`) | `true ^ true == false` |

### Укороченное вычисление (Short-Circuit Evaluation)

Операторы `&&` и `||` работают по принципу ленивых вычислений:

* В выражении `A && B`, если `A` вернуло `false`, правая часть `B` **вообще не запускается**, потому что итог уже гарантированно `false`.
* В выражении `A || B`, если `A` вернуло `true`, правая часть `B` также пропускается.

Это не только защищает от ошибок при проверке на `null`, но и экономит ресурсы, если справа стоит тяжёлый вызов метода или запрос к базе данных.

### Трёхзначная логика: `bool?` (Nullable)

Иногда двух состояний мало — например, в анкете пользователь мог ответить «Да» (`true`), «Нет» (`false`) или вообще пропустить вопрос (`null`). Для таких случаев используют обнуляемый тип `bool?`:

```cs
bool? isSubscribed = null;

// В условии if напрямую использовать bool? нельзя — нужно проверить значение
if (isSubscribed == true)
{
    Console.WriteLine("Подписка активна");
}

```

> [!NOTE]
> Если нужно упаковать тысячи или миллионы флагов без траты целого байта на каждый, используйте класс `BitArray` из пространства имён `System.Collections` — он упаковывает по 8 значений `bool` в один байт памяти.
