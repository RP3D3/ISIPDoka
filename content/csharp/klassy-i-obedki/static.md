# Модификатор static: члены самого класса

Как хранить общие данные для всех объектов сразу, вызывать методы без создания экземпляра через `new` и зачем нужны целиком статические классы?

Обычные поля, свойства и методы принадлежат конкретному экземпляру объекта, но модификатор `static` привязывает элемент к **самому классу** целиком. Статическое поле существует в памяти в единственном экземпляре на всю программу и разделяется между всеми объектами, статический метод вызывается напрямую по имени класса (`Math.Abs(-5)`), а **статический класс** (`static class`) вообще запрещает создавать экземпляры и служит контейнером для вспомогательных функций.

## Сравнение обычных и статических членов

| Критерий | Обычные (экземплярные) | Статические (`static`) |
| --- | --- | --- |
| **Кому принадлежат** | Конкретному объекту, созданному через `new` | Самому типу (классу) в целом |
| **Как вызываются** | Через переменную объекта (`order.Id`) | Напрямую через имя класса (`Order.TotalCount`) |
| **Сколько копий в памяти** | Своя отдельная копия у каждого созданного объекта | Ровно одна общая копия на всё время работы программы |
| **Доступ к данным класса** | Видят и свои поля, и общие `static`-члены | Видят только другие `static`-члены (нет ссылки `this`) |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        Order first = new Order(2500m);
        Order second = new Order(4000m);

        // Обращаемся к static-свойству напрямую через имя класса, а не через объект
        Console.WriteLine($"Всего оформлено заказов: {Order.TotalCount}");

        // Вызов метода из целиком статического класса-помощника без оператора new
        decimal withTax = TaxCalculator.AddVat(second.Amount);
        Console.WriteLine($"Заказ №{second.Id} с НДС: {withTax} руб.");

        // ❌ Ошибка компиляции: к статическому члену нельзя обратиться через экземпляр
        // Console.WriteLine(first.TotalCount);

        // ❌ Ошибка компиляции: нельзя создать экземпляр статического класса
        // TaxCalculator calc = new TaxCalculator();
    }
}

class Order
{
    // Общее для всех объектов свойство-счётчик (одна копия на весь класс)
    public static int TotalCount { get; private set; }

    public int Id { get; }
    public decimal Amount { get; }

    public Order(decimal amount)
    {
        TotalCount++;
        Id = TotalCount;
        Amount = amount;
    }
}

// Статический класс: запрещает создание объектов и хранит только утилитарные методы
static class TaxCalculator
{
    public static decimal AddVat(decimal price) => price * 1.2m;
}

```

## Важные нюансы

* **Почему внутри `static` нельзя обратиться к обычным полям:** у статического метода нет скрытой ссылки `this` на конкретный объект — компилятор просто не знает, у какого именно из тысячи экземпляров взять нестатическое поле, что вызывает ошибку компиляции `CS0120`.
* **Статический конструктор (`static ClassName()`):** срабатывает автоматически ровно один раз перед первым обращением к классу или созданием его первого объекта. У него не бывает модификаторов доступа и параметров, и он используется для разовой подготовки статических данных.
* **Правила `static class`:** целиком статический класс не позволяет создавать экземпляры через `new`, не может участвовать в наследовании и обязан содержать только статические члены (яркие примеры из стандартной библиотеки — `Math` и `Console`).
* **Связь с теорией и соседними темами:** статические поля живут в памяти до завершения работы программы и лежат в основе паттерна *Одиночка*, но злоупотребление ими превращает код в глобальные переменные (см. теоретический раздел: *Паттерн Одиночка* и карточку *Поля и константы*).
