# Свойства: умный доступ к данным

Как проверять и фильтровать данные при записи в объект, сохраняя привычный и удобный синтаксис обращения как к обычному полю?

**Свойство** (*property*) — это гибрид поля и метода: снаружи оно выглядит и читается как обычная переменная (`laptop.Price = 75000`), но внутри содержит специальные блоки кода — аксессоры `get` (чтение) и `set` (запись). Благодаря свойствам класс может проверять корректность переданных значений, запрещать запись снаружи или вычислять результат на лету, не заставляя программиста громоздить десятки методов `GetPrice()` и `SetPrice()`.

## Виды свойств в C#

| Вид свойства | Синтаксис | Когда применять |
| --- | --- | --- |
| **Полное свойство** (*Full property*) | `get { return _field; } set { ... }` | Когда при чтении или записи нужна проверка (валидация) или дополнительная логика |
| **Автосвойство** (*Auto-property*) | `public string Name { get; set; }` | Когда проверок не требуется — компилятор сам создаёт скрытое поле в памяти |
| **Свойство с закрытой записью / `init**` | `{ get; private set; }` или `{ get; init; }` | Когда значение задаётся при создании объекта, а снаружи доступно только для чтения |
| **Вычисляемое свойство** | `public bool IsAdult => Age >= 18;` | Когда значение не хранится в памяти, а каждый раз рассчитывается из других данных |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        Product laptop = new Product("Ноутбук", 75000m);

        // Снаружи работаем со свойством как с обычным полем, но внутри срабатывает проверка set
        laptop.Price = -500m; // Игнорируется проверкой, цена останется 75000
        Console.WriteLine($"{laptop.Title}: {laptop.Price} руб. (со скидкой: {laptop.DiscountPrice} руб.)");

        // ❌ Ошибка компиляции: у Title закрыт сеттер (private set)
        // laptop.Title = "Планшет";
    }
}

class Product
{
    // Закрытое резервное поле (backing field) для хранения реального значения цены
    private decimal _price;

    // Автосвойство с закрытой записью: читать могут все, менять — только сам класс
    public string Title { get; private set; }

    // Полное свойство с проверкой корректности при записи (валидацией)
    public decimal Price
    {
        get => _price;
        set
        {
            if (value > 0)
                _price = value;
        }
    }

    // Вычисляемое свойство (только блок get): не занимает память под отдельное поле
    public decimal DiscountPrice => _price * 0.9m;

    public Product(string title, decimal price)
    {
        Title = title;
        Price = price;
    }
}

```

## Важные нюансы

* **Ловушка бесконечной рекурсии (`StackOverflowException`):** внутри полного свойства нельзя обращаться к самому свойству (`Price = value` внутри блока `set` свойства `Price` вызовет само себя по кругу и аварийно уронит программу) — всегда читайте и записывайте данные через приватное поле (`_price`).
* **Неявный параметр `value`:** внутри блока `set` всегда существует встроенная переменная `value`, которая содержит то значение, которое внешний код пытается присвоить свойству справа от знака `=`.
* **Разница между `private set` и `init`:** модификатор `private set` позволяет самому классу менять значение в любых своих методах позже, а современный `init` (C# 9+) разрешает задать значение строго один раз при создании объекта (в конструкторе или инициализаторе `{ ... }`), после чего замораживает его навсегда.
* **Связь с теорией и соседними темами:** свойства — главный инструмент *инкапсуляции* в C#, который заменяет ручные геттеры и сеттеры, описанные в карточке *Модификаторы доступа*.
