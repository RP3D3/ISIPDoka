# Модификаторы доступа: границы видимости кода

Как скрыть внутреннее устройство класса от случайного вмешательства снаружи и оставить открытым только безопасный интерфейс для работы с объектом?

**Модификаторы доступа** (*access modifiers*) — это ключевые слова в C#, которые определяют, из каких частей программы можно обращаться к классам, полям, свойствам и методам. Они выступают главным инструментом **инкапсуляции**: позволяют спрятать внутренние рабочие детали (`private`) от прямой перезаписи в обход проверок, а наружу выставить только проверенные публичные методы (`public`) или служебные элементы для текущего проекта (`internal`).

## Основные модификаторы доступа в C#

| Модификатор | Где доступен | Для чего применяется |
| --- | --- | --- |
| `public` | Везде: внутри своего класса, в других классах и во внешних проектах | Для открытого интерфейса объекта — методов и свойств, с которыми работает внешний код |
| `private` | Только внутри того класса или структуры, где элемент объявлен | Для внутренних полей и вспомогательных методов, скрытых от постороннего вмешательства |
| `internal` | В любом месте внутри текущего проекта (сборки), но не за его пределами | Для служебных классов и инструментов, нужных только внутри самой программы или библиотеки |
| `protected` | Внутри своего класса и во всех его дочерних классах-наследниках | Для передачи внутренних данных и методов по наследству без открытия для всего кода |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        BankCard card = new BankCard("4276 5500 1234 9876", "1234");

        // ✅ Работаем через открытый (public) интерфейс класса
        card.Deposit(5000m);
        card.Withdraw(1200m, "1234");
        Console.WriteLine($"Текущий баланс: {card.GetBalance()} руб.");

        // ❌ Ошибки компиляции: приватные члены класса надёжно скрыты снаружи
        // card._balance = 999999m;
        // card._pinCode = "0000";
        // card.ValidatePin("1234");
    }
}

// internal: класс доступен только внутри текущего проекта (сборки)
internal class BankCard
{
    // public: открытое неизменяемое поле, доступное любому коду
    public readonly string CardNumber;

    // private: скрытое состояние объекта — изменить его можно только через методы класса
    private decimal _balance;
    private string _pinCode;

    public BankCard(string cardNumber, string pinCode)
    {
        CardNumber = cardNumber;
        _pinCode = pinCode;
    }

    public void Deposit(decimal amount)
    {
        if (amount > 0) _balance += amount;
    }

    public void Withdraw(decimal amount, string pin)
    {
        if (ValidatePin(pin) && amount > 0 && amount <= _balance)
        {
            _balance -= amount;
        }
    }

    public decimal GetBalance() => _balance;

    // private-метод: внутренняя вспомогательная проверка, не нужная внешнему коду
    private bool ValidatePin(string pin) => _pinCode == pin;
}

```

## Важные нюансы

* **Уровни доступа по умолчанию:** если не указать модификатор явно, C# всегда выбирает самый строгий безопасный вариант. Для полей, свойств и методов внутри класса по умолчанию действует `private`, а для самих классов на уровне пространства имён — `internal`.
* **Соглашение об именовании `private`-полей:** в C# принято называть приватные поля с нижнего подчёркивания и маленькой буквы (`_balance`, `_pinCode`), а публичные члены класса — с заглавной (`Deposit`, `CardNumber`). Это позволяет сразу отличать внутренние данные от параметров и открытых методов.
* **Комбинированные модификаторы и `file`:** помимо четырёх основных, существуют `protected internal` (доступен наследникам *или* внутри сборки), `private protected` (только наследникам *внутри* текущей сборки) и `file` (видим строго внутри одного `.cs`-файла).
* **Связь с теорией и следующими темами:** закрытие полей через `private` — основа *инкапсуляции*, но писать для каждого поля пары методов `Get...` и `Set...` неудобно — в C# эту задачу элегантно решают свойства (см. теоретический раздел: *Инкапсуляция* и следующую карточку: *Свойства*).
