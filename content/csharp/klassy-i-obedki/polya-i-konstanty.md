# Поля и константы: хранение состояния объекта

Где объект хранит свои данные, чем обычное поле отличается от неизменяемых `const` и `readonly` и как защитить важные значения от случайной перезаписи?

**Поле** (*field*) — это переменная, объявленная прямо внутри класса, которая хранит состояние конкретного объекта. Чтобы защитить данные от случайного изменения во время работы программы, в C# используют два модификатора: **константу** (`const`), значение которой жёстко фиксируется ещё на этапе компиляции, и **поле только для чтения** (`readonly`), которое можно задать один раз при создании объекта в конструкторе, но нельзя перезаписать позже.

## Сравнение обычных полей, `readonly` и `const`

| Критерий | Обычное поле | Поле `readonly` | Константа `const` |
| --- | --- | --- | --- |
| **Когда задаётся значение** | При объявлении, в конструкторе или в любом методе | При объявлении или внутри конструктора класса | Строго при объявлении в коде |
| **Можно ли изменить позже** | Да, сколько угодно раз во время работы программы | Нет, после завершения конструктора значение заморожено | Нет, значение неизменно навсегда |
| **Поддерживаемые типы** | Любые типы данных C# | Любые типы данных C# (включая объекты и коллекции) | Только примитивы (`int`, `double`, `bool`), `string` и `null` |
| **Принадлежность** | Принадлежит конкретному экземпляру объекта | Принадлежит конкретному экземпляру объекта | Неявно является `static` (одна на весь класс) |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // К const обращаемся через имя класса, так как константа общая для всех объектов
        Console.WriteLine($"Валюта банка: {BankAccount.Currency}");

        BankAccount account = new BankAccount("ACC-7741", 5000m);
        account.Deposit(1500m);

        Console.WriteLine($"Счёт {account.AccountNumber}: баланс {account.Balance} {BankAccount.Currency}");

        // ❌ Ошибка компиляции: нельзя изменить readonly-поле после создания объекта
        // account.AccountNumber = "ACC-0000";
    }
}

class BankAccount
{
    // Константа: известна на этапе компиляции и одинакова для всех счетов
    public const string Currency = "RUB";

    // Поле только для чтения: задаётся один раз для каждого объекта в конструкторе
    public readonly string AccountNumber;

    // Обычное поле: хранит изменяемое состояние конкретного объекта (по умолчанию равно 0)
    public decimal Balance;

    public BankAccount(string accountNumber, decimal initialBalance)
    {
        AccountNumber = accountNumber;
        Balance = initialBalance;
    }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}

```

## Важные нюансы

* **Автоматические значения по умолчанию:** в отличие от локальных переменных внутри методов, поля класса не вызывают ошибку компиляции без явного присваивания — компилятор сам заполняет их значениями по умолчанию (`0` для чисел, `false` для `bool`, `null` для ссылочных типов).
* **`const` неявно работает как `static`:** константа не дублируется в памяти для каждого нового объекта — она принадлежит самому классу, поэтому вызов `account.Currency` через экземпляр приведёт к ошибке компиляции.
* **Ловушка `readonly` со ссылочными типами:** ключевое слово `readonly` запрещает записать в поле ссылку на *другой* объект (`_items = new List<string>()`), но не мешает изменять содержимое внутри уже созданного объекта (`_items.Add("Товар")`).
* **Связь с теорией и следующими темами:** оставлять изменяемые поля открытыми (`public`) опасно, так как любой внешний код может записать туда некорректные данные в обход проверок и нарушить *инкапсуляцию* — для защиты полей используются модификаторы доступа и свойства (см. следующие карточки: *Конструкторы и `this*` и *Свойства*).
