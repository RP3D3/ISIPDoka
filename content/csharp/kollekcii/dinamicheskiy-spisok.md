# Динамический список (List)

Как хранить инвентарь игрока или список задач, куда постоянно добавляются новые предметы и удаляются старые?

:::gap

## Кратко

Обычный массив требует заранее знать точное количество элементов, а вот динамический список `List<T>` умеет сам расти и сжиматься прямо во время работы программы. В угловых скобках `<T>` вы указываете тип данных (например, `List<string>` для строк или `List<int>` для чисел), после чего можно легко добавлять, вставлять и удалять записи без ручного пересоздания массивов. Это самая популярная коллекция в C# для работы с наборами данных переменной длины.

:::gap

## Быстрый пример

Создадим список предметов, добавим и удалим элементы, а затем проверим их наличие:

```cs
List<string> inventory = ["Меч", "Щит"];

inventory.Add("Зелье");           // ["Меч", "Щит", "Зелье"]
inventory.Insert(1, "Лук");       // ["Меч", "Лук", "Щит", "Зелье"]
inventory.Remove("Щит");          // ["Меч", "Лук", "Зелье"]

Console.WriteLine(inventory[0]);              // Меч
Console.WriteLine(inventory.Count);           // 3
Console.WriteLine(inventory.Contains("Лук")); // True

```

:::gap

## Как это работает

При выполнении кода коллекция управляет внутренним хранилищем автоматически:

1. **Создание списка (`List<string>`).** В угловых скобках мы фиксируем тип элементов — сюда можно класть только строки. Запись `["Меч", "Щит"]` (выражение коллекции) сразу наполняет список двумя стартовыми значениями.
2. **Добавление в конец (`Add`).** Метод `Add("Зелье")` дописывает новый элемент в хвост списка за мгновенное время, увеличивая его размер до трёх.
3. **Вставка в середину (`Insert`).** Вызов `Insert(1, "Лук")` ставит элемент на позицию с индексом `1` (вторым по счёту), автоматически сдвигая `"Щит"` и `"Зелье"` вправо.
4. **Удаление по значению (`Remove`).** Метод ищет первое совпадение `"Щит"`, вырезает его и сдвигает оставшиеся элементы влево, чтобы не оставалось пустых дыр. Если элемент найден и удалён, метод возвращает `true`.
5. **Чтение и проверка (`[0]`, `Count`, `Contains`).** Обращение по индексу `[0]` работает так же быстро, как в обычном массиве. Свойство `Count` возвращает текущее число элементов (`3`), а `Contains` проверяет, есть ли нужная запись в списке.

> [!TIP]
> В современных шаблонах проектов .NET пространство имён `System.Collections.Generic` подключено глобально по умолчанию, поэтому писать `using System.Collections.Generic;` в начале файла больше не нужно.

:::gap

## Грабли и частые ошибки

### 1. Удаление элементов внутри цикла `foreach`

* **Так упадёт:** перебирать список через `foreach (var item in inventory)` и внутри вызвать `inventory.Remove(item);`. Коллекция защищена от изменения во время обхода и мгновенно выбросит исключение `InvalidOperationException`.
* **Так правильно:** использовать метод `inventory.RemoveAll(x => x == "Щит")` или идти обычным циклом `for` с конца списка к началу (`for (int i = list.Count - 1; i >= 0; i--)`).

### 2. Путаница между `Count` и `Length`

* **Так не скомпилируется:** написать `inventory.Length` по привычке от массивов. У `List<T>` нет свойства `Length` — компилятор выдаст ошибку `CS1061`.
* **Так правильно:** использовать свойство `inventory.Count` (без круглых скобок).

### 3. Обращение по индексу к пустому списку

* **Так упадёт:** создать пустой список `List<int> nums = [];` и сразу попытаться записать значение в ячейку `nums[0] = 10;`. Индексатор умеет только перезаписывать уже существующие элементы — программа выбросит `ArgumentOutOfRangeException`.
* **Так правильно:** добавлять новые элементы через `nums.Add(10)`.

### 4. Частый поиск `Contains` в огромном списке

* **Так сработает неправильно:** хранить в `List<string>` 100 000 уникальных логинов и в цикле проверять `users.Contains(login)`. Список проверяет элементы перебором по очереди, поэтому программа начнёт заметно тормозить.
* **Так правильно:** для мгновенного поиска по уникальным значениям использовать `HashSet<string>` или `Dictionary<TKey, TValue>`.

:::gap

## Под капотом и нюансы

### Внутренний массив, `Count` и `Capacity`

Никакой магии внутри `List<T>` нет — под капотом он прячет обычный одномерный массив `T[]`. Поэтому у списка есть два разных счётчика:

* `Count` — сколько реальных элементов вы туда положили.
* `Capacity` (ёмкость) — какого размера внутренний массив выделен в памяти прямо сейчас.

Когда вы добавляете элементы через `Add()` и место во внутреннем массиве заканчивается (`Count == Capacity`), список выделяет в куче **новый массив в 2 раза большего размера** (начиная с 4 ячеек), копирует туда все старые элементы и отдаёт старый массив сборщику мусора. Если вы заранее знаете, что в списке будет около 10 000 записей, передайте это число в конструктор `new List<int>(10_000)` — вы избежите лишних перевыделений памяти и копирований.

### Скорость основных операций (сложность Big-O)

| Операция | Метод / синтаксис | Сложность | Почему так |
| --- | --- | --- | --- |
| Доступ по индексу | `list[i]` | `O(1)` | Прямое обращение к ячейке внутреннего массива |
| Добавление в конец | `list.Add(item)` | `O(1)`* | Мгновенно, если есть запас `Capacity` (*`O(N)` при расширении) |
| Вставка в середину | `list.Insert(i, item)` | `O(N)` | Приходится сдвигать вправо все элементы после индекса `i` |
| Удаление элемента | `list.Remove(item)` / `RemoveAt(i)` | `O(N)` | Нужно найти элемент и сдвинуть хвост списка влево |
| Поиск элемента | `list.Contains(item)` / `IndexOf` | `O(N)` | Линейный перебор элементов с начала до первого совпадения |
| Сортировка | `list.Sort()` | `O(N log N)` | Использует гибридный алгоритм IntroSort на месте |

### Быстрый доступ к внутреннему массиву без копирования

В высоконагруженном коде (например, в игровых циклах или при обработке данных) можно получить прямой доступ к внутреннему массиву списка в виде `Span<T>` без выделения памяти:

```cs
using System.Runtime.InteropServices;

List<int> numbers = [1, 2, 3, 4];
Span<int> span = CollectionsMarshal.AsSpan(numbers);
span[0] = 99; // Меняет элемент напрямую внутри списка

```

> [!WARNING]
> Пока вы работаете со `Span<T>`, полученным через `CollectionsMarshal.AsSpan`, **нельзя** вызывать `Add`, `Insert` или `Remove` у исходного списка — при расширении внутреннего массива `Span` продолжит смотреть на старый участок памяти.
