# Словарь (Dictionary<TKey, TValue>)

Как мгновенно найти цену товара по его артикулу или данные игрока по нику среди тысяч записей, не перебирая весь список подряд?

:::gap

## Кратко

Словарь `Dictionary<TKey, TValue>` хранит данные в виде пар «ключ — значение», работая как телефонная книга или оглавление. Каждому уникальному ключу (например, артикулу товара или ID пользователя) соответствует своё значение, которое можно получить мгновенно без перебора всей коллекции. Это главный инструмент для быстрого поиска, кэширования результатов и подсчёта частоты элементов.

:::gap

## Быстрый пример

Создадим словарь цен, добавим и обновим записи, а затем безопасно прочитаем значение по ключу:

```cs
// Ключ — строка (название), значение — число (цена)
Dictionary<string, int> prices = new()
{
    ["Меч"] = 150,
    ["Щит"] = 100
};

prices["Зелье"] = 50; // Добавит новую пару (если ключа нет)
prices["Меч"] = 180;   // Обновит цену существующего ключа

// Безопасное чтение без риска ошибки, если ключа нет
if (prices.TryGetValue("Щит", out int shieldPrice))
{
    Console.WriteLine($"Цена щита: {shieldPrice}"); // Цена щита: 100
}

Console.WriteLine(prices.ContainsKey("Лук")); // False

```

:::gap

## Как это работает

При выполнении кода коллекция связывает каждый ключ с конкретной ячейкой памяти для мгновенного доступа:

1. **Объявление пары типов (`Dictionary<string, int>`).** В угловых скобках задаются два типа: первый (`string`) отвечает за уникальный ключ, по которому идёт поиск, а второй (`int`) — за само хранимое значение.
2. **Запись и обновление через квадратные скобки (`prices[...]`).** В отличие от массивов и списков, в квадратных скобках словаря указывается не порядковый номер, а сам ключ. Если ключа `"Зелье"` ещё нет, словарь создаст новую пару; если ключ `"Меч"` уже существует — перезапишет его значение на `180`.
3. **Безопасное чтение (`TryGetValue`).** Метод ищет ключ `"Щит"`. Если он найден, метод возвращает `true` и записывает цену в выходную переменную `shieldPrice`. Если ключа нет, программа не упадёт, а просто вернёт `false`.
4. **Проверка наличия ключа (`ContainsKey`).** Возвращает `true` или `false`, позволяя мгновенно узнать, зарегистрирован ли ключ `"Лук"` в коллекции.

> [!TIP]
> По умолчанию строковые ключи чувствительны к регистру (`"Меч"` и `"меч"` — разные ключи). Чтобы игнорировать регистр букв, передайте компаратор при создании: `new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)`.

:::gap

## Грабли и частые ошибки

### 1. Чтение несуществующего ключа через квадратные скобки

* **Так упадёт:** написать `int cost = prices["Лук"];`, когда ключа `"Лук"` нет в словаре — программа аварийно завершится с исключением `KeyNotFoundException`.
* **Так правильно:** использовать `prices.TryGetValue("Лук", out int cost)` или `prices.GetValueOrDefault("Лук", 0)`.

### 2. Добавление дубликата ключа через метод `Add`

* **Так упадёт:** вызвать `prices.Add("Меч", 200);`, если ключ `"Меч"` уже присутствует в словаре — метод выбросит `ArgumentException` (элемент с таким ключом уже добавлен).
* **Так правильно:** использовать индексатор `prices["Меч"] = 200;` (он перезапишет значение) или метод `prices.TryAdd("Меч", 200)`, который безопасно вернёт `false` при совпадении ключа.

### 3. Использование изменяемых объектов в качестве ключа

* **Так сработает неправильно:** положить в ключ собственный класс `Player` и потом изменить его свойство `Name`, от которого зависит хэш-код. Словарь потеряет запись внутри себя и больше не найдёт её ни по старому, ни по новому значению.
* **Так правильно:** выбирать в качестве ключей только неизменяемые типы: `int`, `string`, `Guid`, `enum` или `record`.

### 4. Двойной поиск одного и того же ключа

* **Так сработает неправильно:** писать конструкцию `if (prices.ContainsKey(key)) { var val = prices[key]; }` — словарь дважды вычисляет хэш-код и дважды ищет элемент в памяти.
* **Так правильно:** объединить проверку и получение значения в один вызов `if (prices.TryGetValue(key, out var val))`.

:::gap

## Под капотом и нюансы

### Хэш-таблица и доступ за `O(1)`

Под капотом `Dictionary<TKey, TValue>` устроен как **хэш-таблица** (*Hash Table*) на базе двух внутренних массивов: массива корзин (`buckets`) и массива записей (`entries`).

Когда вы добавляете или ищете ключ:

1. Словарь вызывает у ключа метод `GetHashCode()`, превращая строку или число в целый 32-битный хэш-код.
2. По остатку от деления хэш-кода на размер массива корзин он сразу вычисляет точный индекс ячейки.
3. Если у двух разных ключей совпал номер корзины (**коллизия**), словарь проходит по короткой цепочке индексов внутри `entries` и сравнивает ключи точным методом `Equals()`.

Благодаря этому поиск по ключу работает за константное время `O(1)` — одинаково быстро и на 10 записях, и на 10 миллионах.

### Скорость операций (сложность Big-O)

| Операция | Метод / синтаксис | Сложность | Примечание |
| --- | --- | --- | --- |
| Поиск по ключу | `dict[key]` / `TryGetValue` | `O(1)` | Мгновенный переход по хэш-коду |
| Добавление / обновление | `dict[key] = val` / `TryAdd` | `O(1)`* | *`O(N)` только в момент расширения таблицы |
| Удаление по ключу | `dict.Remove(key)` | `O(1)` | Помечает ячейку свободной без сдвига массива |
| Проверка наличия ключа | `dict.ContainsKey(key)` | `O(1)` | Аналогично поиску по ключу |
| Поиск по значению | `dict.ContainsValue(val)` | `O(N)` | **Медленно:** перебирает все записи подряд |

### Перебор и деконструкция в `foreach`

При обходе словаря в цикле каждый элемент имеет тип `KeyValuePair<TKey, TValue>`. В современном C# его удобно сразу раскладывать на две переменные с помощью деконструкции:

```cs
foreach (var (itemName, itemPrice) in prices)
{
    Console.WriteLine($"{itemName}: {itemPrice} зол.");
}

```

> [!NOTE]
> В отличие от старых версий .NET Framework, в современном .NET словарь сохраняет порядок добавления элементов при переборе в `foreach` — до тех пор, пока вы не начнёте удалять старые ключи и вставлять на их освободившиеся места новые.
