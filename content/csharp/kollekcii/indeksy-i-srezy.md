# Индексы и срезы (^ и ..)

Как достать последний элемент массива без громоздкого `arr.Length - 1` или быстро отрезать кусок текста от второго символа до конца?

:::gap

## Кратко

Операторы индекса с конца (`^`) и диапазона (`..`) позволяют обращаться к элементам коллекций и строк относительно их правого края и вырезать из них фрагменты компактным синтаксисом. Вместо длинных вычислений вроде `items[items.Length - 1]` или вызова `Substring` вы пишете понятные выражения `items[^1]` и `items[1..4]`. Это избавляет код от случайных ошибок на единицу и делает работу с массивами, строками и срезами намного чище.

:::gap

## Быстрый пример

Возьмём массив чисел и строку, чтобы достать элементы с конца и вырезать нужные фрагменты:

```cs
int[] nums = [10, 20, 30, 40, 50];

int last = nums[^1];          // 50 (первый с конца)
int beforeLast = nums[^2];    // 40 (второй с конца)

int[] middle = nums[1..4];    // [20, 30, 40] (с 1-го по 3-й индекс включительно)
int[] head = nums[..2];       // [10, 20] (первые два элемента)
int[] tail = nums[3..];       // [40, 50] (от 3-го индекса до конца)

string file = "photo_2026.png";
string ext = file[^3..];      // "png" (последние 3 символа)

```

:::gap

## Как это работает

При выполнении кода компилятор превращает операторы `^` и `..` в вычисления смещений относительно длины коллекции:

1. **Индекс с конца (`^1`).** Крышка `^` (оператор *index from end*) отсчитывает позицию от правого края. Запись `nums[^1]` компилятор автоматически переводит в `nums[nums.Length - 1]`, возвращая последний элемент (`50`).
2. **Полуоткрытый диапазон (`1..4`).** Две точки `..` задают срез (*range*). Левая граница (`1`) **включается** в результат, а правая (`4`) — **исключается**. Поэтому в `middle` попадают элементы с индексами `1`, `2` и `3` (`20`, `30`, `40`).
3. **Открытые границы (`..2` и `3..`).** Если пропустить число слева (`..2`), срез берётся с самого начала (`0`). Если пропустить число справа (`3..`), срез тянется до самого конца (`^0`).
4. **Комбинация с текстом (`file[^3..]`).** Оба оператора можно объединять: `^3..` означает «отступить 3 символа с конца и взять всё до самого края», что сразу даёт расширение `"png"`.

> [!TIP]
> Удобный способ не путаться в границах среза `a..b`: длина итогового фрагмента всегда равна разнице `b - a` (например, `4 - 1 = 3` элемента).

:::gap

## Грабли и частые ошибки

### 1. Попытка взять последний элемент через `^0`

* **Так упадёт:** написать `int last = nums[^0];` по аналогии с обычным нулевым индексом `nums[0]`. Выражение `^0` разворачивается в `nums.Length - 0`, то есть указывает сразу **за** последний элемент — программа выбросит `IndexOutOfRangeException`.
* **Так правильно:** помнить, что отсчёт с конца начинается с `^1`, а `^0` допустим только как правая граница среза (`nums[2..^0]`).

### 2. Ожидание, что правая граница диапазона включена

* **Так сработает неправильно:** написать `nums[0..2]` в надежде получить три элемента (`0`, `1` и `2`). Правая граница всегда исключается, поэтому вернутся только два элемента: `[10, 20]`.
* **Так правильно:** указывать правую границу на единицу больше нужного индекса: `nums[0..3]`.

### 3. Отрицательные числа внутри индекса

* **Так упадёт:** написать `nums[-1]` (как в Python) или `nums[^-1]`. В первом случае среда выбросит `IndexOutOfRangeException`, во втором — `ArgumentOutOfRangeException`, так как отрицательные смещения запрещены.
* **Так правильно:** использовать `nums[^1]` для обращения с конца.

### 4. Использование срезов на коллекциях без поддержки (`List<T>`)

* **Так не скомпилируется:** написать `list[1..3]` на обычном `List<int>`. Хотя индекс с конца `list[^1]` у списка работает, оператор диапазона `..` требует наличия метода `Slice`, которого у `List<T>` нет (ошибка `CS1503`).
* **Так правильно:** использовать `list.GetRange(1, 2)` или срез через спан `CollectionsMarshal.AsSpan(list)[1..3]`.

:::gap

## Под капотом и нюансы

### Структуры `System.Index` и `System.Range`

Операторы `^` и `..` — это не просто синтаксис для массивов, а полноценные значимые типы (`readonly struct`) в пространстве имён `System`. Переменную индекса или диапазона можно сохранить заранее и передавать в методы как обычный аргумент:

```cs
Index fromEnd = ^2;
Range trimEdges = 1..^1; // Всё, кроме первого и последнего элементов

int[] data = [5, 10, 15, 20, 25];
int[] middle = data[trimEdges]; // [10, 15, 20]

```

Внутри `Index` хранит всего одно целое поле `int _value`: неотрицательные числа означают обычный индекс от начала, а отрицательные (в побитовой инверсии `~value`) — отступ от конца, поэтому структура не тратит лишней памяти.

### Аллокации памяти: копия против окна `Span<T>`

Оператор диапазона ведёт себя по-разному в зависимости от типа, к которому применяется:

| Тип данных | Что делает `x[a..b]` под капотом | Выделяет новую память в куче? |
| --- | --- | --- |
| Массив `T[]` | Вызывает `RuntimeHelpers.GetSubArray`, создавая новый массив и копируя элементы | **Да** (`O(N)` по памяти и времени) |
| Строка `string` | Вызывает `str.Substring(start, length)`, создавая новую строку | **Да** (`O(N)` по памяти и времени) |
| `Span<T>` / `ReadOnlySpan<T>` | Вызывает `span.Slice(start, length)`, сдвигая указатель и длину | **Нет** (`O(1)`, нулевые аллокации) |

Поэтому в горячих циклах при разборе больших текстов или массивов выгоднее сначала вызвать `.AsSpan()`, а уже затем применять срез `text.AsSpan()[1..^1]`.

### Поддержка `^` и `..` в собственных типах

Компилятор разрешает использовать `obj[^1]` для любого вашего класса или структуры, если в нём есть свойство `Length` или `Count` (типа `int`) и индексатор `this[int index]`. А чтобы заработали срезы `obj[1..3]`, достаточно добавить в тип метод `Slice(int start, int length)`.
