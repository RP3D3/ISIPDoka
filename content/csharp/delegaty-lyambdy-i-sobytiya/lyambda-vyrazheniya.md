# Лямбда-выражения (=>): анонимные функции

Как записать короткую функцию прямо внутри вызова метода, не объявляя отдельный именованный метод в классе?

**Лямбда-выражение** (*lambda expression*) — это компактный синтаксис для создания анонимной функции прямо в том месте кода, где ожидается делегат (`Action`, `Func` или `Predicate`). Слева от лямбда-оператора `=>` («переходит в») перечисляются входные параметры, а справа записывается тело функции. Компилятор сам выводит типы параметров из сигнатуры делегата, избавляя от лишнего шаблонного кода и делая передачу алгоритмов в методы максимально наглядной.

## Формы записи лямбда-выражений

| Форма записи | Пример синтаксиса | Когда используется |
| --- | --- | --- |
| **Выражение-лямбда** *(Expression lambda)* | `x => x * 2` | Для вычислений в одну строку — результат выражения возвращается автоматически без `return` |
| **Блочная лямбда** *(Statement lambda)* | `(x, y) => { Log(x); return x + y; }` | Когда внутри анонимной функции нужно выполнить несколько инструкций подряд |
| **Без параметров или с отбрасыванием** | `() => DateTime.Now` / `(_, _) => true` | Когда входные данные не требуются или часть параметров делегата намеренно игнорируется |
| **Явное указание типов** *(C# 10+)* | `var isEven = (int n) => n % 2 == 0;` | Когда лямбду сохраняют в переменную `var` или компилятор не может вывести тип сам |

## Пример кода

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<int> prices = new List<int> { 450, 1200, 3100, 890, 2500 };

        // 1. Выражение-лямбда: компилятор сам понимает, что p имеет тип int (из List<int>)
        List<int> expensive = prices.FindAll(p => p >= 1000);

        // 2. Блочная лямбда: фигурные скобки позволяют писать несколько строк и требуют return
        Func<int, double> applyDiscount = price =>
        {
            double rate = price > 2000 ? 0.85 : 0.95;
            return price * rate;
        };

        // 3. Лямбда без параметров () => ...
        Func<string> getTimestamp = () => DateTime.Now.ToString("HH:mm:ss");

        // 4. Естественный тип делегата (C# 10+): с явным типом параметра можно использовать var
        var formatLine = (int raw, double final) =>
            $"[{getTimestamp()}] Было: {raw} руб. -> Со скидкой: {final:F0} руб.";

        foreach (int itemPrice in expensive)
        {
            double discounted = applyDiscount(itemPrice);
            Console.WriteLine(formatLine(itemPrice, discounted));
        }

        // ❌ Ошибка компиляции (CS0815): нельзя присвоить лямбду в var без явного типа параметра
        // var broken = x => x + 1;
    }
}

```

## Важные нюансы

* **Вывод типов и естественный тип делегата (C# 10+):** если лямбда передаётся в параметр метода (например, `prices.FindAll(p => p >= 1000)`), компилятор берёт типы аргументов из описания делегата. Если же вы сохраняете лямбду в локальную переменную `var`, укажите типы параметров явно (`(int a, int b) => a + b`), чтобы компилятор сам подобрал подходящий делегат `Func` или `Action`.
* **Отбрасывание неиспользуемых параметров (`_`) и модификатор `static`:** начиная с C# 9, ненужные аргументы в списке параметров можно заменять символом `_` (например, `(_, _) => Console.WriteLine("Готово")`), чтобы показать, что они не используются. А модификатор `static` перед лямбдой (`static x => x * 2`) запрещает ей случайно захватывать локальные переменные из внешнего метода.
* **Ограничение деревьев выражений (*Expression Trees*):** хотя любая лямбда преобразуется в обычный делегат, в деревья выражений (`Expression<Func<T, bool>>`, которые используют Entity Framework и базы данных для перевода C#-кода в SQL) можно передавать только однострочные **выражения-лямбды** — блочные лямбды с `{ ... }` вызовут ошибку компиляции `CS0834`.
* **Связь с теорией и следующей темой:** лямбда-выражения делают работу со стандартными делегатами `Action` и `Func` лаконичной и лежат в основе всех запросов LINQ, а в следующей карточке разберём, как анонимная функция запоминает внешние переменные и к каким ловушкам это приводит (*Замыкания — Closures*).
