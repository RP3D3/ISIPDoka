# События (event): безопасная подписка на изменения

Как уведомить десятки других объектов о том, что в классе произошло важное действие, но при этом запретить внешнему коду стирать чужих подписчиков и вызывать уведомления от имени объекта?

**Событие** (`event`) — это специальная защитная обёртка над делегатом, реализующая паттерн **«издатель — подписчик»** (*Publisher — Subscriber*). Класс-издатель объявляет событие и сам решает, в какой момент его запустить, а внешние классы-подписчики могут только подписываться на уведомления (`+=`) и отписываться от них (`-=`). В отличие от обычного публичного поля-делегата, ключевое слово `event` запрещает постороннему коду перезаписать весь список обработчиков через `=` или принудительно вызвать `Invoke()` снаружи.

## Сравнение обычного поля-делегата и события (`event`)

| Действие в коде | Публичное поле `Action` | Событие `event Action` |
| --- | --- | --- |
| **Подписка и отписка (`+=` / `-=`)** | Разрешено любому внешнему коду | Разрешено любому внешнему коду |
| **Перезапись списка (`= null` или `= handler`)** | Разрешено всем (риск стереть чужих подписчиков) | **Запрещено** снаружи (ошибка компиляции `CS0070`) |
| **Запуск уведомления (`?.Invoke(...)`)** | Разрешено любому внешнему коду | **Разрешено только внутри** класса-издателя |
| **Устройство под капотом** | Обычное открытое поле класса | Приватное поле-делегат + методы доступа `add` и `remove` |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Издатель (Publisher): ничего не знает о том, кто именно на него подпишется
        TemperatureSensor sensor = new TemperatureSensor(criticalLimit: 80);

        // Подписчики (Subscribers): подключают свои обработчики через +=
        sensor.Overheated += temp => Console.WriteLine($"[Оповещение]: температура достигла {temp}°C!");
        sensor.Overheated += ActivateCooling;

        sensor.UpdateTemperature(65); // Ниже порога — событие не сработает
        sensor.UpdateTemperature(85); // Превышение порога — сработают оба подписчика

        Console.WriteLine("\nОтключаем автоматическое охлаждение:");
        sensor.Overheated -= ActivateCooling;
        sensor.UpdateTemperature(92);

        // ❌ Ошибка компиляции (CS0070): снаружи класса нельзя перезаписать событие через '='
        // sensor.Overheated = null;

        // ❌ Ошибка компиляции (CS0070): внешний код не может принудительно запустить чужое событие
        // sensor.Overheated?.Invoke(100);
    }

    static void ActivateCooling(int currentTemp) =>
        Console.WriteLine($"[Система охлаждения]: включаю вентиляторы на полную мощность ({currentTemp}°C).");
}

class TemperatureSensor
{
    private readonly int _criticalLimit;

    // Объявление события на базе стандартного делегата Action<int>
    public event Action<int>? Overheated;

    public TemperatureSensor(int criticalLimit) => _criticalLimit = criticalLimit;

    public void UpdateTemperature(int newTemp)
    {
        Console.WriteLine($"Датчик зафиксировал: {newTemp}°C");

        if (newTemp > _criticalLimit)
        {
            // Вызывать событие через Invoke разрешено только внутри самого класса-издателя
            Overheated?.Invoke(newTemp);
        }
    }
}

```

## Важные нюансы

* **Что компилятор генерирует под капотом (`add` и `remove`):** ключевое слово `event` работает по аналогии со свойствами: компилятор создаёт закрытое (*private*) поле-делегат и два метода доступа — `add` (вызывается при `+=`) и `remove` (при `-=`). При необходимости эти аксессоры можно написать вручную, чтобы контролировать регистрацию обработчиков или перенаправлять подписку во вложенный объект.
* **Защита инкапсуляции и ошибка `CS0070`:** без модификатора `event` любой внешний класс мог бы написать `sensor.Overheated = myHandler;` и случайно затереть всех остальных подписчиков или спровоцировать ложное срабатывание через `sensor.Overheated(100)`. Модификатор `event` разрешает внешнему коду использовать событие исключительно слева от операторов `+=` и `-=`.
* **Исключения в цепочке подписчиков:** если на одно событие подписаны три обработчика и второй выбросит исключение, третий обработчик уже не выполнится, а ошибка улетит обратно в метод издателя. Если издателю нужно гарантированно уведомить всех даже при сбое одного из подписчиков, обработчики вызывают в цикле поштучно через `Overheated?.GetInvocationList()`.
* **Связь с теорией и следующей темой:** события воплощают паттерн проектирования *Наблюдатель (Observer)* и принцип слабой связанности, а в следующей карточке разберём, как оформлять события по официальному стандарту .NET с помощью `EventHandler<TEventArgs>` и почему забытая отписка приводит к утечкам памяти (*`EventHandler` и `EventArgs*`).
