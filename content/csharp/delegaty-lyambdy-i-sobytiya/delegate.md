# Делегаты (delegate): ссылки на методы

Как передать метод в качестве аргумента в другой метод, сохранить действие в переменную и вызвать сразу несколько обработчиков одной командой?

**Делегат** (`delegate`) — это типобезопасный ссылочный тип, который хранит ссылку на один или несколько методов со строго определённой сигнатурой (списком параметров и возвращаемым значением). В отличие от обычных переменных, хранящих данные, делегат хранит *поведение*, позволяя передавать алгоритмы как параметры и настраивать обратные вызовы (*callbacks*). Компилятор проверяет совпадение сигнатур на этапе сборки, поэтому подставить в делегат метод с неподходящими параметрами невозможно.

## Основные операции с делегатами

| Операция | Синтаксис | Как работает |
| --- | --- | --- |
| **Объявление типа** | `delegate void LogHandler(string msg);` | Создаёт новый тип-шаблон для методов с указанными параметрами и возвращаемым типом |
| **Присваивание метода** | `LogHandler handler = PrintToConsole;` | Связывает переменную с методом (имя метода указывается без круглых скобок) |
| **Безопасный вызов** | `handler?.Invoke("Готово");` | Проверяет делегат на `null` перед запуском, защищая программу от `NullReferenceException` |
| **Многоадресность (*Multicast*)** | `handler += SaveToFile; handler -= PrintToConsole;` | Объединяет несколько методов в единую цепочку вызова или удаляет метод из списка |

## Пример кода

```csharp
using System;

// 1. Объявляем тип делегата: он примет любой метод, получающий string и возвращающий void
delegate void NotificationHandler(string message);

class Program
{
    static void Main()
    {
        // 2. Создаём цепочку вызовов (многоадресный делегат) с помощью +=
        NotificationHandler notifier = SendEmail;
        notifier += SendSms;

        // 3. Передаём делегат как обычный аргумент в метод оформления заказа
        CompleteOrder(orderId: 912, onCompleted: notifier);

        Console.WriteLine("\nОтключаем SMS-уведомления:");
        notifier -= SendSms;

        // 4. Безопасный вызов через ?.Invoke() не упадёт, даже если отпишутся все методы
        notifier?.Invoke("Чек сформирован.");

        // ❌ Ошибка компиляции (CS0123): сигнатура метода PrintCode не совпадает с NotificationHandler
        // NotificationHandler broken = PrintCode;
    }

    static void CompleteOrder(int orderId, NotificationHandler? onCompleted)
    {
        Console.WriteLine($"Заказ #{orderId} успешно оплачен.");
        onCompleted?.Invoke($"Ваш заказ #{orderId} передан в сборку.");
    }

    static void SendEmail(string text) => Console.WriteLine($"  [Email]: {text}");
    static void SendSms(string text) => Console.WriteLine($"  [SMS]: {text}");
    static void PrintCode(int code) => Console.WriteLine(code);
}

```

## Важные нюансы

* **Почему метод передаётся без круглых скобок:** запись `SendEmail` без `()` передаёт в делегат саму ссылку на метод как объект, тогда как `SendEmail("текст")` немедленно вызывает метод и пытается присвоить его результат.
* **Многоадресные делегаты (*MulticastDelegate*) и возвращаемые значения:** любой делегат в C# неявно наследуется от `System.MulticastDelegate` и внутри хранит список вызовов (*invocation list*). При вызове цепочки через `+=` методы запускаются строго по порядку добавления; если у делегата есть возвращаемое значение (не `void`), вызов вернёт результат только *последнего* метода в цепочке.
* **Защита от `NullReferenceException` через `?.Invoke()`:** делегат без подписанных методов равен `null`, поэтому его прямой вызов `notifier("...")` приведёт к аварийному падению. Оператор условного доступа `notifier?.Invoke("...")` безопасно пропускает вызов, если список подписчиков пуст.
* **Связь со следующей темой:** делегаты позволяют гибко подменять части алгоритма без создания лишних классов и интерфейсов (паттерн *Стратегия*), а чтобы не объявлять собственный тип `delegate` под каждую задачу, в .NET предусмотрены готовые универсальные шаблоны (см. следующую карточку: *Стандартные делегаты `Action`, `Func` и `Predicate`*).
