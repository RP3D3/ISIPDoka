# Структуры (struct): лёгкие типы значений

Как описать компактный тип данных, который хранится прямо в стеке, не нагружает сборщик мусора и копируется целиком при передаче?

**Структура** (`struct`) — это пользовательский **тип значений** (*value type*), который, как и класс, объединяет поля, свойства, конструкторы и методы, но иначе работает с памятью. При создании структуры программа не выделяет отдельное место в управляемой куче (*Heap*) и не создаёт ссылку — данные хранятся напрямую в переменной (в стеке или внутри другого объекта). Структуры идеально подходят для небольших неделимых величин: координат точки, цвета пикселя, денежной суммы или вектора.

## Варианты и режимы работы структур

| Вариант | Как объявляется | Особенности работы |
| --- | --- | --- |
| **Обычная структура** | `struct Point { ... }` | Хранится по значению и позволяет менять поля после создания |
| **Неизменяемая структура** | `readonly struct Color { ... }` | Запрещает менять любые поля после конструктора и избавляет от скрытых копирований |
| **Значение по умолчанию** | `Point p = default;` | Никогда не равна `null` — все числовые поля автоматически заполняются нулями |
| **Стековая структура** | `ref struct SpanBuffer { ... }` | Жёстко запрещает попадание в кучу (нельзя положить в поле обычного класса) |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // Создаём структуру: данные размещаются напрямую в переменной в стеке, без кучи
        GeoPoint office = new GeoPoint(55.75, 37.61);

        // При присваивании копируется всё значение целиком (создаётся независимая копия)
        GeoPoint backup = office;
        backup.Latitude = 59.93;

        Console.WriteLine($"Офис: {office.Latitude}; {office.Longitude}");   // Осталось 55.75
        Console.WriteLine($"Копия: {backup.Latitude}; {backup.Longitude}");  // Изменилось на 59.93

        // Значение default: структура не бывает null, её поля заполнены нулями
        GeoPoint zeroPoint = default;
        Console.WriteLine($"Нулевая точка: {zeroPoint.Latitude}; {zeroPoint.Longitude}");

        // Неизменяемая структура гарантирует сохранность данных при передаче
        RgbColor green = new RgbColor(46, 204, 113);
        Console.WriteLine($"Цвет RGB: {green.R}, {green.G}, {green.B}");
    }
}

struct GeoPoint
{
    public double Latitude;
    public double Longitude;

    public GeoPoint(double latitude, double longitude)
    {
        Latitude = latitude;
        Longitude = longitude;
    }
}

readonly struct RgbColor
{
    public byte R { get; }
    public byte G { get; }
    public byte B { get; }

    public RgbColor(byte r, byte g, byte b)
    {
        R = r;
        G = g;
        B = b;
    }
}

```

## Важные нюансы

* **Защита от `NullReferenceException`:** так как структура хранит само значение, а не адрес в памяти, переменная типа `struct` всегда содержит готовые данные — даже без вызова конструктора через `new` она инициализируется нулями через `default`.
* **Почему рекомендуют `readonly struct`:** изменяемые структуры часто сбивают с толку — если передать структуру в метод или достать из списка `List<GeoPoint>`, вы получите её копию, и изменение полей этой копии не затронет оригинал. Модификатор `readonly struct` делает тип полностью неизменяемым и ускоряет вызов его методов.
* **Ограничения по размеру и наследованию:** структура не может наследоваться от другого класса или структуры (она умеет только реализовывать интерфейсы), а её общий размер желательно держать небольшим (до 16–24 байт), иначе постоянное копирование всех полей при передаче в методы замедлит программу.
* **Связь с соседними темами:** экономия на работе сборщика мусора и копирование данных напрямую связаны с устройством памяти (*Память программы: стек и куча*), а подробные правила выбора между классом и структурой разберём в следующей карточке (*class против struct*).
