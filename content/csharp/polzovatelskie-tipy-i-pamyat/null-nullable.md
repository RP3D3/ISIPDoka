# null и Nullable-типы: защита от пустых ссылок

Как безопасно работать с отсутствующими данными, разрешить типам значений хранить пустоту и защитить программу от внезапного падения с ошибкой `NullReferenceException`?

Значение `null` означает, что ссылочная переменная никуда не указывает — объекта в куче (*Heap*) для неё не существует. Обычные типы значений (`int`, `bool`, `struct`) по умолчанию не могут быть `null`, но с помощью суффикса `?` (`int?`) их можно превратить в **Nullable-типы** (`Nullable<T>`), способные хранить либо значение, либо отсутствие данных. Для ссылочных типов (`string?`, `User?`) современный C# включает статический анализ, который предупреждает о риске обращения к `null` ещё до запуска программы, а специальные операторы `?.`, `??` и `??=` позволяют лаконично обрабатывать пустые значения без громоздких проверок `if`.

## Операторы и конструкции для работы с `null`

| Конструкция | Название и смысл | Пример использования |
| --- | --- | --- |
| `T?` | **Nullable-тип:** разрешает переменной хранить значение `null` | `int? score = null;`<br>

<br>`string? comment = null;` |
| `?.` и `?[]` | **Условный доступ:** обращается к члену или индексу, только если объект не `null` | `string? city = user?.Address?.City;` |
| `??` | **Объединение с null:** подставляет запасное значение, если слева оказался `null` | `string name = inputName ?? "Аноним";` |
| `??=` | **Присваивание при null:** записывает значение в переменную, только если она пуста | `cache ??= LoadDefaultData();` |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. Nullable-тип значений (int?): полезно, когда значение может отсутствовать (например, из БД)
        int? discountPercent = null;
        int finalDiscount = discountPercent ?? 0; // Если скидка не задана, берём 0
        Console.WriteLine($"Скидка: {finalDiscount}% (задана явно: {discountPercent.HasValue})");

        // 2. Безопасная цепочка вызовов (?.) в связке с запасным значением (??)
        Customer? guest = null;
        string city = guest?.Profile?.City ?? "Город не указан";
        Console.WriteLine($"Город клиента: {city}");

        // 3. Присваивание только если переменная ещё равна null (??=)
        string? nickname = null;
        nickname ??= "Игрок_1";
        nickname ??= "Другое_имя"; // Не сработает, так как nickname уже не null
        Console.WriteLine($"Никнейм: {nickname}");

        // ❌ Ошибка во время выполнения (NullReferenceException): прямой вызов метода у null
        // Console.WriteLine(guest.Profile.City);
    }
}

class Customer
{
    public UserProfile? Profile { get; set; }
}

class UserProfile
{
    public string? City { get; set; }
}

```

## Важные нюансы

* **Разное устройство `int?` и `string?` под капотом:** для типов значений `int?` — это реальная обёртка-структура `Nullable<int>`, которая хранит само число и логический флаг `HasValue`. Для ссылочных типов `string?` не создаёт новый тип в памяти, а служит разметкой для компилятора, который проверяет код и выдаёт предупреждения (`CS8600`, `CS8602`) при попытке разыменовать потенциальный `null`.
* **Короткое замыкание оператора `?.`:** если в длинной цепочке `order?.Customer?.Profile?.City` первый же элемент равен `null`, C# мгновенно прерывает вычисление и возвращает `null`, не проверяя остальные звенья и не выбрасывая `NullReferenceException`.
* **Осторожно с оператором `!` (*null-forgiving*):** восклицательный знак после переменной (`user!.Name`) лишь приказывает компилятору отключить предупреждение, но не добавляет никакой защиты во время работы программы — если там всё-таки окажется `null`, приложение аварийно завершится.
* **Связь с соседними темами:** запрет на `null` у обычных структур и наличие пустых ссылок у классов напрямую вытекают из различий между стеком и кучей (см. карточки *Память программы: стек и куча* и *class против struct*).
