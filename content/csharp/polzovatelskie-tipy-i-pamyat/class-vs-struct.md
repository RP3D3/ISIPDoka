# class против struct: ссылка или значение

Почему изменение копии объекта класса меняет оригинал, а структура остаётся прежней, и как безошибочно выбрать между ними при проектировании типа?

Главное различие между классом (`class`) и структурой (`struct`) заключается в модели работы с памятью: класс является **ссылочным типом** (*reference type*), а структура — **типом значений** (*value type*). Когда вы присваиваете экземпляр класса другой переменной или передаёте его в метод, копируется только адрес объекта в управляемой куче (*Heap*), поэтому обе переменные смотрят на одни и те же данные. При передаче структуры копируется всё её содержимое целиком, создавая полностью независимый дубликат.

## Сравнение class и struct

| Критерий | Класс (`class`) | Структура (`struct`) |
| --- | --- | --- |
| **Категория типа** | Ссылочный тип (*reference type*) | Тип значений (*value type*) |
| **Хранение в памяти** | Сам объект в куче (*Heap*), ссылка на него — в стеке (*Stack*) | Данные лежат напрямую в стеке или внутри родительского объекта |
| **Копирование и передача** | Копируется только ссылка — изменения через копию меняют оригинал | Копируются все поля целиком — оригинал остаётся нетронутым |
| **Значение `null**` | Поддерживается по умолчанию (ссылка может никуда не указывать) | Не допускается (без обёртки `Nullable`), по умолчанию заполнена нулями |
| **Наследование** | Поддерживает наследование классов и реализацию интерфейсов | Не может наследоваться от других типов (только интерфейсы) |

## Пример кода

```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. КЛАСС (ссылочный тип): две переменные указывают на один объект в куче
        WalletClass walletA = new WalletClass { Balance = 1000 };
        WalletClass walletB = walletA; // Копируется только ссылка (адрес)
        walletB.Balance = 500;
        Console.WriteLine($"Класс — оригинал: {walletA.Balance}, копия: {walletB.Balance}"); // 500 и 500

        // 2. СТРУКТУРА (тип значений): создаётся полная независимая копия данных
        PointStruct pointA = new PointStruct { X = 10, Y = 20 };
        PointStruct pointB = pointA; // Копируются сами числа X и Y
        pointB.X = 99;
        Console.WriteLine($"Структура — оригинал: {pointA.X}, копия: {pointB.X}"); // 10 и 99
    }
}

class WalletClass
{
    public int Balance;
}

struct PointStruct
{
    public int X;
    public int Y;
}

```

## Важные нюансы

* **Ловушка упаковки (*Boxing*):** если передать структуру в переменную типа `object` или привести её к интерфейсу, среде выполнения придётся выделить память в куче и скопировать туда структуру. Частая упаковка в циклах убивает главное преимущество структур — отсутствие нагрузки на сборщик мусора.
* **Изменение структуры внутри коллекции или свойства:** попытка напрямую изменить поле структуры, полученной через свойство или элемент списка (`points[0].X = 5;`), вызовет ошибку компиляции `CS1612`, так как свойство или индексатор возвращает временную копию значения, а не оригинал.
* **Правило выбора на практике:** в 90% случаев используйте `class` — особенно если объект имеет сложную логику, изменяемое состояние, наследование или размер больше 16–24 байт. Выбирайте `struct` только для маленьких, неделимых и желательно неизменяемых (`readonly`) величин вроде координат, дат или денежных сумм.
* **Связь с теорией:** разница в работе ссылок и значений напрямую опирается на устройство стека и кучи, а также на передачу параметров по ссылке через `ref` и `in` (см. теоретический раздел: *Память программы: стек и куча* и практическую группу *Методы: `ref`, `out`, `in*`).
