# async и await: асинхронное программирование

Как выполнять долгие сетевые запросы и чтение файлов без зависания интерфейса и простоя потоков, сохраняя код таким же линейным и читаемым, как обычный синхронный?

Модификатор `async` и оператор `await` позволяют писать неблокирующий асинхронный код в привычном последовательном стиле без вложенных обратных вызовов (*callbacks*). Когда метод доходит до `await` (например, при обращении к API или базе данных), текущий поток не простаивает впустую в ожидании ответа от операционной системы — он мгновенно возвращается в пул потоков (*ThreadPool*) для обслуживания других задач. Как только операция ввода-вывода (*I/O*) завершается, выполнение метода автоматически возобновляется со следующей строки, а состояние локальных переменных сохраняется благодаря скрытому конечному автомату (*state machine*), который генерирует компилятор.

## Ключевые элементы async / await

| Элемент | Синтаксис / сигнатура | Назначение и как работает |
| --- | --- | --- |
| **`async`** | `public async Task SaveAsync()` | Разрешает использовать `await` внутри метода и оборачивает его выполнение в объект задачи (`Task`) |
| **`await`** | `string data = await LoadAsync();` | Приостанавливает метод без блокировки потока до завершения задачи и распаковывает её результат |
| **`Task`** | `public async Task SendEmailAsync()` | Представляет асинхронную операцию, не возвращающую значение (асинхронный аналог `void`) |
| **`Task<TResult>`** | `public async Task<int> GetCountAsync()` | Представляет асинхронную операцию, которая после завершения вернёт значение типа `TResult` |
| **`async void`** | `private async void OnClick(object s, EventArgs e)` | Применяется **только** для обработчиков событий; исключения из него невозможно поймать в `try / catch` |

## Пример кода

```csharp
using System;
using System.Threading.Tasks;

class Program
{
    // В современном C# точка входа Main сама может быть асинхронной (async Task)
    static async Task Main()
    {
        Console.WriteLine("Запуск обработки заказа...");

        try
        {
            await ProcessOrderAsync(orderId: 507);
        }
        catch (InvalidOperationException ex)
        {
            // Исключение, возникшее внутри async-метода, сохраняется в Task и выбрасывается в точке await
            Console.WriteLine($"Ошибка при обработке: {ex.Message}");
        }

        // ❌ Ошибка 1: вызов .Result или .Wait() блокирует поток и может вызвать взаимоблокировку (Deadlock)
        // string blocked = FetchCustomerNameAsync(1).Result;

        // ❌ Ошибка 2: async void в обычных методах нельзя дождаться, а любое исключение в нём уронит процесс
        // BadFireAndForget();
    }

    // 1. Метод без возвращаемого значения возвращает Task (а не void!), чтобы его можно было ждать через await
    static async Task ProcessOrderAsync(int orderId)
    {
        // 2. Асинхронный метод выполняется синхронно вплоть до первого незавершённого await
        string customerName = await FetchCustomerNameAsync(orderId);
        Console.WriteLine($"Клиент найден: {customerName}");

        bool isPaid = await VerifyPaymentAsync(orderId);
        if (!isPaid)
        {
            throw new InvalidOperationException($"Заказ #{orderId} не оплачен.");
        }

        Console.WriteLine($"Заказ #{orderId} успешно передан в доставку.");
    }

    // 3. Метод, возвращающий результат, оборачивает его в Task<TResult>
    static async Task<string> FetchCustomerNameAsync(int orderId)
    {
        // Имитация неблокирующего запроса к базе данных (поток освобождается на 300 мс)
        await Task.Delay(300);
        return $"Пользователь_#{orderId}";
    }

    static async Task<bool> VerifyPaymentAsync(int orderId)
    {
        await Task.Delay(200);
        return orderId > 0;
    }

    static async void BadFireAndForget()
    {
        await Task.Delay(100);
        throw new Exception("Эта ошибка не попадёт в try/catch вызывающего кода!");
    }
}

```

## Важные нюансы

* **Асинхронность не создаёт новые потоки:** связка `async / await` предназначена прежде всего для операций ввода-вывода (*I/O-bound*: сеть, диск, базы данных), где основное время тратится на ожидание ответа от внешнего устройства. Во время `await` текущий поток просто освобождается для других запросов; дополнительные потоки из пула при этом не выделяются.
* **Синхронное начало метода до первого `await`:** любой `async`-метод начинает выполняться строго синхронно в том же потоке, который его вызвал, вплоть до первого оператора `await`, чья задача ещё не завершена. Поэтому проверку входных аргументов (например, `ArgumentNullException.ThrowIfNull`) выносят в начало метода до первого `await` — тогда ошибка выбросится сразу при вызове, а не отложится до ожидания задачи.
* **Почему `async void` опасен, а `.Result` / `.Wait()` приводят к зависаниям:** при объявлении `async void` вызывающий код не получает объект `Task`, не может отследить момент окончания работы и не способен перехватить исключение через `try / catch` — ошибка аварийно завершит весь процесс. Принудительная блокировка через `.Result` или `.Wait()` удерживает поток занятым и в приложениях с контекстом синхронизации (UI, старый ASP.NET) вызывает классическую взаимоблокировку (*deadlock*).
* **Связь с теорией и следующей темой:** перехват исключений из объекта `Task` при помощи `try / catch` опирается на механизм раскрутки стека из группы 160 (*Исключения и ошибки*), а в следующей карточке мы разберём, как запускать несколько асинхронных задач одновременно и экономить память на быстрых результатах (*`WhenAll`, `WhenAny` и `ValueTask*`).
