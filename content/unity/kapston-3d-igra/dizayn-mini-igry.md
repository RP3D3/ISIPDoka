# Дизайн мини-игры

Капстон — это маленькая законченная игра, а не «ещё немного функций». Сначала
опишите игру на одной странице, чтобы не утонуть в деталях.

## Одна страница

Ответьте на вопросы:

1. **Цель игрока** — что нужно сделать, чтобы победить?
2. **Препятствие** — что мешает?
3. **Управление** — какие 3–5 действий доступны?
4. **Проигрыш** — когда игрок терпит поражение?
5. **Длительность** — сколько длится один забег?
6. **Рамки** — что точно не входит в проект?

Пример:

```text
Цель: собрать 5 кристаллов и дойти до выхода.
Препятствия: 3 патрулирующих врага, пропасть, закрытая дверь.
Управление: WASD, прыжок, камера мышью.
Проигрыш: здоровье 0.
Длительность: 3–5 минут.
Не входит: инвентарь, диалоги, сохранения, мультиплеер.
```

## Core loop

Core loop — что игрок делает снова и снова:

```text
Осмотреться → двигаться → избегать врага → собрать предмет → дойти до выхода
```

Если цикл не помещается в одно предложение, проект слишком большой.

## Рамки

Для капстона достаточно:

- одной сцены;
- одного типа врагов;
- одного типа предметов;
- простого UI;
- победы и поражения.

Всё остальное — бонус, а не обязательная часть.

## Критерии готовности

- игра запускается из билда;
- управление работает;
- есть победа и поражение;
- есть рестарт;
- нет критических ошибок;
- проект можно показать другому человеку без объяснений.

## Частые ошибки

- **Слишком большой замысел.** Лучше маленькая законченная игра.
- **Нет критериев победы.** Игрок не понимает, что делать.
- **Добавляют функции до готовности цикла.** Сначала база.
- **Нет рамок.** Проект растёт бесконечно.
