# Делегаты и лямбда-выражения (Action, Func, =>)

Как передать в метод не просто число или строку, а целое действие или условие фильтрации — например, правило расчёта бонусного урона или реакцию на событие — не создавая ради этого десяток отдельных классов?

:::gap

## Кратко

Делегат (*delegate*) — это типобезопасная ссылка на метод, которая позволяет хранить функцию в переменной, передавать её как аргумент в другие методы и вызывать позже. Чтобы не объявлять свои типы делегатов вручную, в C# используют готовые универсальные шаблоны: `Action` (для методов, которые ничего не возвращают) и `Func` (для методов, возвращающих результат). А лямбда-выражения с оператором `=>` позволяют записывать такие мини-функции прямо по месту вызова в одну компактную строчку без лишнего шаблонного кода.

:::gap

## Быстрый пример

Создадим обработчик уведомлений через `Action`, формулу крита через `Func` и передадим лямбда-выражение напрямую в метод атаки:

```cs
// 1. Action: хранит метод, который принимает аргументы и возвращает void
Action<string> notify = msg => Console.WriteLine($"[ЛОГ] {msg}");
notify("Бой начался");

// 2. Func: последний тип в угловых скобках — всегда тип возвращаемого значения
Func<int, int> doubleDamage = dmg => dmg * 2;
Console.WriteLine($"Крит: {doubleDamage(30)}"); // Крит: 60

// 3. Передача лямбда-выражения напрямую как параметра в метод
AttackEnemy("Дракон", baseDamage: 40, modifier: dmg => dmg + 15, onHit: notify);

void AttackEnemy(string target, int baseDamage, Func<int, int> modifier, Action<string> onHit)
{
    int finalDamage = modifier(baseDamage); // Вызываем переданную функцию
    onHit($"{target} получил {finalDamage} урона!");
}

```

:::gap

## Как это работает

При выполнении кода среда .NET оборачивает методы в объекты-делегаты и позволяет вызывать их как обычные функции:

1. **Переменная-действие (`Action<string>`).** В угловых скобках указываются типы входных параметров. Метод ничего не возвращает (`void`), поэтому переменную `notify` можно вызывать напрямую: `notify("Бой начался")`.
2. **Переменная-вычисление (`Func<int, int>`).** У `Func` самый последний параметр в угловых скобках всегда обозначает тип результата, а все предыдущие — входные параметры. Запись `Func<int, int>` означает «принимает `int` и возвращает `int`».
3. **Стрелка лямбда-выражения (`dmg => dmg * 2`).** Оператор `=>` читается как «переходит в» или «возвращает». Слева от стрелки пишутся входные параметры (их типы компилятор выводит сам из `Func<int, int>`), а справа — вычисляемое выражение или блок в фигурных скобках `{ ... }`.
4. **Гибкая настройка логики (`AttackEnemy`).** Метод `AttackEnemy` не знает заранее, по какой формуле считается бонус к урону и куда выводится текст. Мы подставляем правило `dmg => dmg + 15` и обработчик `notify` прямо в момент вызова.

> [!TIP]
> Если метод не принимает никаких параметров, используйте `Action` без угловых скобок (`Action sayHi = () => Console.WriteLine("Привет!");`) или `Func<TResult>` с одним типом результата (`Func<int> rollDice = () => Random.Shared.Next(1, 7);`).

:::gap

## Грабли и частые ошибки

### 1. Захват счётчика цикла `for` в замыкании

* **Так сработает неправильно:** создать в цикле `for (int i = 0; i < 3; i++)` три лямбды `actions.Add(() => Console.WriteLine(i));` и запустить их после окончания цикла. Все три лямбды захватят **одну и ту же** переменную `i` и выведут `3, 3, 3` вместо `0, 1, 2`.
* **Так правильно:** внутри тела цикла `for` скопировать счётчик в локальную переменную `int copy = i;` и использовать `copy` внутри лямбды (в цикле `foreach` компилятор современного C# создаёт новую переменную на каждом шаге автоматически).

### 2. Путаница в порядке типов у `Func`

* **Так не скомпилируется:** написать `Func<bool, string> isLong = s => s.Length > 5;`, поставив тип результата `bool` на первое место (ошибка `CS0029` или `CS1662`).
* **Так правильно:** помнить железное правило `Func`: **возвращаемый тип всегда стоит самым последним** — `Func<string, bool> isLong = s => s.Length > 5;`.

### 3. Вызов пустого делегата без проверки на `null` (`NullReferenceException`)

* **Так упадёт:** объявить `Action? onComplete = null;` и вызвать его напрямую как `onComplete();` — программа аварийно завершится с `NullReferenceException`.
* **Так правильно:** использовать null-условный вызов `onComplete?.Invoke();` — если метод не назначен, вызов безопасно проигнорируется.

### 4. Попытка присвоить друг другу два разных типа делегатов с одинаковой сигнатурой

* **Так не скомпилируется:** объявить собственный `delegate void MyCallback(string text);` и попытаться передать переменную этого типа в параметр `Action<string>` (ошибка `CS0029`). Несмотря на одинаковые параметры, в C# это два разных класса делегатов.
* **Так правильно:** везде в современном коде использовать стандартные `Action` и `Func` вместо объявления собственных `delegate`.

:::gap

## Под капотом и нюансы

### `MulticastDelegate` и замыкания (*Closures*)

На уровне среды выполнения CLR любой делегат — это полноценный ссылочный класс, унаследованный от `System.MulticastDelegate`. Внутри него хранятся указатель на код метода (`_methodPtr`) и ссылка на экземпляр объекта (`_target`), если метод не является статичным.

Когда лямбда-выражение использует локальную переменную из внешнего метода, происходит **замыкание** (*closure*): компилятор незаметно генерирует в куче скрытый класс-контейнер и переносит захваченную переменную в его поле. Благодаря этому переменная продолжает жить в памяти до тех пор, пока жив сам делегат, даже если создавший её метод уже давно завершился.

### Многоадресные делегаты (`+=` и `-=`)

Поскольку все делегаты наследуются от `MulticastDelegate`, в одну переменную `Action` можно подписать сразу несколько методов через оператор `+=`:

```cs
Action pipeline = () => Console.WriteLine("Шаг 1: Сохранение");
pipeline += () => Console.WriteLine("Шаг 2: Отправка в облако");

pipeline(); // Выполнит оба действия по порядку

```

У `Func` при объединении нескольких методов через `+=` сработают все методы по очереди, но наружу вернётся результат только самого последнего из них.

### Шпаргалка по делегатам в C#

| Тип делегата | Что принимает и возвращает | Типичный сценарий |
| --- | --- | --- |
| `Action` / `Action<T1, T2>` | Принимает от 0 до 16 аргументов, возвращает `void` | Колбэки без результата, логирование, `List.ForEach` |
| `Func<T1, TResult>` | Принимает от 0 до 16 аргументов, возвращает `TResult` (последний!) | LINQ (`Where`, `Select`), формулы расчётов, фабрики |
| `Predicate<T>` | Принимает один аргумент `T`, всегда возвращает `bool` | Устаревший аналог `Func<T, bool>` в `List.Find` и `List.RemoveAll` |
| `delegate int MathOp(int a, int b)` | Пользовательский тип с именованными параметрами | Когда нужны имена параметров в подсказках или `ref`/`out`/`in` |
