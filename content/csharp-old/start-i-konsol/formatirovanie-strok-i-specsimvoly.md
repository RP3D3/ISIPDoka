# Форматирование строк и спецсимволы

Как красиво выровнять столбцы в таблице, округлить дробное число до копеек или вставить кавычки и перенос строки прямо внутрь текста?

:::gap

## Кратко

Форматирование строк и управляющие символы (escape-последовательности) позволяют управлять внешним видом текста: добавлять переносы и табуляцию, подставлять значения переменных, выравнивать колонки пробелами и аккуратно отображать числа или даты. Без этих инструментов любой вывод превращается в нечитаемую кашу из склеенных слов и длинных дробей вроде `33.333333333333336`. Это базовый набор для создания аккуратных отчётов, логов и консольных меню.

:::gap

## Быстрый пример

Соберём в одном месте интерполяцию, выравнивание столбцов, форматы чисел и спецсимволы:

```cs
string item = "Зелье маны";
int count = 1250;
double price = 49.9;

// Интерполяция ($), табуляция (\t), выравнивание (-14) и форматы чисел (:N0, :F2)
Console.WriteLine($"Товар:\t{item,-14} | Кол-во: {count:N0} | Цена: {price:F2} руб.");
// Товар:	Зелье маны     | Кол-во: 1 250 | Цена: 49,90 руб.

// Составное форматирование через плейсхолдеры ({0}) и перенос строки (\n)
Console.WriteLine("Код ошибки: 0x{0:X4}\nСтатус: \"Критично\"", 255);
// Код ошибки: 0x00FF
// Статус: "Критично"

// Буквальная строка (@) отключает экранирование обратных слэшей
string path = @"C:\Games\Save\slot_1.dat";

```

:::gap

## Как это работает

Компилятор и среда выполнения .NET обрабатывают специальные маркеры внутри кавычек перед тем, как собрать итоговую строку:

1. **Escape-последовательности (`\t`, `\n`, `\"`).** Обратный слэш `\` внутри обычной строки работает как команда: `\t` вставляет горизонтальную табуляцию (отступ), `\n` переводит текст на новую строку, а `\"` позволяет напечатать двойные кавычки, не закрывая саму строку.
2. **Выравнивание ширины (`{item,-14}`).** Внутри интерполированной строки (со знаком `$`) после имени переменной можно поставить запятую и число. Значение `-14` выделяет под текст ровно 14 символов и выравнивает его по левому краю (добивая остаток пробелами). Если указать положительное число `14`, текст прижмётся к правому краю.
3. **Спецификаторы формата (`:N0`, `:F2`, `:X4`).** Двоеточие после переменной задаёт шаблон отображения: `N0` разбивает число на разряды пробелами без дробной части (`1 250`), `F2` оставляет строго два знака после запятой (`49,90`), а `X4` переводит число в шестнадцатеричный вид и дополняет нулями до четырёх символов (`00FF`).
4. **Плейсхолдеры (`{0}`).** Классический способ форматирования (как в `string.Format`): в тексте расставляются нумерованные заглушки `{0}`, `{1}`, а сами значения передаются следом через запятую.
5. **Буквальные строки (`@"..."`).** Символ `@` перед открывающей кавычкой отключает обработку обратного слэша. Все символы внутри читаются буквально как есть — это спасает при записи путей к файлам Windows и регулярных выражений.

> [!TIP]
> Форматирование работает не только в `Console.WriteLine` — точно так же можно собирать готовые строки в переменную: `string text = $"Баланс: {gold:N0}";`.

:::gap

## Грабли и частые ошибки

### 1. Одинарный обратный слэш в пути к файлу

* **Так не скомпилируется:** написать `string path = "C:\Users\new\test.txt";`. Компилятор увидит `\U` как начало Юникод-символа и остановит сборку с ошибкой `CS1009` (неизвестная escape-последовательность). Даже если путь скомпилируется, `\n` и `\t` внутри него превратятся в разрыв строки и отступ.
* **Так правильно:** использовать буквальную строку `string path = @"C:\Users\new\test.txt";` или экранировать каждый слэш вторым слэшем `"C:\\Users\\new\\test.txt"`.

### 2. Фигурные скобки внутри интерполированной строки

* **Так не скомпилируется:** написать `string json = $"{{ \"id\": {id} }}";` с одинарными внешними скобками `$"..."` — компилятор попытается воспринять `{ "id":` как C#-код и выдаст ошибку `CS8076`.
* **Так правильно:** удваивать фигурные скобки, которые должны попасть в текст как обычные символы: `$"{{ \"id\": {id} }}"`.

### 3. Запятая вместо точки в дробях из-за региональных настроек

* **Так сработает неправильно:** сформировать строку для CSV-файла или SQL-запроса через `$"{price:F2}"` на компьютере с русской Windows — число `12.5` превратится в `"12,50"` с запятой, что сломает парсер.
* **Так правильно:** для машинного обмена данными передавать инвариантную культуру через `string.Create(CultureInfo.InvariantCulture, $"{price:F2}")` или `price.ToString("F2", CultureInfo.InvariantCulture)`.

### 4. Разрыв обычной строки клавишей Enter

* **Так не скомпилируется:** перенести текст внутри обычных кавычек `"..."` на новую строку в редакторе — компилятор выдаст ошибку `CS1010` (новая строка в константе).
* **Так правильно:** использовать `\n`, буквальную строку `@"..."` или сырые строковые литералы `"""..."""`.

:::gap

## Под капотом и нюансы

### Основные escape-последовательности

| Последовательность | Название | Что делает |
| --- | --- | --- |
| `\n` | Новая строка (Line Feed) | Переносит курсор на следующую строку |
| `\r` | Возврат каретки (Carriage Return) | Возвращает курсор в самое начало **текущей** строки без перехода вниз |
| `\t` | Горизонтальная табуляция | Вставляет отступ до следующей позиции табуляции |
| `\\` | Обратный слэш | Выводит обычный символ `\` |
| `\"` | Двойная кавычка | Выводит символ `"` внутри строки |
| `\0` | Нулевой символ (Null) | Символ с кодом `0` (используется при работе с низкоуровневыми буферами) |
| `\a` | Звуковой сигнал (Alert) | Заставляет терминал издать системный звуковой сигнал |

> [!NOTE]
> Комбинация `\r` (возврат каретки без `\n`) позволяет обновлять текст прямо поверх старого в одной и той же строке консоли — так делают текстовые индикаторы загрузки: `Console.Write($"\rЗагрузка: {percent}%");`.

### Популярные спецификаторы форматов

| Спецификатор | Пример входных данных | Результат (ru-RU) | Назначение |
| --- | --- | --- | --- |
| `:F2` | `12.345` | `12,35` | Число с фиксированным количеством знаков после запятой |
| `:N0` | `1500000` | `1 500 000` | Число с разделителями групп разрядов |
| `:C` | `99.5` | `99,50 ₽` | Денежный формат с символом валюты текущей системы |
| `:P1` | `0.854` | `85,4%` | Умножает число на 100 и добавляет знак процента |
| `:D5` | `42` | `00042` | Дополняет целое число ведущими нулями до нужной длины |
| `:X` / `:x` | `255` | `FF` / `ff` | Переводит целое число в шестнадцатеричную систему |
| `:dd.MM.yyyy` | `DateTime.Now` | `11.11.2026` | Пользовательский формат даты и времени |

### Сырые строковые литералы (C# 11+)

Если в строку нужно вставить большой кусок JSON, HTML-шаблон или ASCII-арт, даже `@"..."` заставляет удваивать кавычки `""`. В современном C# для этого есть **сырые строки** (Raw String Literals), которые открываются и закрываются тремя (или более) кавычками `"""`:

```cs
int userId = 7;

// Двойной знак $$ означает, что код пишется в двойных {{ }}, а одиночные { } — обычный текст
string payload = $$"""
    {
        "id": {{userId}},
        "role": "admin"
    }
    """;

```

Вся левая отбивка пробелами, которая совпадает с отступом закрывающих кавычек `"""`, автоматически обрезается компилятором — в итоговой строке не будет лишних пробелов слева.

### Во что компилируется интерполяция `$""`

До C# 10 любая интерполированная строка `$"{a} {b}"` превращалась компилятором в вызов `string.Format("{0} {1}", a, b)`. Это приводило к упаковке (*boxing*) значимых типов вроде `int` или `double` в объекты и созданию лишних временных массивов в памяти.

Начиная с C# 10 (и .NET 6), компилятор подставляет специальную структуру `DefaultInterpolatedStringHandler`. Она заранее вычисляет примерную длину будущей строки, берёт временный массив символов из общего пула памяти (`ArrayPool<char>`) и записывает числа напрямую в буфер без упаковки. Это делает современную интерполяцию быстрее и экономнее по памяти, чем ручная склейка через `+` или `string.Format`.
