# Значимые и ссылочные типы (стек и куча)

Почему изменение копии числа `b = a` не трогает исходную переменную `a`, а изменение копии объекта `player2 = player1` внезапно меняет здоровье обоим?

:::gap

## Кратко

Все типы данных в C# делятся на две большие семьи: **значимые** (*Value Types*: числа, `bool`, `char`, `enum`, `struct`) и **ссылочные** (*Reference Types*: `class`, `string`, массивы, интерфейсы). Значимые типы хранят само значение напрямую и при присваивании или передаче в метод копируются целиком. Ссылочные типы размещают сам объект в управляемой куче (*Heap*), а в переменной хранят только 8-байтный адрес (ссылку) на него, поэтому при копировании дублируется лишь адрес, а не данные. Понимание этой разницы спасает от скрытых багов с общими объектами и помогает писать быстрый код без лишней нагрузки на сборщик мусора.

:::gap

## Быстрый пример

Сравним поведение структуры (значимого типа) и класса (ссылочного типа) при копировании переменной:

```cs
// 1. Значимый тип (struct): копируются сами данные
PointStruct s1 = new() { X = 10 };
PointStruct s2 = s1; // Создаётся полная независимая копия
s2.X = 99;
Console.WriteLine($"Struct: s1.X = {s1.X}, s2.X = {s2.X}"); // s1.X = 10, s2.X = 99

// 2. Ссылочный тип (class): копируется только ссылка (адрес в куче)
PointClass c1 = new() { X = 10 };
PointClass c2 = c1; // Обе переменные смотрят на один и тот же объект
c2.X = 99;
Console.WriteLine($"Class: c1.X = {c1.X}, c2.X = {c2.X}");  // c1.X = 99, c2.X = 99

struct PointStruct { public int X; }
class PointClass { public int X; }

```

:::gap

## Как это работает

При выполнении кода среда .NET по-разному размещает данные в памяти и обрабатывает операцию присваивания:

1. **Копирование значения (`s2 = s1`).** Поскольку `PointStruct` — значимый тип, локальная переменная `s1` хранит число `10` прямо внутри своей ячейки в стеке. При присваивании `s2 = s1` процессор копирует байты в новую ячейку `s2`. Изменение `s2.X` никак не затрагивает `s1`.
2. **Выделение памяти в куче (`new PointClass()`).** Класс — ссылочный тип. Оператор `new` выделяет блок памяти в управляемой куче (*Managed Heap*), записывает туда поле `X = 10`, а в локальную переменную `c1` в стеке кладёт только адрес этого блока (например, `0x00A4F100`).
3. **Копирование ссылки (`c2 = c1`).** При присваивании `c2 = c1` копируется не сам объект из кучи, а только 8-байтный адрес `0x00A4F100`. Теперь две переменные указывают на одну и ту же область памяти.
4. **Общее изменение (`c2.X = 99`).** Когда мы меняем `X` через `c2`, программа переходит по сохранённому адресу и перезаписывает данные в единственном экземпляре объекта — поэтому `c1.X` тоже показывает `99`.

> [!TIP]
> Проверить, указывают ли две ссылочные переменные на один и тот же объект в куче, можно с помощью встроенного метода `object.ReferenceEquals(c1, c2)`.

:::gap

## Грабли и частые ошибки

### 1. Миф «значимые типы всегда живут только в стеке»

* **Так сработает неправильно:** думать, что `int` или `struct` всегда попадают в стек, даже если объявлены внутри класса. На самом деле место хранения зависит от контекста: если `int Hp` является полем класса `Hero`, он хранится внутри объекта `Hero` прямо в управляемой куче (*Heap*).
* **Так правильно:** запоминать главное различие не по месту в памяти, а по семантике: **значимые типы всегда копируются по значению, ссылочные — по ссылке**.

### 2. Случайное изменение чужих данных через общую ссылку

* **Так сработает неправильно:** передать список `List<int>` или объект в метод и очистить его там (`items.Clear()`), считая, что метод получил копию. Ссылка передаётся в метод по значению, но указывает на тот же самый список в куче — данные удалятся и у вызывающего кода.
* **Так правильно:** создавать явную копию коллекции (`[..items]` или `new List<int>(items)`) или принимать её через интерфейс только для чтения `IReadOnlyList<T>`.

### 3. Попытка присвоить `null` обычному значимому типу

* **Так не скомпилируется:** написать `int age = null;` или `PointStruct p = null;`. Значимые типы всегда содержат конкретное значение и не могут быть пустой ссылкой (ошибка `CS0037`).
* **Так правильно:** использовать Nullable-обёртку со знаком вопроса: `int? age = null;` (под капотом это структура `Nullable<int>`).

### 4. Неявная упаковка (*Boxing*) в горячих циклах

* **Так сработает неправильно:** складывать тысячи чисел или структур в нетипизированный массив `object[]` либо передавать `struct` через интерфейс `IComparable`. Для каждого значения среда выделяет в куче объект-обёртку (*Boxing*), что резко нагружает сборщик мусора.
* **Так правильно:** использовать обобщённые (*Generic*) коллекции вроде `List<int>` и `Dictionary<int, PointStruct>`, которые работают напрямую без упаковки.

:::gap

## Под капотом и нюансы

### Как устроены стек (*Stack*) и управляемая куча (*Managed Heap*)

* **Стек (*Stack*).** Быстрая область памяти конкретного потока (обычно 1 МБ в Windows), работающая по принципу стопки тарелок (LIFO). Выделение и очистка памяти для локальных переменных происходят мгновенно простым сдвигом указателя стека при входе и выходе из метода — сборщик мусора сюда не заходит.
* **Управляемая куча (*Managed Heap*).** Большая общая область памяти всего приложения. Выделение памяти здесь тоже быстрое (сдвиг указателя свободной области), но живут объекты дольше, чем один метод. Очисткой заброшенных объектов занимается **сборщик мусора (*Garbage Collector, GC*)**, периодически приостанавливая потоки для освобождения и уплотнения памяти.

### Упаковка и распаковка (*Boxing* и *Unboxing*)

Если присвоить значимый тип переменной типа `object` или интерфейсу, среда CLR вынуждена выделить объект в куче и скопировать туда значение — это называется **упаковкой** (*Boxing*). Обратное извлечение называется **распаковкой** (*Unboxing*) и требует явного приведения типа:

```cs
int num = 42;
object boxed = num;      // Boxing: выделение памяти в куче и копирование 42
int unboxed = (int)boxed; // Unboxing: проверка типа и копирование обратно в стек

```

### Сводная таблица типов в C#

| Критерий | Значимые типы (*Value Types*) | Ссылочные типы (*Reference Types*) |
| --- | --- | --- |
| Примеры типов | `int`, `double`, `bool`, `char`, `enum`, `struct`, кортежи | `class`, `string`, массивы `T[]`, `delegate`, `interface`, `record` |
| Базовый предок | Неявно наследуются от `System.ValueType` | Наследуются от `System.Object` |
| Что хранит переменная | Само значение целиком | 8-байтный адрес (ссылку) на объект в куче |
| Присваивание `b = a` | Копируются все данные (две независимые копии) | Копируется только ссылка (один общий объект) |
| Значение по умолчанию | Нули (`0`, `false`, `\0`) | `null` (пустая ссылка) |
| Очистка памяти | Мгновенно при выходе из области видимости | Сборщиком мусора (*GC*) в куче |

> [!NOTE]
> Строка `string` является **ссылочным типом** (живёт в куче), но на практике ведёт себя как значимый благодаря **неизменяемости** (*immutability*): любая операция изменения текста создаёт в куче новую строку, оставляя все существующие ссылки на старую строку нетронутыми.
