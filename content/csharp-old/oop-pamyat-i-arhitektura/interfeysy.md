# Интерфейсы (interface)

Как научить абсолютно разные объекты — врага, деревянный ящик и взрывную бочку — одинаково реагировать на удар мечом, не загоняя их в общую иерархию классов?

:::gap

## Кратко

Интерфейс (`interface`) — это контракт, который перечисляет, какие методы, свойства или события обязан реализовать класс или структура, но не описывает, как именно они работают. В отличие от наследования классов, один тип может реализовать сразу сколько угодно интерфейсов через запятую. Это позволяет объединять несвязанные сущности по общим способностям («умеет получать урон», «умеет открываться») и строить гибкую архитектуру без жёсткой привязки к конкретным классам.

:::gap

## Быстрый пример

Создадим два контракта — получение урона и взаимодействие — и подключим их к разным игровым объектам:

```cs
// Собираем разные по природе объекты по их общей способности получать урон
List<IDamageable> targets = [new WoodenChest(), new ExplosiveBarrel()];

foreach (IDamageable target in targets)
{
    target.TakeDamage(25); // Вызовется реализация каждого конкретного класса
}

// Контракт 1: объект можно повредить
interface IDamageable
{
    int Hp { get; }
    void TakeDamage(int amount);
}

// Контракт 2: с объектом можно взаимодействовать
interface IInteractable
{
    void Interact();
}

// Сундук реализует сразу ДВА интерфейса через запятую
class WoodenChest : IDamageable, IInteractable
{
    public int Hp { get; private set; } = 50;

    public void TakeDamage(int amount)
    {
        Hp = Math.Max(0, Hp - amount);
        Console.WriteLine($"Сундук трещит! Осталось прочности: {Hp}");
    }

    public void Interact() => Console.WriteLine("Сундук открыт!");
}

// Бочка реализует только получение урона
class ExplosiveBarrel : IDamageable
{
    public int Hp { get; private set; } = 20;

    public void TakeDamage(int amount)
    {
        Hp = Math.Max(0, Hp - amount);
        if (Hp == 0) Console.WriteLine("БА-БАХ! Бочка взорвалась!");
    }
}

```

:::gap

## Как это работает

При компиляции и выполнении кода среда .NET проверяет соблюдение контракта и связывает вызовы с конкретными классами:

1. **Объявление контракта (`interface IDamageable`).** По соглашению C# имена всех интерфейсов начинаются с заглавной буквы `I` (`IDamageable`, `IDisposable`, `IEnumerable`). Внутри перечислены только заголовки свойства `Hp` и метода `TakeDamage` без тел реализации.
2. **Множественная реализация (`class WoodenChest : IDamageable, IInteractable`).** В C# унаследоваться можно только от одного класса, а вот интерфейсов разрешено подключить сколько угодно через запятую. Если у класса есть ещё и базовый класс, он всегда пишется первым (`class Boss : Enemy, IDamageable`).
3. **Выполнение требований контракта.** Реализующий класс обязан объявить все свойства и методы из списка интерфейса с модификатором `public` и точно такими же сигнатурами. Ключевое слово `override` при этом не пишется.
4. **Работа через тип интерфейса (`List<IDamageable>`).** Переменная или список с типом `IDamageable` принимает любые классы и структуры, подписавшиеся на этот контракт. Через такую ссылку видны только члены самого интерфейса (`TakeDamage` и `Hp`), а остальные детали объекта скрыты.

> [!TIP]
> Проектируйте интерфейсы маленькими и узкими (принцип разделения интерфейсов — ISP): лучше сделать два отдельных контракта `IReadable` и `IWritable`, чем один гигантский интерфейс на двадцать методов, половину из которых классам придётся оставлять пустыми.

:::gap

## Грабли и частые ошибки

### 1. Забытая реализация одного из членов интерфейса (`CS0535`)

* **Так не скомпилируется:** указать `class Barrel : IDamageable`, реализовать метод `TakeDamage`, но забыть свойство `Hp` (или сделать его `private`). Компилятор остановит сборку с ошибкой `CS0535` (класс не реализует член интерфейса).
* **Так правильно:** реализовать абсолютно все члены интерфейса с публичным доступом `public`.

### 2. Попытка написать `override` при реализации метода интерфейса (`CS0115`)

* **Так не скомпилируется:** написать `public override void TakeDamage(int amount)` в классе, который реализует интерфейс. Модификатор `override` используется только для `virtual`- и `abstract`-членов базового класса, поэтому компилятор выдаст ошибку `CS0115`.
* **Так правильно:** объявлять метод просто как `public void TakeDamage(int amount)` (при желании можно добавить `virtual`, если уже ваши наследники будут его переопределять).

### 3. Попытка добавить в интерфейс обычное поле или конструктор (`CS0525`)

* **Так не скомпилируется:** объявить внутри `interface` поле `int _hp = 100;` или конструктор. Интерфейс описывает поведение, а не хранение данных в памяти (ошибка `CS0525`).
* **Так правильно:** описывать в интерфейсе свойства (`int Hp { get; }`), а реальные поля для хранения заводить уже внутри классов.

### 4. Попытка создать экземпляр интерфейса через `new` (`CS0144`)

* **Так не скомпилируется:** написать `IDamageable target = new IDamageable();`. У интерфейса нет реализации, поэтому создать его напрямую невозможно (ошибка `CS0144`).
* **Так правильно:** создавать экземпляр конкретного класса, реализующего интерфейс: `IDamageable target = new WoodenChest();`.

:::gap

## Под капотом и нюансы

### Явная реализация интерфейса (*Explicit Interface Implementation*)

Если класс реализует сразу два интерфейса с одинаковыми именами методов (например, `IWalker.Move()` и `ISwimmer.Move()`), конфликт разрешают с помощью **явной реализации** — указывают имя интерфейса перед методом без модификатора `public`:

```cs
interface IWalker { void Move(); }
interface ISwimmer { void Move(); }

class Duck : IWalker, ISwimmer
{
    void IWalker.Move() => Console.WriteLine("Утка идёт по берегу");
    void ISwimmer.Move() => Console.WriteLine("Утка плывёт по воде");
}

```

Такие методы скрыты при обращении через переменную класса `Duck` и становятся доступны только после приведения переменной к нужному интерфейсу: `((ISwimmer)duck).Move()`.

### Реализация по умолчанию и встроенные интерфейсы .NET

Начиная с C# 8 интерфейсам разрешили добавлять **реализацию методов по умолчанию** прямо внутри `interface`. Это позволяет авторам библиотек расширять существующие интерфейсы новыми методами, не ломая старые классы пользователей.

В стандартной библиотеке .NET на интерфейсах держится большинство возможностей языка:

* `IEnumerable<T>` — позволяет перебирать коллекцию в цикле `foreach` и работать с LINQ.
* `IDisposable` — разрешает использовать конструкцию `using` для гарантированного закрытия файлов и сетевых соединений.
* `IComparable<T>` — учит объекты сравнивать себя друг с другом, чтобы работала сортировка `List.Sort()`.

### Сравнение интерфейса (`interface`) и абстрактного класса (`abstract class`)

| Критерий | Интерфейс (`interface`) | Абстрактный класс (`abstract class`) |
| --- | --- | --- |
| Множественное подключение | **Да** (сколько угодно через запятую) | **Нет** (можно унаследовать только 1 класс) |
| Хранение полей и конструкторов | **Нет** (только свойства, методы, события) | **Да** (полноценное состояние и конструкторы) |
| Поддержка структурами (`struct`) | **Да** (структура может реализовать интерфейс) | **Нет** (структуры не наследуются от классов) |
| Модификаторы доступа членов | По умолчанию `public` | Любые (`public`, `protected`, `private`, `internal`) |
| Главный смысл в архитектуре | Описывает **способность** («что умеет делать») | Описывает **сущность** («чем является») |
