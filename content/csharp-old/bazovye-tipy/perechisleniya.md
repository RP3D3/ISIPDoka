# Перечисления (enum)

Как заменить непонятные «магические числа» вроде статуса заказа `0`, `1` или `2` на читаемые названия прямо в коде?

:::gap

## Кратко

Перечисление (`enum`) — это собственный набор именованных констант, который превращает сухие числа в понятные слова: например, дни недели, уровни сложности или статусы доставки. Вместо того чтобы гадать, что означает `status == 2`, вы пишете `status == OrderStatus.Shipped`. Это защищает от опечаток, включает автодополнение в редакторе и делает код понятным без лишних комментариев.

:::gap

## Быстрый пример

Создадим перечисление для статуса заказа, проверим его в условии и получим скрытый числовой код:

```cs
OrderStatus current = OrderStatus.Paid;

if (current == OrderStatus.Paid)
{
    Console.WriteLine($"Статус: {current}");      // Статус: Paid
    Console.WriteLine($"Код: {(int)current}");    // Код: 1
}

// Объявление перечисления (в файле с инструкциями верхнего уровня — в самом низу)
enum OrderStatus
{
    Created,    // 0
    Paid,       // 1
    Shipped,    // 2
    Delivered   // 3
}

```

:::gap

## Как это работает

При выполнении кода компилятор подставляет вместо текстовых имён обычные целые числа, сохраняя при этом строгую проверку типов:

1. **Объявление набора вариантов (`enum OrderStatus`).** Мы создаём новый тип данных и перечисляем внутри фигурных скобок все допустимые состояния через запятую. По умолчанию компилятор автоматически нумерует их с нуля (`Created = 0`, `Paid = 1` и так далее).
2. **Создание переменной (`OrderStatus current`).** Теперь `OrderStatus` работает как полноценный тип (наравне с `int` или `string`). В переменную можно записать только один из заранее заданных вариантов через точку.
3. **Сравнение и вывод имени.** В условии `current == OrderStatus.Paid` мы сравниваем значения без единого «магического числа». При передаче в `Console.WriteLine` среда .NET автоматически превращает значение в его текстовое имя (`"Paid"`).
4. **Получение числового кода (`(int)current`).** Под капотом каждый элемент остаётся целым числом. Явное приведение `(int)` позволяет вытащить его порядковый номер (`1`), например, для записи в базу данных.

> [!TIP]
> В конструкции `switch` по перечислению современные редакторы (Visual Studio, Rider) умеют автоматически сгенерировать все ветки `case` для каждого элемента `enum` за одно нажатие.

:::gap

## Грабли и частые ошибки

### 1. Присваивание обычного числа без явного приведения

* **Так не скомпилируется:** написать `OrderStatus status = 1;`. Несмотря на то что внутри лежат целые числа, в C# строгая типизация запрещает неявно превращать `int` в `enum` (ошибка `CS0266`).
* **Так правильно:** использовать имя константы `OrderStatus.Paid` или явное приведение `(OrderStatus)1`.

### 2. Несуществующее число при кастинге

* **Так сработает неправильно:** выполнить `OrderStatus bad = (OrderStatus)999;`. Программа **не выбросит ошибку**, а спокойно запишет число `999` в переменную, из-за чего сломается логика проверок, а при выводе в консоль напечатается просто `"999"`.
* **Так правильно:** при получении чисел извне (из файла, сети или от пользователя) проверять их существование через `Enum.IsDefined<OrderStatus>(value)`.

### 3. Объявление `enum` выше инструкций верхнего уровня

* **Так не скомпилируется:** написать `enum Direction { Up, Down }` в первой строчке `Program.cs`, а ниже писать `Console.WriteLine(...)` — компилятор выдаст ошибку `CS8803`.
* **Так правильно:** размещать объявления всех `enum` строго после основного исполняемого кода внизу файла (или выносить в отдельный `.cs`-файл).

### 4. Использование строк вместо `enum` для фиксированных состояний

* **Так сработает неправильно:** хранить роль пользователя как `string role = "Admin";` — любая опечатка вроде `"admin"` или `"Admim"` приведёт к тихому багу при сравнении.
* **Так правильно:** заменить строки на `enum UserRole { Guest, User, Admin }` — компилятор сам отловит любую опечатку ещё до запуска программы.

:::gap

## Под капотом и нюансы

### Базовый тип и экономия памяти

По умолчанию каждый `enum` наследуется от `System.Enum` и хранит значения как стандартный `int` (4 байта). Если вариантов немного и нужно сэкономить память (например, в больших игровых картах или сетевых пакетах), после имени перечисления через двоеточие можно указать любой другой целочисленный тип (кроме `char`): `byte`, `sbyte`, `short`, `ushort`, `uint`, `long` или `ulong`:

```cs
enum CellState : byte
{
    Empty = 0,
    Wall = 1,
    Player = 2
}

```

### Ручная нумерация и коды

Элементам можно задавать любые произвольные числа (например, коды ошибок HTTP: `NotFound = 404`, `ServerError = 500`). Если указать число только одному элементу, следующие за ним продолжат отсчёт с шагом `+1`.

### Комбинации состояний: атрибут `[Flags]`

Обычно переменная `enum` хранит только одно значение. Но если добавить атрибут `[Flags]` и задавать числа как степени двойки (`1, 2, 4, 8...`), несколько состояний можно объединять в одной переменной через побитовое ИЛИ (`|`) и проверять через `HasFlag()`:

```cs
[Flags]
enum Permissions
{
    None = 0,
    Read = 1,    // 0001
    Write = 2,   // 0010
    Delete = 4   // 0100
}

Permissions userAccess = Permissions.Read | Permissions.Write;
bool canWrite = userAccess.HasFlag(Permissions.Write); // True

```

### Полезные методы класса `Enum`

| Метод | Назначение | Пример |
| --- | --- | --- |
| `Enum.TryParse<T>(str, ignoreCase, out val)` | Безопасно переводит строку в элемент `enum` | `Enum.TryParse("paid", true, out OrderStatus s)` |
| `Enum.IsDefined<T>(val)` | Проверяет, существует ли такое число или имя в `enum` | `Enum.IsDefined((OrderStatus)999)` > `false` |
| `Enum.GetValues<T>()` | Возвращает массив всех значений (удобно для `foreach`) | `foreach (var s in Enum.GetValues<OrderStatus>())` |
| `Enum.GetNames<T>()` | Возвращает массив строковых названий всех элементов | `string[] names = Enum.GetNames<OrderStatus>()` |

> [!NOTE]
> В высоконагруженном коде старайтесь не вызывать метод `ToString()` у `enum` в горячих циклах без необходимости — под капотом он использует рефлексию и выделяет память. Для быстрого получения имени в современном C# лучше использовать оператор `nameof(OrderStatus.Paid)`, который подставляет строку прямо на этапе компиляции.
