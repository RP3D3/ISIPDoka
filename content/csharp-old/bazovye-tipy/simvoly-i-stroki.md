# Символы и строки (char, string)

Как хранить никнейм игрока, текст сообщения в чате или отдельную букву нажатой клавиши?

:::gap

## Кратко

Тип `char` хранит ровно один одиночный знак в одинарных кавычках (например, букву, цифру или символ пунктуации), а `string` — это целая последовательность знаков в двойных кавычках, то есть привычный текст. Они нужны для работы с любыми текстовыми данными: от имён пользователей и путей к файлам до парсинга команд и вывода сообщений. В C# строки устроены так, что их нельзя изменить «на месте» — любая правка создаёт в памяти новый объект.

:::gap

## Быстрый пример

Объявим одиночный символ и строку, узнаем длину текста и выполним базовые операции:

```cs
char rank = 'S';                  // Одиночный знак — строго в одинарных кавычках
string nickname = "CyberDragon";  // Текст — в двойных кавычках

Console.WriteLine(nickname.Length);        // 11 (количество знаков)
Console.WriteLine(nickname[0]);            // C (первый знак по индексу)
Console.WriteLine(nickname.ToUpper());     // CYBERDRAGON (новый текст в верхнем регистре)
Console.WriteLine($"[{rank}] {nickname}"); // [S] CyberDragon

```

:::gap

## Как это работает

При выполнении кода среда .NET размещает значения в памяти по-разному и предоставляет готовые методы для работы с текстом:

1. **Одиночный знак (`char`).** Переменная `rank` хранит букву `'S'`. В C# тип `char` всегда пишется в одинарных кавычках `'...'` и занимает ровно 2 байта в стеке.
2. **Текстовая строка (`string`).** Переменная `nickname` хранит цепочку из 11 знаков в двойных кавычках `"..."`. Под капотом она представляет собой непрерывный набор `char` в управляемой куче, доступный только для чтения.
3. **Длина и доступ по индексу (`Length` и `[0]`).** Свойство `Length` возвращает общее число элементов в строке (`11`), а квадратные скобки `[0]` позволяют достать конкретный `char` по его позиции (отсчёт всегда идёт с нуля).
4. **Преобразование текста (`ToUpper`).** Метод `ToUpper()` не меняет исходную переменную `nickname` — он создаёт в памяти совершенно новую копию `"CYBERDRAGON"` заглавными буквами и возвращает её.
5. **Объединение данных.** Интерполяция склеивает `rank` и `nickname` в единый готовый текст для вывода.

> [!TIP]
> Чтобы проверить, ввёл ли пользователь осмысленный текст, а не пустоту или одни пробелы, используйте готовый метод `string.IsNullOrWhiteSpace(text)` вместо ручных проверок через `== ""`.

:::gap

## Грабли и частые ошибки

### 1. Путаница между одинарными и двойными кавычками

* **Так не скомпилируется:** написать `char letter = "A";` или `string word = 'Привет';`. В C# одинарные кавычки работают строго для одного элемента типа `char`, а двойные — только для `string` (ошибка `CS0029` или `CS1012`).
* **Так правильно:** использовать `'A'` для `char` и `"A"` для текста длиной в один знак.

### 2. Попытка изменить отдельный знак внутри строки по индексу

* **Так не скомпилируется:** написать `nickname[0] = 'K';`, чтобы заменить первую букву в нике. Индексатор у `string` работает только на чтение — компилятор выдаст ошибку `CS0200`.
* **Так правильно:** собрать новую строку с помощью диапазонов `"K" + nickname[1..]` или использовать для частых правок класс `StringBuilder`.

### 3. Склейка тысяч фрагментов через `+=` внутри цикла

* **Так сработает неправильно:** собирать большой отчёт в цикле через `result += line;`. Из-за неизменяемости на каждой итерации в памяти заново копируется вся накопленная строка, что резко тормозит программу и забивает память мусором.
* **Так правильно:** накапливать фрагменты в `StringBuilder` внутри цикла и вызвать `.ToString()` один раз в конце.

### 4. Вызов методов у переменной со значением `null`

* **Так упадёт:** написать `input.Trim()` или `input.Length`, если переменная `string? input` оказалась равна `null` — приложение аварийно закроется с исключением `NullReferenceException`.
* **Так правильно:** проверять значение через `string.IsNullOrWhiteSpace(input)` или использовать оператор безопасного доступа `input?.Trim()`.

:::gap

## Под капотом и нюансы

### Значимый `char` против ссылочного `string`

В системе типов .NET эти два типа устроены принципиально по-разному:

* `char` (`System.Char`) — **значимый тип** (*value type*). Хранит 16-битный код символа в кодировке UTF-16 прямо в стеке (от `'\u0000'` до `'\uFFFF'`). Над ним даже можно делать арифметику: `'A' + 1` даст код `66`, что соответствует `'B'`.
* `string` (`System.String`) — **ссылочный тип** (*reference type*). Сама переменная хранит лишь ссылку на объект в управляемой куче (*Heap*), где лежит заголовок объекта, длина и непрерывный массив байтов.

### Неизменяемость (Immutability) и интернирование

Любой объект `string` после создания невозможно модифицировать. Это даёт три важных преимущества: безопасность (переданный в метод путь к файлу или пароль никто не подменит извне), потокобезопасность (текст можно спокойно читать из десятка потоков без блокировок) и **интернирование** (*String Interning*).

При запуске программы среда .NET складывает все одинаковые текстовые литералы из кода в специальную внутреннюю таблицу (пул интернирования). Если вы в десяти разных классах напишете `"Admin"`, в оперативной памяти будет существовать только один экземпляр этого текста, а все десять переменных будут ссылаться на один и тот же адрес.

### Инструменты для работы с текстом

| Тип / Класс | Где хранится | Изменяемость | Когда использовать |
| --- | --- | --- | --- |
| `char` | Стек (2 байта) | Значимый тип | Одиночные буквы, разделители, проверка клавиш |
| `string` | Куча (ссылка) | Неизменяемый | Обычный текст, ключи словарей, редкие склейки |
| `StringBuilder` | Куча (буфер) | Изменяемый | Сборка большого текста в циклах (сотни и тысячи правок) |
| `ReadOnlySpan<char>` | Стек (окно памяти) | Только чтение | Быстрый разбор (парсинг) кусков текста без выделения памяти |

### Суррогатные пары и эмодзи в UTF-16

Кодировка UTF-16 отводит под один `char` 2 байта (16 бит) — этого хватает для всех основных алфавитов мира. Но современные эмодзи и редкие иероглифы не помещаются в 16 бит и кодируются **суррогатной парой** — двумя значениями `char` подряд (4 байта):

```cs
string dragon = "🐉";
Console.WriteLine(dragon.Length); // 2 (один эмодзи занимает два char!)

```

Из-за этого обращение `dragon[0]` вернёт не целого дракона, а «битую» половину суррогатной пары. Для корректного подсчёта и перебора графем (видимых пользователю знаков) в .NET используют класс `System.Globalization.StringInfo` или структуру `System.Text.Rune`.
