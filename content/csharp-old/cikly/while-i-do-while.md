# Цикл while и do..while

Как заставить программу повторять попытку подключения к серверу или запрашивать пароль до тех пор, пока он не окажется верным?

:::gap

## Кратко

Циклы `while` и `do..while` повторяют один и тот же блок кода до тех пор, пока заданное условие остаётся истинным. Они незаменимы там, где заранее неизвестно точное количество шагов: например, при ожидании ответа от сети, чтении файла до конца или проверке пользовательского ввода. Главное отличие между ними в моменте проверки: `while` сначала смотрит на условие и может не запуститься ни разу, а `do..while` гарантированно выполнит код хотя бы один раз перед первой проверкой.

:::gap

## Быстрый пример

Сравним оба цикла на примере расхода энергии и проверки PIN-кода:

```cs
// while: сначала проверяет условие, потом выполняет код
int energy = 30;
while (energy >= 10)
{
    energy -= 10;
    Console.WriteLine($"Рывок! Осталось энергии: {energy}"); // 20, затем 10, затем 0
}

// do..while: гарантированно сработает хотя бы 1 раз, проверка идёт в конце
int pin;
int tries = 0;
do
{
    tries++;
    pin = 1234; // Имитация получения верного PIN-кода
} while (pin != 1234);

Console.WriteLine($"Доступ разрешён с попытки #{tries}"); // Доступ разрешён с попытки #1

```

:::gap

## Как это работает

При выполнении кода среда .NET управляет повторениями в зависимости от расположения условия:

1. **Проверка перед стартом (`while`).** Перед каждой итерацией программа проверяет условие `energy >= 10`. Пока оно даёт `true`, тело цикла выполняется, уменьшая энергию на `10`. Как только `energy` становится равно `0`, проверка `0 >= 10` возвращает `false`, и цикл завершается. Если бы изначально `energy` было равно `5`, цикл не запустился бы вообще.
2. **Гарантированный первый шаг (`do..while`).** В конструкции `do { ... } while (...);` программа сразу заходит внутрь фигурных скобок без предварительных проверок. Это удобно, когда значение для проверки (в примере — `pin`) появляется только в процессе выполнения самого шага.
3. **Проверка в конце (`while (pin != 1234);`).** После выполнения тела цикла проверяется условие. Поскольку `pin` уже равен `1234`, выражение `1234 != 1234` возвращает `false`, и цикл останавливается, сделав ровно одну итерацию.

> [!TIP]
> Для управления ходом любого цикла используйте `break` (мгновенно выйти из цикла досрочно) и `continue` (пропустить остаток текущего шага и сразу перейти к следующей проверке условия).

:::gap

## Грабли и частые ошибки

### 1. Бесконечный цикл из-за забытого изменения счётчика

* **Так сработает неправильно:** написать `int i = 0; while (i < 5) { Console.WriteLine(i); }` и забыть внутри `i++;`. Условие `0 < 5` останется истинным навсегда, программа зависнет и начнёт бесконечно печатать нули.
* **Так правильно:** убедиться, что внутри тела цикла есть код, который приближает условие к завершению (или предусмотрен явный выход через `break`).

### 2. Забытая точка с запятой в конце `do..while`

* **Так не скомпилируется:** написать `do { x++; } while (x < 5)` без `;` в самом конце — в отличие от обычного `while`, пост-условие требует обязательной точки с запятой (ошибка `CS1002`).
* **Так правильно:** всегда завершать конструкцию символом `;`: `do { ... } while (условие);`.

### 3. Случайная точка с запятой после заголовка обычного `while (...) ;`

* **Так сработает неправильно:** написать `while (isLoading); { DrawSpinner(); }`. Точка с запятой создаёт пустой цикл, который будет крутиться вечно при `isLoading == true`, так и не дойдя до кода в фигурных скобках.
* **Так правильно:** никогда не ставить `;` сразу после круглых скобок в обычном `while`.

### 4. Ловушка `continue` в цикле `while`

* **Так сработает неправильно:** поставить `if (i == 2) continue;` **до** строки `i++;` внутри `while`. Когда `i` дойдёт до `2`, программа будет каждый раз прыгать в начало цикла, минуя увеличение счётчика, и уйдёт в вечный цикл.
* **Так правильно:** обновлять переменную-счётчик до вызова `continue` или использовать цикл `for`.

:::gap

## Под капотом и нюансы

### Во что разворачивает компилятор (IL-код)

На уровне промежуточного языка IL конструкций `while` и `do..while` не существует — компилятор превращает их в метки и инструкции условного перехода (`br` и `brtrue`). Интересная оптимизация: даже обычный цикл `while (cond) { body }` компилятор Roslyn разворачивает по схеме `do..while` — ставит безусловный прыжок `br` в самый низ к проверке условия, а затем условный прыжок `brtrue` наверх к телу. Это экономит одну лишнюю инструкцию перехода на каждой итерации.

### Сравнение всех циклов в C#

| Цикл | Когда проверяет условие | Минимум итераций | Когда лучше применять |
| --- | --- | --- | --- |
| `while` | Перед каждой итерацией | `0` (может не сработать) | Неизвестно число шагов, нужно проверить условие до старта |
| `do..while` | После каждой итерации | `1` (сработает минимум раз) | Меню, ввод данных, запросы с повтором до первого успеха |
| `for` | Перед каждой итерацией | `0` | Известно точное число шагов или нужен индекс элемента |
| `foreach` | На каждом шаге итератора | `0` | Безопасный перебор готовых коллекций и массивов |

### Намеренный бесконечный цикл `while (true)`

В разработке игр, парсеров и сетевых серверов часто специально пишут `while (true)` (или `for (;;)`), чтобы главный цикл обработки работал непрерывно, а выход организуют по внутреннему событию через `break` или `return`:

```cs
while (true)
{
    ConsoleKey key = Console.ReadKey(true).Key;
    if (key == ConsoleKey.Escape) break; // Единственная точка выхода
}

```

> [!NOTE]
> Переменная, объявленная внутри фигурных скобок `{ ... }` блока `do`, **не видна** внутри круглых скобок `while (...)` в конце — её область видимости заканчивается на закрывающей скобке `}`. Объявляйте такие переменные до слова `do`.
