# Управление циклом (break, continue)

Как досрочно остановить поиск в списке, как только нужный предмет найден, или пропустить битые записи при обработке данных?

:::gap

## Кратко

Операторы `break` и `continue` позволяют гибко менять ход выполнения любого цикла (`for`, `foreach`, `while`, `do..while`) прямо в процессе работы. Оператор `break` мгновенно прерывает весь цикл и передаёт управление коду после него, а `continue` лишь пропускает остаток текущей итерации и сразу переходит к следующему шагу. Они помогают избавиться от лишних проверок, ускорить поиск данных и сделать логику внутри циклов чище без глубокой вложенности `if`.

:::gap

## Быстрый пример

Обработаем массив чисел, игнорируя отрицательные значения и останавливая работу при встрече с нулём:

```cs
int[] numbers = [10, -5, 20, 0, 30];

foreach (int num in numbers)
{
    if (num < 0)
    {
        continue; // Пропускаем отрицательное число и идём к следующему
    }

    if (num == 0)
    {
        Console.WriteLine("Встречен стоп-сигнал!");
        break; // Полностью выходим из цикла
    }

    Console.WriteLine($"Обработано: {num}"); // Выведет 10, затем 20
}

```

:::gap

## Как это работает

При выполнении кода среда .NET меняет стандартный маршрут перебора элементов при встрече с операторами управления:

1. **Пропуск шага (`continue`).** На первом элементе (`10`) оба условия ложны, и программа печатает `"Обработано: 10"`. На втором элементе (`-5`) срабатывает проверка `num < 0`: оператор `continue` мгновенно обрывает текущую итерацию, не доходя до вывода в консоль, и переводит цикл к числу `20`.
2. **Продолжение работы.** Для числа `20` условия снова не срабатывают, поэтому оно штатно выводится на экран.
3. **Досрочный выход (`break`).** Когда очередь доходит до `0`, срабатывает `num == 0`. После сообщения о стоп-сигнале оператор `break` полностью останавливает цикл — до числа `30` программа уже никогда не дойдёт.
4. **Универсальность.** Оба оператора работают одинаково во всех четырёх видах циклов C#, а `break` также используется для завершения веток в конструкции `switch`.

> [!TIP]
> Используйте `continue` как «защитное условие» в самом начале тела цикла, чтобы сразу отсекать неподходящие элементы — это избавит основной код итерации от лишнего уровня вложенности `if / else`.

:::gap

## Грабли и частые ошибки

### 1. Бесконечный цикл из-за `continue` до изменения счётчика в `while`

* **Так сработает неправильно:** написать `int i = 0; while (i < 5) { if (i == 2) continue; i++; }`. Когда `i` станет равно `2`, `continue` каждый раз будет перебрасывать выполнение в начало цикла до строки `i++`, и программа зависнет навсегда.
* **Так правильно:** увеличивать счётчик `i++` до проверки с `continue` или использовать цикл `for`, где шаг `i++` в заголовке выполняется при любых обстоятельствах.

### 2. Попытка выйти сразу из двух вложенных циклов одним `break`

* **Так сработает неправильно:** поставить `break` внутри внутреннего цикла в двойном цикле `for` в надежде полностью остановить поиск в двумерной таблице. Оператор `break` прерывает только **самый ближний** цикл, в котором находится, а внешний продолжит крутиться дальше.
* **Так правильно:** вынести поиск в отдельный метод и выйти из обоих циклов сразу через `return`, либо использовать логическую переменную-флаг.

### 3. Использование `break` или `continue` вне цикла

* **Так не скомпилируется:** написать `if (isError) break;` в обычном коде без цикла или `switch` вокруг — компилятор остановит сборку с ошибкой `CS0139` (отсутствует охватывающий цикл).
* **Так правильно:** использовать `return` для досрочного выхода из метода или программы.

### 4. Ожидание, что `break` внутри `switch` остановит внешний цикл

* **Так сработает неправильно:** написать `switch` внутри `while` и поставить `break;` внутри ветки `case`, ожидая, что он завершит сам цикл `while`. Внутри `switch` оператор `break` закрывает только текущую ветку `case`, а цикл продолжает работать.
* **Так правильно:** если нужно выйти из цикла прямо из ветки `switch`, используйте `return` (внутри метода) или булевый флаг в условии цикла.

:::gap

## Под капотом и нюансы

### Безусловные переходы в IL-коде

На уровне промежуточного языка IL операторы `break` и `continue` компилируются в простейшие инструкции безусловного прыжка (`br` и `br.s`) на заранее расставленные компилятором метки:

* `break` выполняет прыжок на метку, стоящую сразу **после** закрывающей фигурной скобки цикла.
* `continue` прыгает на метку в конце тела цикла — прямо перед секцией обновления счётчика (`i++` в `for`), проверкой условия (`while` / `do..while`) или вызовом `MoveNext()` (в `foreach`). Поэтому в цикле `for` шаг счётчика гарантированно срабатывает даже после `continue`.

### Сравнение операторов досрочного выхода

| Оператор | Что делает | Где работает | Что выполняется дальше |
| --- | --- | --- | --- |
| `break` | Полностью завершает текущий цикл (или `switch`) | `for`, `foreach`, `while`, `do..while`, `switch` | Первая инструкция сразу после цикла |
| `continue` | Прерывает только текущий шаг (итерацию) | `for`, `foreach`, `while`, `do..while` | Шаг счётчика (`for`) и проверка условия следующей итерации |
| `return` | Мгновенно завершает весь текущий метод | В любом месте метода или программы | Возврат управления в вызывающий код |

### Как чисто выйти из вложенных циклов

Самый читаемый способ прервать сразу два или три вложенных цикла при поиске элемента — обернуть их в локальную функцию или отдельный метод и использовать `return`:

```cs
bool ContainsZero(int[,] grid)
{
    for (int r = 0; r < grid.GetLength(0); r++)
    {
        for (int c = 0; c < grid.GetLength(1); c++)
        {
            if (grid[r, c] == 0) return true; // Сразу выходит из обоих циклов и метода
        }
    }
    return false;
}

```

> [!NOTE]
> В отличие от Java или Rust, в C# нет синтаксиса именованных циклов вроде `break outer;`. Если выносить вложенные циклы в отдельный метод неудобно, в редких случаях допускается переход по метке `goto EndSearch;` сразу за пределы внешнего цикла — это один из немногих сценариев в современном C#, где `goto` считается оправданным.
