# Перебор коллекций foreach

Как пройтись по всем элементам списка, массива или словаря подряд, не боясь ошибиться в индексах и выйти за границы памяти?

:::gap

## Кратко

Цикл `foreach` последовательно берёт каждый элемент из массива, списка, словаря или даже обычной строки и передаёт его в удобную переменную только для чтения. Он избавляет от ручного создания счётчиков `i`, проверки длины коллекции и риска случайно поймать ошибку выхода за границы массива. Это самый безопасный и читаемый способ обойти любые данные от начала до конца, когда вам не нужно менять саму структуру коллекции на ходу.

:::gap

## Быстрый пример

Переберём список участников отряда и воспользуемся методом `.Index()` для получения порядкового номера:

```cs
List<string> squad = ["Алекс", "Кира", "Макс"];

// Классический перебор всех элементов подряд
foreach (string member in squad)
{
    Console.WriteLine($"В отряде: {member}");
}

// Получение индекса и элемента одновременно (.NET 9+)
foreach (var (index, member) in squad.Index())
{
    Console.WriteLine($"#{index + 1}: {member}"); // #1: Алекс, #2: Кира, #3: Макс
}

```

:::gap

## Как это работает

При выполнении кода среда .NET автоматически управляет курсором внутри коллекции от первого элемента до последнего:

1. **Заголовок цикла (`foreach (string member in squad)`).** Ключевое слово `in` связывает коллекцию справа (`squad`) с временной переменной слева (`member`). На каждом шаге цикла в `member` копируется очередной элемент списка.
2. **Последовательный проход.** Программа сама отслеживает начало и конец данных: сначала `member` принимает значение `"Алекс"`, на следующем витке — `"Кира"`, затем `"Макс"`, после чего цикл аккуратно завершается.
3. **Индексация без счётчика (`squad.Index()`).** В современном .NET (начиная с .NET 9) метод `.Index()` оборачивает каждый элемент в пару `(индекс, значение)`, которую удобно сразу разложить на две переменные с помощью деконструкции.

> [!TIP]
> Цикл `foreach` работает даже с обычной строкой `string` — на каждом шаге он выдаёт по одному символу типа `char`, что удобно для подсчёта букв или поиска знаков препинания.

:::gap

## Грабли и частые ошибки

### 1. Изменение самой коллекции внутри `foreach` (`InvalidOperationException`)

* **Так упадёт:** добавить или удалить элемент списка прямо во время обхода (`foreach (var item in squad) { squad.Remove(item); }`). Внутренний перечислитель следит за версией коллекции и при любом изменении размера мгновенно прерывает программу с исключением `InvalidOperationException`.
* **Так правильно:** удалять записи через `squad.RemoveAll(...)`, использовать обратный цикл `for` с конца к началу или собрать элементы на удаление в отдельный список.

### 2. Попытка перезаписать переменную итерации

* **Так не скомпилируется:** написать `foreach (string member in squad) { member = "Гость"; }`. Переменная `member` доступна строго только для чтения — компилятор выдаст ошибку `CS1656`.
* **Так правильно:** использовать обычный цикл `for (int i = 0; i < squad.Count; i++)`, если нужно заменять элементы внутри массива или списка.

### 3. Ожидание, что `foreach` защищает свойства ссылочных объектов

* **Так сработает неправильно:** думать, что внутри `foreach` нельзя менять данные внутри объектов. Если в `List<Player>` лежат экземпляры класса, строка `player.Hp = 0;` сработает и изменит здоровье реального игрока в списке — запрещена только замена самой переменной цикла (`player = new Player();`).
* **Так правильно:** помнить, что ограничение «только для чтения» касается самой ссылки в переменной цикла, а не свойств объекта внутри неё.

### 4. Лишнее приведение коллекции к `IEnumerable<T>` в горячих циклах

* **Так сработает неправильно:** передавать игровые списки в часто вызываемые методы через интерфейс `IEnumerable<T>` без необходимости — при каждом запуске `foreach` в управляемой куче создаётся объект-перечислитель (упаковка структуры), что нагружает сборщик мусора.
* **Так правильно:** в критичных к производительности участках перебирать непосредственно сам тип `List<T>`, массив `T[]` или `Span<T>`.

:::gap

## Под капотом и нюансы

### Паттерн `IEnumerable` и утиная типизация (*Duck Typing*)

На уровне компиляции цикл `foreach` разворачивается в вызов метода `GetEnumerator()`, который возвращает специальный объект-перечислитель (*Enumerator*) с двумя главными членами: методом `MoveNext()` (сдвинуть курсор вперёд и вернуть `false`, если элементы кончились) и свойством `Current` (получить текущий элемент).

Любопытный нюанс C#: типу даже не обязательно реализовывать интерфейсы `IEnumerable<T>` или `IEnumerable`. Компилятор использует **утиную типизацию** — если у вашего класса или структуры просто есть публичный метод `GetEnumerator()`, цикл `foreach` спокойно с ним заработает. Именно так без единого выделения памяти в куче работает перебор `Span<T>` и `ReadOnlySpan<T>`.

### Как `foreach` обходит разные типы данных

| Тип коллекции | Что попадает в переменную цикла | Особенности под капотом |
| --- | --- | --- |
| Массив `T[]` | Элемент массива `T` | Компилятор разворачивает в обычный быстрый цикл `for` по индексу |
| Список `List<T>` | Элемент списка `T` | Использует структуру `List<T>.Enumerator` в стеке без аллокаций в куче |
| Словарь `Dictionary<K, V>` | Пара `KeyValuePair<K, V>` | Удобно раскладывать сразу на две переменные: `foreach (var (k, v) in dict)` |
| Строка `string` | Одиночный символ `char` | Проходит по внутреннему буферу UTF-16 с помощью индексатора |
| `Span<T>` / `ReadOnlySpan<T>` | Элемент `T` (или ссылка `ref T`) | Работает через утиную типизацию с нулевыми затратами памяти |

### Безопасный захват переменной в лямбдах

В отличие от цикла `for`, начиная с C# 5 переменная цикла `foreach` логически создаётся **заново на каждой итерации**. Благодаря этому её можно безопасно передавать в лямбда-выражения и отложенные задачи — каждая функция запомнит именно своё значение:

```cs
List<Action> actions = [];
foreach (string name in squad)
{
    actions.Add(() => Console.WriteLine(name)); // Запомнит каждое имя отдельно
}

```
