# Цикл со счетчиком for

Как повторить действие ровно десять раз, пройтись по массиву задом наперёд или обработать каждый второй элемент списка?

:::gap

## Кратко

Цикл `for` нужен, когда заранее известно, сколько раз нужно повторить действие, или когда для работы требуется порядковый номер (индекс) текущего элемента. Он собирает в одной компактной строке сразу три вещи: создание счётчика, условие продолжения и шаг его изменения. Это главный инструмент для обхода массивов, построения таблиц умножения и выполнения любых задач с чётким количеством итераций.

:::gap

## Быстрый пример

Выведем обратный отсчёт перед стартом и пройдёмся по массиву с шагом через один элемент:

```cs
// Классический счётчик: от 3 до 1
for (int i = 3; i > 0; i--)
{
    Console.WriteLine($"Старт через: {i}"); // 3, затем 2, затем 1
}

// Обход массива по индексам с шагом 2
string[] days = ["Пн", "Вт", "Ср", "Чт", "Пт"];
for (int i = 0; i < days.Length; i += 2)
{
    Console.Write($"{days[i]} "); // Пн Ср Пт
}

```

:::gap

## Как это работает

Заголовок цикла `for (инициализация; условие; шаг)` управляет повторениями по строгому алгоритму:

1. **Инициализация (`int i = 3`).** Выполняется ровно **один раз** перед самым началом цикла. Здесь создаётся переменная-счётчик `i`, которая видна только внутри этого цикла.
2. **Проверка условия (`i > 0`).** Запускается перед каждым новым шагом. Пока условие даёт `true`, программа заходит внутрь фигурных скобок. Как только `i` станет равно `0`, проверка вернёт `false`, и цикл завершится.
3. **Выполнение тела цикла.** Программа печатает текущее значение `i` в консоль.
4. **Изменение счётчика (`i--`).** Срабатывает в самом конце каждой итерации после выполнения всех команд в фигурных скобках, уменьшая `i` на единицу, после чего управление снова возвращается к проверке условия.
5. **Гибкий шаг (`i += 2`).** Во втором примере счётчик увеличивается не на единицу, а сразу на `2`, позволяя перепрыгивать через элементы массива `days` и забирать только чётные позиции (`0`, `2`, `4`).

> [!TIP]
> В Visual Studio и Rider достаточно набрать `for` и дважды нажать `Tab`, чтобы редактор сам развернул готовый шаблон цикла, а `forr` создаст обратный цикл с уменьшением счётчика.

:::gap

## Грабли и частые ошибки

### 1. Ошибка на единицу (`<=` вместо `<` при обходе массива)

* **Так упадёт:** написать `for (int i = 0; i <= days.Length; i++)`. Поскольку индексы в массиве из 5 элементов идут от `0` до `4`, на шаге `i == 5` программа попытается прочитать `days[5]` и вылетит с `IndexOutOfRangeException`.
* **Так правильно:** всегда использовать строгое неравенство `i < days.Length` (или `i <= days.Length - 1`).

### 2. Перепутанные знаки в обратном цикле

* **Так сработает неправильно:** написать обратный отсчёт `for (int i = 5; i > 0; i++)`. Счётчик будет расти вверх (`5, 6, 7...`), условие `i > 0` останется истинным почти вечно (до переполнения `int`), и цикл зависнет.
* **Так правильно:** при движении от большего к меньшему уменьшать счётчик (`i--` или `i -= 1`).

### 3. Изменение счётчика `i` вручную внутри тела цикла

* **Так сработает неправильно:** менять переменную `i` одновременно и в заголовке `i++`, и внутри фигурных скобок `i += 2;` — логика шагов становится запутанной, легко пропустить нужные элементы или уйти в бесконечный цикл.
* **Так правильно:** оставить управление счётчиком только в третьей секции заголовка `for`, а для пропуска отдельных шагов использовать `continue`.

### 4. Захват переменной счётчика в лямбдах и делегатах

* **Так сработает неправильно:** создать внутри `for` несколько задач или кнопок, которые выводят `i` при нажатии (`actions.Add(() => Console.WriteLine(i));`). В отличие от `foreach`, в цикле `for` переменная `i` создаётся **один раз** на весь цикл, поэтому все задачи выведут одно и то же финальное число (например, `5`).
* **Так правильно:** скопировать счётчик в локальную переменную внутри каждой итерации: `int copy = i; actions.Add(() => Console.WriteLine(copy));`.

:::gap

## Под капотом и нюансы

### Оптимизация JIT-компилятора (Bounds Check Elimination)

В C# каждое обращение к массиву `arr[i]` безопасно: среда выполнения проверяет, не вышел ли индекс за границы `0 .. arr.Length - 1`. Однако когда JIT-компилятор видит классический шаблон `for (int i = 0; i < arr.Length; i++)`, он математически доказывает, что `i` гарантированно не выйдет за пределы массива, и **полностью вырезает проверку границ** из машинного кода. Поэтому кэшировать длину в отдельную переменную `int len = arr.Length` для обычных одномерных массивов не нужно — прямой доступ к `arr.Length` работает быстрее.

### Гибкость заголовка `for`: несколько счётчиков и пустые секции

Ни одна из трёх секций внутри `for ( ; ; )` не является обязательной, а в первой и третьей можно перечислять несколько выражений через запятую (например, для одновременного движения с двух концов массива навстречу друг другу):

```cs
// Два указателя: i идёт с начала, j — с конца
for (int i = 0, j = 10; i < j; i++, j--)
{
    Console.WriteLine($"{i} - {j}");
}

// Бесконечный цикл без условий (аналог while (true))
for (;;)
{
    break;
}

```

### Сравнение `for` и `foreach`

| Критерий | `for` | `foreach` |
| --- | --- | --- |
| Доступ к индексу | Есть напрямую (`i`) | Нет (нужен отдельный счётчик или метод `.Index()`) |
| Изменение элементов массива | Можно (`arr[i] = 0;`) | Нельзя (переменная итерации только для чтения) |
| Направление и шаг | Любое (вперёд, назад, через `N` элементов) | Только последовательно от начала до конца |
| Читаемость и безопасность | Выше риск ошибиться в границах индексов | Максимально чистый код без ручных индексов |
