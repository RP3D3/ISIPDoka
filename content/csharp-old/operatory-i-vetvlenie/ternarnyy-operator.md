# Тернарный оператор ? :

Как записать выбор между двумя значениями в одну аккуратную строчку, не раздувая код громоздкой конструкцией `if / else`?

:::gap

## Кратко

Тернарный оператор `?:` — это компактная замена простому блоку `if / else`, которая возвращает одно из двух значений в зависимости от проверки условия. Он называется «тернарным», потому что принимает сразу три части: само условие, результат для истины и результат для лжи. Это незаменимый инструмент для быстрой подстановки текста в сообщения, расчёта скидок или присваивания значений переменным прямо при их объявлении.

:::gap

## Быстрый пример

Выберем ранг игрока и размер скидки в зависимости от набранных очков:

```cs
int points = 120;

// Синтаксис: условие ? значение_если_true : значение_если_false
string rank = points >= 100 ? "Профи" : "Новичок";
int discount = points >= 100 ? 15 : 0;

Console.WriteLine($"Ранг: {rank}, скидка: {discount}%"); // Ранг: Профи, скидка: 15%

// Вставка прямо внутрь интерполяции (обязательно в круглых скобках)
Console.WriteLine($"Доступ: {(points > 0 ? "Открыт" : "Закрыт")}"); // Доступ: Открыт

```

:::gap

## Как это работает

При выполнении кода среда .NET вычисляет условие и возвращает ровно один из двух предложенных вариантов:

1. **Проверка условия (`points >= 100`).** Слева от вопросительного знака `?` стоит любое выражение, дающее `bool`. Поскольку `120 >= 100`, проверка возвращает `true`.
2. **Выбор ветки истины (`? "Профи"`).** Когда условие истинно, оператор возвращает значение сразу после знака `?`, а часть после двоеточия полностью пропускается.
3. **Выбор ветки лжи (`: "Новичок"`).** Если бы очков было меньше ста (`false`), программа проигнорировала бы первый вариант и вернула значение после двоеточия `:`.
4. **Подстановка внутрь строки.** В отличие от `if / else`, тернарный оператор является **выражением** — он всегда вычисляется в готовый результат, поэтому его можно сразу передавать в `Console.WriteLine` или присваивать переменной.

> [!TIP]
> При вставке тернарного оператора внутрь интерполированной строки `$"..."` всегда берите его в круглые скобки `{(условие ? а : б)}` — иначе компилятор воспримет двоеточие `:` как спецификатор формата числа или даты.

:::gap

## Грабли и частые ошибки

### 1. Попытка выполнить команду вместо возврата значения

* **Так не скомпилируется:** написать `isReady ? Console.WriteLine("Да") : Console.WriteLine("Нет");`. Тернарный оператор обязан возвращать результат, а `Console.WriteLine` возвращает `void` (пустоту) — компилятор выдаст ошибку `CS0201`.
* **Так правильно:** использовать обычный `if / else` для вызова действий или передавать тернарный оператор внутрь аргумента: `Console.WriteLine(isReady ? "Да" : "Нет");`.

### 2. Несовместимые типы в ветках после `?` и `:`

* **Так не скомпилируется:** написать `var result = isOk ? "Успех" : 404;`. Обе ветки должны приводиться к одному общему типу — нельзя вернуть одновременно строку и число (ошибка `CS0173`).
* **Так правильно:** привести оба варианта к общему типу (например, сделать оба строками `"404"`) или заменить конструкцию на `if / else`.

### 3. Вложенные тернарные операторы («спагетти»)

* **Так сработает неправильно:** строить длинные цепочки вида `a ? b : c ? d : e ? f : g`. Такой код крайне тяжело читать, а при добавлении нового условия легко перепутать порядок скобок и сломать логику.
* **Так правильно:** использовать `?:` только для простого выбора из двух вариантов, а для трёх и более сценариев применять `switch`-выражение или `else if`.

### 4. Забытые круглые скобки внутри интерполяции строк

* **Так не скомпилируется:** написать `Console.WriteLine($"Статус: {isOnline ? "В сети" : "Офлайн"}");`. Двоеточие внутри `{...}` заставит компилятор искать шаблон форматирования вместо второй ветки (ошибка `CS1003`).
* **Так правильно:** оборачивать всё выражение в круглые скобки: `$"Статус: {(isOnline ? "В сети" : "Офлайн")}"`.

:::gap

## Под капотом и нюансы

### Выражение против инструкции и скорость работы

В C# есть чёткое разделение: `if / else` — это **инструкция** (*statement*), она управляет ходом программы, но сама по себе не имеет значения (поэтому нельзя написать `int x = if (...) ...`). Тернарный оператор `?:` — это **выражение** (*expression*), которое всегда возвращает конкретный результат. При этом на уровне промежуточного языка IL компилятор генерирует для них одинаковые команды условного перехода (`brfalse.s`), поэтому по скорости выполнения они абсолютно идентичны.

### Ленивое вычисление веток

Тернарный оператор вычисляет **только ту ветку, которая победила**. Например, в строке `int safeDiv = divisor == 0 ? 0 : (100 / divisor);` при нулевом делителе правая часть `(100 / divisor)` вообще не запустится, и программа не упадёт с `DivideByZeroException`.

### Целевая типизация в C# 9+

В старых версиях C# код `int? count = hasItems ? 5 : null;` или выбор между двумя классами-наследниками требовал явного приведения типов, потому что компилятор смотрел только на правую часть выражения. В современном C# работает **целевая типизация** (*target-typed conditional expression*): компилятор проверяет тип переменной слева от `=` и автоматически приводит к нему обе ветки:

```cs
// В C# 9+ работает без явного приведения (int?)5
int? bonus = isVip ? 500 : null;

```

### Выбор переменной по ссылке (`ref` тернарный оператор)

Редкая, но мощная возможность C# — тернарный оператор умеет возвращать не само значение, а **ссылку на переменную**, в которую можно сразу записать данные:

```cs
int teamAScore = 10;
int teamBScore = 10;
bool isTeamA = true;

// Прибавляем очко той переменной, которую выберет условие
(isTeamA ? ref teamAScore : ref teamBScore) += 1;
Console.WriteLine(teamAScore); // 11

```

### Когда какую конструкцию выбрать

| Инструмент | Когда применять |
| --- | --- |
| `?:` (тернарный) | Выбор одного из **двух** значений при присваивании или в аргументе метода |
| `if / else` | Выполнение блоков кода с действиями, сложная логика с несколькими командами |
| `switch`-выражение | Выбор значения из **трёх и более** вариантов или проверка диапазонов |
