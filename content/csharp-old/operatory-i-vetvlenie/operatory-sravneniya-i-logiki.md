# Операторы сравнения и логики (==, !=, &&, ||, !)

Как научить программу проверять пароль, сравнивать очки игроков и объединять несколько условий в одно правило?

:::gap

## Кратко

Операторы сравнения проверяют соотношение между двумя значениями (равны ли они, больше или меньше), а логические операторы связывают несколько таких проверок в единое решение. Результатом их работы всегда становится одно из двух значений: истина (`true`) или ложь (`false`). Без них программа не смогла бы проверять права доступа, фильтровать товары по цене или определять, победил ли игрок.

:::gap

## Быстрый пример

Сравним показатели игрока и объединим несколько условий для допуска в закрытую локацию:

```cs
int level = 15;
int gold = 300;
bool isBanned = false;

// Операторы сравнения: ==, !=, >, <, >=, <=
bool isRich = gold >= 500;           // false
bool notZeroLevel = level != 0;      // true

// Логические операторы: && (И), || (ИЛИ), ! (НЕ)
bool canEnter = !isBanned && (level >= 10 || isRich); // true

Console.WriteLine(canEnter); // True

```

:::gap

## Как это работает

При выполнении кода среда .NET вычисляет выражения слева направо с учётом скобок и сводит их к логическому итогу:

1. **Сравнение значений (`>=`, `!=`).** Выражение `gold >= 500` проверяет, больше или равно количество золота пятистам. Поскольку `300` меньше `500`, результат равен `false`. Оператор `!=` («не равно») проверяет, отличается ли уровень от нуля, и возвращает `true`.
2. **Логическое отрицание (`!`).** Восклицательный знак перед `isBanned` переворачивает значение наоборот: поскольку игрок не забанен (`false`), выражение `!isBanned` превращается в `true`.
3. **Логическое ИЛИ (`||`).** Внутри скобок `level >= 10 || isRich` программе достаточно, чтобы выполнилось **хотя бы одно** условие. Уровень равен `15` (`true`), поэтому вся скобка даёт `true`, даже несмотря на нехватку золота.
4. **Логическое И (`&&`).** Оператор `&&` требует, чтобы истинными были **оба** условия одновременно: игрок не забанен (`true`) И прошёл проверку в скобках (`true`). Итоговый результат в `canEnter` становится `true`.

> [!TIP]
> Ставьте круглые скобки вокруг сложных комбинаций `&&` и `||`, даже если помните таблицу приоритетов — так код читается быстрее и защищает от случайных ошибок в логике.

:::gap

## Грабли и частые ошибки

### 1. Одинарное `=` вместо двойного `==`

* **Так не скомпилируется:** написать `if (score = 10)` вместо `if (score == 10)`. Для чисел компилятор выдаст ошибку `CS0029`, а вот для `bool`-переменных (`if (isAdmin = true)`) код скомпилируется, перезапишет переменную на `true` и всегда зайдёт внутрь ветки.
* **Так правильно:** всегда использовать двойное равно `==` для проверки равенства.

### 2. Двойное неравенство как в математике (`1 <= x <= 10`)

* **Так не скомпилируется:** написать `if (1 <= level <= 10)`. Выражение вычисляется слева направо: сначала `1 <= level` возвращает `bool` (`true`), а затем C# пытается сравнить `true <= 10`, что запрещено строгой типизацией (ошибка `CS0019`).
* **Так правильно:** разбивать проверку на два условия через `&&`: `if (level >= 1 && level <= 10)` (или использовать шаблоны `if (level is >= 1 and <= 10)`).

### 3. Сравнение содержимого разных массивов или объектов через `==`

* **Так сработает неправильно:** написать `int[] a = [1, 2]; int[] b = [1, 2]; bool same = (a == b);`. Для ссылочных типов (кроме `string` и `record`) оператор `==` проверяет, указывают ли переменные на **один и тот же объект в памяти**, поэтому вернёт `false`.
* **Так правильно:** сравнивать содержимое коллекций методом `a.SequenceEqual(b)`.

### 4. Использование `&` и `|` вместо `&&` и `||`

* **Так упадёт:** написать `if (text != null & text.Length > 0)`. Одинарный оператор `&` не останавливается после первой проверки, поэтому при `text == null` всё равно попытается прочитать `text.Length` и уронит программу с `NullReferenceException`.
* **Так правильно:** использовать двойные операторы `&&` и `||` с укороченным вычислением.

:::gap

## Под капотом и нюансы

### Шпаргалка по операторам и их приоритету

Операторы в C# выполняются не строго слева направо, а по старшинству: сначала арифметика, затем сравнения, потом равенства, следом `&&` и в самом конце `||`. Поэтому выражение `a || b && c` всегда вычисляется как `a || (b && c)`.

| Оператор | Назначение | Пример | Приоритет |
| --- | --- | --- | --- |
| `!` | Логическое НЕ (инверсия) | `!isClosed` | Высший (унарный) |
| `<`, `>`, `<=`, `>=` | Меньше, больше, меньше/больше или равно | `age >= 18` | Высокий |
| `==`, `!=` | Равно, не равно | `role != "Guest"` | Средний |
| `&&` | Условное И (оба условия истинны) | `hasKey && isOpen` | Ниже среднего |
| `\|\|` | Условное ИЛИ (хотя бы одно истинно) | `isAdmin \|\| isOwner` | Низший |

### Укороченное вычисление (Short-Circuit Evaluation)

Операторы `&&` и `||` работают по принципу «ленивых» вычислений и останавливаются сразу, как только итоговый ответ становится очевиден:

* В выражении `A && B`, если `A` вернуло `false`, правая часть `B` **не вызывается вообще**.
* В выражении `A || B`, если `A` вернуло `true`, правая часть `B` пропускается.

Благодаря этому приёму слева всегда ставят быстрые и защитные проверки (например, `user != null`), а справа — обращение к свойствам объекта или тяжёлые запросы к базе данных.

### Современный синтаксис: логические паттерны (`is`, `and`, `or`, `not`)

В современном C# для проверки диапазонов и сравнения с константами можно использовать текстовые шаблоны сопоставления с образцом (*Pattern Matching*). Они читаются почти как обычный текст и не позволяют случайно перепутать `=` с `==`:

```cs
int temperature = 24;

// Вместо (temperature >= 18 && temperature <= 25)
if (temperature is >= 18 and <= 25)
{
    Console.WriteLine("Комфортная температура");
}

// Наглядная проверка на null без восклицательных знаков
if (temperature is not 0)
{
    Console.WriteLine("Датчик активен");
}

```
