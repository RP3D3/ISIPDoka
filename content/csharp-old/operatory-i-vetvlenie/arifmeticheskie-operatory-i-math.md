# Арифметические операторы и класс Math

Как посчитать урон от критического удара, ограничить здоровье персонажа максимумом или вычислить расстояние между двумя точками на карте?

:::gap

## Кратко

Арифметические операторы (`+`, `-`, `*`, `/`, `%`) отвечают за базовые расчёты, а встроенный класс `Math` добавляет к ним готовые математические функции: округление, возведение в степень, извлечение корня и поиск минимума или максимума. Вместе они избавляют от необходимости вручную писать формулы для модулей, тригонометрии или ограничения значений в заданных рамках. Это основа любой игровой физики, финансовых калькуляторов и обработки данных.

:::gap

## Быстрый пример

Выполним базовые вычисления с сокращёнными операторами и применим популярные методы `Math`:

```cs
int damage = 15;
damage += 5; // Сокращённая запись для damage = damage + 5 -> 20

int remainder = 17 % 5; // Остаток от деления -> 2
int step = 1;
Console.WriteLine(step++); // 1 (сначала выведет текущее значение, потом увеличит до 2)

// Полезные методы класса Math
double root = Math.Sqrt(16);            // 4 (квадратный корень)
double power = Math.Pow(2, 10);         // 1024 (2 в степени 10)
int hp = Math.Clamp(135, 0, 100);       // 100 (зажимаем число в диапазон 0..100)
double rounded = Math.Round(3.1415, 2); // 3.14 (округление до 2 знаков)

```

:::gap

## Как это работает

При выполнении кода среда .NET вычисляет выражения с учётом приоритета операций и вызывает встроенные функции:

1. **Составное присваивание (`+=`).** Запись `damage += 5` обновляет значение переменной на месте, прибавляя к нему `5`. Точно так же работают `-=`, `*=`, `/=` и `%=`.
2. **Остаток от деления (`%`).** Оператор `%` возвращает то, что осталось после деления нацело (`17 = 5 * 3 + 2`, поэтому остаток равен `2`). Это удобно для проверки чётности или зацикливания индексов.
3. **Постфиксный инкремент (`step++`).** Оператор `++` увеличивает переменную на единицу. Поскольку плюсы стоят *после* имени переменной, выражение сначала отдаёт в `Console.WriteLine` старое значение (`1`), и только после этого меняет `step` на `2`.
4. **Математические функции (`Math`).** Класс `Math` содержит готовые статические методы: `Sqrt` вычисляет квадратный корень, `Pow` возводит число в степень, `Clamp` удерживает значение в пределах от минимума до максимума (`135` обрезается до `100`), а `Round` округляет дробь до двух знаков после запятой.

> [!TIP]
> Чтобы проверить, является ли число чётным, используйте остаток от деления: `number % 2 == 0`. Если остаток равен нулю — число делится на два без остатка.

:::gap

## Грабли и частые ошибки

### 1. Потеря дробной части при делении целых чисел

* **Так сработает неправильно:** написать `double half = 5 / 2;`. Поскольку оба числа целые, C# сначала выполнит деление нацело (получит `2`), и только потом запишет это в переменную `double` как `2.0`.
* **Так правильно:** сделать хотя бы один из операндов дробным (`5.0 / 2` или `(double)a / b`).

### 2. Путаница между префиксным `++i` и постфиксным `i++`

* **Так сработает неправильно:** написать `int a = 5; int b = a++;` в надежде получить `6` в обеих переменных — в `b` запишется старое значение `5`, а `6` окажется только в `a`.
* **Так правильно:** ставить плюсы перед переменной (`int b = ++a;`), если нужно сначала увеличить значение, а затем использовать результат, или выносить `a++;` на отдельную строку.

### 3. Использование `Math.Pow(x, 2)` для простого квадрата

* **Так сработает неправильно:** вычислять квадрат расстояния в игровом цикле через `Math.Pow(dx, 2) + Math.Pow(dy, 2)`. Метод `Pow` работает через сложные логарифмы и экспоненты, что в десятки раз медленнее обычного умножения.
* **Так правильно:** для второй и третьей степени использовать прямое умножение `dx * dx + dy * dy`.

### 4. Передача градусов вместо радиан в `Math.Sin` и `Math.Cos`

* **Так сработает неправильно:** написать `Math.Sin(90)` в ожидании получить `1` — метод воспримет `90` как радианы и вернёт `0.89399...`.
* **Так правильно:** переводить градусы в радианы перед вызовом: `Math.Sin(90 * Math.PI / 180.0)`.

:::gap

## Под капотом и нюансы

### Приоритет операторов

Как и в обычной алгебре, умножение (`*`), деление (`/`) и остаток (`%`) имеют одинаковый высокий приоритет и выполняются слева направо раньше, чем сложение (`+`) и вычитание (`-`). Унарные операторы (`-x`, `++x`) выполняются ещё раньше, а круглые скобки `(...)` всегда задают наивысший приоритет.

### Шпаргалка по популярным методам `Math`

| Метод / константа | Назначение | Пример |
| --- | --- | --- |
| `Math.Abs(x)` | Модуль числа (убирает знак минус) | `Math.Abs(-12)` > `12` |
| `Math.Min(a, b)` / `Math.Max(a, b)` | Возвращает меньшее или большее из двух чисел | `Math.Max(10, 25)` > `25` |
| `Math.Clamp(val, min, max)` | Ограничивает значение в рамках `[min, max]` | `Math.Clamp(-5, 0, 100)` > `0` |
| `Math.Floor(x)` | Округляет дробь строго **вниз** к меньшему целому | `Math.Floor(3.9)` > `3` |
| `Math.Ceiling(x)` | Округляет дробь строго **вверх** к большему целому | `Math.Ceiling(3.1)` > `4` |
| `Math.Round(x, digits)` | Округляет число до указанного количества знаков | `Math.Round(2.345, 2)` > `2.34` |
| `Math.PI` / `Math.E` | Встроенные константы чисел Пи и Эйлера | `2 * Math.PI * r` |

### Банковское округление в `Math.Round`

По умолчанию `Math.Round(2.5)` вернёт `2`, а `Math.Round(3.5)` вернёт `4`. В .NET используется **банковское округление** (*MidpointRounding.ToEven*) — половина округляется к ближайшему чётному числу. Если нужно привычное школьное округление (`2.5 > 3`), передайте специальный режим третьим или вторым аргументом:

```cs
double schoolRound = Math.Round(2.5, MidpointRounding.AwayFromZero); // 3

```

### Класс `MathF` для игр и `float`

Все методы классического `Math` работают с типом `double` (8 байт). Если вы пишете игру (например, в Unity) или обрабатываете 3D-координаты в типе `float` (4 байта), используйте специальный класс-близнец `MathF` (`MathF.Sqrt(x)`, `MathF.Sin(x)`, `MathF.Clamp(...)`) — он работает напрямую с `float` без лишних преобразований типов и использует быстрые векторные инструкции процессора.

> [!WARNING]
> Деление на `0` для целых чисел (`int`, `long`) и типа `decimal` всегда выбрасывает исключение `DivideByZeroException`, поэтому при делении на переменную обязательно проверяйте её на ноль.
