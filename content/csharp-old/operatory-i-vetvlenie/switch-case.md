# Конструкция switch / case

Как аккуратно обработать выбор пункта меню, код ошибки сервера или нажатую клавишу, не превращая код в бесконечную «лесенку» из `if / else`?

:::gap

## Кратко

Конструкция `switch / case` сравнивает одно значение с набором заранее известных вариантов и запускает только ту ветку кода, которая совпала. Вместо десяти однотипных проверок `else if (command == ...)` вы получаете чистую и наглядную таблицу маршрутов с запасным вариантом `default` на случай непредвиденного ввода. В современном C# у неё также есть компактная форма (`switch`-выражение), которая умеет сразу возвращать готовый результат.

:::gap

## Быстрый пример

Покажем классический оператор `switch` для выполнения действий и современное `switch`-выражение для возврата значения:

```cs
string command = "start";

// Классический оператор switch
switch (command)
{
    case "start":
        Console.WriteLine("Запуск двигателя..."); // Сработает эта ветка
        break;
    case "stop":
    case "exit": // Несколько вариантов для одного действия
        Console.WriteLine("Остановка системы");
        break;
    default:
        Console.WriteLine("Неизвестная команда");
        break;
}

// Современное switch-выражение (C# 8+)
int code = 404;
string status = code switch
{
    200 => "OK",
    404 => "Не найдено",
    >= 500 => "Ошибка сервера",
    _ => "Другой код" // Символ _ заменяет default
};
Console.WriteLine(status); // Не найдено

```

:::gap

## Как это работает

При выполнении кода среда .NET сопоставляет входное значение с ветками сверху вниз и запускает только первую подошедшую:

1. **Передача значения (`switch (command)`).** Программа берёт значение в круглых скобках (`"start"`) и начинает искать подходящую метку `case`.
2. **Совпадение и выход (`case "start":` и `break`).** На первом же совпадении выполняется вывод в консоль. Оператор `break` обязательно завершает работу всего блока `switch`, чтобы программа не пошла выполнять остальные ветки.
3. **Объединение веток (`case "stop": case "exit":`).** Если две метки идут подряд без кода между ними, они ведут к одному и тому же действию — это удобно для синонимов команд.
4. **Запасной вариант (`default`).** Если ни один `case` не подошёл, управление переходит в секцию `default`, которая работает как финальный `else`.
5. **Компактное `switch`-выражение (`code switch { ... }`).** В современной записи вместо `case` и `break` используется стрелка `=>`, ветки разделяются запятыми, а роль `default` играет символ отбрасывания `_` (*discard*).

> [!TIP]
> Если вам нужно не просто выполнить команду, а выбрать одно из нескольких значений для присваивания переменной — всегда выбирайте `switch`-выражение. Оно короче и не позволяет забыть присваивание в одной из веток.

:::gap

## Грабли и частые ошибки

### 1. Забытый оператор `break` в конце ветки

* **Так не скомпилируется:** написать код внутри `case 1:`, а в конце забыть `break;`. В отличие от C++ и JavaScript, в C# запрещено случайное «проваливание» (*fall-through*) из непустой ветки в следующую — компилятор выдаст ошибку `CS0163`.
* **Так правильно:** завершать каждую непустую ветку оператором `break`, `return` или `throw`, а если нужно перейти к другой ветке намеренно — использовать `goto case 2;`.

### 2. Неполный набор вариантов в `switch`-выражении

* **Так не скомпилируется:** написать `string res = num switch { 1 => "Один", 2 => "Два" };` без ветки `_ => ...`. Компилятор требует, чтобы `switch`-выражение возвращало результат для любого возможного входного значения (ошибка или предупреждение `CS8509`).
* **Так правильно:** всегда добавлять ветку по умолчанию `_ => ...` в самом конце `switch`-выражения.

### 3. Неправильный порядок шаблонов с диапазонами

* **Так не скомпилируется:** поставить общий диапазон выше узкого, например `>= 50 => "Норма"` перед `>= 90 => "Отлично"`. Компилятор проверяет достижимость веток и остановит сборку с ошибкой `CS8510` (шаблон недостижим).
* **Так правильно:** размещать строгие и частные условия в самом верху, а более широкие диапазоны — ниже.

### 4. Использование обычной переменной вместо константы в `case`

* **Так не скомпилируется:** написать `int target = 10; switch (x) { case target: ... }`. Классические метки `case` требуют значения, известные уже на этапе компиляции (ошибка `CS0150`).
* **Так правильно:** объявлять эталон через `const int target = 10;` или использовать защитное условие `case int n when n == target:`.

:::gap

## Под капотом и нюансы

### Как компилятор ускоряет `switch` (Jump Table и бинарный поиск)

Главное преимущество `switch` перед длинной цепочкой `if / else` в том, что компилятор оптимизирует поиск нужной ветки вместо линейного перебора:

* **Таблица переходов (*Jump Table*).** Если числовые значения в `case` идут плотно подряд (например, `1, 2, 3, 4, 5`), компилятор строит в памяти таблицу адресов и перепрыгивает к нужной ветке за одну операцию `O(1)`.
* **Бинарный поиск.** Если числа разбросаны далеко друг от друга (например, `10, 500, 10000`), код разворачивается в дерево бинарного поиска за `O(log N)`.
* **Хэширование строк.** Если в `switch` передаётся `string` и веток много (обычно от 6–7 и выше), компилятор на этапе сборки генерирует внутренний статический словарь на базе хэш-функции FNV-1a, превращая поиск строки в мгновенный переход за `O(1)`.

### Сравнение классического оператора и `switch`-выражения

| Критерий | Оператор `switch (x) { ... }` | Выражение `x switch { ... }` |
| --- | --- | --- |
| Назначение | Выполнение блоков команд и действий | Вычисление и возврат одного значения |
| Завершение ветки | Обязателен `break` или `return` | Не нужен (ветки разделяются запятой) |
| Ветка по умолчанию | `default:` | `_ =>` |
| Проверка полноты | Необязательна (`default` можно опустить) | Обязательна (компилятор следит за всеми случаями) |

### Продвинутые шаблоны и условие `when`

Современный `switch` умеет работать не только с конкретными числами и строками, но и с диапазонами, логическими связками `and` / `or` / `not`, а также дополнительными фильтрами через ключевое слово `when`:

```cs
int score = 85;
bool hasBonus = true;

string grade = score switch
{
    >= 90 => "A",
    >= 75 and < 90 when hasBonus => "A-", // Диапазон + дополнительная проверка
    >= 75 and < 90 => "B",
    >= 50 => "C",
    _ => "F"
};

```
