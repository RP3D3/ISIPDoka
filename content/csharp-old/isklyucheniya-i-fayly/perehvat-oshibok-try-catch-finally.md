# Перехват ошибок (try / catch / finally)

Как защитить программу от внезапного вылета на рабочий стол, если пользователь ввёл буквы вместо числа или нужный файл сохранения оказался удалён?

:::gap

## Кратко

Конструкция `try / catch / finally` позволяет изолировать опасный участок кода и безопасно перехватить исключение (*exception*), не давая программе аварийно завершиться. В блок `try` помещают код, способный вызвать сбой, блок `catch` ловит конкретную ошибку и корректно её обрабатывает, а необязательный блок `finally` гарантированно выполняется в самом конце — независимо от того, произошла ошибка или нет.

:::gap

## Быстрый пример

Попробуем преобразовать строку в число и разделить на него награду, защитив код от неверного ввода и деления на ноль:

```cs
string input = "ноль";

try
{
    int divisor = int.Parse(input); // Выбросит FormatException
    int reward = 100 / divisor;
    Console.WriteLine($"Награда: {reward}");
}
catch (FormatException)
{
    Console.WriteLine("Ошибка: нужно ввести целое число!");
}
catch (DivideByZeroException)
{
    Console.WriteLine("Ошибка: делить на ноль нельзя!");
}
catch (Exception ex)
{
    Console.WriteLine($"Непредвиденный сбой: {ex.Message}");
}
finally
{
    Console.WriteLine("Проверка завершена — блок finally сработает всегда.");
}

```

:::gap

## Как это работает

При выполнении кода среда .NET контролирует каждый шаг внутри защищённого блока и перенаправляет управление при сбое:

1. **Опасная зона (`try`).** Программа начинает выполнять инструкции внутри `try`. На строке `int.Parse("ноль")` преобразование проваливается: среда мгновенно прерывает блок `try` (до строки с делением код даже не доходит) и создаёт объект исключения `FormatException`.
2. **Поиск подходящего перехватчика (`catch`).** Среда просматривает блоки `catch` строго сверху вниз. Первый же блок `catch (FormatException)` совпадает с типом ошибки, перехватывает её и выводит понятное сообщение.
3. **Запасной общий блок (`catch (Exception ex)`).** Все исключения в C# наследуются от базового класса `Exception`. Последний блок ловит любые другие непредвиденные сбои и через свойство `ex.Message` позволяет прочитать описание проблемы.
4. **Гарантированное завершение (`finally`).** После того как отработает `try` или один из блоков `catch`, управление обязательно переходит в `finally`. Этот блок используют для закрытия файлов, сетевых соединений или скрытия индикатора загрузки.

> [!TIP]
> Ставьте конкретные исключения (`FormatException`, `FileNotFoundException`) выше, а общий `Exception` — строго в самом конце, иначе общий блок перехватит все ошибки на себя, и до нижних веток очередь никогда не дойдёт.

:::gap

## Грабли и частые ошибки

### 1. Пустой «проглатывающий» блок `catch { }`

* **Так сработает неправильно:** написать `catch (Exception) { }` без единой строчки кода внутри. Программа молча скроет сбой, продолжит работать с некорректными данными и рухнет гораздо позже в совсем другом месте, где найти причину будет в разы сложнее.
* **Так правильно:** как минимум записывать ошибку в лог или выводить предупреждение, а перехватывать только те исключения, которые вы действительно знаете, как обработать.

### 2. Неправильный порядок блоков `catch` (от общего к частному)

* **Так не скомпилируется:** поставить `catch (Exception ex)` первым, а `catch (DivideByZeroException)` ниже. Компилятор увидит, что нижний блок никогда не сможет сработать, и остановит сборку с ошибкой `CS0160`.
* **Так правильно:** выстраивать блоки `catch` строго от самых узких и конкретных типов исключений к более общим.

### 3. Использование `try / catch` вместо обычных проверок `if` или `TryParse`

* **Так сработает неправильно:** оборачивать в `try / catch` каждый ввод пользователя ради проверки корректности числа. Генерация исключения — дорогая операция для процессора и памяти, которая сильно замедляет программу.
* **Так правильно:** для ожидаемых ситуаций (неверный ввод, отсутствие ключа в словаре) использовать штатные проверки: `int.TryParse()`, `dict.TryGetValue()` и условия `if`.

### 4. Потеря истории вызовов при повторном выбросе (`throw ex;` вместо `throw;`)

* **Так сработает неправильно:** поймать исключение `catch (Exception ex)`, записать его в лог и пробросить дальше командой `throw ex;`. Такая запись перезаписывает исходный адрес ошибки (`StackTrace`) текущей строчкой, скрывая истинное место сбоя.
* **Так правильно:** писать голый оператор `throw;` без имени переменной — он сохранит оригинальную цепочку вызовов нетронутой.

:::gap

## Под капотом и нюансы

### Раскрутка стека (*Stack Unwinding*) и цена исключений

Когда внутри метода происходит сбой, среда CLR начинает «раскручивать стек» — поочерёдно завершать активные методы снизу вверх по цепочке вызовов, пока не встретит подходящий блок `catch`. На этом пути для каждого метода гарантированно исполняются его блоки `finally`.

Пока исключение не выброшено, сам блок `try` работает практически бесплатно и не замедляет программу. Но в момент возникновения ошибки среда собирает полную трассировку стека (`StackTrace`) и выделяет объекты в управляемой куче — поэтому исключения предназначены только для реальных нештатных ситуаций, а не для обычного ветвления логики.

### Фильтры исключений (`when`)

В современном C# можно уточнить условие перехвата прямо в заголовке `catch` с помощью ключевого слова `when`. Блок сработает только тогда, когда выражение вернёт `true`, причём при ложном условии стек вызовов даже не будет раскручиваться:

```cs
catch (HttpRequestException ex) when (ex.StatusCode == System.Net.HttpStatusCode.NotFound)
{
    Console.WriteLine("Запрошенная страница не найдена (404)");
}

```

### Популярные встроенные исключения .NET

| Класс исключения | Когда возникает | Как предотвратить без `try / catch` |
| --- | --- | --- |
| `NullReferenceException` | Обращение к члену объекта, который равен `null` | Проверка `is not null`, операторы `?.` и `??` |
| `IndexOutOfRangeException` | Обращение к элементу массива или списка по несуществующему индексу | Проверка границ индекса через свойство `Length` или `Count` |
| `FormatException` | Неверный формат строки при `int.Parse()` или `DateTime.Parse()` | Безопасный метод `int.TryParse()` |
| `DivideByZeroException` | Целочисленное деление на ноль (`10 / 0`) | Проверка делителя на неравенство нулю перед операцией |
| `InvalidOperationException` | Недопустимое состояние объекта (например, удаление из списка внутри `foreach`) | Использование `RemoveAll()` или обратного цикла `for` |
| `FileNotFoundException` | Попытка открыть несуществующий файл на диске | Проверка `File.Exists(path)` перед чтением |
