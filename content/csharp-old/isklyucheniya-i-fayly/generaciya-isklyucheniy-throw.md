# Генерация исключений (throw)

Как немедленно остановить работу метода, если ему передали отрицательную сумму перевода или пустое имя игрока, вместо того чтобы молча испортить данные в программе?

:::gap

## Кратко

Оператор `throw` позволяет вручную сгенерировать исключение (*exception*), когда метод сталкивается с некорректными аргументами или недопустимым состоянием объекта. Вместо возврата сомнительных «кодов ошибок» вроде `-1` вы создаёте экземпляр нужного класса исключения (`throw new ArgumentException(...)`), мгновенно прерывая выполнение и передавая сигнал о проблеме выше по стеку вызовов в ближайший блок `catch`. Также в современном C# `throw` можно использовать прямо внутри коротких выражений `??` и `=>`, а для частых проверок аргументов в .NET есть готовые методы вида `ArgumentNullException.ThrowIfNull()`.

:::gap

## Быстрый пример

Проверим корректность имени и уровня при создании персонажа и перехватим ошибку в вызывающем коде:

```cs
try
{
    Hero player = CreateHero("Артур", -5);
}
catch (ArgumentException ex)
{
    Console.WriteLine($"Сбой создания: {ex.Message}");
}

Hero CreateHero(string? name, int level)
{
    // throw-выражение: проверяем на null прямо при присваивании
    string validName = name ?? throw new ArgumentNullException(nameof(name), "Имя не может быть null.");

    if (level < 1)
    {
        throw new ArgumentOutOfRangeException(nameof(level), "Уровень должен быть не меньше 1.");
    }

    return new Hero(validName, level);
}

record Hero(string Name, int Level);

```

:::gap

## Как это работает

При выполнении кода среда .NET прерывает обычный ход программы и запускает механизм обработки исключений:

1. **Создание объекта ошибки (`throw new ...`).** Исключение в C# — это обычный объект класса, унаследованного от `System.Exception`. Ключевое слово `new` создаёт экземпляр ошибки с текстовым пояснением, а `throw` «выбрасывает» его в среду выполнения.
2. **Безопасное имя параметра (`nameof(level)`).** Оператор `nameof` превращает имя переменной `level` в обычную строку `"level"` ещё на этапе компиляции. Если позже переименовать параметр через рефакторинг в IDE, имя в исключении обновится автоматически.
3. **Мгновенный выход из метода.** Как только срабатывает `throw`, выполнение `CreateHero` обрывается — строчка `return new Hero(...)` не запустится, а управление полетит вверх по стеку вызовов в поисках подходящего блока `catch`.
4. **Выражение `throw` (`name ?? throw ...`).** В современном C# оператор `throw` разрешено писать справа от `??`, тернарного оператора `?:` и стрелки `=>`, что позволяет проверять данные на `null` в одну компактную строчку.

> [!TIP]
> Всегда передавайте имя проблемного параметра через `nameof(paramName)` в конструкторы `ArgumentException` и `ArgumentNullException` — это избавит от опечаток в строках и сразу покажет в логах, какой именно аргумент сломал метод.

:::gap

## Грабли и частые ошибки

### 1. Повторный выброс через `throw ex;` вместо голого `throw;`

* **Так сработает неправильно:** поймать ошибку в `catch (Exception ex)`, записать её в лог и пробросить дальше командой `throw ex;`. Такая запись перезаписывает исходную трассировку стека (`StackTrace`), и в отчёте будет казаться, что сбой произошёл на строке с `throw ex;`, а не в реальном месте проблемы.
* **Так правильно:** использовать пустой оператор `throw;` без имени переменной — он передаст исходное исключение дальше с сохранением полной истории вызовов.

### 2. Выброс слишком общего `new Exception("Ошибка")`

* **Так сработает неправильно:** бросать базовый класс `Exception` на любую проблему. Вызывающий код не сможет отличить передачу неверного аргумента от сбоя сети и будет вынужден перехватывать вообще все ошибки подряд.
* **Так правильно:** выбирать специализированные стандартные классы (`ArgumentNullException`, `ArgumentOutOfRangeException`, `InvalidOperationException`) или объявлять свой класс исключения.

### 3. Перепутанные местами аргументы у `ArgumentException`

* **Так сработает неправильно:** написать `new ArgumentException(nameof(age), "Неверный возраст")`. У базового `ArgumentException` первым аргументом идёт **текст сообщения** (`message`), а вторым — имя параметра (`paramName`), тогда как у `ArgumentNullException` и `ArgumentOutOfRangeException` первым идёт `paramName`.
* **Так правильно:** сверяться с подсказкой конструктора в редакторе или использовать современные встроенные методы `ArgumentException.ThrowIfNullOrWhiteSpace(name)`.

### 4. Использование `throw` для обычного ветвления логики

* **Так сработает неправильно:** выбрасывать исключение каждый раз, когда пользователь ввёл неверный пароль или ключ не нашёлся в словаре. Генерация исключения тратит много ресурсов на сбор трассировки стека и сильно тормозит программу при частых срабатываниях.
* **Так правильно:** использовать `throw` только для нарушения контракта метода и нештатных сбоев, а для ожидаемых ситуаций возвращать `bool` (паттерн `Try...`), `null` или специальный объект-результат.

:::gap

## Под капотом и нюансы

### Современные хелперы `ThrowIf...` (.NET 6–8+)

В стандартной библиотеке .NET появились статические методы-проверки, которые заменяют однотипные блоки `if (...) throw new ...`. Помимо краткости записи, они помогают JIT-компилятору лучше оптимизировать машинный код, вынося редкую ветку выброса исключения за пределы основного пути выполнения метода:

```cs
void RegisterUser(string? login, int age)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(login);
    ArgumentOutOfRangeException.ThrowIfNegativeOrZero(age);
}

```

### Создание собственного класса исключения

Когда стандартных типов недостаточно и вызывающему коду нужно передать дополнительные данные о сбое (например, сколько маны не хватило для заклинания), создают свой класс, унаследованный от `Exception`, с обязательным суффиксом `Exception` в имени:

```cs
class InsufficientManaException(int required, int current)
    : Exception($"Не хватает маны: нужно {required}, доступно {current}.")
{
    public int Required { get; } = required;
    public int Current { get; } = current;
}

```

### Шпаргалка по стандартным исключениям для `throw`

| Класс исключения | Когда выбрасывать | Короткий хелпер в .NET |
| --- | --- | --- |
| `ArgumentNullException` | В метод передали `null`, хотя ожидался объект | `ArgumentNullException.ThrowIfNull(obj)` |
| `ArgumentOutOfRangeException` | Число или индекс выходит за допустимые границы | `ArgumentOutOfRangeException.ThrowIfNegative(x)` |
| `ArgumentException` | Аргумент не `null`, но его содержимое некорректно | `ArgumentException.ThrowIfNullOrWhiteSpace(str)` |
| `InvalidOperationException` | Объект в неподходящем состоянии для вызова метода (выстрел без патронов) | `if (ammo == 0) throw new InvalidOperationException(...)` |
| `NotSupportedException` | Операция принципиально не поддерживается этим классом | `throw new NotSupportedException("Только для чтения")` |
| `NotImplementedException` | Заглушка для метода, который ещё находится в разработке | `void Save() => throw new NotImplementedException();` |
