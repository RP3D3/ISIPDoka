# Параметры по умолчанию и params

Как сделать аргументы метода необязательными или научить функцию принимать сколько угодно значений через запятую — хоть два, хоть сто?

:::gap

## Кратко

Параметры по умолчанию позволяют задать аргументу запасное значение прямо в заголовке метода, чтобы при вызове его можно было пропустить. Ключевое слово `params` разрешает передавать в метод произвольное количество аргументов через запятую — компилятор сам упакует их в массив или коллекцию. Вместе эти инструменты избавляют от необходимости писать десятки однотипных перегрузок одного и того же метода для разных наборов входных данных.

:::gap

## Быстрый пример

Объявим метод логирования с необязательными настройками и функцию суммирования с переменным числом аргументов:

```cs
// Параметры по умолчанию: count = 1, prefix = "[INFO]"
LogMessage("Сервер запущен");                      // [INFO] Сервер запущен
LogMessage("Ошибка диска", 2, "[ERROR]");          // Печатает 2 раза с [ERROR]
LogMessage("Таймаут", prefix: "[WARN]");           // Именованный аргумент пропускает count

// params: передаём любое количество чисел через запятую
Console.WriteLine(SumAll(5, 10));                  // 15
Console.WriteLine(SumAll(1, 2, 3, 4, 5));          // 15
Console.WriteLine(SumAll());                       // 0 (можно не передать ничего)

void LogMessage(string text, int count = 1, string prefix = "[INFO]")
{
    for (int i = 0; i < count; i++)
    {
        Console.WriteLine($"{prefix} {text}");
    }
}

int SumAll(params int[] numbers)
{
    int total = 0;
    foreach (int n in numbers) total += n;
    return total;
}

```

:::gap

## Как это работает

При выполнении кода компилятор самостоятельно подставляет недостающие значения или собирает разрозненные аргументы в единый контейнер:

1. **Запасные значения (`int count = 1`).** В заголовке `LogMessage` обязательным является только первый параметр `text`. У `count` и `prefix` указаны значения по умолчанию через знак `=`, поэтому при вызове `LogMessage("Сервер запущен")` компилятор автоматически подставляет `1` и `"[INFO]"`.
2. **Пропуск средних параметров (`prefix: "[WARN]"`).** Если нужно изменить только третий параметр, оставив второй со стандартным значением, используют **именованный аргумент** — указывают имя параметра и двоеточие перед значением.
3. **Переменное число аргументов (`params int[] numbers`).** Модификатор `params` превращает обычный параметр-массив в приёмник для любого числа аргументов. При вызове `SumAll(1, 2, 3, 4, 5)` компилятор незаметно создаёт массив `new int[] { 1, 2, 3, 4, 5 }` и передаёт его внутрь метода.
4. **Вызов без аргументов (`SumAll()`).** Если в `params`-метод ничего не передать, компилятор подставит пустой массив нулевой длины (`Array.Empty<int>()`), поэтому цикл `foreach` не сделает ни одного шага и метод безопасно вернёт `0`.

> [!TIP]
> В метод с модификатором `params` можно по-прежнему передать и уже готовый массив `int[] arr = [1, 2, 3]; SumAll(arr);` — компилятор примет его напрямую без создания лишней копии.

:::gap

## Грабли и частые ошибки

### 1. Обязательный параметр после параметра по умолчанию

* **Так не скомпилируется:** написать `void Attack(int damage = 10, string target)` — обязательный параметр `target` стоит правее необязательного `damage` (ошибка `CS1737`).
* **Так правильно:** всегда размещать все обязательные параметры слева, а параметры со значениями по умолчанию — строго в конце списка (единственное исключение — параметр `params`).

### 2. Попытка поставить `params` не последним или объявить два `params`

* **Так не скомпилируется:** написать `void Test(params int[] nums, string tag)` или `void Test(params int[] a, params string[] b)` — модификатор `params` разрешён только для самого последнего параметра в сигнатуре и только один раз (ошибка `CS0231`).
* **Так правильно:** перенести обычный параметр влево: `void Test(string tag, params int[] nums)`.

### 3. Неконстантное выражение в значении по умолчанию

* **Так не скомпилируется:** написать `void Log(string msg, DateTime time = DateTime.Now)` или `int def = 5; void Calc(int x = def)`. Значения по умолчанию должны быть известны уже на этапе компиляции (ошибка `CS1736`).
* **Так правильно:** использовать только константы (`const`), литералы или `null`: `void Log(string msg, DateTime? time = null) { time ??= DateTime.Now; ... }`.

### 4. Путаница при передаче `null` в `params`

* **Так упадёт:** вызвать `SumAll(null)`. Компилятор воспримет `null` не как массив из одного элемента `null`, а как пустую ссылку вместо самого массива `numbers`, из-за чего `foreach` внутри упадёт с `NullReferenceException`.
* **Так правильно:** проверять параметр на `null` внутри метода (`if (numbers is null) return 0;`) или вызывать `SumAll()` без аргументов для передачи пустого набора.

:::gap

## Под капотом и нюансы

### Подстановка значений на стороне вызывающего кода

Значения по умолчанию записываются компилятором в метаданные метода с помощью атрибутов `[Optional]` и `[DefaultParameterValue]`, но подставляются **прямо в точке вызова**. Это важный нюанс при работе с внешними библиотеками (`.dll`): если вы поменяете значение по умолчанию в библиотеке и пересоберёте только её, старая программа продолжит передавать прежнее значение, пока вы не перекомпилируете и сам вызывающий проект.

### Эволюция `params` в C# 13+: нулевые аллокации через `Span`

Долгое время модификатор `params` работал исключительно с одномерными массивами `T[]`, из-за чего каждый вызов `SumAll(1, 2, 3)` выделял в управляемой куче новый массив и нагружал сборщик мусора. Начиная с C# 13 (.NET 9+), `params` поддерживает коллекции и срезы: `ReadOnlySpan<T>`, `Span<T>`, `List<T>` и `IEnumerable<T>`.

Если объявить параметр как `params ReadOnlySpan<int> numbers`, компилятор разместит переданные аргументы прямо в стеке без единого выделения памяти в куче:

```cs
int FastSum(params ReadOnlySpan<int> numbers)
{
    int sum = 0;
    foreach (int n in numbers) sum += n;
    return sum;
}

```

### Сравнительная таблица

| Инструмент | Синтаксис | Когда применять |
| --- | --- | --- |
| Параметры по умолчанию | `void Foo(int a, int b = 10)` | Есть 1–3 необязательные настройки с разумным стандартным значением |
| Именованные аргументы | `Foo(1, c: 20)` | Нужно задать только конкретный необязательный параметр, пропустив остальные |
| `params T[]` | `void Foo(params int[] items)` | Количество однотипных аргументов заранее неизвестно (0, 1 или 50 штук) |
| `params ReadOnlySpan<T>` | `void Foo(params ReadOnlySpan<int> items)` | То же самое, но в горячем коде без выделения памяти под массив (C# 13+) |
