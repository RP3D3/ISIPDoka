# Классы и объекты (class, new)

Как объединить имя, здоровье, уровень и атаки персонажа в одну удобную сущность вместо десятка разрозненных переменных?

:::gap

## Кратко

Класс — это чертёж или шаблон, который описывает, какие данные (поля и свойства) и действия (методы) будут у будущей сущности. Объект (экземпляр класса) — это конкретная вещь, созданная в памяти по этому чертежу с помощью оператора `new`. Такой подход лежит в основе объектно-ориентированного программирования (ООП): вместо десятка разрозненных списков для имён, очков и координат вы работаете с цельными персонажами, товарами или заказами.

:::gap

## Быстрый пример

Создадим два независимых объекта персонажа по одному классу `Hero` и вызовем метод получения урона:

```cs
// Создаём два независимых объекта по одному чертежу
Hero warrior = new Hero();
warrior.Name = "Артур";
warrior.Hp = 120;

Hero mage = new() { Name = "Лира", Hp = 80 }; // Инициализатор объекта

warrior.TakeDamage(30);
Console.WriteLine($"{warrior.Name}: {warrior.Hp} HP"); // Артур: 90 HP
Console.WriteLine($"{mage.Name}: {mage.Hp} HP");       // Лира: 80 HP

// Объявление класса (в файле с инструкциями верхнего уровня — внизу)
class Hero
{
    public string Name = "Безымянный";
    public int Hp = 100;

    public void TakeDamage(int damage)
    {
        Hp = Math.Max(0, Hp - damage);
    }
}

```

:::gap

## Как это работает

При выполнении кода среда .NET разделяет описание шаблона и выделение памяти под конкретные экземпляры:

1. **Описание чертежа (`class Hero`).** Ключевое слово `class` создаёт новый тип данных, внутри которого мы объединяем состояние (поля `Name` и `Hp`) и поведение (метод `TakeDamage`). Модификатор `public` разрешает обращаться к ним из внешнего кода.
2. **Создание экземпляра (`new Hero()`).** Оператор `new` выделяет в памяти место под нового персонажа, заполняет его поля начальными значениями (`"Безымянный"` и `100`) и возвращает ссылку на созданный объект в переменную `warrior`.
3. **Короткий `new()` и инициализатор.** Если тип переменной уже указан слева (`Hero mage`), имя класса после `new` можно не повторять. Фигурные скобки `{ Name = "Лира", Hp = 80 }` позволяют сразу задать нужные значения при создании объекта.
4. **Независимость экземпляров (`warrior.TakeDamage(30)`).** Вызов метода через точку изменяет здоровье только у `warrior` (`90`), тогда как у `mage` оно остаётся прежним (`80`) — каждый объект хранит собственный набор данных.

> [!TIP]
> Называйте классы существительными в единственном числе с заглавной буквы (`Player`, `BankAccount`, `Order`), а в реальных проектах размещайте каждый класс в отдельном файле с таким же именем (`Player.cs`).

:::gap

## Грабли и частые ошибки

### 1. Забытый оператор `new` при объявлении переменной (`NullReferenceException`)

* **Так упадёт:** написать `Hero player; player.Name = "Макс";` или `Hero player = null!; player.TakeDamage(10);`. Без `new` создаётся только пустая ссылка без самого объекта в памяти, из-за чего компилятор выдаст ошибку `CS0165`, а при `null` программа аварийно завершится с `NullReferenceException`.
* **Так правильно:** всегда создавать экземпляр через `Hero player = new();` перед обращением к его полям и методам.

### 2. Ожидание, что присваивание `copy = warrior` создаёт дубликат объекта

* **Так сработает неправильно:** написать `Hero copy = warrior; copy.Hp = 10;` и думать, что здоровье у `warrior` осталось `90`. Класс — ссылочный тип, поэтому обе переменные указывают на **один и тот же** объект в памяти, и у `warrior` тоже станет `10 HP`.
* **Так правильно:** для независимой копии создавать новый экземпляр `new Hero { Name = warrior.Name, Hp = warrior.Hp }` или использовать тип `record` с выражением `with`.

### 3. Попытка обратиться к полям и методам без `public`

* **Так не скомпилируется:** объявить внутри класса `int Hp = 100;` без модификатора доступа и написать снаружи `warrior.Hp = 50;`. По умолчанию все члены класса скрыты (`private`), поэтому компилятор выдаст ошибку `CS0122`.
* **Так правильно:** явно добавлять `public` к тем полям, свойствам и методам, которые должны быть доступны снаружи класса.

### 4. Объявление класса выше инструкций верхнего уровня

* **Так не скомпилируется:** написать `class Hero { ... }` в самом начале `Program.cs`, а основной код расположить ниже — компилятор остановит сборку с ошибкой `CS8803`.
* **Так правильно:** размещать объявления всех классов внизу файла после основного исполняемого кода (или выносить в отдельные `.cs`-файлы).

:::gap

## Под капотом и нюансы

### Ссылочный тип: как объект живёт в стеке и куче

В системе типов .NET любой класс является **ссылочным типом** (*Reference Type*). Когда выполняется строка `Hero warrior = new Hero();`, память распределяется между двумя областями:

* **Управляемая куча (*Managed Heap*).** Оператор `new` выделяет здесь блок памяти под сам объект: служебный заголовок (указатель на таблицу методов класса и блок синхронизации) плюс все поля (`Name` и `Hp`).
* **Стек (*Stack*).** Локальная переменная `warrior` живёт в стеке и хранит вовсе не самого героя, а лишь 8-байтный адрес (ссылку), указывающий на место в куче.

Когда на объект в куче больше не остаётся ни одной активной ссылки, сборщик мусора (*Garbage Collector*) автоматически освобождает занятую им память.

### Сравнение класса (`class`) и структуры (`struct`)

| Характеристика | Класс (`class`) | Структура (`struct`) |
| --- | --- | --- |
| Категория типа | Ссылочный тип (*Reference Type*) | Значимый тип (*Value Type*) |
| Где хранятся данные | В управляемой куче (*Heap*), ссылка — в стеке | Непосредственно в стеке (или внутри объекта) |
| Присваивание `b = a` | Копируется только **ссылка** (объект общий) | Копируются **все данные** целиком |
| Значение по умолчанию | `null` (пустая ссылка) | Готовый экземпляр с нулями в полях |
| Когда выбирать | Сущности со сложным поведением и общим состоянием | Маленькие неизменяемые наборы данных (точка, цвет) |

### Сравнение объектов через `==`

По умолчанию оператор `==` для классов сравнивает **адреса в памяти** (*Reference Equality*), а не содержимое полей. Даже если создать два объекта `new Hero { Name = "Артур" }` и `new Hero { Name = "Артур" }`, проверка `h1 == h2` вернёт `false`, потому что это два разных экземпляра в куче.

> [!NOTE]
> Если вам нужно создавать объекты-модели данных, которые автоматически сравниваются по значениям своих полей и легко копируются с изменениями через `with`, в современном C# вместо обычного `class` часто используют ключевое слово `record`.
