# Очередь и Стек (Queue, Stack)

Как организовать справедливую очередь заказов на печать документов или кнопку «Отменить действие» (`Ctrl + Z`) в редакторе?

:::gap

## Кратко

Очередь (`Queue<T>`) и стек (`Stack<T>`) — это коллекции с жёсткими правилами порядка, которые регулируют, какой элемент вы возьмёте следующим. Очередь работает по принципу «первым пришёл — первым ушёл» (FIFO), как в кассе супермаркета, а стек действует наоборот: «последним пришёл — первым ушёл» (LIFO), как стопка тарелок. Они избавляют от ручной возни с индексами там, где важна строгая последовательность обработки задач, истории действий или отмены операций.

:::gap

## Быстрый пример

Посмотрим, как добавляются и извлекаются элементы в обеих коллекциях:

```cs
// Очередь (FIFO): кто первый встал, того и обслужили
Queue<string> printQueue = new();
printQueue.Enqueue("Договор.pdf");
printQueue.Enqueue("Чек.pdf");

Console.WriteLine(printQueue.Peek());    // Договор.pdf (только посмотреть)
Console.WriteLine(printQueue.Dequeue()); // Договор.pdf (забрать и удалить)

// Стек (LIFO): забираем всегда самый верхний (свежий) элемент
Stack<string> undoHistory = new();
undoHistory.Push("Написал заголовок");
undoHistory.Push("Удалил абзац");

Console.WriteLine(undoHistory.Pop());    // Удалил абзац (забрать с вершины)
Console.WriteLine(undoHistory.Peek());   // Написал заголовок (теперь он сверху)

```

:::gap

## Как это работает

При выполнении кода среда .NET управляет порядком элементов строго по заданным правилам:

1. **Постановка в очередь (`Enqueue`).** Метод `Enqueue` ставит `"Договор.pdf"` первым на выход, а `"Чек.pdf"` — строго за ним в хвост.
2. **Просмотр и извлечение из очереди (`Peek` и `Dequeue`).** Метод `Peek()` подсматривает первый элемент (`"Договор.pdf"`), не удаляя его. А вот `Dequeue()` забирает первый документ в работу и убирает его из коллекции, продвигая `"Чек.pdf"` на первое место.
3. **Укладка на вершину стека (`Push`).** В стеке `Push` работает как стопка книг: `"Написал заголовок"` оказывается внизу, а `"Удалил абзац"` ложится сверху на вершину.
4. **Снятие с вершины (`Pop`).** Вызов `Pop()` снимает самый последний добавленный элемент (`"Удалил абзац"`), возвращая историю ровно на один шаг назад — теперь на вершине снова лежит `"Написал заголовок"`.

> [!TIP]
> Чтобы не проверять перед каждым извлечением, пуста ли коллекция, используйте безопасные методы `TryDequeue(out var item)` и `TryPop(out var item)` — они вернут `false` вместо ошибки, если элементы закончились.

:::gap

## Грабли и частые ошибки

### 1. Вызов `Dequeue`, `Pop` или `Peek` на пустой коллекции

* **Так упадёт:** вызвать `printQueue.Dequeue()` или `undoHistory.Pop()`, когда все элементы уже разобраны — программа аварийно завершится с исключением `InvalidOperationException`.
* **Так правильно:** использовать безопасные аналоги `TryDequeue(out var item)`, `TryPop(out var item)` или предварительно проверять `collection.Count > 0`.

### 2. Попытка обратиться к элементу по индексу

* **Так не скомпилируется:** написать `printQueue[0]` или `undoHistory[1]`, чтобы заглянуть в середину коллекции. Очередь и стек намеренно скрывают доступ по индексу ради соблюдения порядка — компилятор выдаст ошибку `CS0021`.
* **Так правильно:** работать только с краями через `Peek`, `Dequeue` и `Pop`, а если нужен произвольный доступ — выбрать `List<T>`.

### 3. Изменение очереди или стека внутри цикла `foreach`

* **Так упадёт:** перебирать очередь в `foreach (var doc in printQueue)` и внутри вызывать `printQueue.Dequeue()` — коллекция выбросит `InvalidOperationException` из-за модификации во время обхода.
* **Так правильно:** разгребать задачи циклом `while (printQueue.TryDequeue(out var doc))` — он сам остановится, когда очередь опустеет.

### 4. Имитация очереди на обычном `List<T>`

* **Так сработает неправильно:** использовать список через `list.Add(item)` и удаление с начала `list.RemoveAt(0)`. На каждом удалении первого элемента списку приходится сдвигать весь остальной хвост влево (`O(N)`), что сильно тормозит на тысячах задач.
* **Так правильно:** использовать `Queue<T>`, где добавление и извлечение работают за мгновенное время `O(1)`.

:::gap

## Под капотом и нюансы

### Кольцевой буфер против обычного массива

Обе коллекции внутри хранят обычный массив `T[]`, но распоряжаются им по-разному:

* **`Stack<T>`** держит массив и один указатель на вершину (`_size`). `Push` записывает элемент в следующую свободную ячейку и увеличивает счётчик, а `Pop` просто уменьшает счётчик и затирает ссылку (для ссылочных типов, чтобы не мешать сборщику мусора).
* **`Queue<T>`** использует **кольцевой буфер** (*Ring Buffer*) с двумя указателями: `_head` (голова) и `_tail` (хвост). Когда `_tail` доходит до конца массива, а в начале уже освободились ячейки после `Dequeue`, хвост просто «заворачивается» на нулевой индекс по кругу без сдвига элементов. Перевыделение массива в 2 раза большего размера происходит только тогда, когда хвост догонит голову.

### Сравнительная таблица

| Характеристика | `Queue<T>` | `Stack<T>` |
| --- | --- | --- |
| Принцип работы | FIFO (*First-In, First-Out*) | LIFO (*Last-In, First-Out*) |
| Добавить элемент | `Enqueue(item)` — `O(1)`* | `Push(item)` — `O(1)`* |
| Забрать элемент | `Dequeue()` / `TryDequeue` — `O(1)` | `Pop()` / `TryPop` — `O(1)` |
| Посмотреть без удаления | `Peek()` / `TryPeek` — `O(1)` | `Peek()` / `TryPeek` — `O(1)` |
| Устройство внутри | Кольцевой буфер на массиве `T[]` | Массив `T[]` + указатель вершины |
| Типичные сценарии | Очередь запросов, обход графа в ширину (BFS) | История отмены (Undo), обход в глубину (DFS), парсинг скобок |

**Сложность `O(N)` возникает только в редкий момент расширения внутреннего массива.*

### Очередь с приоритетом (`PriorityQueue<TElement, TPriority>`)

Если задачи нужно обрабатывать не в порядке поступления, а по степени важности (например, срочный баг важнее обычной задачи), в .NET есть коллекция `PriorityQueue<TElement, TPriority>`. Под капотом она устроена как двоичная куча (*min-heap*) и всегда выдаёт элемент с наименьшим числом приоритета за время `O(log N)`:

```cs
var tasks = new PriorityQueue<string, int>();
tasks.Enqueue("Обычный отчёт", 2);
tasks.Enqueue("Срочный фикс", 1); // Меньше число = выше приоритет

Console.WriteLine(tasks.Dequeue()); // Срочный фикс

```
