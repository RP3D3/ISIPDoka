# Множество (HashSet)

Как мгновенно отсеять повторяющиеся теги, проверить наличие игрока в чёрном списке или найти общих друзей у двух пользователей?

:::gap

## Кратко

Множество `HashSet<T>` — это коллекция, которая хранит только уникальные элементы без дубликатов и умеет мгновенно отвечать на вопрос «есть ли это значение внутри?». В отличие от списка `List<T>`, в нём нет индексов и строгого порядка, зато проверка наличия элемента работает за доли микросекунды даже на миллионе записей. Это идеальный инструмент для фильтрации повторов, чёрных списков и математических операций над наборами данных (объединения или пересечения).

:::gap

## Быстрый пример

Создадим множество тегов, попробуем добавить дубликат и найдём общие элементы двух наборов:

```cs
HashSet<string> tags = ["csharp", "dotnet", "csharp"]; // Дубликат игнорируется

bool addedNew = tags.Add("unity");    // True (элемент добавлен)
bool addedDup = tags.Add("dotnet");   // False (такой уже есть)

Console.WriteLine(tags.Count);              // 3
Console.WriteLine(tags.Contains("unity"));  // True (мгновенный поиск)

// Пересечение множеств: оставляем только общие элементы
HashSet<string> otherTags = ["unity", "sql", "git"];
tags.IntersectWith(otherTags); // В tags остался только ["unity"]

```

:::gap

## Как это работает

При выполнении кода коллекция вычисляет хэш-код каждого элемента и следит за их уникальностью:

1. **Автоматическая очистка при создании.** При инициализации `["csharp", "dotnet", "csharp"]` множество сразу отбрасывает второй `"csharp"`, оставляя внутри только два уникальных значения.
2. **Добавление с проверкой (`Add`).** В отличие от `List<T>.Add()`, метод `Add()` у множества возвращает `bool`. Для нового тега `"unity"` он вернёт `true` и сохранит его, а при попытке повторно положить `"dotnet"` не выдаст ошибку, а просто вернёт `false`.
3. **Мгновенный поиск (`Contains`).** Вызов `tags.Contains("unity")` не перебирает элементы по очереди, а сразу вычисляет место в памяти по хэш-коду и возвращает `true`.
4. **Операции над множествами (`IntersectWith`).** Метод сравнивает текущую коллекцию `tags` с набором `otherTags` и оставляет внутри только те элементы, которые есть в обоих списках сразу (`"unity"`).

> [!TIP]
> Если нужно быстро убрать все дубликаты из обычного списка или массива, просто передайте его в конструктор множества: `HashSet<int> unique = [..numbers];` (или `new HashSet<int>(numbers)`).

:::gap

## Грабли и частые ошибки

### 1. Попытка обратиться к элементу по индексу `[0]`

* **Так не скомпилируется:** написать `string first = tags[0];` по привычке от списков и массивов. У множества нет понятия «первый» или «третий» элемент — компилятор выдаст ошибку `CS0021`.
* **Так правильно:** перебирать элементы через `foreach (var tag in tags)` или, если нужен доступ по индексу, перевести в список `[..tags]`.

### 2. Использование `List<T>` вместо `HashSet<T>` для частых проверок `Contains`

* **Так сработает неправильно:** хранить 50 000 забаненных ID в `List<int>` и проверять `bannedList.Contains(userId)` при каждом запросе — линейный перебор резко замедлит программу.
* **Так правильно:** заменить `List<int>` на `HashSet<int>`, где `Contains()` работает за константное время `O(1)`.

### 3. Изменение полей объекта после добавления в множество

* **Так сработает неправильно:** положить в `HashSet<User>` изменяемый объект класса и поменять у него свойство `Id` или `Name`, участвующее в расчёте `GetHashCode()`. Элемент останется в старой корзине памяти, и метод `Contains()` перестанет его находить.
* **Так правильно:** хранить в множестве неизменяемые типы (`int`, `string`, `Guid`, `record`) или не менять свойства, от которых зависит хэш-код.

### 4. Неожиданное изменение исходного набора при `UnionWith` или `IntersectWith`

* **Так сработает неправильно:** вызвать `setA.UnionWith(setB)` и ожидать, что `setA` останется нетронутым — методы модификации изменяют саму коллекцию `setA` на месте.
* **Так правильно:** если нужно сохранить исходный набор, сначала сделать копию `HashSet<string> result = [..setA]; result.UnionWith(setB);` или использовать LINQ-методы `setA.Union(setB)`.

:::gap

## Под капотом и нюансы

### Как это устроено: `Dictionary` без значений

Под капотом `HashSet<T>` устроен практически так же, как `Dictionary<TKey, TValue>`, только без второй колонки со значениями: он хранит массив корзин (`buckets`) и массив слотов (`slots`) с хэш-кодами. По сути, это «словарь одних только ключей». Благодаря такой архитектуре добавление (`Add`), удаление (`Remove`) и проверка наличия (`Contains`) выполняются за константное время `O(1)`.

### Математические операции над множествами

`HashSet<T>` поддерживает классическую теорию множеств прямо из коробки:

| Метод | Операция | Что делает с исходным набором `A` |
| --- | --- | --- |
| `A.UnionWith(B)` | Объединение (`A U B`) | Добавляет в `A` все недостающие элементы из `B` |
| `A.IntersectWith(B)` | Пересечение | Оставляет в `A` только те элементы, которые есть и в `B` |
| `A.ExceptWith(B)` | Разность (`A \ B`) | Удаляет из `A` все элементы, которые встречаются в `B` |
| `A.SymmetricExceptWith(B)` | Симметрическая разность | Оставляет только уникальные элементы, которых нет в пересечении |
| `A.IsSubsetOf(B)` | Проверка подмножества | Возвращает `true`, если все элементы `A` содержатся в `B` |

### Компараторы и регистр строк

Как и в словаре, строковое множество по умолчанию различает заглавные и строчные буквы (`"Admin"` и `"admin"` считаются разными). Чтобы игнорировать регистр, передайте компаратор в конструктор:

```cs
var emails = new HashSet<string>(StringComparer.OrdinalIgnoreCase)
{
    "User@Mail.ru",
    "user@mail.ru" // Не добавится, так как без учёта регистра строки равны
};

```

### Когда нужен порядок: `SortedSet<T>`

Если помимо уникальности вам важно, чтобы элементы всегда автоматически поддерживались в отсортированном виде (например, таблица уникальных рекордов по возрастанию), используйте `SortedSet<T>`. Под капотом он построен на красно-чёрном дереве поиска (*Red-Black Tree*), поэтому операции вставки и поиска занимают `O(log N)`, зато перебор в `foreach` всегда выдаёт элементы строго по порядку.

> [!NOTE]
> Если нужно проверить наличие элемента по значению, которое отличается от типа хранения (например, искать строку по `ReadOnlySpan<char>` без создания новой строки в памяти), используйте метод `set.GetAlternateLookup<ReadOnlySpan<char>>()`, появившийся в .NET 9.
