# Многомерные и зубчатые массивы ([,], [][])

Как представить в коде шахматную доску, таблицу оценок по предметам или расписание звонков с разным числом уроков в каждом дне?

:::gap

## Кратко

Когда обычного списка в одну линию мало, данные удобно раскладывать по таблицам и сеткам. Двумерный прямоугольный массив `[,]` хранит строгую таблицу с одинаковым числом столбцов в каждой строке — идеально для игровых карт или матриц. Зубчатый массив `[][]` — это «массив массивов», где каждая строка может иметь собственную длину, что экономит память для неровных данных вроде расписания занятий или списков групп разного размера.

:::gap

## Быстрый пример

Объявим строгую таблицу `2x3` и зубчатый массив со строками разной длины:

```cs
// Прямоугольный массив (матрица: 2 строки, 3 столбца)
int[,] matrix = {
    { 1, 2, 3 },
    { 4, 5, 6 }
};
Console.WriteLine(matrix[1, 2]); // 6 (вторая строка, третий столбец)

// Зубчатый массив (массив из 2 независимых массивов)
int[][] jagged = [
    [10, 20],
    [30, 40, 50, 60]
];
Console.WriteLine(jagged[1][3]); // 60 (второй подмассив, четвёртый элемент)

```

:::gap

## Как это работает

При выполнении кода среда .NET строит две принципиально разные структуры в памяти и предоставляет свой синтаксис координат для каждой:

1. **Прямоугольная сетка (`int[,]`).** Запятая внутри квадратных скобок создаёт единую таблицу с фиксированными размерами (в примере — 2 строки и 3 столбца). Все строки здесь обязаны иметь одинаковую ширину.
2. **Координаты через запятую (`matrix[1, 2]`).** Обращение идёт сразу по двум индексам: сначала номер строки (`1`), затем номер столбца (`2`). Поскольку отсчёт начинается с нуля, `[1, 2]` указывает на правый нижний элемент `6`.
3. **Массив массивов (`int[][]`).** Две пары скобок означают, что перед нами обычный одномерный массив, внутри ячеек которого лежат ссылки на другие одномерные массивы. Первая строка хранит 2 числа, а вторая — 4.
4. **Двойная индексация (`jagged[1][3]`).** Сначала выражение `jagged[1]` достаёт второй внутренний массив `[30, 40, 50, 60]`, а вторые скобки `[3]` берут из него четвёртый элемент (`60`).

> [!TIP]
> Цикл `foreach` по прямоугольному массиву `matrix` автоматически обходит все его ячейки подряд слева направо и сверху вниз, а вот `foreach` по зубчатому `jagged` на каждом шаге выдаёт целый вложенный массив `int[]`.

:::gap

## Грабли и частые ошибки

### 1. Использование зубчатого массива без создания вложенных строк

* **Так упадёт:** написать `int[][] grid = new int[3][]; grid[0][0] = 5;`. Внешний массив выделил место только под 3 пустые ссылки (`null`), самих внутренних массивов ещё нет — программа завершится с `NullReferenceException`.
* **Так правильно:** проинициализировать каждую строку отдельно перед заполнением: `grid[0] = new int[4];`.

### 2. Перебор матрицы через `matrix.Length` вместо `GetLength`

* **Так упадёт:** написать цикл `for (int i = 0; i < matrix.Length; i++)` для обхода строк в таблице `3x4`. Свойство `Length` возвращает **общее** количество всех ячеек (`12`), а не число строк (`3`), поэтому программа вылетит с `IndexOutOfRangeException`.
* **Так правильно:** узнавать размер каждого измерения через `matrix.GetLength(0)` (строки) и `matrix.GetLength(1)` (столбцы).

### 3. Путаница со скобками при обращении к элементам

* **Так не скомпилируется:** обращаться к прямоугольному массиву через двойные скобки `matrix[0][1]` или к зубчатому через запятую `jagged[0, 1]` (ошибка `CS0021` или `CS1501`).
* **Так правильно:** ориентироваться на объявление: если при создании была запятая `[,]`, ставим запятую `[i, j]`; если две пары скобок `[][]`, пишем `[i][j]`.

### 4. Разная длина строк в инициализаторе `[,]`

* **Так не скомпилируется:** написать `int[,] bad = { { 1, 2 }, { 3, 4, 5 } };`. Прямоугольный массив требует строгой сетки без пустых углов (ошибка `CS0847`).
* **Так правильно:** дополнить короткую строку значениями по умолчанию или заменить тип на зубчатый массив `int[][]`.

:::gap

## Под капотом и нюансы

### Сравнение `[,]` и `[][]`

| Критерий | Прямоугольный `[,]` | Зубчатый `[][]` |
| --- | --- | --- |
| Форма данных | Строгая таблица `N x M` | Строки произвольной длины |
| Расположение в памяти | Единый непрерывный блок в куче | Внешний массив ссылок + отдельные массивы в куче |
| Расход памяти | Минимальный (один заголовок объекта) | Выше (заголовок объекта у каждого подмассива) |
| Узнать число строк | `arr.GetLength(0)` | `arr.Length` |
| Узнать длину строки `i` | `arr.GetLength(1)` (одинакова для всех) | `arr[i].Length` (своя у каждой строки) |
| Скорость в горячих циклах | Чуть медленнее из-за расчёта смещения | Быстрее за счёт оптимизаций JIT для 1D-массивов |

### Устройство в памяти и парадокс производительности

В управляемой куче .NET прямоугольный массив `int[,]` лежит сплошным куском построчно (*row-major order*): сначала вся нулевая строка, сразу за ней первая и так далее. Это отлично дружит с кэшем процессора, но при каждом обращении `matrix[i, j]` среда выполнения вычисляет индекс по формуле `i * ширина + j` и проверяет границы по обоим измерениям.

Зубчатый массив `int[][]` разбросан в куче на несколько отдельных объектов, зато каждый внутренний массив — это обычный одномерный вектор. JIT-компилятор умеет выносить проверку границ одномерных массивов за пределы цикла, поэтому в интенсивных математических расчётах `[][]` часто работает быстрее, чем `[,]`.

### Трёхмерные массивы и трюк с плоским `1D`

В C# можно создавать массивы с тремя и более измерениями (например, для воксельного мира `int[,,] world = new int[16, 256, 16];`), а количество измерений узнать через свойство `arr.Rank`.

Однако в высоконагруженных играх и обработке изображений вместо `[,]` и `[,,]` часто используют обычный одномерный массив `int[]` длиной `width * height`, вычисляя координату вручную:

```cs
int width = 10;
int height = 5;
int[] flatGrid = new int[width * height];

// Запись в ячейку (x = 3, y = 2)
int x = 3, y = 2;
flatGrid[y * width + x] = 99;

```

Такой подход объединяет плюсы обоих миров: данные лежат единым блоком без лишних заголовков объектов, а JIT-компилятор работает с максимально быстрым одномерным массивом.
