# U•ᴥ•U Дока ИСИП — статическая документация с гибридным поиском

Статический сайт (GitHub Pages) документации ИСИП с гибридным поиском:

1. **Лексический слой (MiniSearch)** — мгновенный отклик 1–2 мс, нечёткий поиск
   (fuzzy 0.2) и поиск по префиксу: опечатки вида «стрка», «swich» находят темы.
   Локальный бандл: `js/libs/minisearch.min.js`.
2. **Семантический слой (transformers.js + rubert-tiny2)** — поиск по смыслу
   («вывод текста в консоль» → «Привет, мир!»). Все веса и WASM-рантайм
   лежат локально:
   - `js/libs/transformers.min.js` — Transformers.js v2 (ESM, импортируется лениво),
   - `js/libs/ort-wasm*.wasm` — ONNX Runtime Web,
   - `models/rubert-tiny2/` — fp32 модель (config + tokenizer + `onnx/model.onnx`).
3. **Оффлайн-векторизация** — вся база документов заранее превращена в векторы.
   В рантайме браузер векторизует только запрос и сравнивает косинусом
   с заранее посчитанными векторами из `data/embeddings.json`.

## Структура контента

Весь контент лежит в `content/`:

```
content/
  csharp/
    meta.json                  ← название, акцент, описание области
    osnovy/
      meta.json                ← название группы
      hello-world.html         ← страница темы
      types.html
    kollekcii/
      meta.json
      arrays.html
      lists.html
  sql/
    meta.json                  ← область «Базы данных (SQL)»
```

Шаблон страницы `_template.html` лежит в корне проекта — `sync` его не видит.

- **Область** — папка первого уровня: `content/<domain>/`.
- **Группа** — папка второго уровня: `content/<domain>/<group>/`.
- **Тема** — `.html`-файл внутри группы. Файлы и папки, начинающиеся с `_`,
  синхронизация игнорирует.

### `meta.json` области

```json
{
  "title": "C#",
  "accent": "#614fa8",
  "description": "Объектно-ориентированный строго типизированный язык..."
}
```

- `title` — русское название области (обязательно).
- `accent` — цвет шапки и hero (необязательно, по умолчанию `#6c47ff`).
- `description` — описание на странице области (необязательно).

### `meta.json` группы

```json
{
  "title": "Основы"
}
```

### Страница темы

Страница содержит **только** hero с уникальным SVG и статью. Шапку, хлебные
крошки, оглавление, поиск и подсветку кода добавляет `js/page.js` во время
загрузки. Минимальный шаблон — `_template.html` в корне проекта.

Единственные обязательные метаданные темы — русское название в `<title>`:

```html
<title>Привет, мир!</title>
```

Оглавление собирается из `h2`/`h3`. ID заголовков генерируются транслитом
автоматически (например, «Современный C#» → `sovremennyy-c`), поэтому вручную
их расставлять не нужно.

Клик по пункту оглавления плавно ставит соответствующую секцию по центру
экрана, подсвечивает её анимацией `active-flash` и записывает якорь в адрес
(`#id`). Последняя секция, которую нельзя отцентрировать, прижимается к низу
окна. Пустое пространство под статьёй не добавляется.

## `data/structure.json`

Это **единственный источник порядка** и данных для поиска. Он генерируется
скриптом `scripts/sync-structure.js` и не редактируется вручную:

```json
{
  "csharp": {
    "order": 10,
    "title": "C#",
    "accent": "#614fa8",
    "description": "...",
    "groups": [
      {
        "id": "osnovy",
        "order": 10,
        "name": "Основы",
        "topics": [
          {
            "order": 10,
            "title": "Привет, мир!",
            "url": "content/csharp/osnovy/hello-world.html",
            "keywords": "привет console.writeline класс ..."
          }
        ]
      }
    ]
  }
}
```

- `id` группы — имя её папки. Если переименовать русское название в
  `meta.json`, группа сохранит своё место.
- `order` есть у области, группы и темы. Сортировка выполняется при отрисовке,
  поэтому изменение `order` в `structure.json` видно сразу после перезагрузки,
  без повторной синхронизации.
- `keywords` извлекаются из текста статьи автоматически и используются
  лексическим поиском.

## Как добавить тему

1. Создайте файл `content/<domain>/<group>/<slug>.html` по шаблону
   `_template.html`.
2. Укажите русское название в `<title>`, оставьте пустой маркер
   `HERO_SVG_START … HERO_SVG_END` в `.topic-hero` (SVG генерируется отдельным
   `hero_svg.md`) и напишите статью с `h2`/`h3`.
3. Для **новой** темы можно добавить seed-порядок в `<head>`:

   ```html
   <meta name="order" content="25">
   ```

   Число лучше согласовать по `data/structure.json` (например, между 20 и 30).
   Для существующей темы тег не нужен: её порядок уже хранится в
   `structure.json`.
4. Запустите синхронизацию:

   ```bash
   npm run sync
   ```

   Скрипт просканирует `content/`, прочитает `<title>`, соберёт ключевые слова,
   сохранит существующие `order`, добавит новые сущности и удалит seed-теги.
5. Если добавляли/удаляли темы или меняли URL — пересоберите векторы:

   ```bash
   npm run sync:embeddings
   ```

   Или отдельно: `npm run build:embeddings`.

### Порядок: что главнее

- Существующая запись в `structure.json` всегда сохраняет свой `order`.
- Seed из HTML/meta.json используется **только** для новой сущности.
- Если у существующей темы есть seed, но порядок уже задан в `structure.json`,
  seed игнорируется и удаляется, а в консоль выводится предупреждение.
- Принудительно применить seed из HTML ко всем темам:

  ```bash
  node scripts/sync-structure.js --apply-html-order
  ```

- Пересобрать порядок с нуля (только по seed-значениям и авто-нумерации):

  ```bash
  node scripts/sync-structure.js --reset
  ```

- Без seed новая тема получает `max(order родителя) + 10`.

## Alert-блоки в Markdown

В `.md`-темах поддерживаются GitHub-style alert-блоки:

```markdown
> [!NOTE]
> Полезная информация для пользователя.

> [!TIP]
> Совет, как сделать лучше или быстрее.

> [!IMPORTANT]
> Ключевая информация, без которой ничего не заработает.

> [!WARNING]
> Важное предупреждение, требующее внимания.

> [!CAUTION]
> Опасность! Это действие может привести к потере данных.
```

Теги можно писать в любом регистре. Внутри блока работает обычное
Markdown-форматирование: ссылки, списки, `код`, жирный шрифт и блоки кода.
Вкладывать один alert-блок в другой нельзя.

## Консоль управления `doka.bat`

Для Windows есть интерактивная консоль `doka.bat`. Она показывает:

- время последней синхронизации `data/structure.json`;
- время последнего пересчёта `data/embeddings.json`;
- когда последний раз менялся контент;
- нужна ли синхронизация/векторизация;
- запущен ли dev-сервер на порту 5173 (с PID, чтобы его можно было найти
  в Диспетчере задач);
- установлены ли зависимости и на месте ли модель.

Меню позволяет:

1. запустить dev-сервер без обновлений;
2. запустить с `sync`;
3. запустить с `sync` + пересборкой эмбеддингов;
4. выполнить только `sync`;
5. выполнить только `build:embeddings`;
6. выполнить `sync` + `build:embeddings`;
7. прогнать семантический тест;
8. открыть сайт в браузере;
9. остановить dev-сервер;
10. установить/обновить зависимости;
11. открыть дополнительное меню (`--dry-run`, `--reset`, `--apply-html-order`, проверка JS).

Сервер запускается в отдельном окне с заголовком «Doka ISIP dev». Пункт 9
останавливает именно слушающий процесс на `127.0.0.1:5173` (вместе с окном),
а не любые соединения с этим портом.

Быстрые команды без меню:

```bat
doka.bat run          :: просто запустить dev-сервер
doka.bat sync         :: синхронизировать structure.json
doka.bat build        :: пересобрать embeddings.json
doka.bat update       :: sync + build, без запуска сервера
doka.bat update-run   :: sync + build + запуск сервера
doka.bat status       :: показать статус
doka.bat stop         :: остановить dev-сервер
```

## Локальная админка

`admin.html` работает только на локальном `scripts/dev-server.js`
(на GitHub Pages редактирование недоступно). Откройте
`http://127.0.0.1:5173/admin.html`.

Пароль по умолчанию — `isip-admin`, переопределяется переменной окружения
`DOKA_ADMIN_PASSWORD`.

Что умеет админка:

- создавать, переименовывать и редактировать области и группы;
- удалять области, группы и темы с подтверждением: для области или группы
  нужно ввести её название;
- перемещать темы между группами одной области;
- создавать темы `.md` и `.html`, редактировать содержимое с предпросмотром;
- менять `order` у областей, групп и тем прямо в интерфейсе — без ручной
  правки `data/structure.json`;
- переключаться кнопкой «Просмотр» на главной и странице области в обычный
  вид — без кнопок редактирования и полей порядка;
- после сохранения темы автоматически пересобирать `structure.json`
  и `embeddings.json`.

Кнопки `+ область`, `+ группа`, `+ тема`, меню действий `›` и поля порядка
появляются только когда бэкенд доступен, то есть при запуске через `doka.bat`
или `node scripts/dev-server.js`.

## Скрипты

| Команда | Что делает |
|---|---|
| `doka.bat` | интерактивная консоль управления (Windows) |
| `node scripts/status.js` | статус синхронизации, эмбеддингов и контента |
| `npm run sync` | сканирует `content/`, обновляет `data/structure.json`, удаляет seed-теги |
| `npm run sync:embeddings` | `sync` + пересборка `data/embeddings.json` |
| `npm run build:embeddings` | пересобрать векторы из `structure.json` и текста страниц |
| `npm run test:semantic` | смоук-тест семантики в Node |
| `npm run dev` | локальный статический сервер (порт 5173) |

Полезные флаги `scripts/sync-structure.js`:

- `--dry-run` — показать дерево и планируемые изменения, ничего не записывая;
- `--verbose` — вывести области, группы и темы с порядком;
- `--apply-html-order` — принудительно взять `order` из HTML;
- `--reset` — игнорировать старый `structure.json`;
- `--embeddings` — после синхронизации запустить сборку векторов.

## Промпт для нейросети

Приложите к запросу:

- `_prompt.md` — основной промпт с правилами страницы;
- `_example.html` — эталон разметки и стилей;
- `_template.html` — минимальный шаблон;
- `data/structure.json` — текущая структура и порядок;
- `hero_svg.md` — отдельный промпт для hero-иллюстрации.

В `_prompt.md` уже описано, что должно быть в статье, и почему SVG-блок
в `.topic-hero` остаётся пустым: иллюстрацию генерирует отдельный
`hero_svg.md`.

После генерации запустите `npm run sync` (и `npm run sync:embeddings`, если
нужно обновить поиск).

## Ранжирование выдачи

- Сначала мгновенно показываются точные и fuzzy-совпадения MiniSearch.
- Через 250 мс после ввода запрос векторизуется (mean pooling, normalized);
  документы с косинусным сходством **> 0.45** дописываются ниже, дубли по `url`
  отсекаются; смысловые пункты помечаются бейджем `смысл`.
- Модель (≈111 МБ fp32) загружается лениво — при первом открытии окна поиска;
  пока идёт загрузка, внизу модалки виден индикатор «Инициализация ИИ-поиска…».
- Никаких внешних обращений к CDN в рантайме — всё локально.

## Деплой на GitHub Pages

Пушьте весь репозиторий целиком: Pages отдаёт статику как есть.
`node_modules/`, `.cache/` и транспортные файлы исключены через `.gitignore`.
Клиенту нужны `index.html`, `domain.html`, `content/`, `css/`, `fonts/`, `js/`,
`data/` и `models/`.

Важно: `data/structure.json` нужно коммитить. После `npm run sync` seed-теги
из HTML удаляются, и именно `structure.json` хранит порядок и ключевые слова.

## Известные ограничения

- `model_quantized.onnx` (~2 МБ вместо 111 МБ fp32) можно положить в
  `models/rubert-tiny2/onnx/` и переключить `quantized: true` в `js/search.js`
  и `scripts/build-embeddings.js` — репозиторий и кэш браузера станут легче.
- `js/page.js` подключает `search.js` и `highlight.min.js` динамически; на
  страницах `index.html` и `domain.html` поиск подключён статически.
